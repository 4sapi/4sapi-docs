# 为什么去掉 AI 口癖，文章还是没有活人感

这几年，很多人把“去 AI 味”理解成一项文字清洁工作：删掉“不是……而是……”，少用几个“底层逻辑”“关键抓手”“最后一公里”，把段落切短一点，再补几处口语化表达。

这些调整当然有用。读者看到过量的固定句式，确实会很快猜到文章是模型生成的。但它们解决的通常只是表面问题。文章即使没有明显的 AI 口癖，仍然可能像一份完成度很高的空白表格：观点齐全，结构完整，句子顺滑，读完却不知道作者究竟是谁，也不知道这段话为什么非要在今天由这个人写出来。

真正的活人感，不是把句子变得不工整，也不是故意加入错别字、口头禅和情绪词。它来自文字背后确实有一个人生活过、判断过、犹豫过，并且愿意为自己的判断承担一点风险。

本文不讨论某个模型的排行榜，也不提供一张“禁用词清单”。我们只解决一个问题：为什么文章看起来什么都有，却仍然没有活人感？读完之后，你应该能判断一篇稿子到底缺的是语言修饰，还是缺真实材料；也能知道怎样和 AI 协作，才不会让模型替你编造一个看起来很完整的自己。

## 一、AI 味最明显的地方，往往不是句式

先看一个常见的写作任务：

> 请写一篇文章，劝大家养成每天写日记的习惯，要求真诚、有温度、有启发。

模型通常可以很快给出一篇结构完整的文章。它会先说现代人生活节奏很快，接着说记忆会随着时间流逝，然后把日记定义为与自己对话的方式，最后落到“从今天开始记录”这样的结尾。

这篇文章未必有语病，甚至可能有几句很漂亮的话。但它的问题也很明显：任何一个人都可以写，任何一个人都可以署名，文章中的经历并不需要这个作者真正出现。

模型知道“日记”在公共表达里通常意味着什么，却不知道你为什么突然想写日记。是某天翻到旧照片，发现自己已经不记得照片里的心情？是工作几年后，意识到每周都在重复同一套生活？还是你曾经认真写过几个月，后来因为某件事停了下来？

这几个问题没有答案，模型就只能调用“关于日记的平均知识”。它写出来的不是你的故事，而是人类社会对日记这个词的共同印象。

所以，判断 AI 味时，第一步不是数“不是而是”出现了几次，而是问：

这段文字里有没有只有作者才知道的事实？

有没有一个别人不一定同意、但作者确实这样判断的观点？

有没有一处具体细节，能够证明作者不是站在概念外面谈论它？

如果三个问题都答不上来，换掉几个词也只是把“机器生成”伪装得更自然。

## 二、活人感不是随意，而是有来处

很多人误以为“有人味”的文字就应该松散、跳跃、像聊天一样。于是他们要求模型少列提纲、多用口语、偶尔说半句没有说完的话。

结果往往是另一种模板：看上去很随意，实际上每个停顿、每个感叹都很平均；看上去很真实，实际没有任何可核验的生活细节。

真正的活人感通常有四个来源。

### 1. 有位置

作者不是在空中讨论一个主题，而是站在某个具体位置上说话。

同样是谈 AI 写作，产品经理可能关心团队如何审核内容，学生可能关心自己明明有想法却写不出来，程序员可能关心怎样把文章生产流程接入自己的工具链。位置不同，关注点、举例方式和结论都不会一样。

“AI 会改变写作”是一句没有位置的话；“我第一次让模型替我写周报时，最不舒服的不是它写错了，而是它把我一周里真正发愁的事情压缩成了一个看起来很积极的结论”，这句话就有位置。

### 2. 有代价

没有代价的观点很容易趋同。因为作者不需要解释自己为什么这样想，也不需要面对被反驳的可能。

真正的判断通常和某种损失有关：你放弃了一个看似省事的方法，承认自己曾经做错过，或者选择了一条更慢但更符合长期目标的路径。

比如，“使用 AI 写作要保持独立思考”是正确但空泛的提醒。如果作者愿意补充：自己曾经因为模型写得太顺而直接发布，后来发现其中一段关键事实没有来源，导致整篇文章被迫重写，那么这个判断就有了重量。

### 3. 有不对称

模型喜欢把每个问题讲得平衡：一方面有优点，另一方面有缺点，最后得出“要结合实际情况”的结论。真实的人却很少对所有事情保持同样的距离。

我们往往对某件事特别在意，对另一件事并不关心；在一个问题上极其谨慎，在另一个问题上又会凭经验快速判断。这样的不对称，反而构成了人的辨识度。

如果你在文章里说“所有人都应该使用 AI”，读者很难相信；如果你说“我不建议刚开始写作的人一上来就装一堆 Skill，因为他们还没有形成自己的判断标准”，这就是一个可以被讨论的立场。

### 4. 有未完成的地方

模型天然倾向于把事情说圆。它会补上转折、解释隐含情绪、总结段落意义，尽量让每句话都服务于完整结论。

人写东西时常常会留下没有完全处理好的部分。不是因为能力不足，而是因为生活本来就有一些暂时说不清的地方。

一个人可能知道某段经历影响了自己，却还不知道具体影响在哪里；可能能描述一种不舒服，却暂时找不到准确的概念。文章保留一点这种迟疑，并不会自动变差。相反，它可以让读者感觉到作者不是在复述结论，而是在接近一个结论。

## 三、为什么模型会把文章写得“正确但不像你”

模型的训练目标决定了它很擅长生成公共表达。面对“写一篇关于自我成长的文章”，它会优先选择大多数读者都能理解、也不容易引发争议的说法。

这是一种能力，也是一种限制。

模型可以把零散信息组织成结构，可以帮你发现文章缺少过渡，可以根据读者调整解释深度。但如果输入里只有题目和要求，它并不知道哪些经历真的发生过，也不知道哪一个判断对你来说最重要。它只能根据语言概率，生成一篇在统计意义上合理的文章。

这里有一个很容易被忽略的区别：

模型可以生成“像一个有故事的人写的句子”，但不能凭空生成一个属于你的故事。

如果你让它直接补充真实细节，它往往会给出一些具有生活质感、却并未发生过的细节：凌晨两点亮着的台灯、窗外的雨声、桌边放凉的咖啡、手机屏幕上的某条消息。这些东西之所以危险，是因为它们读起来很像真的。

写作中的具体，不等于随便编一个物件。真正有效的细节必须来自材料，或者明确标注为虚构。否则，所谓“活人感”只是用另一种方式制造了不真实。

## 四、别先让模型写，先让模型采访你

在没有足够材料时，最有价值的动作不是继续优化提示词，而是把写作流程改成访谈流程。

你可以让模型先不要成稿，只做提问。下面这组问题适用于日记、工作经历、产品复盘、学习记录和个人观点等多种主题：

```text
先不要写文章，只采访我。

主题是：________。
文章的读者是：________。
我希望读者最终理解或做出什么判断：________。

请一次只问一个问题，并优先追问：
1. 这件事具体发生在什么时候、什么场景？
2. 当时有哪些人、物、动作或对话？
3. 我当时原本以为会怎样，后来实际发生了什么？
4. 哪个细节让我改变了看法？
5. 我现在仍然不确定什么？
6. 我是否做过与当前观点相反的事情？
7. 这件事给我带来的实际代价是什么？
8. 哪些内容是我亲身经历，哪些只是听说或推断？

不要替我补充没有说过的事实。
如果我的回答太抽象，请要求我提供一个真实场景或原话。
当你认为材料足够时，先输出“事实材料表”和“我的核心判断”，等待我确认后再写作。
```

这段提示的重点不在于问题数量，而在于顺序。它先把事实和判断从作者那里取出来，再让模型处理结构和语言。这样做可能比“直接生成一篇好文章”慢，但它减少了最昂贵的返工：你读完全文才发现里面没有一句真正属于自己。

## 五、一个小案例：同一个主题可以有两种完全不同的文章

假设主题是“为什么应该用语音记录日记”。

没有个人材料时，文章可能这样写：

> 语音日记降低了记录门槛，让我们可以随时随地保存当下的想法。与文字相比，声音还保留了语气和停顿，未来回听时更容易重新进入当时的情绪。

这段话没有错，但它更像产品说明。

如果作者提供了下面这些材料，文章就会改变：

- 自己曾经坚持写纸质日记，但每次写到一半都会开始整理句子；
- 有一天在回家路上，因为不想让某个念头消失，第一次对着手机说了三分钟；
- 回听时发现，自己反复说了“其实也没什么”，但每次语气都不一样；
- 后来才意识到，语音记录保存的不只是观点，还有当时没有意识到的迟疑；
- 目前仍然担心语音文件太多，正在寻找一种不会把记录变成新负担的整理方式。

有了这些材料，文章不需要再人为添加“深刻”“温暖”“治愈”等词。语气、动作、犹豫和限制本身已经在说话。

注意，真正重要的不是把材料全部写进去，而是让材料改变文章的判断。作者可能最后得出一个并不宏大的结论：语音日记的价值，不是让你记录得更多，而是让你在还没有想清楚时，也能先把声音留下来。

这就比“语音更方便”多了一层个人认识。

## 六、四种常见的伪活人感

### 1. 过量口语化

每句话都加“说实话”“其实吧”“你有没有发现”，并不会自动变得像人。真正的口语感来自思路和语境，而不是口头填充物。一个严肃的判断，即使句子很短，也可以很有人的气息；一段塞满网络口头禅的文字，也可能只是另一个模板。

### 2. 故意保留错误

把标点改乱、加入错别字、让模型故意写得不完整，只能制造粗糙感，不能制造经验。它还会损害准确性，尤其是技术文章和事实性内容。

### 3. 强行加故事

每一段都放一个“我有个朋友”，每个观点都配一段所谓亲身经历，反而会让读者警觉。故事必须解释观点从何而来，而不是作为装饰粘在观点后面。

### 4. 结尾替读者感动

当一个动作已经足够表达情绪，模型常常会再补一段总结：这让我们明白了什么，这正是成长的意义。这种解释不是永远错误，但如果每次都把余味翻译出来，读者就没有参与的空间了。

写完后可以做一个简单测试：删掉最后两句，看看前面的动作、事实和判断是否已经成立。如果文章立刻失去意义，说明前文可能还没有把内容写实。

## 七、让 AI 做它擅长的事，让人保留决定权

一个可靠的协作分工大致是这样：

| 环节 | 人负责什么 | AI 负责什么 |
| --- | --- | --- |
| 选题 | 为什么现在要写、真正想解决什么 | 帮忙拆解读者问题 |
| 材料 | 事实、经历、原话、限制和情绪 | 追问缺口、整理素材 |
| 判断 | 我怎么看、愿意承担什么立场 | 提供反例、指出跳跃 |
| 结构 | 哪些内容必须保留、哪些不能展开 | 设计顺序、合并重复 |
| 初稿 | 确认哪些话确实是自己的 | 组织语言、补足过渡 |
| 修改 | 哪些地方失真、过度解释或越界 | 检查逻辑、事实和表达 |
| 发布 | 是否愿意署名、是否经得起追问 | 做最后的格式检查 |

如果把全部工作都交给 AI，最先消失的不是文采，而是选择。文章会越来越完整，却越来越难说明为什么必须这样写。

## 八、发布前的“活人感”检查清单

可以把下面的问题复制到每篇稿子的最后，让模型做审稿人，但最终答案必须由作者确认：

```text
请不要润色，先审查这篇文章是否真的有作者存在。

请逐项回答：
1. 哪三处内容只能由作者本人提供？如果找不到，明确写“没有”。
2. 哪些句子只是公共正确意见，换一个作者也成立？
3. 哪些具体细节没有来源，可能是模型自行补写？
4. 作者的核心判断是什么？是否存在可被反驳的立场？
5. 文章有没有把一个尚未想清楚的问题伪装成确定结论？
6. 哪些地方解释过度，替读者完成了本来可以保留的余味？
7. 如果删掉所有形容词，文章还剩下哪些事实、动作和判断？

不要为了让文章更像人而编造故事、添加错误或制造口语填充。
请把问题列出，不要直接替我改写，等待我确认材料后再修改。
```

这张清单不能保证文章一定优秀，但可以有效拦住一个常见错误：把语言上的自然，误认为内容上的真实。

## 结语：不要把自己训练成一个更像模型的人

模型生成文字的速度会越来越快，流畅、完整、结构合理的文章也会越来越便宜。真正稀缺的不会是“像文章的文字”，而是一个人对经验的保留、对事实的诚实，以及愿意说出自己并不完全安全的判断。

所以，去 AI 味最重要的一步，不是建立更长的禁用词表，而是把自己的材料带回写作现场。你经历过什么，在哪个瞬间改变了看法，仍然不确定什么，又愿意为什么负责，这些内容无法由模型替你凭空生成。

活人感不是一种字体，也不是一种腔调。它是文章里确实有人生活过的证据。
