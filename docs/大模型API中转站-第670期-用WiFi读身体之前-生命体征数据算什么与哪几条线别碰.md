# 用 WiFi 读身体之前：生命体征数据算什么、哪几条线别碰

WiFi 感知的 demo 很吸引人：房间空着，波形是平的；有人躺下，呼吸曲线出来了。看完第二个念头通常是"这能装在哪"。

问题就出在这个"哪"字上。同一套硬件，装在自家客厅和装在出租屋、员工工位、邻户隔壁，是完全不同的三件事——前者是技术实验，后两者是数据处理行为。

本文只讨论边界，不谈精度（那是上一篇）。说三件事：这类输出在数据分类上算什么、哪些部署场景本身越界、必须部署时能落地的技术与流程约束。

**先说明边界**：本文不给"不告知就采集他人信号"的步骤，也不写规避告知的做法，理由见第二节。

## 一、输出的东西比"有人"多得多

上一篇列的流水线，最终输出是这四类：人体 17 个关键点、生命体征（呼吸、心率）、房间指纹、漂移告警。这四类性质完全不同：

| 输出 | 能推断出什么 | 数据性质 |
| --- | --- | --- |
| 存在/人数 | 空间是否被占用、几个人 | 占用状态，弱识别 |
| 生命体征 | 呼吸、心率趋势；睡眠与健康 | 健康相关，最敏感 |
| 17 关键点 | 姿态、动作、跌倒；长期行为画像 | 行为/生物特征 |
| 房间指纹 | 设备与房间绑定 | 位置与设备标识 |

关键在**组合**：呼吸是生理指标、姿态是动作、房间指纹是设备状态，三者叠加若干天，就接近"这个空间里生活的人是谁、作息如何、身体怎样"——这已不是传感器读数，而是对人的画像。

所以它不是"PIR 的升级版"：PIR 只回答"有没有动"，WiFi 感知回答"这个人现在什么状态"，合规档位不同。

## 二、为什么"穿墙"这条不能当成卖点

这类设备的能力来源是"读信道的扰动"，而无线电不认墙。设备装在自己房间，信号穿过隔墙，同样会被人家的移动调制。也就是说，**技术上它天然能读到不属于你的空间**。

这在任何隐私框架下都站不住：

- 空间边界是隐私期待最基础的载体。隔着墙测量他人的生理与行为，无论是否留存原始数据，都构成对他人在其住所内活动的推断。
- 你无法向邻户做有效告知，也就无法取得任何形式的同意。
- 一旦发生误判（把邻户的活动当成自家异常），后果落在被误判的人身上，而不是部署者身上。

所以本文不提供"跨户部署"的任何技术建议，包括如何提高穿墙后的信噪比、如何区分自家与邻户的目标——这两类内容即便技术上可行，写出来只会降低滥用的门槛。

同样不写：隐蔽安装、伪装成路由器绕过告知、针对特定个人的追踪——这三类既不合适，也不构成工程问题。

## 三、数据分类：大概率落在"敏感个人信息"这一档

不同法域的条文不同，但判断路径类似。以两个常被引用的框架为例：

**欧盟 GDPR**：第 9 条把"揭示健康的数据"和"以唯一识别自然人为目的的生物识别数据"列为特殊类别，原则禁止、仅在满足例外条件时允许处理（[EUR-Lex 全文](https://eur-lex.europa.eu/legal-content/EN/TXT/HTML/?uri=CELEX:32016R0679)，检索于 2026-11-12）。WiFi 姿态与房间指纹是否构成生物识别，取决于是否被用于唯一识别——这是部署方式问题，不是技术属性。

**中国《个人信息保护法》**：第二十八条把生物识别、医疗健康列为敏感个人信息，并要求"特定的目的和充分的必要性"；第二十九条要求取得**单独同意**；第五十五条要求处理敏感个人信息前做**个人信息保护影响评估**（[全国人大网原文](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)，检索于 2026-11-12）。

这里不做逐条法律判断，只给工程结论：**输出生命体征或可识别个体姿态的系统，应按"敏感个人信息"设计，而不是按"匿名传感器数据"设计。** 举证责任在部署方。

还有一个容易忽略的第三层：无线电本身受监管。802.11bf 讨论的是 1 GHz 到 7.125 GHz 以及 45 GHz 以上的免许可频段，前提是遵守各地区的发射功率与占空比规定。为了"看得更清"而加大发射功率或改用未获许可的频段与波形，是另一类独立的合规风险。

## 四、部署时能真正落地的六条

如果场景确实需要（比如独居老人居家监护、自己的住宅、明确的科研实验），下面六条是可执行的约束，按优先级排列。

**1. 目的限定，写进需求。** "检测跌倒"与"监测作息"是两件事：前者输出事件，后者输出连续画像。不为后者顺手收集，是最有效的降险手段。

**2. 输出最小化：只算你要的那一列。** 姿态与生命体征是分开的模块。只需要"在/不在"时，就不开启心率和关键点，让敏感数据根本不产生。

**3. 原始 CSI 不出设备。** CSI 能反演出很多信息。把特征提取放在端上（ESP32 或本地网关），只上行聚合结果，能显著缩小泄露面；PyPI 轮子约 250 KB，可本地跑完整提取。

**4. 现场校准数据按个人数据对待。** 空房间基线与 8 个锚点描述了特定房间与特定人，常被当成"配置"放进共享目录；它应与业务数据同级管理，并有删除路径。

**5. 告知与同意分层。** 自住房屋对家庭成员说明即可；员工工位、出租房、护理机构需要机构层面的告知、可拒绝选项与访问控制。最容易被漏掉的是访客，他们无从得知房间里有这类设备。

**6. 留存与聚合。** 留"事件 + 聚合计数"，不留逐帧时序；期限与用途绑定；可识别到个人的记录设更短期限。

六条里第 2、3 条是技术手段，其余是流程。技术手段降泄露面，风险大头在流程：有没有告知、有没有留存超期、有没有超范围使用。

## 五、误判也是一种伤害

可靠性高度依赖现场校准（上一篇写了 600 帧下限与换房间重校），因此误判是常态：宠物、气流、邻户 AP、家具挪动都会造成漂移。

安防与监护场景里代价不对称：

- 把无人判成有人 → 误报警，浪费响应资源；
- 把有人判成无人 → 漏报，对独居监护是最坏情况；
- 把"异常姿态"判成"跌倒" → 可能引发不必要的上门，或者让真正的跌倒被当成噪声。

任何部署都该有第二信号（门磁、可穿戴、人工确认），并把"设备不确定"作为一等状态，而不是强行二分类。

## 六、技术上把精度换成隐私的三种做法

如果必须在"要能力"与"要隐私"之间折中，有三种常见做法，成本递增：

| 做法 | 牺牲 | 换来 |
| --- | --- | --- |
| 只输出聚合计数（如每 15 分钟一次在场人数） | 实时性、个体区分 | 逐帧时序不落盘 |
| 端上出特征、不上行原始 CSI | 远端重训能力 | 原始信号不出户 |
| 事件化输出（过阈值才发一条） | 连续观测 | 数据量与留存压力同步下降一个量级 |

三种做法都不改变"测量已经发生"这一事实，不能替代告知与同意，只缩小暴露面。

## 七、三个常见的自我说服，以及它们错在哪

**"只输出结果、不存原始数据，所以没问题。"**

不存原始信号确实降低泄露面，但"测量已经发生"没变：仍在处理他人的生理与行为推断，告知与目的限定不因不留存而免除。

**"设备装在我家，读到的都是我家的人。"**

无线电不认房产证：扰动来自所有会反射信号的东西，包括隔墙之后的邻居。要么用校准把范围收紧在自有空间内，要么承认它做不到"只看我家"。

**"只要不告诉具体是谁，就是匿名化。"**

姿态、作息与房间指纹的组合，足以把一个人从人群中挑出来。是否"可识别"取决于是否存在合理的重识别路径，而不是取决于你的表里有没有姓名列。按敏感个人信息设计，比争论"算不算匿名"更省事。

三句在评审会上常出现，共同点是把"技术上的降低"当成"合规上的免除"：前者是工程，后者要证据。

## 八、一份可以直接拿去评审的检查表

把这篇文章的约束压成一页，按部署前、部署中、上线后三段排：

| 阶段 | 必须回答的问题 | 不合格信号 |
| --- | --- | --- |
| 部署前 | 目的、输出哪几列、谁被测量 | 答不出"输出哪几列" |
| 部署前 | 怎么告知、能否拒绝 | 只有访客无从得知 |
| 部署前 | 范围是否限于自有空间 | 靠穿墙提高覆盖 |
| 部署中 | 校准记录存哪、谁能读、怎么删 | 校准文件放共享目录 |
| 部署中 | 原始 CSI 是否出设备 | 全量上行云端 |
| 上线后 | 留存期限是否绑定用途 | 无限期保留逐帧时序 |
| 上线后 | 误报与漏报怎么处置 | 只有告警，没有误报流程 |
| 上线后 | 有没有第二信号确认 | 单传感器直接触发上门 |

最容易跳过的是最后三行：前五行决定能不能合法开始，后三行决定跑起来会不会出事。

## 九、限制与结论

结论三条：

- **这不是传感器数据，是对人的推断。** 输出含生命体征或可识别姿态，就按敏感个人信息设计。
- **穿墙能力不是特性，是风险。** 跨出自有空间的部署没有可用的同意路径，本文也不提供这类做法。
- **工作量在流程不在算法。** 目的限定、最小化、告知、留存、访问控制这五件事，比换更准的模型更能决定它能否长期跑。

如果你的场景确实成立（自住、监护、科研），建议先写一页纸：目的是什么、输出哪几列、谁可以看、留多久、怎么删。这页纸写不出来，说明还没到部署的阶段。

还有一条：风险在部署后不会停止增长。房间重布置、家具移动、邻居换路由器都会让基线漂移；漂移以"误报变多"表现，团队往往先怀疑模型，最后才发现是环境变了。

运维上应把"重跑校准"列为定期动作，并记录校准前后的误报率——这两条数据比任何隐私政策都更能说明态度。
