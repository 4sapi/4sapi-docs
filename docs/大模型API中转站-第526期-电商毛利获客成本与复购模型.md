# 月销售额怎么拆才算得清：电商毛利、获客成本和复购模型

“月入百万”听起来很有冲击力，但销售额本身不能说明业务是否健康。

一笔订单卖得越多，可能也意味着更多物流、广告、支付、售后和退款成本。

真正要先算清楚的，是每一笔订单留下了多少可以继续经营的钱。

## 一、销售额只是第一层

一笔订单的基本关系是：

```text
销售额 = 订单数量 × 平均订单金额
```

如果平均订单金额是 5000 元，月销售额 100 万元对应 200 个订单。

如果平均订单金额是 2 万元，对应 50 个订单。

这两个业务的流量、销售周期、客服方式和交付压力完全不同。

所以看到一个销售目标时，先拆订单数和客单价，不要直接把它当成利润目标。

## 二、毛利和贡献毛利不是一回事

假设一笔订单卖 1000 元，产品成本 500 元，看起来毛利是 500 元。

但继续扣掉物流、支付手续费、平台费、广告、售后和退款之后，真正留下的钱可能少很多。

可以用下面的简化公式：

```text
贡献毛利 = 销售额 - 产品成本 - 物流 - 平台费 - 支付费 - 广告费 - 售后成本 - 退款损失
```

贡献毛利更接近这笔订单对经营的实际贡献。

如果贡献毛利为负，订单越多，问题越大。

## 三、先建立产品卡

产品卡不应只放标题和图片。

至少保存：

| 字段 | 说明 |
| --- | --- |
| product_id | 产品标识 |
| purchase_cost | 采购成本 |
| suggested_price | 建议售价 |
| min_price | 最低可接受价格 |
| margin_floor | 毛利底线 |
| lead_time | 交付时间 |
| available_stock | 可供库存 |
| supplier | 供应商 |
| alternatives | 替代方案 |
| restrictions | 不能承诺的内容 |

客户询价时，系统可以根据产品卡生成价格范围。

低于毛利底线的报价，必须要求人工确认。

## 四、获客成本要按有效结果计算

总广告费除以全部点击，不等于获客成本。

更有意义的口径是：

```text
有效获客成本 = 获客相关支出 / 新增合格客户数
```

这里的合格客户要先定义清楚。

只留下邮箱地址、不符合目标市场、没有真实需求信号的记录，不能算作合格客户。

如果线索来源不同，还应按来源分别计算，避免高质量渠道被低质量渠道的平均值掩盖。

## 五、B2C 和 B2B 的漏斗不一样

B2C 通常更关注：

```text
曝光 -> 点击 -> 加购 -> 支付 -> 复购
```

B2B 或高客单价业务更关注：

```text
有效线索 -> 需求确认 -> 报价 -> 谈判 -> 成交 -> 复购
```

两种业务都可以使用 AI，但优化重点不同。

B2C 可能更关心页面转化和客服响应速度。

B2B 更关心需求证据、报价质量、交付能力和跟进周期。

## 六、把 AI 成本挂到漏斗上

客户调研、SEO、客服、报价和订单分析的成本，应该关联到业务动作。

例如：

- 每个合格线索的调研成本；
- 每条有效询盘的客服成本；
- 每份有效报价的生成成本；
- 每个成交订单的 AI 成本；
- 每笔退款的分析成本。

如果只能看到“本月 AI 花了多少钱”，就无法判断哪些任务值得保留。

## 七、报价转化率反映什么

报价转化率可以先按这个口径计算：

```text
报价转化率 = 成交报价数 / 有效报价数
```

报价低不一定只是价格问题。

也可能是：

- 产品匹配错误；
- 交期不可信；
- 回复速度太慢；
- 报价没有回答客户关键疑虑；
- 付款和售后条件不清楚。

因此，报价系统要保留报价版本、产品卡版本和客户需求字段，方便回看是哪一环出了问题。

## 八、退款和交付要放进同一张表

前端自动化带来更多订单以后，后端指标不能恶化。

至少追踪：

- 发货准时率；
- 交付周期；
- 退款率；
- 售后响应时间；
- 客户投诉率；
- 供应商延期次数。

如果订单增长伴随退款率上升，说明系统正在把供应链问题放大。

## 九、复购比一次成交更值得跟踪

新客户通常需要支付获客成本。

老客户如果复购，新增获客支出可能较低，但仍要考虑服务、折扣和交付成本。

可以记录：

```text
first_order_at
repeat_order_at
repeat_order_count
repeat_revenue
repeat_contribution_margin
```

复购率不能只看有没有第二单，还要看复购带来的贡献毛利。

## 十、客户生命周期价值要保守估计

一个简化口径是：

```text
客户生命周期价值 = 预计累计贡献毛利 - 累计服务和维护成本
```

不要直接用销售额估算客户价值。

如果一个客户订单金额高，但每次都需要大量定制、折扣和售后，实际价值未必高。

估算时最好使用已经发生的历史数据，并明确样本数量和时间范围。

## 十一、每日经营看板应该显示什么

建议分成四组：

### 获客

有效线索率、有效回复率、首次响应时间。

### 成交

报价转化率、成交率、平均订单金额。

### 交付

准时交付率、退款率、投诉率和供应商延期。

### 价值

贡献毛利、有效获客成本、复购率和客户生命周期价值。

“生成内容数量”可以保留，但不应放在经营看板最前面。

## 十二、按来源和产品拆分

总表看起来正常，不代表每个渠道都正常。

一个来源可能带来很多低质量线索，另一个来源线索少但报价转化率更高。

一个产品可能销售额高但退款多，另一个产品订单少却贡献毛利稳定。

因此，指标至少按来源、产品、国家和客户类型拆分。

## 十三、设置停止线

经营模型需要明确什么时候暂停某条流程。

例如：

- 有效线索率连续下降；
- 获客成本超过贡献毛利可承受范围；
- 退款率连续上升；
- 交付周期超过客户承诺；
- 某个供应商连续延期；
- AI 自动化带来的人工返工超过节省时间。

停止线不是失败判断，而是防止问题继续扩大。

## 十四、先从一个产品和一种客户开始

不要一开始同时做十几个品类、所有国家和全部渠道。

先选择一个产品，定义一类客户，跑通：

```text
线索
-> 需求确认
-> 报价
-> 订单
-> 交付
-> 复购
```

每一步都记录成本和结果。

当一条链路能够稳定运行，再考虑扩大流量和产品范围。

## 十五、结论

月销售额只是经营结果的一部分。

真正需要持续观察的是贡献毛利、有效获客成本、报价转化率、交付稳定性和复购价值。

AI 可以帮助你采集、整理、分析和提醒，但不能替你把亏损订单变成利润，也不能用内容产量代替客户价值。

把业务拆成可计算的订单、成本、状态和结果，才能知道自动化是在放大增长，还是只是在更快地放大问题。
