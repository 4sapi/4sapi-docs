# Obsidian 插件如何分层选择并制作可编辑图表
Obsidian 插件越多，更新、权限和兼容性变量就越多；画图工具也不是装上就能得到可复用的结果。本文围绕 Editing Toolbar、Diagrams 和 Excalidraw，说明如何按排版、正式图表和自由草图分层选择，并用最小示例确认每个插件的输入、输出与可编辑性。文中只讨论可复现的步骤，不把单次结果扩展成产品承诺；每个结论都标注前提、证据和无法覆盖的边界。读者可以先完成最小验证，再按自己的版本、权限和数据补充实验。




~~~text
Editing Toolbar：少记 Markdown 格式命令
Diagrams：画正式流程图和架构图
Excalidraw：画手绘白板和知识结构图
~~~

插件不是越多越好。每多装一个插件，就多一个更新、权限、兼容性和数据处理变量。建议一次只安装一个，确认它能正常工作后再继续。

## 一、社区插件从哪里安装

Obsidian 的第三方插件统一从设置进入。不要从搜索结果里随便下载压缩包，也不要把来路不明的插件复制进 `.obsidian/plugins`。

操作路径通常是：

1. 打开 Obsidian。
2. 点击左下角齿轮进入 **Settings**。
3. 进入 **Community plugins** 或“第三方插件”。
4. 如果显示安全模式已开启，先按界面提示关闭安全模式。
5. 点击社区插件市场旁边的 **Browse**。
6. 在搜索框输入插件名称。
7. 打开插件详情，核对名称、作者、说明和更新时间。
8. 点击安装。
9. 回到已安装插件列表，打开启用开关。

### 安全模式的按钮为什么容易点反

有些界面显示的是当前状态，有些按钮显示的是“点击后要执行的动作”。判断标准不要只看按钮文字，而要看安装完成后第三方插件列表里是否出现插件，以及右侧启用开关是否处于打开状态。

如果插件市场显示已安装但工具栏没有变化，先回到已安装插件列表确认启用，再重启 Obsidian 或用 `Ctrl + P` 搜索插件命令。

## 二、安装前的最小检查

每个插件安装前看四项：

| 检查项 | 目的 |
| --- | --- |
| 名称 | 防止点到相似插件 |
| 作者 | 确认不是同名搬运版本 |
| 最近更新时间 | 判断是否长期无人维护 |
| 权限和说明 | 知道它会处理什么数据 |

插件可以读写 Vault 文件，也可能调用网络服务。涉及 AI、同步或远程服务的插件，不要在测试前导入客户资料、密码、OAuth 或个人授权信息。

## 三、Editing Toolbar：不记语法也能排版

### 它解决什么问题

Editing Toolbar 会在编辑区顶部或光标附近提供一排格式按钮，适合经常写文章、课程笔记和公众号草稿的人。

它通常可以帮助你快速完成：

- 标题和段落格式
- 粗体、斜体和删除线
- 列表和引用
- 文字颜色和背景色
- 格式刷
- 常用 Markdown 命令

### 安装后怎么配

打开插件设置，先处理三项：

1. **位置**：新手建议先选顶部，工具栏固定，容易找到；熟悉后再试光标跟随。
2. **命令**：只保留自己常用的按钮，不要把整套命令都塞进工具栏。
3. **栏目数**：可以先设置在 12 列左右，再根据窗口宽度调整。

### 格式刷怎么用

1. 先选中一段已经排好格式的文字。
2. 点击格式刷按钮。
3. 再选中目标文字。
4. 检查目标段落是否继承了格式。

如果格式刷没有生效，先确认你选中的是文字，而不是整个文件列表项目；再检查插件是否已启用。

### Editing Toolbar 的验收笔记

新建一篇测试笔记，写下：

~~~markdown
# 格式测试

普通文字、粗体、列表和引用。
~~~

用工具栏分别修改一处，关闭并重新打开笔记，确认格式仍然保留。通过后再把工具栏用于正式文章。

## 四、Diagrams：画正式流程图

Diagrams 适合流程图、架构图、系统图和产品方案图。它背后的图形编辑方式通常更规整，适合放进课程文档、技术方案和长文。

### 适合画什么

- RAG 检索流程
- API 请求链路
- Agent 工作流
- 系统组件关系
- 用户注册和支付流程
- 产品功能架构

### 创建一张图

按 `Ctrl + P` 打开命令面板，搜索 Diagrams 的创建或新建图命令。画布打开后，先用矩形放模块，再用箭头连接，最后补文字。

保存后，文件列表里通常会出现 `.drawio` 或 `.svg` 等图文件。具体文件扩展名取决于插件当前版本和保存方式。

### 图文件怎么放

建议把图放到当前文章旁边的 `assets` 文件夹：

~~~text
03-未发布/
  ├── RAG文章.md
  └── assets/
      ├── rag-online-flow.drawio
      └── rag-online-flow.svg
~~~

Markdown 中可以引用导出的图片：

~~~markdown
![RAG 在线检索流程](assets/rag-online-flow.svg)
~~~

保留 `.drawio` 源文件，后续要改节点和箭头时还能继续编辑；只保存 `.svg`，以后修改会不方便。

### 让 AI 画 RAG 流程图

可以把下面提示交给 Claudian、Claude Code 或其他能操作当前 Vault 的工具：

~~~text
请使用当前 Obsidian Vault 里的 Diagrams 插件画一张正式的 RAG 在线检索流程图。

图中包含：
1. 用户问题
2. 问题编码
3. 相似度计算
4. Top-K 召回
5. 重排
6. 大模型回答

要求：
- 横向布局，箭头从左到右
- 节点文字使用中文
- 文件保存到当前文章旁边的 assets 文件夹
- 保留可继续编辑的源文件
- 不修改其他笔记，不删除已有图文件

完成后告诉我：
1. 创建了哪些文件
2. 当前文章应该引用哪个文件
3. 在 Obsidian 里如何打开并继续编辑
~~~

AI 画图前要先确认它有权调用对应插件。不要因为 Prompt 写得完整，就默认工具一定能自动点击 Obsidian 界面。

## 五、Excalidraw：画手绘白板图

Excalidraw 更适合自由草图、概念讲解、知识结构图和头脑风暴。它的价值不在于画得规整，而在于让复杂关系先快速出现在画布上。

### 常用工具

- 选择工具
- 矩形和椭圆
- 箭头和连接线
- 文字
- 自由画笔
- 橡皮和撤销

### 创建一张白板图

1. 按 `Ctrl + P` 打开命令面板。
2. 搜索 Excalidraw。
3. 选择创建新绘图。
4. 先放模块，再连接关系，最后补解释文字。
5. 保存到当前笔记旁边或 `assets` 文件夹。

建议先用黑白和两种形状完成第一版，不要一开始就花时间调颜色。图的结构清楚，比配色漂亮更重要。

### 让 AI 画知识库结构图

~~~text
请使用当前 Obsidian Vault 里的 Excalidraw 创建一张手绘风白板图。

主题：AI 产品经理的知识库结构
图中包含 5 个模块：
- 收件箱
- 原始资料
- 知识库
- 未发布内容
- 已发布内容

布局要求：
- 中间放“知识库”
- 其他模块围绕在四周
- 用箭头表示资料流向
- 风格简单，像白板草图，不要花哨
- 保存到当前笔记旁边
- 不修改已有绘图和笔记

完成后告诉我文件名、保存位置和在 Obsidian 中打开的方法。
~~~

打开生成的 `.excalidraw` 文件，检查节点是否重叠、文字是否超出画布、箭头方向是否正确。AI 生成的图必须人工看一眼，不能只根据“已完成”三个字验收。

## 六、Diagrams 和 Excalidraw 怎么选

| 需求 | 选择 |
| --- | --- |
| 正式技术架构 | Diagrams |
| 产品流程和业务流程 | Diagrams |
| 课程讲解草图 | Excalidraw |
| 知识关系快速发散 | Excalidraw |
| 需要交给别人继续编辑 | 两者都保留源文件 |
| 只需要放进文章的图片 | 导出 SVG/PNG，但保留源文件 |

不要试图用 Excalidraw 画每一条标准系统连线，也不要用 Diagrams 做每次头脑风暴。工具要服从任务。

## 七、一次只启用一个插件

推荐按这个顺序测试：

1. Editing Toolbar：测试格式按钮和格式刷。
2. Diagrams：创建一个两节点流程图并保存。
3. Excalidraw：创建三个模块并连接箭头。

每次完成后记录：

- 插件名称和版本
- 是否启用
- 生成了哪些文件
- 文件保存在哪里
- 是否能重新打开
- 是否影响其他笔记

如果某个插件异常，先关闭它，确认 Obsidian 主体仍能正常打开，再决定是否升级或替换。

## 八、给 AI 的插件检查 Prompt

如果你使用能读写 Vault 的 AI 工具，可以先让它只检查插件状态：

~~~text
请检查这个 Obsidian Vault 中下列插件的启用状态：
Claudian、Diagrams、Excalidraw、Remotely Save、Editing Toolbar。

只告诉我：
- 哪些已安装
- 哪些已启用
- 哪些缺失
- 哪些配置需要我在界面中手动确认

不要安装清单外插件，不要修改笔记正文，不要读取、展示或记录个人登录信息、授权信息和私密配置。
完成后告诉我检查了哪些位置，不要执行删除、移动或批量修改。
~~~

## 总结

插件安装的目标不是把 Obsidian 变成一个复杂的全能软件，而是让三个动作更顺：

~~~text
写文章更快
画图更清楚
AI 更容易理解你的资料结构
~~~
