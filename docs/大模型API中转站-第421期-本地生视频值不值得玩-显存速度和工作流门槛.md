# 本地生视频值不值得玩：显存、速度和工作流门槛

本地生图已经可以作为日常实验工具，本地生视频则是另一种体验：模型更大，显存压力更高，单次生成时间更长，而且一次成功并不等于结果可用。很多人看到“消费级显卡也能运行开源视频模型”，就直接把它理解成“家用电脑可以稳定生产视频”，中间少算了分辨率、帧数、采样步数、显存溢出和重试次数。

本文不做视频模型排名，只回答一个问题：什么条件下值得在本地尝试视频生成，怎样用官方公开数据做第一次验证，以及为什么“能生成”与“能生产”是两件事。

## 1. 先把本地生视频拆成四个成本

### 模型成本

视频模型往往同时处理空间和时间维度，参数、VAE、文本编码器和中间缓存都会占用资源。同一个模型可能有不同参数规模、不同分辨率版本和不同任务版本，例如文生视频、图生视频和视频编辑并不一定共用同一套权重。

### 显存成本

视频生成过程中不仅要加载模型权重，还要保存一段视频的多帧中间状态。分辨率从 480P 提高到 720P，帧数从短片增加到长片，都可能放大显存和计算压力。offload 可以缓解显存不足，但会增加数据搬运和时间。

### 时间成本

单次生成时间取决于模型、GPU、分辨率、采样步数、优化方式和是否启用 CPU offload。官方 README 的单卡时间可以作为一个条件样本，不能直接推导所有显卡和所有工作流的耗时。

### 重试成本

视频比图片更容易出现动作不连贯、人物变形、闪烁、镜头逻辑错误或主体漂移。一个可用片段可能需要多次生成，因此要用“得到一条可用片段的总时间”评估，而不是只看第一次运行时间。

## 2. 用 Wan2.1 的官方数据做基线

Wan2.1 官方仓库当前 README 给出了一个很有用的入门基线：T2V-1.3B 模型需要约 8.19 GB VRAM；在 RTX 4090 上生成 5 秒 480P 视频约需 4 分钟，且说明该数据没有使用量化等优化技巧。这个数字只适用于该模型、该分辨率、该显卡和官方给出的测试条件，不能写成“所有本地视频都只要 4 分钟”。[Wan2.1 官方仓库](https://github.com/Wan-Video/Wan2.1)（访问日期：2026-08-07）

同一仓库还说明，1.3B 模型支持 480P 和 720P，但由于 720P 训练量有限，480P 结果通常更稳定；14B 系列支持更高规格的任务和分辨率，但运行条件也更重。这个信息足以说明两件事：8 GB 级显存已经可以尝试某些小模型，但不等于可以自由选择所有视频模型；分辨率和模型规模需要同时纳入预算。

## 3. 第一次尝试应该选择什么任务

建议从“短时长、低分辨率、单一主体、简单运动”的文生视频开始。第一次不要同时加入复杂镜头、多人互动、快速运动、长时长和高分辨率，因为出现问题时无法判断是哪一个变量导致失败。

可以把验收输入固定成：

- 5 秒左右的短片；
- 480P 级别的分辨率；
- 单一主体和一个清晰动作；
- 不要求复杂文字、手指细节或精确口型；
- 固定随机种子，重复生成两次。

这样做的目的不是追求最好看，而是建立自己的时间、显存和稳定性基线。

## 4. 按官方路径运行第一个 1.3B 模型

以下命令来自 Wan2.1 官方仓库的单卡示例，运行位置是已经准备好依赖和模型文件的 Wan2.1 项目目录：

```powershell
python generate.py --task t2v-1.3B --size 832*480 --ckpt_dir ./Wan2.1-T2V-1.3B --offload_model True --t5_cpu --sample_shift 8 --sample_guide_scale 6 --prompt "A small paper boat floating slowly on a quiet stream at sunrise."
```

参数的作用可以这样理解：

- `--task t2v-1.3B`：选择 1.3B 文生视频任务；
- `--size 832*480`：设置较低的 480P 级别画面尺寸；
- `--ckpt_dir`：指向已下载的模型目录；
- `--offload_model True`：在显存有限时启用模型卸载路径；
- `--t5_cpu`：把文本编码器放到 CPU，减少显存压力；
- `--prompt`：输入本次生成的描述。

官方 README 还提醒，1.3B 模型在 720P 下虽然可以运行，但稳定性通常不如 480P；遇到显存不足时，优先使用仓库提供的 offload 参数，而不是随意修改脚本内部的内存逻辑。

### 第一次运行检查什么

不要只看命令有没有报错。至少记录：

1. 模型加载是否完成；
2. 生成了多少帧、最终分辨率和时长是多少；
3. 单次生成耗时；
4. 峰值显存和是否触发系统内存占用；
5. 生成的视频是否能正常播放；
6. 固定 seed 后重复运行是否能得到一致或可解释的结果。

如果结果能播放但动作完全崩坏，说明“推理流程成功”，不说明模型已经适合你的用途。把运行成功和内容质量分成两个指标记录。

## 5. 为什么本地生视频暂时不等于生产力

### 5.1 一条可用视频需要多次抽样

图片不满意时重抽一张，成本可能是几十秒；视频不满意时重抽一段，成本可能是几分钟甚至更久。镜头、动作和人物一致性都可能随机波动。评估时可以记录：

```text
可用片段成本 = 单次生成时间 × 平均重试次数
```

如果一个 5 秒片段平均需要 5 次重试，官方给出的 4 分钟单次基线就会变成约 20 分钟，而且还没有算筛选、剪辑和音频。

### 5.2 长视频需要额外工作流

本地模型更适合短片段实验。要做较长内容，通常需要分镜、图生视频、首尾帧控制、片段拼接、补帧、字幕和音频后期。工作流越复杂，模型、节点、磁盘和排错成本越高。

### 5.3 生成质量和硬件不是线性关系

显存更大可以尝试更大的模型、更高分辨率或更长片段，但它不会自动解决主体一致性、动作逻辑和提示词理解问题。模型版本、训练数据、采样设置和工作流同样影响结果。

## 6. 哪些人适合现在开始

### 适合尝试的人

- 有支持目标模型的 GPU，并接受先从短片和低分辨率开始；
- 已经熟悉 ComfyUI 或愿意学习节点式工作流；
- 想研究开源视频模型、提示词、控制条件和推理优化；
- 任务更看重本地实验、隐私或可控性，而不是立即批量交付。

### 暂时不适合的人

- 只需要快速交付稳定商业视频；
- 没有足够显存，也不愿意等待 CPU offload；
- 还没有跑通本地生图，却想直接搭建复杂视频工作流；
- 预算只按“模型能下载”计算，没有考虑重试、存储和后期制作。

如果目标是生产效率，云端视频服务仍可能更省时间；如果目标是学习、研究和可控实验，本地运行的价值在于看见整个过程，而不是保证每次都得到成片。

## 7. 内容和授权也要提前检查

使用视频模型时，至少检查模型许可证、训练数据声明、参考图片或视频的使用权、人物肖像和音乐版权。Wan2.1 官方仓库在许可证说明中也强调，模型使用者需要对生成内容承担相应责任。模型是开源的，不等于任意输入、任意输出和任意发布都没有限制。

建议为每次实验保存模型版本、工作流、提示词、seed、输入素材来源和最终文件。未来需要复现或解释某个片段时，这些记录比“当时大概用了某个模型”有用得多。

## 8. 结论和限制

本地生视频值得尝试，但适合把它当成一个高资源消耗的实验项目，而不是安装后马上替代云端生产。Wan2.1 官方数据表明，1.3B 模型在约 8 GB 显存级别已经可以开始尝试 480P 短视频；同一数据也提醒我们，模型规模、分辨率和单次生成时间会快速上升。

第一次验证应从官方支持的低规格任务开始，记录真实耗时和失败率，再决定是否升级硬件或增加工作流。只有当你能接受重试成本，并且明确本地运行的实验价值，继续投入才比较合理。
