# 普通 WiFi 怎么读出呼吸和姿态：CSI 感知的原理与它做不到的事

2022 年底有一篇论文叫 DensePose From WiFi，把 WiFi 信号的相位与幅值映射到 24 个人体区域的 UV 坐标，结论是只用 WiFi 也能估出多人的密集姿态。这个方向后来进入 IEEE 标准化（802.11bf，WLAN sensing），也催生了一批开源实现。

RuView 是其中体量最大的一个：截至 2026-11-12，仓库 10.4 万 star、1.35 万 fork，MIT 许可，含 ESP32 固件、Rust 处理端、Python 轮子与可复现的证明脚本。

但"WiFi 能看穿墙"这类说法在网上被传播得比它的适用范围广得多。本文只回答一个问题：从无线电到"有人在呼吸"之间，究竟发生了什么，哪些环节是硬的、哪些是脆的。

所有数字都注明是谁测的；仓库自身的数字与第三方基准分开写。

## 一、物理层：人为什么会让 WiFi 信号变化

WiFi 发的是 2.4/5 GHz 连续波。房间里除墙和家具还有人；人在动，甚至只是呼吸，都会改变多径的叠加方式——反射路径长度变化，落在接收端就是每个子载波上幅度与相位的变化。

能观察到这种变化的量叫 CSI（Channel State Information，信道状态信息）。它不是 RSSI 那种"信号强度一个数"，而是逐子载波的复数：每个子载波有自己的幅度和相位。

于是有第一个关键点：**信息密度取决于子载波数与天线数。** 一个 20 MHz 信道在常见实现里是 56 个子载波；多天线、多频段叠起来，观测维度才够做空间推断。

IEEE 802.11bf 的定位也印证了这一点。那个任务组的范围是修订 MAC 与 DMG/EDMG PHY，覆盖 1 GHz 到 7.125 GHz 以及 45 GHz 以上频段，并定义能力通告、测量请求与建立、反馈交换——也就是说，标准承认"用 WiFi 做感知"需要协议层面的配合，而不是抓包就能完成。

## 二、流水线：从 CSI 到"17 个关节点"

RuView 的 README 把整条链路画成一张图，压缩后是这几步：

1. 路由器发波，人体散射；
2. ESP32 mesh（4 到 6 个节点）在 1、6、11 三个信道按 TDM 轮流抓 CSI；
3. 多频段融合：3 信道 × 56 子载波 = 168 个虚拟子载波每条链路；
4. 多站融合：N 个节点组成 N×(N-1) 条链路，做注意力加权的跨视角嵌入；
5. 相干门：接受或拒绝这次测量，据称可在无调参的情况下稳定数天；
6. 信号处理：Hampel 滤波、SpotFi、Fresnel 区模型、BVP、谱图；
7. 神经网络输出 17 个人体关键点、生命体征与房间模型。

第 3、4 步最容易被忽略：单条链路的 CSI 只说明"这条路径的多径变了"；要知道变在房间哪个位置，需要多条几何分散的链路交叉。所以仓库反复强调节点数——单节点只到"有没有变"。

第 5 步的相干门值得单独说：真实环境里 CSI 会因空调、开门、邻户路由器漂移，没有"这次测量是否可信"的判据，模型会持续输出噪声级判断。它被放在流水线里，不是后处理补丁。

## 三、为什么必须先"空房间校准"

这是整篇里最硬的约束，也是最容易被教程略过的一步。

RuView 的校准分三步，且**不能跳步**：

```bash
wifi-densepose calibrate --port <PORT>   # 空房间基线
wifi-densepose enroll --room <NAME>      # 8 个引导锚点，约 4 分钟
wifi-densepose train-room --room <NAME>  # 拟合该房间的专用模型
```

第一步有硬性下限：记录的帧数少于 600 帧时，`finalize()` 直接返回 `InsufficientFrames` 并失败，不会产出"降级版"基线。默认时长 30 秒与 600 帧是"先到者"关系——如果节点流 CSI 的速度低于假定的 20 Hz，30 秒可能凑不满 600 帧，校准就会报 `insufficient frames: have X, need 600`。

这个设计说明了一件本质的事：**CSI 感知是"相对环境"的测量，基准随房间变化。** 同一个模型换到另一个房间、换了家具位置，基线就变了。仓库自己的"诚实局限"写得很直白：零样本跨房间/跨人很弱，按每次部署约 30 秒现场校准来准备。

## 四、两个姿态数字：82.69% 与 3.0%

同一个仓库里出现两个差异巨大的姿态精度，看标题会以为是矛盾，读标签才知道是两件事。

| 层级 | 载荷 | 数字 | 状态 |
| --- | --- | --- | --- |
| 公开基准上的模型 | MM-Fi 数据集，17 关键点 | torso-PCK@20 **82.69%**（单模型）、**83.59%**（ensemble+TTA） | 已测、可复现 |
| 极小模型变体 | 75K 参数 | **74.30%** | 已测 |
| 端上首版模型 | 仓库内 `pose_v1.safetensors`，217 样本留出集 | PCK@20 **3.0%**、PCK@50 **18.5%** | 已测，但低于自定 ≥35% 目标 |
| `archive/v1` 的 DensePoseHead | 无 checkpoint | 无 | 只有架构，已弃用 |

第一行是"在公开数据集上，这套方法能做到什么"，第三行是"在这块硬件上，现在的权重能做到什么"。仓库自己在"Model weights: what's real, what's not"一节里把这两者分开标注，还写明端上首版模型的运行时路径仍是返回 `confidence=0` 的居中骨架桩，权重尚未接入。

更值得注意的是它还撤回过一个数字：早期的"100% 存在检测"被下架，现在的存在检测准确率是 82.3%（held-out temporal-triplet）。一个项目主动撤回自己的最好数字，比它给出多少新数字更能说明可核验性。

关于单节点，仓库的说法也很克制：单天线、56 子载波、20 帧窗口不携带多天线研究依赖的细粒度空间信息，端上测量也印证了这一点——远端与面部关节接近随机。**可背书的姿态精度是 MM-Fi 基准数字，不是单块 ESP32 的实测数字。**

## 五、硬件与成本：$9 起步的代价

README 给的入口有几档：

- ESP32-S3，约 9 美元，单节点起步；
- ESP32-C6，6 到 10 美元，支持 802.15.4 与 Wi-Fi 6 的 HE-LTF 子载波标记；
- Cognitum Seed，140 美元，做持久存储、kNN 与证据链；
- Docker 模拟数据，无硬件也能跑通流程；
- PyPI 轮子（PyO3，abi3-py310，约 250 KB），带呼吸与心率提取器。

便宜是真的，但成本要按"能用的最小配置"算：多人或定位需 2 个以上节点，加上 4 分钟校准人工与定期重跑。单节点只能做到"有没有变化"。

## 六、这套东西现在能做什么、不能做什么

把仓库自述的能力与局限并排放，比较接近真实边界：

**能做的**：单人存在检测；呼吸与心率的趋势输出（仓库未给可比误差，本文不引精度）；单房间粗粒度姿态；房间指纹与漂移告警。

**做不到或很弱的**：跨房间零样本迁移；单节点多人定位与计数；远端与面部关节的精度；相机级的密集姿态。仓库把这些写进了"honest limitations"，也写了"Beta 软件，API 与固件会变"。

评估能否进生产，问三件事而不是"准不准"：场景是单人还是多人；能否接受每次部署 4 分钟校准；房间里有没有持续扰动的多径源（空调、邻户 AP、玻璃幕墙）。

## 七、如果你想自己验证

仓库给了另一条路：确定性流水线重放。跑脚本，把输出与已发布的 SHA-256 比对，期望打印 `VERDICT: PASS`。它验证的是"输出可复现"，不是"精度达标"，两个命题要分开看。

要验证精度，只能回到公开基准：MM-Fi 数据集、PCK@20 的定义、以及 split 协议（仓库标注了 `random_split`）。同一个百分比在不同协议下不可比，这是读这类数字的通用前提。

## 八、和摄像头方案比，差在哪一端

把两套方案放在同一条任务上比，差异集中在三处，不在"准不准"。

| 维度 | 摄像头 | WiFi 感知 |
| --- | --- | --- |
| 遮挡 | 被墙、帘、家具挡住即失效 | 穿墙、穿帘仍能读到扰动 |
| 光照 | 需要可见光，暗光下降明显 | 与光照无关 |
| 身份 | 人脸可直接识别 | 不直接给身份，但姿态与作息组合可间接识别 |
| 精度上限 | 公开基准的人体关键点误差已很低 | 数据集级可用，端上首版仍差一个量级 |
| 部署成本 | 镜头、存储、算力都便宜 | 节点、校准、调参的人力更贵 |

值得注意的是第一行与第四行的组合：WiFi 的强项是"摄像头看不到的地方"，而它在那些地方的精度恰恰最难保证——穿墙后的多径更复杂，校准更难。这个错位是很多演示看起来很美、落地却很慢的原因。

## 九、如果你只想复现一次最小实验

不需要 140 美元的硬件，也能验证这条链路是否真的在跑：

1. 用 Docker 起模拟数据版本，打开本地页面确认存在检测的波形会随模拟目标变化；
2. 跑一遍确定性流水线重放，确认输出与发布哈希一致（`VERDICT: PASS`）；
3. 如果要接真硬件，从单节点 ESP32-S3 起步，先只做存在检测，不要一上来就上姿态；
4. 记录空房间基线的帧数——低于 600 帧会直接失败，这一步能帮你判断采集链路是否稳定。

第 4 步是最实用的自检：校准失败往往不是模型问题，而是 CSI 流本身断断续续。能在 30 秒内稳定产出 600 帧，说明采集端是健康的。

## 十、两个容易过度解读的说法

**"不需要摄像头，所以没有隐私问题。"**

只对一半：它不产生影像，但输出含生命体征与姿态（见下一篇）。"不拍照"不等于"不敏感"。

**"数据集上 82%，已经接近摄像头。"**

两者口径不同：82.69% 是 MM-Fi 上 torso-PCK@20，只评躯干关键点，且限定在公开数据集的 split 协议下；摄像头同类指标通常报全身关键点与不同阈值。跨数据集、跨指标比数字没有意义。

## 十一、限制与结论

WiFi 感知的物理基础是可靠的：人扰动多径，CSI 记录扰动，多节点多频段提供空间分辨能力，标准组织也在做协议层支持。不可靠的是"从扰动到语义"的这一段——它高度依赖现场校准、节点数量与训练数据的来源。

三条可以直接用的判断：

- 看到"WiFi 看穿墙"时，先问节点数。单节点的结论通常只到"有变化"。
- 看到姿态百分比时，先问数据集与协议。数据集上的数字与端上实测可以差一个数量级，前者是论文级，后者常常还只是首版权重。
- 看到"无需校准"时，直接怀疑。这个技术的测量基准是房间本身，换房间就得重校。

至于这类能力用在别人的空间里意味着什么，是下一篇的事。
