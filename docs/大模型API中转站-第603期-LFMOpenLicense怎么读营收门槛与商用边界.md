# LFM Open License v1.0 怎么读：年营收 1000 万美元门槛对商用意味着什么

LFM3 的权重可以在 Hugging Face 上直接下载，不需要申请，页面也没有设置访问门槛。很多人因此默认"可以随便用"。但模型卡的协议一栏写的是 other，协议名为 lfm1.0，仓库里附了一份 LFM Open License v1.0。这份协议里有一个以年营收 1000 万美元为界的商用限制。

本文只做一件事：把协议原文里与商用、关联实体、再分发、终止有关的条款读清楚，列出文字上没有回答的问题，并给出一份自查清单。文章不是法律意见。涉及商用决策时，请把协议原文交给你的法务或律师确认。

信息截止日期为 2026-10-30。协议版本为 v1.0，之后若更新，以仓库里的最新文本为准。

## 一、先确认读的是哪份文本

| 项目 | 内容 |
| --- | --- |
| 协议名称 | LFM Open License v1.0 |
| 许可方 | Liquid AI, Inc. |
| 全文来源 | [LFM3-1.7B 仓库的 LICENSE 文件](https://huggingface.co/LiquidAI/LFM3-1.7B/raw/main/LICENSE)（检索于 2026-10-30，文件无日期） |
| 模型卡声明 | license: other，license_name: lfm1.0（LFM3-1.7B 与 LFM3-Omni-2B 均如此） |
| 下载门槛 | 未设置（gated 为 false） |

我完整读了 LFM3-1.7B 仓库里的 LICENSE。LFM3-Omni-2B 的模型卡声明了同一个协议名，但我没有逐字比对它的 LICENSE 文件。其他模型和社区转换的版本（例如第三方量化仓库）请各自核对。

"下载不需要同意任何条款"和"不受协议约束"是两回事。门槛为 false 只说明获取权重不需要登录确认，协议对使用和再分发的约束依然存在。

另外，官方博客自己用的措辞是 open-weight（开放权重）。本文也沿用这个词。这份协议是否符合某个具体的开源定义，我没有去核对对应定义的原文，这里不下结论。

## 二、核心条款：第 5 条商用限制

原文的结构如下：

- 5(a)：商用方面的权利，以"你或你的法律实体不超过门槛"为条件。
- 5(b)：超过门槛的法律实体，其对作品或衍生作品的任何商用，不在本协议许可之内。
- 5(c)：门槛不适用于合格非营利组织为非商业或研究目的使用作品或衍生作品。

相关定义：

| 术语 | 原文含义 |
| --- | --- |
| Threshold（门槛） | 年营收 10,000,000 美元或以上 |
| Commercial Use（商用） | 为直接或间接的商业利益或金钱报酬而使用作品 |
| Non-Commercial or Research Purposes | 不涉及任何商用的用途 |
| Qualified Non-Profit Organization | 按美国《国内税收法典》501(c)(3) 免税的组织，或其他司法辖区的等效非营利或慈善组织 |

注意"或以上"：年营收恰好 1000 万美元也算达到门槛。

## 三、逐条读：几个容易误解的点

### 1. 门槛看的是"实体"，不是"项目"

5(a) 和 5(b) 的主体是 You 或 Your Legal Entity。Legal Entity 的定义把"控制、被控制或与之处于共同控制下的其他实体"都算进去，控制的标准包括：直接或间接决定管理方向的权力，或持有 50% 或以上的流通股份，或受益所有权。

字面含义是：判断是否超过门槛时，看的是整个关联实体集合。一家年营收 500 万美元的子公司，如果它的母公司或同一控制下的其他公司合计超过 1000 万美元，按文字有被认定为超过门槛的风险。协议没有给出示例，怎么合并计算需要法务判断。

### 2. "商用"的定义很宽

Commercial Use 的定义是"为直接或间接的商业利益或金钱报酬而使用"。关键词是"间接"。

- 把模型放进对外销售的产品：显然是商用。
- 公司内部用它提升效率，例如客服辅助、内部知识库：没有直接收入，但可能带来间接商业利益。协议没有对内部使用单独说明。偏保守的读法是把它算作商用。

这一点没有现成答案，只能向法务确认。

### 3. 协议没有说怎么算营收

原文只写了"年营收 1000 万美元或以上"。以下问题文字上没有回答：

- 用哪个年度：上一个财年、当前财年，还是滚动十二个月。
- 营收是否包含关联实体，前面第 1 点已讨论。
- 外币如何折算成美元。
- 当年中途越过门槛时，之前已经开始的使用怎么办。

### 4. 5(c) 的作用不完全清楚

5(c) 说门槛不适用于合格非营利组织的非商业或研究用途。但按字面，5(b) 只限制"商用"。非商业用途本来就不在 5(b) 的范围里，那么 5(c) 具体多出了什么，文字上不够明确。

可能的解释有几种，我无法判断哪个是起草者的原意：

- 为了明确，把非营利组织的情形再写一遍。
- 针对"非营利组织也有较大营收"的情形做的特别说明。
- 起草时留下的冗余。

对读者的实际影响是：如果你的组织是大型非营利机构，或者是营收超过门槛的商业公司但只做研究，需要向法务确认自己属于哪一类。

### 5. 超过门槛之后怎么办

协议正文没有写"超过门槛后如何取得商用授权"，也没有给出联系方式或流程。第 6 条提到的单独许可协议只针对向许可方提交的贡献（Contributions），不能读成商用授权的入口。要了解超过门槛后的选项，需要直接联系 Liquid AI。

## 四、再分发义务（第 4 条）

如果你要分发权重或衍生作品，需要满足：

| 要求 | 内容 |
| --- | --- |
| (a) | 把协议副本交给其他接收者 |
| (b) | 被修改的文件要带有明显的修改声明 |
| (c) | 在分发的衍生作品的源码形式中保留所有版权、专利、商标和署名声明（与衍生部分无关的除外） |
| (d) | 如果作品带有 NOTICE 文本文件，衍生作品要在 NOTICE 文件、文档或界面中附上其中的署名声明 |

此外，你可以为自己的修改增加版权声明，也可以为自己的修改或衍生作品提供不同或额外的许可条款，条件是你对作品本身的使用、复制和分发仍然符合本协议。

对做微调模型并对外发布的团队，这意味着：

1. 发布的权重仓库里要放协议副本。
2. 要标注哪些文件被你改过。
3. 不能把协议里的商用限制说成不存在。你的额外条款不能削弱对原作品的约束。
4. 第三方转换的量化版本，如果没有附带协议副本，从文字上就没有满足 (a)。使用这类版本时，要自己对照检查。

## 五、衍生作品的边界

协议对 Derivative Works 的定义是：基于作品或从作品派生的作品，且其编辑修订、注释、扩展或其他修改整体上构成原创作品。定义同时说明，不包括仍可与作品分离的、或仅仅链接（或按名称绑定）到作品及其衍生作品接口的作品。

可以读出的内容：

- 微调后的权重，通常是从原作品派生的，更可能被视为衍生作品。
- 只通过接口调用模型的应用程序，如果与模型保持可分离，按这个定义不属于衍生作品。

这是对文字的一般性阅读，具体如何认定要看实际的集成方式和适用法律。

协议没有关于下面这些问题的专门条款：

- 模型生成的输出内容归谁，是否受协议约束。
- 用模型输出去训练另一个模型是否允许。
- 评测结果能否公开发表。

没有条款不等于没有限制，也不等于允许。这些问题请直接向法务提出。

## 六、终止和责任

| 条款 | 内容 |
| --- | --- |
| 第 11 条 终止 | 未遵守任何条款，许可自动、立即终止；终止后必须停止使用作品及衍生作品，并删除持有的所有副本 |
| 第 3 条 专利 | 如果你就作品或其中的贡献提起专利侵权诉讼，你在本协议下获得的专利许可自该日起终止 |
| 第 7 条 商标 | 不授予使用许可方名称、商标、服务标记或产品名称的权利，描述作品来源的合理惯常使用除外 |
| 第 8 条 免责 | 作品按"现状"提供，不作任何明示或默示担保；使用和再分发的适当性由你自己判断 |
| 第 9 条 责任限制 | 许可方不对因使用或无法使用作品产生的损害负责，法律另有规定或书面约定的除外 |

第 11 条的自动终止值得单独强调。如果一家公司在使用过程中越过了营收门槛，却继续商用，从文字上看，这属于不符合第 5 条，可能触发自动终止，继而需要删除所有副本。这个后果比"补缴费用"严重得多。

## 七、自查清单

下面这张表可以交给法务一起过一遍。

| 问题 | 为什么重要 | 本文能回答吗 |
| --- | --- | --- |
| 我们（含关联实体）上一年营收是否达到 1000 万美元 | 决定商用是否在授权范围内 | 只能告诉你判断主体是整个关联实体集合 |
| 我们的使用算不算商用 | 内部使用可能有间接商业利益 | 不能，需要法务判断 |
| 我们是否属于合格非营利组织 | 决定 5(c) 是否适用 | 只能给出定义 |
| 我们会不会分发权重或衍生作品 | 触发第 4 条的义务 | 能，见第四节 |
| 我们会不会微调并对外发布 | 需附协议副本、标注修改 | 能 |
| 所用的权重来自官方仓库还是第三方转换 | 第三方版本的协议声明要单独看 | 不能，需逐个核对 |
| 营收按哪个年度、怎么折算 | 协议没写 | 不能 |
| 产品会不会在未来越过门槛 | 越过后商用不在授权内 | 能指出风险点，不能给出方案 |
| 模型输出是否会用于训练其他模型 | 协议没有专门条款 | 不能 |

## 八、实用建议

1. **保留协议快照。** 下载权重时，把当时仓库里的 LICENSE 文件和提交版本一起存档。协议更新后，你需要知道自己当初依据的是哪个版本。
2. **在内部台账里记录模型来源。** 官方仓库、第三方转换、自己微调的版本分别登记，便于再分发时对照第 4 条。
3. **把营收门槛放进风险清单。** 如果产品增长预期接近 1000 万美元，要在越过之前就和许可方联系，而不是越过之后。
4. **评估替代方案。** 如果门槛对你不合适，可以评估使用其他协议的开放权重模型，但要同样逐份阅读各自的协议，不要只看"开放权重"这个标签。
5. **不要依赖二手解读。** 包括本文。协议全文约 1600 个英文单词，花十分钟读原文是值得的。

## 九、限制与结论

LFM Open License v1.0 的主干很清楚：在年营收低于 1000 万美元的前提下，可以复制、修改、再分发并商用；达到或超过门槛的法律实体，商用不在本协议授权之内；任何不合规都可能导致许可自动终止。

不清楚的部分同样明确：营收的计算方式、内部使用是否算商用、5(c) 的作用、模型输出的归属，协议文字都没有给出答案。

这篇文章的限制：只读了 LFM3-1.7B 仓库里的协议文本；没有核对其他仓库的协议文件；没有查阅任何法院判例或其他司法辖区的解释；没有向许可方求证任何一条的原意。

下一步建议：如果你准备把 LFM3 用于商业产品，先拿到协议原文和你的最新营收口径，约法务做一次 30 分钟的评审，把第七节的表格逐行填完，再决定是否投入集成。
