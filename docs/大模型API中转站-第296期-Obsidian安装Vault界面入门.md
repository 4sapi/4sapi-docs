# Obsidian Vault 如何从零建立本地 Markdown 知识库
很多资料散落在聊天记录、云文档和浏览器收藏里，真正要复用时却找不到原始文件和上下文。本文从安装 Obsidian、创建 Vault 和写第一篇 Markdown 笔记开始，说明本地文件结构、备份位置和 AI 可读边界，让知识库先具备可定位、可迁移的基础。文中只讨论可复现的步骤，不把单次结果扩展成产品承诺；每个结论都标注前提、证据和无法覆盖的边界。读者可以先完成最小验证，再按自己的版本、权限和数据补充实验。



微信收藏里躺着一篇文章，飞书里记了半页课，浏览器还开着昨天和 Claude 的对话。

两周后真要用，翻了十分钟，还是没找到。最后不仅资料没找到，连当初为什么收藏它都忘了。

问题通常不是资料太少，而是资料住在不同的软件里，彼此没有关系。Obsidian 适合拿来收这个烂摊子，因为它的核心很简单：把笔记保存成你本地文件夹里的 Markdown 文件。

这篇不讲复杂的卡片盒、标签哲学和知识图谱。我们先做一件更实际的事：把 Obsidian 装起来，创建一个 Vault，知道文件在哪里，写出第一篇笔记。

## 一、Obsidian、Vault 和 Markdown 是什么

### Obsidian 是什么

Obsidian 是一个本地优先的 Markdown 笔记工具。它提供编辑器、链接、搜索、关系图、插件和主题，但你的笔记正文仍然可以作为普通文件被其他工具读取。

### Vault 是什么

Vault 不用理解成复杂的数据库。它就是一个文件夹：

~~~text
AI产品知识库/
  ├── 课程笔记.md
  ├── 微信文章.md
  ├── assets/
  └── .obsidian/
~~~

其中 `.obsidian` 保存 Obsidian 自己的设置、插件和工作区信息；其他 `.md` 文件就是你的笔记正文。

### Markdown 为什么重要

Markdown 是纯文本格式，优点是：

- 可以用 Obsidian 打开
- 可以用 VS Code、记事本或其他编辑器打开
- 可以被 Claude Code、Codex 等 AI 工具读取
- 可以用脚本批量搜索和处理
- 不容易被某个软件完全锁死
- 迁移和备份都比较直接

这也是 Obsidian 适合做 AI 知识库的原因：AI 不需要先学会一个封闭数据库，只要被允许访问对应的本地 Markdown 文件即可。

## 二、先下载安装

建议从官方页面下载：[Obsidian 官方下载页](https://obsidian.md/download)。不要从不明网盘或所谓“破解版”获取安装包。

### Windows

Windows 用户下载对应安装包，按系统提示完成安装。安装完成后从开始菜单或桌面启动 Obsidian。

### macOS

根据自己的芯片和系统版本选择对应安装包。第一次打开时，如果系统提示来源确认，先确认下载渠道确实是官方页面。

### 第一次启动不要急着装插件

新手经常一打开就搜索十几个插件，最后连笔记在哪都没弄清楚。先创建 Vault，写一篇测试笔记，确认文件真的落在本地，再开始扩展功能。

## 三、创建第一个 Vault

打开 Obsidian 后，会出现创建或打开 Vault 的界面。

按下面步骤操作：

1. 点击 **Create new vault**。
2. 给 Vault 起一个容易理解的名字，例如 `AI产品知识库`。
3. 选择一个你找得到、也方便备份的位置。
4. 点击创建并进入主界面。

Windows 示例路径可以是：

~~~text
D:\Obsidian\AI产品知识库
~~~

不要把 Vault 放在临时下载目录，也不要放进某个不清楚会不会自动清理的同步缓存目录。第一次使用时，建议使用一个明确的本地路径。

### Vault 位置怎么选

可以按下面三个标准判断：

| 标准 | 为什么重要 |
| --- | --- |
| 你能快速找到 | 后续给 AI 或脚本指定路径时不容易出错 |
| 可以定期备份 | 本地文件需要有第二份副本 |
| 路径稳定 | 不要频繁移动，避免插件和外部工具失效 |

如果你计划使用同步插件，先让本地 Vault 正常工作，再配置同步。不要第一次打开就把“本地目录、云端目录、移动端目录、自动同步”全部一起改。

## 四、第一次打开，先认清四个区域

Obsidian 的主题和版本可能改变界面样式，但核心区域大致不变。

### 1. 左侧窄工具栏

这里通常放文件、新建笔记、搜索、关系图、命令等入口。它更像一列快捷按钮，不是你的笔记目录。

### 2. 左侧文件列表

这里显示 Vault 里的文件和文件夹。你新建的 Markdown 笔记、图片、`.drawio`、`.excalidraw` 等附件，都会在这里出现。

### 3. 中间编辑区

这是写笔记、编辑 Markdown、查看图表和处理资料的主要区域。大部分内容生产都在这里完成。

### 4. 右侧辅助面板

这里通常可以放反向链接、标签、搜索结果、关系图和第三方插件面板。后面安装 Claudian 后，AI 对话也可能出现在右侧。

### 设置入口

左下角的齿轮通常进入 Settings。主题、插件、快捷键、文件与链接、同步和第三方插件都从设置进入。

如果你的布局和截图不完全一样，不要先判断软件坏了。先按 `Ctrl + P` 打开命令面板，搜索你想做的动作。

## 五、新手只记住三个动作

### 动作一：新建笔记

在文件列表上方点击新建按钮，或者打开命令面板搜索创建新笔记。给笔记起一个清楚的名字，例如：

~~~text
AI产品经理面试准备.md
~~~

### 动作二：在编辑区写内容

先写普通文字，不需要一开始就研究所有 Markdown 语法。最少可以这样：

~~~markdown
# AI 产品经理面试准备

## 我需要补的内容

- 用户研究
- 指标设计
- AI Agent
~~~

### 动作三：打开命令面板

按 `Ctrl + P`，输入动作名称。你不知道某个功能在哪时，优先搜索命令面板，不要立刻去网上找一张旧版本截图。

## 六、先建一个最小目录

不要一开始设计几十层文件夹。可以先用这个最小结构：

~~~text
AI产品知识库/
  ├── 00-收件箱/
  ├── 00-索引.md
  ├── 01-资料/
  ├── 02-知识库/
  ├── 03-未发布/
  └── assets/
~~~

每个目录只承担一种职责：

| 目录 | 用途 |
| --- | --- |
| `00-收件箱` | 微信剪藏、临时摘录、还没整理的资料 |
| `00-索引.md` | 记录重要文件和入口 |
| `01-资料` | 原始资料，尽量少改正文 |
| `02-知识库` | AI 或人工整理后的概念、案例和方法 |
| `03-未发布` | 文章草稿、课程和待发布内容 |
| `assets` | 图片、流程图和白板文件 |

如果你目前只有几篇笔记，甚至只创建 `00-收件箱` 和 `00-索引.md` 就够了。目录是为了让资料更容易找到，不是为了证明你已经搭好了系统。

## 七、写出第一篇测试笔记

新建 `00-索引.md`，先写三行：

~~~markdown
# 知识库索引

- 用途：保存 AI 产品学习资料、网页剪藏和文章草稿
- 当前入口：00-收件箱
- 最后整理时间：2026-07-24
~~~

再在 `00-收件箱` 新建 `第一次测试笔记.md`：

~~~markdown
# 第一次测试笔记

我正在搭建一个本地 Markdown 知识库。
~~~

完成后关闭 Obsidian，再从文件管理器打开 Vault 文件夹，确认这两个 `.md` 文件真的存在。这个动作很重要，它让你知道 Vault 不是一个只能在软件里访问的黑箱。

## 八、文件、链接和附件怎么放

### 文件名

文件名先追求可搜索：

- `RAG在线检索流程.md`
- `ClaudeCode测试记录-2026-07.md`
- `微信剪藏-某篇文章.md`

### 内部链接

如果一个笔记和另一个笔记有关，可以使用：

~~~markdown
[[RAG在线检索流程]]
~~~

不要为了追求“每句话都链接”而强行建立关系。先保存内容，再在真正需要复用时补链接。

### 附件

图片、流程图和白板文件可以统一放进 `assets`。文件夹位置可以按你的设置调整，但最好保持稳定，便于 AI 和脚本找到附件。

## 九、给 AI 访问 Vault 的最小边界

Obsidian 文件是本地文件，但“本地”不等于“AI 可以随便改”。以后让 Claude Code、Codex 或其他工具访问 Vault 时，先说清楚范围：

~~~text
请只读取 D:\Obsidian\AI产品知识库\00-收件箱。
只做标题提取和摘要，不要删除、覆盖、移动任何文件。
处理完成后告诉我：读取了哪些文件、新增了哪些内容、哪些文件没有处理。
不要读取、展示或记录登录信息、授权信息和私密配置。
~~~

如果任务范围不清楚，先让 AI 写出它理解的范围，再允许它继续处理。不要一开始就说“帮我整理整个 Vault”，这句话的边界太大。

## 十、备份从第一天开始

至少保留一份 Vault 的副本。可以使用：

- 定期复制整个 Vault 到备份硬盘
- Git 管理 Markdown 变更
- 云盘同步，但先确认冲突策略
- 后续使用 Remotely Save 等同步插件

同步和备份不是一回事：同步可能把错误修改同步到所有设备，备份则应该允许你找回旧版本。第298期会单独讲同步插件和网页剪藏。

## 总结

Obsidian 入门真正要完成的不是“把界面研究透”，而是：

~~~text
安装软件
创建 Vault
找到本地文件夹
写出第一篇 Markdown
建立一个收件箱入口
~~~
