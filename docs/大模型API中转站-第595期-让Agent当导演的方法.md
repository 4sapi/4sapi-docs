# 让 Agent 当导演而不是技术演示：一套短片导演方法拆解

让编程 Agent 用代码做短片，第一版通常很像一个技术演示：每一帧单看都不错，连起来却没有起伏，声音只有一条背景音乐，镜头从头到尾一个速度，字幕一闪就过去了。

问题不在画面能力，而在没有人在"导"。开源项目 [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) 专门写了一份给 Agent 读的导演指南 `DIRECTOR.md`，开篇第一句就是：你是导演，不是技术演示。一支片子按这个顺序评判：**声音、节奏、镜头、导演**（表演、调度、情绪弧线），好看的帧只是起点。

本文拆解这份指南，把它整理成一套可以迁移到任何"让 Agent 做内容"场景的方法。来源为项目文档，检索 2026-10-29。

## 第一步：只问一次

指南对需求沟通的要求非常明确：**一次问完，之后不再追问**。用户通常只给一个风格和一个主题，其余全部由 Agent 决定。

默认值也写得很清楚：

| 项目 | 默认值 |
| --- | --- |
| 片长 | 30–60 秒；超过两三分钟会成倍增加时间和 token 成本，要提前告诉用户 |
| 分辨率与帧率 | 1920×1080、24 fps；风格另有规定时以风格为准 |
| 配音与字幕语言 | 跟用户写字用的语言一致 |
| 字幕 | 烧录进画面，同时导出 `.srt` |
| 响度 | −14 LUFS |

只在一次提问里问的，是 Agent 自己定不了的事：主题里必须出现的事实或名称、用户有没有自己的配音和素材、要不要先看分镜。

这条规则的价值在于成本可预期。Agent 每问一次，用户就要回来一次；问题散落在整个流程里，用户会觉得自己一直在被打断。把所有不确定性集中到开工前一次问完，剩下的全部按默认值推进。

## 第二步：先找标杆

动笔之前，先为这个风格**和这个主题**挑一到两部参考作品（电影、片头、游戏、广告），并且分开写清两件事：

| 要学什么 | 不能拿什么 |
| --- | --- |
| 构图、节奏、镜头语法、配色逻辑、配乐结构 | 角色、设计、旋律、具体镜头、标志、字体 |

指南的原话是：标杆对质量的提升，比后面任何一条规则都大。

这一步之所以重要，是因为"好看"没有标准，"像某部作品那样好看"有。给 Agent 一个具体参照，它就能把"有电影感"这种模糊要求翻译成具体的镜头运动和剪辑节奏。同时明确"不能拿什么"，也就提前划好了版权红线。

## 第三步：故事只要一个转折

指南对故事结构的要求很克制：

- **一个主体、一个目标、一个转折。** 一个角色（或者一件物品、一个产品、一个想法）想要某样东西，发生了变化，结局和开头不一样。
- **前 3 秒必须有钩子。** 不要在任何事情发生之前先慢慢亮一个 logo。
- **结尾要有回响。** 呼应开头、揭示规模，或者让角色第二次把事情做对。
- **一个只有这种媒介能做的动作**，放在情绪最高点。比如一次折叠变成转场、墨迹晕开成下一个场景。
- **删掉多余的。** 一个观众在缩略图尺寸就能看懂的笑点，胜过三个看不懂的。

## 第四步：先写分镜脚本，再画任何东西

在画任何一帧之前，Agent 要先写一份 `TREATMENT.md`，包含八项内容：

| 内容 | 作用 |
| --- | --- |
| 三种候选结构及最终选择的理由 | 避免第一个念头就是这个风格的陈词滥调 |
| 一句话梗概与弧线 | 开端、转折、结局 |
| 标杆：学什么、不学什么 | 见上一节 |
| 镜头表 | 每个镜头的景别、角度、运镜、时长，以及**为什么这样拍** |
| 逐秒节拍表 | 每一秒发生什么 |
| 节拍对位表 | 速度、小节网格、每段配器，每个切点和关键动作落在哪一拍 |
| 声音设计表 | 每段的环境声、主要拟音、音乐状态 |
| 字幕与标题设计 | 字体是风格的一部分 |

第一项最值得照抄。要求 Agent 先列三种结构再选一种，等于强迫它跳出第一反应。指南的解释是：一个风格最先想到的点子，通常就是它的陈词滥调。

## 第五步：声音是一半

这份指南把声音放在评判顺序的第一位，具体要求非常可操作：

| 要求 | 具体做法 |
| --- | --- |
| 每个可见动作都有声音 | 落地、翻页、切换、滴水、点击、布料；材质不同声音不同 |
| 三层声音 | 环境声、拟音、音乐；对白和关键拟音出现时压低音乐 |
| 至少两次真正的安静 | 放在转折或情绪高点之前；安静之后的第一个声音要是全片最重要的声音之一 |
| 至少两次用声音转场 | 下一场的声音提前进来，或上一场的声音延续过切点 |
| 不用"钢琴加弦乐"的万能配乐 | 用这个风格声音调色板里的乐器 |

"至少两次安静"这条很少有人想到。没有安静就没有对比，没有对比就没有高潮。

## 第六步：节奏先于画面

画面要锁到音乐网格上，所以节拍对位表必须在做动画之前写好。

节奏的要求有两类。第一类是变化：快慢交替，至少一次明显的加速或减速，至少给观众一次喘息（一个长镜头或一次停顿）。**全片一个速度就是失败**。

第二类是给观众留出读懂的时间，指南给了具体公式：

| 对象 | 最短停留时间 |
| --- | --- |
| 字幕 | 至少 1.8 秒，且不短于这句话的朗读时长加 0.6 秒 |
| 动画入场后的英文文字 | 约（字母数 ÷ 15 + 1.5）秒 |
| 动画入场后的中文文字 | 约（字数 ÷ 4.5 + 1.5）秒 |
| 标题卡 | 至少 4 秒 |

快可以，但要靠每屏少放字来实现，而不是在观众读完之前就切走。项目里有一个 `readcheck.mjs` 专门按这些规则检查每一段文字。

## 第七步：每个镜头都要有理由

- 至少用**四种不同的运镜**，景别要有真正的变化。2D 也有镜头：推、拉、视差、焦点转移、画中画。
- 一个让人记住的**标志性镜头**：一镜到底、一次规模揭示，或者用媒介本身做出的转场。
- **转场在媒介内部设计**（翻页、刻线生长、墨迹扩散），并且全片保持一套语法；避免默认的淡入淡出和硬切。
- 关键时刻，主体至少占画面高度的三分之一，调度清晰，剪影可读。

## 最常见的失败

指南总结了它们最常看到的问题，可以直接当成检查表：

| 失败 | 怎么查 |
| --- | --- |
| 主体太小、太远或贴着画面边缘 | 每 1–2 秒抽一帧拼成联系表看 |
| 太暗看不清，或同色叠同色（红上叠红） | 缩小到缩略图尺寸看 |
| 字幕挡住主体 | 联系表上逐帧看 |
| 笑点或失败场面太快看不懂 | 关键动作按 0.2 秒间隔抽帧 |
| 转场里出现空白帧 | 用 ffmpeg 的黑帧检测 |
| 镜头移动后特效没跟上主体 | 检查是否所有跟随特效都走同一个坐标函数 |

## 交付前：只修一轮

自检流程有几条规则值得单独拿出来：

- **只修一轮。** 自检发现的问题在一轮里全部修完，再检查一次。第二次检查发现的小问题（一个电平、一帧）算同一轮；更大的问题，交付时用一句话告诉用户。用户交付后提的意见是新的一轮，只改用户要求的地方。
- **不能做成样片的翻版。** 写完分镜脚本后，再拿库里的样片对比六个维度：结构、开场、标志镜头、镜头路线、配乐形状、结尾。**六项里至少四项要不同**，相同的重新想。
- **配音逐句回检**：每一句都要能被语音识别正确转回来。
- **响度约 −14 LUFS**，没有黑帧、没有坏帧，字幕同步且不挡关键动作。
- 声音设计表里的每一行，都真的出现在混音里。

"只修一轮"这条规则解决的是 Agent 最常见的毛病：无限自我修改。给它一个明确的停止条件，交付时间才可控。

## 这套方法能迁移到哪里

这份指南虽然是为短片写的，但其中几条原则可以直接用到其他"让 Agent 产出内容"的场景：

| 原则 | 迁移到写作 | 迁移到网页 |
| --- | --- | --- |
| 只问一次 | 开写前一次问清读者、篇幅、语气 | 开工前一次问清品牌、内容、页面数 |
| 先找标杆 | 指定一篇参考文章，写清学什么、不学什么 | 指定一个参考网站，写清借鉴哪部分 |
| 先写三种结构再选 | 先列三种大纲 | 先出三种布局草图 |
| 只修一轮 | 自检一遍就交 | 自检一遍就交 |
| 不能做成样例的翻版 | 与参考文章的结构差异要足够大 | 与模板的布局差异要足够大 |

## 限制与结论

需要说明的是：这份指南是为特定风格库和特定模型写的，其中的数值（字幕停留公式、−14 LUFS、六项里四项不同）是项目方的经验值，不是行业标准；遵守全部规则会显著增加单支片子的耗时与 token 消耗。

可以确定的是方法的骨架：把评判顺序定为声音、节奏、镜头、导演；把所有不确定性集中在开工前一次问完；动笔前先写包含三种候选结构的分镜脚本；给自检一个明确的停止条件。这几条把 Agent 从"会画画的技术演示"变成了"有判断的导演"，而且不依赖任何具体工具。
