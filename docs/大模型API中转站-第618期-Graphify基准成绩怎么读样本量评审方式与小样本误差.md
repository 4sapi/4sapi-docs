# Graphify 基准成绩怎么读：样本量、评审方式与小样本的误差

Graphify 的 README 有一节标题就带着数字："0.497 recall@10，0 LLM 积分"。基准文档的摘要说它在 LOCOMO 上有"测试过的所有系统中最好的检索召回"。读到这类句子，值得先问：样本多大，谁评的分，对手是怎么跑的，差距在误差范围之内吗。

本文把仓库里的基准数字逐项过一遍，回答它们能支持什么结论。数字来自 [BENCHMARKS.md](https://github.com/Graphify-Labs/graphify/blob/HEAD/BENCHMARKS.md) 和[原理文档](https://github.com/Graphify-Labs/graphify/blob/HEAD/docs/how-it-works.md)（检索于 2026-10-30）。这些都是项目自己的测试，我没有复现任何一项。误差范围是我按样本量算的粗略估计，用正态近似，忽略了配对设计，只用于判断量级。

## 一、测试是怎么搭的

BENCHMARKS.md 描述的设置：

| 项目 | 内容 |
| --- | --- |
| 框架 | 项目自己的 harness；对手系统（mem0、supermemory）作为适配器接入 |
| 统一条件 | 同一个模型、同样的 token 预算、同一套评分 |
| 模型 | 所有 LLM 角色都用 Kimi K2.6 |
| 嵌入器 | 系统允许时统一用本地的 BGE-m3 |
| 评分 | 对照一组"正确答案必须包含的原子事实"，覆盖率等于（覆盖加 0.5 倍部分覆盖）除以总数 |
| 评审验证 | 与第二位独立评审的一致率 90.6%，Cohen's kappa 0.81 |

要注意的两点：

1. **评审与回答者是同一个模型。** 文档说"每个 LLM 角色一个模型"，评分也由 Kimi K2.6 做。第二位评审的验证降低了单一评审的风险，但没有消除模型偏好自己输出风格的可能。文档没有说第二位评审是谁、抽样多大。
2. **对手是作为适配器跑在项目自己的 harness 里。** 这保证了条件一致，但对手系统的最佳配置未必被使用。文档也说 supermemory 的自托管版锁定了它自己的 768 维英文嵌入器。

## 二、逐项看数字

### LOCOMO（n=300）

| 系统 | QA 准确率 | recall@10 | 摄取成本 |
| --- | --- | --- | --- |
| graphify（图扩展） | 45.3% | 0.497 | 约 $1.40 |
| hybrid RRF | 43.3% | 0.493 | $0（共用索引） |
| dense RAG | 41.3% | 0.439 | $0（共用索引） |
| BM25 | 31.3% | 0.362 | $0（共用索引） |
| supermemory | 49.7% | 0.149 | $15.67 |
| mem0 | 27.3% | 0.048 | $3.48 |

读法：

- **"召回最好"的差距很小。** graphify 0.497 对 hybrid RRF 0.493，差 0.004，没有理由说它领先。对 BM25 的 0.362 差距才明显。
- **QA 准确率上 supermemory 更高。** 49.7% 对 45.3%，文档摘要也承认这点，并强调成本差约 11 倍。我复算：15.67 除以 1.40 约 11.2。
- **supermemory 的召回数字不能直接比。** 文档脚注说它受嵌入器混杂影响，QA 准确率才是干净的比较。
- **误差。** n=300、准确率约 45% 时，95% 误差约正负 5.6 个百分点。graphify 与 hybrid RRF 差 2.0 点、与 dense RAG 差 4.0 点，都在这个范围内。与 BM25 差 14 点、与 mem0 差 18 点，超出误差范围。

这最后一条意味着：能支持的结论是"明显优于 BM25 和 mem0"，而不是"优于混合检索和稠密检索"。

### LongMemEval-S（n=50）

| 系统 | QA 准确率 | recall@10 |
| --- | --- | --- |
| graphify（图扩展） | 76% | 0.844 |
| dense RAG | 76% | 0.848 |
| hybrid RRF | 74% | 0.822 |
| BM25 | 70% | 0.710 |
| mem0 | 70% | 0.344 |

n=50 时，每题占 2.0 个百分点，准确率 76% 的 95% 误差约正负 11.8 点。所有系统的 QA 准确率在 70% 到 76% 之间，差距小于误差范围。这一项能说明的只有召回上 mem0 明显偏低。

### ERPNext 跨工具（n=6）

文档称，给一个固定的编码智能体加一个 graphify 工具，关键事实覆盖率从 grep 与读文件基线的 70.8% 升到 82.0%，约 14 万 token 每次查询。

n=6 意味着每题占平均覆盖率的 16.7 个百分点。11.2 点的差距小于一道题的权重。这个结果最多是个方向性的迹象。此外：

- 智能体固定为 Claude Opus 4.8，最多 14 轮。换模型或轮数，结论可能变。
- 仓库规模约 100 万行，文档没有说明 6 道题的选择方式。

### 推断边精度（FastAPI）

12 条跨文件推断边全部正确。我按精确二项分布算：12 个里 0 个错，错误率的 95% 单侧上界约 22%。文档自己的说法是"带日期的人工抽查，不是持续测量的指标"，我认为这个定位是准确的。

### 15 年的时间序列

689 个每周检查点，用确定性提取建图，无需模型。

| 检查点 | 节点 | 边 | 文件 |
| --- | --- | --- | --- |
| 2011-06-08 | 3,069 | 2,900 | 1,032 |
| 2026-06-24 | 22,620 | 48,710 | 3,758 |

我复算：节点约 7.4 倍，边约 16.8 倍，文档写"约 7 倍和 17 倍"，一致。这一项展示的是确定性提取能跑完 15 年的历史，是工程稳定性的证据，不是准确率的证据。

### 令牌节省

原理文档给出三组：

| 语料 | 文件数 | 每次查询减少 |
| --- | --- | --- |
| 混合语料（含他人仓库、论文、图片） | 52 | 71.5 倍 |
| graphify 源码加一篇论文 | 4 | 5.4 倍 |
| httpx（合成的 Python 库） | 6 | 约 1 倍 |

文档自己说明：6 个文件已能放进上下文窗口，此时图的价值是结构清晰，不是压缩。这组数字很能说明问题：节省随语料规模增长，小仓库几乎没有收益。71.5 倍是 52 个文件语料的结果，不能外推到你的仓库。另外它比较的是"读原始文件"与"读图"，没有与 grep 或检索增强对比。

## 三、文档里不一致的地方

| 不一致 | 内容 |
| --- | --- |
| 更新日期 | BENCHMARKS.md 写"最后更新 2026-07-05"，同文件里却有 2026-10-05 的审计 |
| 语言数量 | 原理文档写 25 种，README 写约 40 种 |
| 召回措辞 | 摘要写"最好的检索召回"，表中 hybrid RRF 仅低 0.004 |

这些不影响数字本身，但说明文档在快速演进，引用时要写明检索日期。

## 四、读这类厂商自测的清单

| 问题 | 本项目的情况 |
| --- | --- |
| 样本量多大 | 300、50、6、12，差异极大 |
| 差距超过误差吗 | 对弱基线是，对强基线多数不是 |
| 评审是谁 | 与回答者同一个模型，有第二评审的验证 |
| 对手是否最佳配置 | 作为适配器运行，有嵌入器混杂的披露 |
| 能否复现 | 有命令，需要模型密钥和预算上限；我没有复现 |
| 对比的是什么 | 记忆系统、检索基线、grep 基线，各项不同 |
| 有没有成本 | 有摄取成本和 token 数 |

值得肯定的是：文档披露了评审验证、嵌入器混杂、n 值，并给了复现命令和花费上限参数。这些让数字可审计。

## 五、对你意味着什么

- **能信的：** 确定性的代码提取不耗模型积分；明显优于弱基线的方向；小仓库收益有限。
- **只能当线索的：** 与强基线的差距；ERPNext 的 11 点提升；推断边的精度。
- **完全不能外推的：** 71.5 倍的节省；对话记忆基准上的名次对代码库问答的意义。

LOCOMO 和 LongMemEval 是对话记忆数据集，不是代码库问答。它们衡量的能力与"让智能体理解仓库"只有间接关系。

## 六、自己估算误差

读任何基准数字时，先用样本量估一下误差。下面的函数我在本机跑过，输出与上文引用的数字一致：n=300、准确率 0.453 时正负 5.6 个百分点；n=50、0.76 时正负 11.8，一题占 2.0 点；n=6 时一题占 16.7 点；12 个样本 0 个错误时，错误率的 95% 单侧上界为 0.221。

```python
import math

def moe(p, n):
    """正态近似下比例的 95% 误差，单位：百分点"""
    return 1.96 * math.sqrt(p * (1 - p) / n) * 100

def upper_bound_zero_errors(n, alpha=0.05):
    """n 个样本 0 个错误时，错误率的精确单侧 (1-alpha) 上界"""
    return 1 - alpha ** (1 / n)
```

两点限制：正态近似在准确率接近 0 或 1、样本很小时不可靠；对两个系统在同一批题上的比较，应当用配对检验，它的误差通常小于各自单独估算的误差，本文没有做。所以这个函数只用来判断"差距有没有可能是噪声"，不用来宣布显著。

## 七、限制与结论

Graphify 的基准文档在透明度上做得比常见的厂商自测好，但样本量决定了多数差距无法区分。最大的一组（LOCOMO，n=300）能支持的也只是"明显优于弱基线"。

本文的限制：没有复现任何基准；误差为粗略估计，未考虑配对；没有读 harness 代码；第二位评审的细节文档没写；数字截至 2026-10-30。

下一步建议：不要拿这些数字做决定，在你的仓库上准备 10 到 20 个已知答案的问题，分别用图查询和你现用的方案回答，对比召回。
