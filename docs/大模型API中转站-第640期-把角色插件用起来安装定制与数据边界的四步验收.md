# 把角色插件用起来：安装、定制与数据边界的四步验收

一个岗位插件装上去，最典型的失望是：它看起来懂你的专业，但一动手就发现连不上你的系统、用的不是你的术语、流程和你们实际做法不一致。

这不是插件写错了，而是它的默认形态是"通用版"。这类插件的设计里已经留了改造入口——占位符与配置文件——但改造顺序错了会白花时间。

本文给一套四步落地顺序，来自这套插件的官方文档与我读配置文件的观察。信息检索日期为 2026-11-04。我没有在 Cowork 或 Claude Code 里安装运行过这些插件。

## 一、两条安装路径不一样

| 环境 | 安装方式 | 注意 |
| --- | --- | --- |
| Cowork | 从其插件页安装 | 图形界面，看不到配置文件 |
| Claude Code | 先 `claude plugin marketplace add anthropics/knowledge-work-plugins`，再 `claude plugin install <插件>@knowledge-work-plugins` | 配置文件在本地，可以改 |

第二条路径的关键差别是：**你能直接编辑 `.mcp.json` 与 `SKILL.md`。** 而定制恰恰都要改文件。

所以如果团队打算定制，建议用命令行路径装一份改一份，别在图形界面里装了之后去找文件。文档里也说明这两条路径都支持、且安装后自动生效。

## 二、第一步：先看占位符映射，再决定接哪些系统

不要一上来就填地址。先打开目标插件的 `CONNECTORS.md`，看它按哪些类别取数据。

以财务插件为例，它列了六类：数据仓库、邮件、办公套件、聊天、ERP/会计、分析/BI。每类下面是内置服务器与其他可选项。

这一步的产出应该是两张清单：

| 清单 | 内容 |
| --- | --- |
| 需要接的系统 | 这个岗位的技能真正会读到哪些类别 |
| 暂时接不上的 | 标注"暂无受支持的 MCP 服务器"的类别（本例是 ERP/会计与分析/BI） |

第二张清单更重要。如果你们的账在 NetSuite 或 SAP 里，而这个插件对这两类只写了"其他可选"、没有受支持的服务器，那么无论装得多顺，"从 ERP 取数"这一步都走不通。**先接受这个缺口，再决定要不要自己补。**

## 三、第二步：按类别填连接地址

打开 `.mcp.json`，会看到形如这样的结构：

```json
{
  "mcpServers": {
    "bigquery": { "type": "http", "url": "https://bigquery.googleapis.com/mcp" },
    "slack": {
      "type": "http",
      "url": "https://mcp.slack.com/mcp",
      "oauth": { "clientId": "…", "callbackPort": 3118 }
    },
    "snowflake": { "type": "http", "url": "" }
  }
}
```

我在财务插件的这个文件里看到 6 个服务器，其中 4 个的 `url` 是空字符串（Snowflake、Databricks、Google 日历、Gmail），只有 BigQuery 与 Slack 有真实地址。同一插件的 `CONNECTORS.md` 用星号标注了其中两个（Snowflake 与 Databricks），脚注写"占位符——MCP 地址尚未配置"；另外两个空地址（Google 日历、Gmail）不在那张类别表里，属于"留了位置但既没配也没文案"的情况。两类要分开看。

所以"内置服务器"在这一层的含义是"留了位置"。填的时候注意三件事：

1. **只填你确实要用的。** 空地址的服务器如果被留着，第一次运行可能会报连接错误，排查时容易误判成插件坏了。
2. **OAuth 类服务器要留意回调端口。** 上例里 Slack 声明了 `callbackPort: 3118`，本机或容器里这个端口被占用时，授权会失败。
3. **地址来源要可核验。** 填进去的地址决定了数据发到哪里。别只贴同事转来的链接，回官方文档核对。

## 四、第三步：把公司上下文写进技能文本

技能是 Markdown，所以可以直接改。要加的东西通常是三类：

| 要加 | 加在哪 | 例子 |
| --- | --- | --- |
| 术语与口径 | 技能的分类或步骤段 | 你们叫"结算单"不叫"对账单" |
| 组织结构与审批链 | 流程段 | 超过某个金额要谁签 |
| 实际做法 | 步骤段 | 你们先对明细账再对银行账，顺序与默认相反 |

改的时候有一条底线：**不要删掉原文里的免责与复核要求。** 财务、法务类技能的开头通常写着"不提供专业建议、须由具备资质的人复核"，那句话是技能的一部分，删了等于把一个流程工具改成结论工具。

另一个建议是保留原文副本。技能会随插件版本更新，你的改动越多，将来合并越麻烦；留一份原版便于对比。

## 五、第四步：不够用就自建，而不是硬改

仓库里有一个专门用于这件事的插件（`cowork-plugin-management`），它的两个技能是"定制现有插件"与"创建新插件"。

什么时候该自建：

| 情形 | 建议 |
| --- | --- |
| 只是术语与审批链不同 | 改现有技能即可 |
| 流程差异大，改完原文只剩三成 | 自建 |
| 岗位没有被覆盖（例如某个细分职能） | 自建 |
| 需要接一类完全没有受支持服务器的系统 | 自建或先做连接器 |

自建的成本比想象中低：组件都是文件，一个插件最小需要 `.claude-plugin/plugin.json` 与若干 `SKILL.md`（清单放在这个子目录里，不是插件根目录）。真正的成本在写技能正文——那需要把你们的方法论写清楚，而这部分没法自动生成。

## 六、数据边界：文件化不等于数据不出门

这是最该讲清的一点。多数插件的组件确实是 Markdown 与 JSON，但**不能由此推出"插件里没有代码"**：例如生物研究那个插件带着若干 Python 脚本（QC 分析、绘图等），它的技能正文直接指示去执行这些脚本。所以插件层面的风险有两层：一是本地代码被执行，二是连接器把请求发到外部 MCP 服务。

因此要做三件事：

1. **审 `.mcp.json` 指向谁。** 每一个地址都是一个数据出口。逐个确认域名与用途。
2. **区分"读"与"写"。** 有些服务器既能读也能写（例如项目跟踪器、文档库）。插件调它做什么，取决于技能怎么写，所以改技能时要留意新增的写操作。
3. **看插件的来源。** 仓库自带的第一方插件与市场里的第三方插件，维护方不同，权限声明也不同。市场清单有 123 条，其中不少是第三方。

如果你们有出网白名单，第一步不是装插件，而是先把要用的 MCP 域名加进白名单，否则会卡在授权环节。

## 七、验收清单

装完之后按下面几项各跑一次，比读文档有用：

| 检查 | 怎么做 | 预期 |
| --- | --- | --- |
| 技能是否被触发 | 提一个该岗位的典型请求 | 相关技能自动生效，输出里带该插件的流程痕迹 |
| 命令是否可用 | 输入文档里列出的斜杠命令 | 能列出参数提示（技能 frontmatter 里的 argument-hint） |
| 连接是否真的通 | 让技能取一条真实数据 | 返回数据而不是连接错误 |
| 空地址是否清掉 | 检查 `.mcp.json` | 不用的服务器已删除或填好 |
| 免责是否还在 | 打开改过的技能 | "须由专业人士复核"一类句子仍在 |
| 数据出口 | 抓一次请求或看服务端日志 | 只发往你批准的域名 |

第四行与第六行是这套清单里唯一两处容易被跳过、又最难事后补救的地方。

## 八、四类常见失败

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 装好但技能不触发 | 请求与该技能的 description 不匹配 | 改 description 或直接用斜杠命令 |
| 一运行就报连接错误 | `.mcp.json` 里留着空地址或用了没开的服务器 | 删掉不用的、填好要用的 |
| 授权反复失败 | OAuth 回调端口被占用或不匹配 | 换端口或换授权方式 |
| 输出与团队做法不符 | 技能正文没改 | 按第三节加公司上下文 |

第三行在容器或远程环境里尤其常见：回调要回到发起授权的机器，端口不通就永远循环。

## 九、一个务实的顺序

如果只记一条：**先决定接哪些系统，再填地址，最后改文本。**

反过来做（先改技能文本）会出问题：技能里写死了某个类别的取数逻辑，等你发现那类系统接不上，改过的文本又得回退。

## 十、限制与结论

这类插件的落地路径可以概括为：用命令行方式安装以便改文件；先看占位符映射确认哪些类别能接、哪些有缺口；按类别填好连接地址并清掉空值；把公司上下文写进技能文本但保留免责；差异过大时改用自建。

数据边界要单独看：文件化的是插件，联网的是连接器。审 `.mcp.json` 等于审数据出口。

本文的限制：没有安装或运行任何插件；配置样例取自仓库里的财务插件，其他插件的字段可能不同；没有核验第三方市场条目；没有实测授权流程与回调端口行为；"验收清单"是按文件结构推得的，未在真实团队验证。

下一步建议：先只接一个类别（例如聊天或数据仓库），跑通一次真实取数。一条链路通了，再补其他类别——一次全接上，出问题时很难判断是插件、配置还是权限。
