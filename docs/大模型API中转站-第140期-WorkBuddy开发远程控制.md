# 【大模型API中转站】第140期 WorkBuddy开发与远程控制 | 小项目能跑起来

本文是【大模型API中转站】系列的第140篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

前两篇讲了 WorkBuddy 的新手入门和办公实战。

这一篇讲两个更有意思的能力：

```text
开发小项目。
远程控制电脑干活。
```

先说结论：

```text
WorkBuddy 可以做开发，但不要把它神化成 Claude Code / Codex 的完全替代品。
```

它更适合：

```text
小网页。
小工具。
简单脚本。
PPT / 文档 / 数据周边自动化。
前端页面原型。
本地文件整理。
远程发邮件、找文件、跑低风险任务。
```

如果你要改一个复杂生产级代码仓库，尤其是：

```text
多服务后端。
复杂权限系统。
大型重构。
高风险生产代码。
```

那我依然建议你优先想办法用 Claude Code、Codex 或更成熟的 Coding Agent。

WorkBuddy 的正确位置是：

```text
普通人的轻量开发 + 办公自动化 + 远程助手。
```

## 1. 先认识专家、Skills 和连接器

WorkBuddy 左侧的“专家”里，通常有三个 tab：

```text
专家
技能
连接器
```

这三个东西很容易混。

先用一句话区分：

```text
专家：一个调好方向的垂直 Agent。
技能：一份可复用的操作手册或能力包。
连接器：把外部服务接进来的 MCP。
```

专家解决：

```text
谁来干。
```

技能解决：

```text
按什么方法干。
```

连接器解决：

```text
能连接哪些外部工具和数据。
```

把这三层理解清楚，后面用 WorkBuddy 会顺很多。

## 2. 专家：适合找“带专业视角的人”

专家可以理解成：

```text
已经配好角色、工具、知识和提示词的垂直 Agent。
```

比如：

```text
内容创作专家。
UI 设计师。
AI 图像提示词工程师。
产品经理。
数据分析师。
代码工程师。
```

你点进去就能对话。

区别是它不会像普通聊天那样从零理解任务。

它已经有一个方向。

适合：

```text
你知道要做什么，但不知道该找什么角度。
```

例如你要做一个活动页面。

普通对话可能只会问：

```text
你想做什么页面？
```

UI 设计师专家会更容易关注：

```text
布局。
配色。
组件。
信息层级。
视觉风格。
移动端适配。
```

专家的价值不是“更玄学”。

而是减少你每次解释专业背景的成本。

## 3. 专家团：适合复杂但低风险的任务

专家团就是多个专家协作。

例如软件开发团：

```text
交付总监
产品经理
架构师
工程师
QA
```

你一句话：

```text
帮我做一个世界杯主题网页。
```

它可能会自动拆成：

```text
需求澄清。
页面结构。
视觉方案。
代码实现。
测试检查。
交付说明。
```

听起来很爽。

但要注意：

```text
专家团成本更高。
```

附件里提到，积分消耗可能是单专家的 3-5 倍。

所以专家团适合：

```text
任务确实需要多个视角。
结果有复用价值。
你愿意为更完整的过程买单。
```

不适合：

```text
一句话小任务。
简单改文案。
随手问问题。
低价值批量任务。
```

## 4. Skills：把好方法沉淀下来

Skills 是 WorkBuddy 值得认真看的部分。

它不是简单插件。

更像：

```text
给 Agent 的专业操作手册。
```

比如你经常做：

```text
前端页面设计。
服务器部署。
PPT 生成。
合同审查。
数据清洗。
竞品分析。
公众号文章改写。
```

你就可以把一套固定方法做成 Skill。

WorkBuddy 的好处是，它有 Skills 市场。

常见分区包括：

```text
官方推荐。
社区作品。
套件。
自定义技能。
```

新手不要一口气装一堆。

先按任务装。

比如你想做网页：

```text
前端开发 Skill
UI 设计 Skill
部署 Skill
```

你想做办公：

```text
文档整理 Skill
PPT Skill
数据分析 Skill
```

你想做内容：

```text
选题 Skill
爆款标题 Skill
平台改写 Skill
```

Skills 的关键不是多。

而是：

```text
装了以后真的反复用。
```

## 5. 连接器：MCP 把外部服务接进来

连接器就是 MCP。

一句话：

```text
让 WorkBuddy 能连接外部服务。
```

WorkBuddy 的优势之一，是腾讯生态接得顺。

附件里提到的例子包括：

```text
QQ 邮箱
腾讯会议
腾讯文档
通达信 MCP
```

以 QQ 邮箱为例：

```text
点 QQ 邮箱连接器
-> 扫码
-> 手机授权
-> 完成
```

这比很多海外 Agent 配 MCP server、token、JSON 配置要简单。

连接器能带来什么？

比如：

```text
搜索邮件。
整理附件。
读取腾讯文档。
提取会议纪要。
把结果发给指定联系人。
```

但这里要强调权限边界。

邮箱、文档、会议记录都可能有敏感信息。

不要一上来就给所有连接器完全权限。

先从只读任务开始。

## 6. 开发案例：做一个世界杯主题网页

附件里的开发案例很典型。

任务是：

```text
帮我开发一个世界杯即将开始的主题网页，有足球主题风格。
```

新手建议流程：

```text
切到代码开发
-> 点网站开发
-> 模式选 Plan
-> 点优化提示词
-> 回答它的反问
-> 确认方案
-> Craft 执行
```

不要直接一句话让它开干。

更好的提示词是：

```text
请帮我做一个世界杯主题宣传网页。

目标：
用于活动预热和分享。

要求：
1. 单页网站。
2. 有足球、赛程、倒计时、球队氛围。
3. 适配桌面和手机。
4. 先给页面结构和视觉方案。
5. 确认后再生成代码。

限制：
- 不要接真实支付。
- 不要调用需要 Key 的外部服务。
- 代码放在当前工作空间。
```

生成第一版后，不要直接结束。

再让它做一轮自检：

```text
请检查这个网页：
1. 移动端是否可读。
2. 按钮是否有明确作用。
3. 文案是否像活动页。
4. 是否有明显布局错位。
5. 代码是否能直接本地打开。
```

如果你有前端开发 Skill，可以再让它按 Skill 重新设计一版。

通常第二版会比第一版更像样。

## 7. 开发任务的真实边界

这里要说实话。

WorkBuddy 做小项目没问题。

比如：

```text
静态网页。
活动页。
数据小工具。
脚本草稿。
文档自动化。
轻量原型。
```

但复杂工程不要硬上。

特别是：

```text
涉及线上数据库。
涉及支付。
涉及权限。
涉及安全。
涉及大量历史代码。
涉及团队协作规范。
```

这些任务更适合 Claude Code、Codex 或团队内部成熟 Coding Agent。

国产模型这几年进步很快，但眼下做复杂代码工程，最重要的不是“能不能写出来第一版”。

而是：

```text
能不能读懂旧代码。
能不能最小修改。
能不能跑测试。
能不能处理失败。
能不能不乱动无关文件。
```

所以我的建议是：

```text
WorkBuddy 做轻量开发和原型。
Claude Code / Codex 做复杂工程。
4SAPI 做模型统一入口和成本治理。
```

## 8. 远程控制：这才是普通人很常用的能力

WorkBuddy 的远程控制很值得写。

因为它直接打通微信。

这对普通用户非常实用。

场景很真实：

```text
人在外面。
电脑上有个文件。
同事催你发。
你不想赶回去开电脑。
```

如果 WorkBuddy 已经配置好远程控制和邮箱连接器，就可以让它帮你处理。

配置大致是：

```text
左侧功能区 -> 助理
-> 设置
-> 打开远程相关开关
-> 微信扫码
-> 小程序授权登录
-> 客户端显示已连接
```

手机端通常有两种模式：

```text
云端工作
连接电脑
```

云端工作：

```text
任务在云端沙箱跑。
电脑不一定要开着。
适合不依赖本地文件的任务。
```

连接电脑：

```text
远程操控你本机。
适合读取本地文件、处理桌面任务。
```

两种模式要分清。

如果任务需要你电脑里的文件，就要连接电脑。

## 9. 远程任务最适合做什么

适合远程的任务：

```text
找某个文件。
把文件发到邮箱。
整理当天会议纪要。
读取某个文档并总结。
生成一份临时汇报。
把资料打包。
检查任务是否跑完。
```

不建议远程做：

```text
删除文件。
批量移动大量文件。
修改重要代码。
提交生产系统。
发送敏感邮件。
处理财务付款。
```

远程控制最大的风险是：

```text
你不在电脑前，验收能力下降。
```

所以远程任务应该默认低风险。

如果涉及发邮件、上传文件、转发资料，最好让它先把内容发到小程序对话里，你确认后再发送。

## 10. 一个远程办公提示词

可以这样用：

```text
请帮我在电脑里查找今天需要发给财务的报销材料。

要求：
1. 只搜索 Documents 和 Downloads。
2. 不要删除或移动文件。
3. 找到候选文件后，先列出文件名、路径和修改时间。
4. 等我确认后，再打包或发送。
5. 如果需要发邮件，先生成邮件草稿，不要直接发送。
```

这个提示词的关键是：

```text
限定目录。
禁止删除移动。
先列候选。
发送前确认。
```

不要简单说：

```text
帮我把文件发给财务。
```

这句话权限太大。

## 11. 设置里建议打开什么

附件里提到几个设置。

可以按优先级来。

第一，技能自动更新。

```text
建议打开。
```

Skills 市场更新快，自动更新可以少维护。

但团队场景要注意：

```text
关键生产 Skill 不要无审查自动升级。
```

个人用户可以开。

企业建议先在测试环境验证。

第二，锁屏远程。

```text
需要远程跑任务就打开。
```

但要配合电脑电源、休眠策略和权限边界。

第三，对话记忆。

```text
个人用户建议打开。
```

它会提炼你的偏好和工作习惯。

但如果你处理企业敏感材料，要先看数据和隐私策略。

第四，自定义指令。

这个很重要。

可以把它当成 WorkBuddy 的全局作业规则。

## 12. 一份适合 WorkBuddy 的总指令

可以放进自定义指令：

```markdown
# WorkBuddy 总指令

## 工作原则

- 先理解任务目标、输入、输出和限制，再开始执行。
- 不确定时先问，不要硬猜。
- 多步任务先给简短计划。
- 修改文件前说明会改哪些文件。
- 完成后说明生成了哪些产物。

## 文件安全

- 不删除文件。
- 不批量移动文件，除非我明确确认。
- 不覆盖原始文件，优先另存为新文件。
- 涉及邮件、外发、上传、分享前，先让我确认。

## 输出要求

- 默认中文。
- 默认 Markdown。
- 先给结论，再给步骤。
- 数据和事实要标注来源。
- 不确定内容写“待确认”。

## 开发任务

- 先给方案，再写代码。
- 保持最小改动。
- 不接真实支付、生产数据库或敏感 API。
- 生成后要给本地预览和验收步骤。
```

这份指令不复杂。

但能让 WorkBuddy 少犯很多低级错。

## 13. 团队使用要加治理层

个人用 WorkBuddy 可以轻量。

团队用必须上治理。

至少要管：

```text
谁能开完全访问。
谁能接邮箱和文档。
谁能创建自动化。
哪些 Skill 能用。
哪些任务必须人工确认。
哪些模型可以调用。
成本怎么统计。
日志保存多久。
```

如果团队还接 4SAPI，可以把模型层统一起来：

```text
WorkBuddy
-> 4SAPI / 企业 API 网关
-> DeepSeek / GLM / Kimi / Claude / GPT / Gemini
```

然后按任务分组：

```text
办公低成本模型。
开发主力模型。
强模型复核。
敏感任务禁用外发。
```

Agent 越方便，越要有边界。

## 14. 最后总结

WorkBuddy 的开发和远程控制，不是为了替代所有专业工具。

它更像是：

```text
普通人的 AI 执行台。
```

你可以让它：

```text
做小网页。
写小工具。
整理文件。
跑办公任务。
接邮箱。
远程找文件。
生成汇报。
把流程沉淀成 Skill。
```

但不要让它一上来：

```text
改生产代码。
删重要文件。
发敏感邮件。
操作财务系统。
接管复杂工程。
```

正确姿势是：

```text
Plan 先看方案。
Skill 固化方法。
连接器接数据。
默认权限保安全。
远程任务先确认。
4SAPI 做团队模型治理。
```

这样用，WorkBuddy 才是让生活变轻的助手。

不是让你多一个需要收拾的烂摊子。
