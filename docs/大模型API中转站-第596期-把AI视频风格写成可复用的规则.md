# 把一种视觉风格写成 Agent 能复用的规则：风格文件的结构与改法

让 Agent 做"油画风""水墨风""像素风"的内容，最常见的抱怨是不稳定：今天画得像，明天就跑偏；同一支片子里，第三个镜头和第一个镜头像是两个人画的。

原因很简单："油画风"三个字给 Agent 的信息太少。它不知道笔触多大、颜色怎么搭、镜头能不能动、配什么乐器、哪些做法会让这个风格变味。

开源项目 [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) 的做法是把每种风格写成一份固定结构的 `STYLE.md`，并且提供了一套"把库里的风格改成自己的版本"的流程。本文拆解这份风格文件的结构与改法，它对任何需要让 Agent 稳定复现某种视觉调性的场景都适用，比如品牌短片、系列栏目、固定 IP。来源为项目文档，检索 2026-10-29。

## 风格和故事要分开

这套做法的第一条原则是：**风格文件只写不变的东西，故事每次重新决定**。

| 写进风格文件的（不变） | 每次重新定的（可变） |
| --- | --- |
| 材质与画法、配色逻辑、字体 | 讲什么故事、几个角色 |
| 动作质感、镜头语法 | 开场怎么开、结尾怎么收 |
| 声音调色板 | 具体镜头、时长、节奏 |
| 这种媒介独有的动作 | 要不要配音 |
| 常见的坑 | 镜头路线 |

把这两类混在一起写，是风格提示词最常见的问题：写着写着就把某支样片的剧情、镜头顺序、片尾卡也写进去了，结果 Agent 每次都在复刻同一支片子。

## 一份风格文件的十一个章节

以库里的"油画厚涂"风格为例，它的 `STYLE.md` 分成十一个章节：

| 章节 | 管什么 | 举例（油画厚涂） |
| --- | --- | --- |
| 1. 本质，以及它不是什么 | 一句话定义，加反例 | 是刮刀厚涂的移动油画；不是梵高旋涡滤镜，不是笔刷纹理叠在扁平矢量上 |
| 2. 材质与渲染 | 笔触大小、层次、光照 | 先定明暗再上笔触；笔触不跨形状组；超采样渲染，不加颗粒 |
| 3. 配色逻辑 | 颜色怎么组织，而不只是用哪几个颜色 | 暖光对冷影；最纯的颜色留给故事主体 |
| 4. 字体与字幕 | 标题与小字分别怎么处理 | 标题用刮刀一笔笔铺出来；小字保持清晰的网页文字 |
| 5. 动作质感 | 什么在动、怎么动 | 静止的颜料不动，只有故事里的东西动 |
| 6. 镜头语法 | 一张运镜词汇表 | 慢推、仰摇、俯拍旋转升起、同一构图重复 |
| 7. 声音调色板 | 拟音、环境声、乐器 | 每次重绘都有刮刀声；手工质感的原声乐器 |
| 8. 媒介独有的动作 | 只有这种风格能做的转场或揭示 | 刮刀重新上色、全片只有一样东西有颜色 |
| 9. 常见的坑 | 这种媒介最容易出的错 | 笔触每帧重新随机会"沸腾"；颗粒会吃掉刀痕 |
| 10. 引擎 | 画法对应的代码与调用方式 | 渲染器文件、主要函数、最小示例 |
| 11. 变化空间 | 故事层面可以怎么变 | 列出几种远离样片的结构、开场、结尾 |

有两个章节最值得借鉴。

**第一章写"不是什么"。** 只写"是什么"，Agent 会往最常见的方向靠；加上反例，它才知道边界在哪里。

**第六章是词汇表，不是路线图。** 每种运镜后面写的是"表达什么"和"适合什么内容"，比如"推镜穿过一段安静"表达内心压力，适合怀疑、决定、放弃。Agent 拿到的是选项，不是固定剧本。

## 哪些能改，哪些不能改

想把库里的风格改成自己的版本，最大的风险是改着改着就变成了另一个风格。项目把风格文件的章节分成三组：

| 分组 | 涉及章节 | 对用户的说法 |
| --- | --- | --- |
| **放心改** | 配色（在原有逻辑之内换颜色）、字体、动作快慢、声音调色板、换或加一个独有动作 | 风格还是它自己，每项可以给两三个方向 |
| **一改就变味** | 材质与渲染、配色逻辑本身、镜头语法 | 能改，但要说清楚这个风格会失去什么 |
| **不能改** | 本质（及"不是什么"）、引擎 | 改了就是另一个风格，建议换一个更接近的底子 |

这张表的价值在于它把"改风格"变成了一个有代价意识的决定。用户说"把水彩改得更硬朗一点"，Agent 能判断这是在动材质（一改就变味），而不是在动配色（放心改），并提前说清楚代价。

几条配套规则：

- **一轮最多改五处。** 改得太多，没法判断每一处的效果。
- **独有动作最多换一个。** 它是这个风格最能被认出来的地方。
- **联动的改动要一起考虑。** 动作变快，声音就要变密；配色变暗，字的对比度就要重新检查；换了新材质，就会带来新的坑。

## 把模糊的说法翻译成具体改法

用户通常只知道自己想要的感觉，不知道该改哪一章。项目给了一张翻译表，非常实用：

| 用户说 | 通常意味着 |
| --- | --- |
| 高级一点 | 颜色更少、明暗对比更强、动作更慢、留白更多、字体更细 |
| 年轻、活泼一点 | 更亮的点缀色、卡着节拍剪、更有弹性的缓动、更多打击乐 |
| 安静一点 | 速度更慢、停留更长、动的东西更少、乐器更稀疏 |
| 像我们的品牌 | 品牌色做点缀而不是底色；标题用品牌字体；开头和结尾放 logo |

最后一行有个细节值得照做：**品牌色先当点缀，不要当底色**。保留原风格的明暗结构，文字才能保持可读。很多品牌片一上来就把整个画面刷成品牌色，结果字看不清、主体不突出。

还有两条品牌相关的检查：品牌字体必须覆盖片子的语言（中文片要有中文字形），并且允许用于视频；logo 和字体文件由用户提供。

## 什么时候根本不需要改风格

这是最容易被忽略的一条。如果用户想改的只是故事、结构、开场、结尾、角色、场景、节奏或配音，**那就不需要自己的风格**——这些在每支片子里本来就是自由的，做片时直接说就行。

只有当想改的是材质、配色、字体、动作质感、镜头语法、声音、独有动作这些"不变量"时，才值得存一个自己的版本。

## 改完之后怎么验证

项目给的验证流程分三步，每一步都用真实的绘制代码，而不是示意图：

**第一步：一张风格图。** 改库里风格的，同一个画面用原风格再出一张，左边原版、右边改后版并排放，只有改动的地方不同。不满意就再改，两轮还不对就直说，建议换一个更接近的底子。

**第二步：一支 15–30 秒的样片。** 每一处改动都要在画面里至少出现一次，独有动作出现一次；配音乐和音效，默认不配音、不加字幕。这个长度下，一次真正的安静、三种运镜就够了。

**第三步：确认后再固化。** 用户可以选择存成自己的风格、再改一轮，或者先不存。没确认之前，一切只在这次的项目文件夹里。

固化后的风格存在用户目录下，和库里的风格同样的结构：

| 文件 | 内容 |
| --- | --- |
| `STYLE.md` | 这个风格的不变量，章节与库里风格一致 |
| `CHANGES.md` | 每一处改动一行：哪一章、原来是什么、现在是什么、为什么 |
| `style.json` | 名称、底子风格、借用了哪些风格的动作、默认尺寸、创建时的库版本 |
| `DEMO.md` 与 `demo/` | 样片怎么做的，以及能一条命令重建的源码 |
| `styleframe.jpg` | 确认过的风格图 |
| `test.mp4` | 样片 |

`CHANGES.md` 是最值得照抄的一份文件。它让每一次改动都有记录、有理由，样片也按它来逐条检查。以后底子风格更新了，也能对照它判断哪些修复值得同步过来。

## 一个完整的改法示例

假设一家做茶饮的品牌想用“水彩笔刷”风格做每周一支竖屏短片，品牌色是墨绿，希望“安静、高级一点”。按上面的规则，改动清单可以是这样：

| 改动 | 章节 | 分组 | 原来 | 现在 | 代价 |
| --- | --- | --- | --- | --- | --- |
| 画幅 | — | — | 1920×1080 | 1080×1920 | 构图要重新排，字幕区上移 |
| 点缀色 | 配色 | 放心改 | 流动的暖色 | 墨绿，只用在茶杯与标题 | 画面整体偏冷 |
| 字体 | 字体 | 放心改 | 通用衬线体 | 品牌字体（需含中文字形） | 字体授权由品牌提供 |
| 动作快慢 | 动作 | 放心改 | 中速 | 更慢，镜头停留更长 | 同样片长里内容更少 |
| 乐器 | 声音 | 放心改 | 木管与弦乐 | 古琴与环境声 | 节奏感变弱，靠安静撑起情绪 |

五处都在“放心改”一组，风格的本质不动。画幅是由发布平台决定的，不计入改动数。如果品牌还想把水彩改成硬边的版画质感，那就动到了材质，属于“一改就变味”，要先说清楚会失去水彩的晕染和透明感，或者干脆换一个版画类的底子。

## 常见问题

**Q：可以把两种风格混在一起吗？**
可以，但只能有一个底子。做法是选本质最接近的那个当底子，另一个只借用需要的动作，并在记录里写明借了哪个。

**Q：风格文件为什么要写成英文？**
项目的风格文件是写给 Agent 看的，统一用英文，风格名保留中英双语。用户跟 Agent 交流仍然可以用中文。

**Q：底子风格更新了怎么办？**
自己的风格存在库之外，库更新不会改它。`style.json` 里记了创建时的库版本，底子变了时 Agent 会提一句，问要不要把有用的修复同步过来，不会自动改。

## 迁移到其他场景

这套结构不只适用于短片：

| 场景 | 怎么用 |
| --- | --- |
| 品牌社媒图 | 写一份品牌视觉的"不变量"文件，每次只换文案和主体 |
| 系列栏目 | 固定开场、配色、字体、片尾；每期只换内容 |
| 网页设计 | 用"放心改 / 一改就变味 / 不能改"三组划分设计系统 |
| 写作风格 | 第一章写"它是什么、不是什么"，第九章写"最容易写坏的地方" |

## 限制与结论

需要说明的是：这套风格文件是按特定模型调出来的，换模型后效果不保证；"一轮最多改五处""最多换一个独有动作"是项目方的经验规则；所有画面都要求用代码画，不使用图片或视频生成，这限制了可实现的风格范围。

可以确定的是方法的骨架：把不变量和故事分开写；用"是什么 / 不是什么"定义边界；把章节分成放心改、一改就变味、不能改三组；用一张翻译表把模糊需求变成具体改法；改完先出并排对比的风格图，再出一支短样片，确认后才固化。这几步能让 Agent 在同一种调性下稳定产出，而不是每次都靠运气。
