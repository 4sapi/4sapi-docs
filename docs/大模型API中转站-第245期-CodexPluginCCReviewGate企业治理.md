# Codex Review Gate 的启用、关闭与循环边界

Review Gate 会在 Claude Code 准备停止时触发 Codex 审查；如果审查发现问题，停止可能被阻止，Claude 处理后又可能再次触发门禁。它适合在操作者在线时，为一段明确的高风险改动增加补充检查，不适合永久开启或替代 CI。本文只解决如何控制这条循环：先完成仓库规定的测试，写清哪些发现需要处理以及何时转人工，临时启用 Gate，全程观察每轮结果，任务结束后显式关闭并确认配置状态。操作者还要保留触发原因、发现内容、处理决定和关闭结果，避免会话结束后无法解释门禁为何阻塞。

[`openai/codex-plugin-cc` 官方 README](https://github.com/openai/codex-plugin-cc) 明确警告：

```text
Review Gate 可能形成长时间的 Claude/Codex 循环，并快速消耗使用额度。
只应在计划主动监控会话时开启。
```

## 1. 如何启用和关闭

启用：

```text
/codex:setup --enable-review-gate
```

关闭：

```text
/codex:setup --disable-review-gate
```

不要只记得怎么开。

团队 runbook 必须同时写清什么时候关。

## 2. Review Gate 的运行链

```text
Claude Code 完成当前回答或任务
              ↓
        触发 Stop hook
              ↓
    插件生成定向 Codex Review
              ↓
      没有问题：允许结束
      发现问题：阻止停止
              ↓
      Claude 继续处理发现
              ↓
        可能再次触发门禁
```

风险就出在最后一步。

如果发现不明确、修复不彻底或两个模型意见不同，循环可能持续。

## 3. 哪些任务适合开启

适合：

```text
发布前最后一轮改动。
认证和授权逻辑。
支付、退款与计费。
数据库迁移。
批量数据删除。
并发、事务与重试。
大型重构的关键阶段。
模型调用、预算和自动回退逻辑。
```

不适合：

```text
文档改字。
小型样式调整。
探索性原型。
每次保存后的日常循环。
没有明确验收标准的任务。
```

门禁应该由风险触发，不应该默认覆盖所有开发。

## 4. 开门禁前必须定义停止条件

至少写清：

```text
何时停止自动处理并转人工。
哪些风险等级阻塞。
哪些发现必须有代码证据。
哪些问题转人工处理。
什么时候立即关闭 gate。
```

插件本身的实际循环控制能力以当前版本为准。操作者应在发现重复、缺少证据或超出任务范围时手工关闭门禁，并转为人工审核。

## 5. Review Gate 不替代 CI

门禁能分析代码和上下文，但不能替代：

```text
单元测试。
集成测试。
类型检查。
静态分析。
依赖漏洞扫描。
构建。
数据库迁移演练。
浏览器或端到端测试。
```

正确顺序：

```text
Claude Code 实现。
  ↓
本地测试和静态检查。
  ↓
Codex Review Gate 查遗漏。
  ↓
人工确认高风险发现。
  ↓
CI/CD 再做确定性门禁。
```

AI 门禁是补充，不是测试框架。

## 6. 不要让两个模型自动互相说服

最危险的循环：

```text
Codex 提出模糊风险。
Claude 做大范围重构。
Codex 又对新结构提出新建议。
Claude 继续重构。
```

控制方法：

```text
发现必须包含文件位置和触发条件。
修复必须优先最小改动。
新增行为必须补测试。
纯替代方案不自动执行。
连续两轮发现变化时交给人工。
```

## 7. 一套任务结束前的工作流

第一步，确认工作区，并运行仓库实际规定的测试和静态检查：

```bash
git status --short
```

第二步，短时间开启 Gate：

```text
/codex:setup --enable-review-gate
```

第三步，让 Claude Code 完成发布前检查与总结。

第四步，Codex Gate 审查发现。

第五步，逐条确认高风险问题并重跑验证。

第六步，关闭 Gate：

```text
/codex:setup --disable-review-gate
```

第七步，保存审查结果和人工决策。

不要把 Gate 永久留在所有会话里。

## 8. 常见错误

### 日常永久开启

会增加循环、延迟和额度消耗。

### 不定义阻塞等级

任何建议都可能触发修改。

### Gate 通过就直接上线

仍然需要测试、CI 和人工批准。

### 忘记关闭

关键任务结束后应显式禁用。

## 9. 检查清单

```text
[ ] 只有高风险任务开启 Gate
[ ] 已写明转人工和立即关闭的条件
[ ] 风格建议不会阻塞
[ ] Gate 前已运行确定性测试
[ ] 每条阻塞发现都有位置和触发条件
[ ] 修复优先最小改动并补回归测试
[ ] 发现重复或缺少证据时转人工
[ ] 任务完成后关闭 Gate
[ ] 已保存关键发现、测试结果和人工决定
```

## 10. 结论与限制

Review Gate 是一把强工具。

它把“记得找 Codex 审一下”变成 Claude Code 停止前的自动检查。

但自动化越强，越需要停止条件：

```text
只在高风险任务开启。
只让真实风险阻塞。
重复或缺少证据时转人工。
保留人工批准。
任务结束立即关闭。
```

CI 与人工负责人仍然负责最终发布。Gate 只提供一次补充审查，不会证明代码正确，也不会替代确定性测试。

本文只覆盖当前官方 README 中的启用、禁用和循环警告。插件版本变化可能改变 hook 行为；实际使用时必须由操作者在线监控，并在任务结束后显式关闭，不能承诺自动循环一定在某一轮停止。
