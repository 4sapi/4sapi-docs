# 电商询盘自动化怎么做：让 AI 写草稿，人工守住成交风险

电商询盘最容易被自动化做坏。

很多系统能快速生成一封看起来完整的邮件，却没有确认客户是否真的需要这个产品，也没有检查价格、库存和交期。

一旦把错误内容直接发出去，前面节省的几分钟，可能换来退订、投诉甚至一笔错误承诺。

更稳的做法是把 AI 放在识别、整理和起草环节，把发送、价格和承诺留在明确的审核点。

## 一、先区分四种询盘

客户发来的消息不一定都是采购机会。

可以先分为：

| 类型 | 例子 | 后续处理 |
| --- | --- | --- |
| 需求明确 | 给出产品、数量和时间 | 进入需求确认 |
| 信息咨询 | 询问规格、材质或交期 | 读取产品卡后待确认 |
| 售后问题 | 反馈损坏、延迟或退款 | 转售后流程 |
| 无效或营销 | 广告、空邮件、明显无关内容 | 标记并结束 |

分类结果只是起点。

涉及价格、认证、合同和退款时，不应由分类模型直接决定最终回复。

## 二、保存原始回复

系统先保存客户原文、发件人、时间和关联客户，不要只保存 AI 摘要。

建议字段：

```text
message_id
lead_id
received_at
sender
raw_content
attachments
language
intent
status
```

原文是后续复核的依据。

如果只保留模型改写后的摘要，出了争议很难还原客户到底说了什么。

附件也要单独记录，不要默认模型已经读取并理解其中全部内容。

## 三、让模型提取需求字段

询盘处理的第一步，不是写回复，而是把需求拆成结构化字段：

- 产品名称；
- 规格和材质；
- 数量；
- 目标市场；
- 交付地点；
- 期望时间；
- 认证要求；
- 预算或价格区间；
- 客户提出的问题；
- 尚未提供的信息。

缺失字段要明确标记为空或待确认。

不要让模型为了“完整”而自行补全数量、交期和认证。

## 四、需求确认要有问法模板

如果关键字段缺失，系统可以生成补充问题草稿。

例如只知道产品名称，不知道数量和交付地时，下一步应询问：

```text
预计采购数量是多少？
希望送达哪个国家或地区？
期望的交付时间是什么？
是否有指定认证或包装要求？
```

一次不要问十几个问题。

优先询问会直接影响价格、交期和产品匹配的字段。

## 五、报价草稿必须读取产品卡

报价不是自由写作任务。

系统需要读取结构化产品卡：

| 字段 | 说明 |
| --- | --- |
| product_id | 产品标识 |
| purchase_cost | 采购成本 |
| price_range | 建议价格区间 |
| min_margin | 最低毛利底线 |
| lead_time | 标准交期 |
| inventory | 可用库存 |
| certification | 已确认的认证 |
| exclusions | 不能承诺的内容 |

模型可以生成表达，但数字必须来自产品卡或人工输入。

如果库存不足、交期未知或报价低于毛利底线，直接进入人工审核。

## 六、回复草稿分成三层

### 第一层：确认事实

只复述客户已经提供的需求和系统已经确认的产品信息。

### 第二层：回答问题

从产品卡、物流规则和售后政策中取值。

### 第三层：列出待确认项

告诉客户还需要补充什么，或者告诉内部负责人哪些内容不能自动承诺。

这样的草稿比一段流畅但没有来源的营销文案更有用。

## 七、人工审核看什么

审核人不必从头重写每封邮件。

可以只检查高风险字段：

- 产品型号；
- 数量和单位；
- 价格和折扣；
- 交期；
- 认证和合规；
- 付款方式；
- 退换货条件；
- 客户是否已经回复或退订。

如果这些字段都能追溯到来源，审核效率会高很多。

## 八、客户回复后暂停自动跟进

客户一旦回复，原来的自动跟进任务应该暂停。

原因很简单：回复意味着对话进入了新阶段，旧的“未回复”逻辑已经不适用。

如果系统继续按旧计划发送“提醒一下”，客户会收到互相矛盾的内容。

状态转换可以写成：

```text
等待回复 -> 收到回复 -> 暂停自动跟进 -> 人工或新任务处理
```

明确拒绝、退订和投诉，则应进入不可自动触达状态。

## 九、跟进不是越多越好

跟进策略应该基于客户状态和业务价值。

如果客户明确表示暂时没有需求，可以记录下一次联系时间，但不要每天重复发送。

如果客户索要报价后沉默，系统可以提醒负责人检查报价是否完整，而不是立即连续追加多封邮件。

每次跟进都要有理由：补充信息、确认时间、回答问题或提供客户明确需要的材料。

没有新信息的重复触达，会快速消耗信任。

## 十、退订和投诉要优先级最高

系统收到以下信号时，应立即停止营销触达：

- unsubscribe；
- stop；
- remove me；
- 明确拒绝；
- 投诉或举报；
- 邮箱无效。

不同地区的营销和隐私规则不同，实际发送前应由负责人确认适用要求。

退订状态要作用到公司、联系人和相关邮箱，避免换一个任务又重新触达同一个人。

## 十一、把 AI 结果和证据放在一起

每一封草稿最好同时显示：

```text
引用了哪条客户信号
读取了哪个产品卡版本
使用了哪条价格规则
哪些字段是模型推测
哪些字段需要人工确认
```

审核人可以快速定位风险，而不是通读一封看似完整的邮件再猜它依据了什么。

## 十二、用小批量做上线测试

上线前先使用历史询盘做干跑。

不发送，只生成分类、字段提取和草稿。

检查：

1. 意图分类是否把售后误判成新销售；
2. 关键字段是否被漏提取；
3. 产品匹配是否引用真实产品；
4. 价格、库存和交期是否越界；
5. 已退订客户是否被重新排队。

干跑通过后，再允许小批量进入人工审核队列。

## 十三、衡量询盘自动化的指标

推荐关注：

- 首次响应时间；
- 需求字段完整率；
- 草稿审核通过率；
- 人工平均修改时间；
- 有效回复率；
- 报价转化率；
- 退订率；
- 投诉率；
- 回复后的成交率。

“生成了多少封邮件”不是核心指标。

如果产量增长但有效回复率下降，自动化可能只是在增加噪声。

## 十四、一个最小的审核队列

审核队列可以按风险排序：

```text
高金额报价
-> 涉及认证或交期承诺
-> 新客户首触
-> 客户投诉和退款
-> 普通规格咨询
```

高风险内容优先由经验丰富的人处理。

低风险、信息完整的重复问题，可以逐步提高自动化程度。

## 十五、结论

询盘自动化的目标不是让 AI 代替销售做所有决定，而是让它先把原始回复、需求字段、产品信息和草稿整理好，把人的时间集中到真正需要判断的地方。

原文留存、字段抽取、产品卡约束、审核点、退订状态和小批量上线，构成了一条更稳的路径。

让 AI 写得快一点很容易。

让它每次都知道依据是什么、哪些话不能承诺，以及什么时候必须停下来，才是询盘系统真正的难点。
