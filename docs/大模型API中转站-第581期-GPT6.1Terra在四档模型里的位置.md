# GPT-6.1 Terra 在四档模型里的位置：$1/$5 买到什么，买不到什么

OpenAI 在 2026-10-26 发布 GPT-6.1 Terra，模型 ID `gpt-6.1-terra`。标准价 **输入 $1、输出 $5 / 每百万 tokens**——是 GPT-6.1 Sol 的一半，GPT-6 Astra 的十分之一。官方给它的定位不是"更强"，而是"够快够用还便宜"：视觉推理、精确的 computer use、更清楚的写作。

便宜档最容易踩的坑是把它当"小一号的 Astra"来用。这篇只解决一个问题：在 Astra、6.1 Sol、6.1 Terra、6 Luna 这四档里，什么任务该给谁。价格与规格引自 OpenAI 官方模型页与定价页，第三方数据引自 Artificial Analysis，检索 2026-10-27。

## 四档的硬规格对照

| 项目 | GPT-6 Astra | GPT-6.1 Sol | GPT-6.1 Terra | GPT-6 Luna |
| --- | --- | --- | --- | --- |
| 模型 ID | `gpt-6-astra` | `gpt-6.1-sol` | `gpt-6.1-terra` | `gpt-6-luna` |
| 输入 / 输出（每 MTok） | $10 / $50 | $2 / $10 | $1 / $5 | $0.10 / $0.50 |
| 缓存输入 | $1.00 | $0.10 | $0.05 | $0.01 |
| 上下文窗口 | 1.05M | 1.05M | 1.05M | 1.05M |
| 最大输出 | 128K | 128K | 128K | 128K |
| 知识截止 | 2026-04-30 | 2026-04-30 | **2026-06-01** | 2026-05-18 |
| 推理强度 | low→max | low→max | **none**/low→max | none/low→max |

来源：[OpenAI 模型页](https://platform.openai.com/docs/models)、[定价页](https://platform.openai.com/docs/pricing)，检索 2026-10-27。

三处值得单独看一眼的差异。

**知识截止更晚。** Terra 是 2026-06-01，比 Astra 和 Sol 的 2026-04-30 晚一个月。这不代表更强，但意味着处理近期资料时，它对"需要检索"的依赖略低一点。别把这个差异当成版本新旧的证明——Luna 是 05-18，夹在中间。

**上下文和输出上限完全一致。** 四档都是 1.05M 上下文、128K 最大输出。便宜档没有在这些硬参数上缩水，缩的是能力密度。

**Terra 多一个 `none` 档。** 它可以完全不推理，这对"读表单、抽字段、分类打标"这类任务是有意义的省成本开关；Astra 和 Sol 没有这一档。

## 官方基准说了什么

官方博客给出的对照集中在 computer use 与视觉推理：

| 基准 | 官方结论 |
| --- | --- |
| Agents' Last Exam（专业 computer use 任务） | medium effort 比 GPT-5.6 Terra 高 15 个百分点、成本约 1/3；与 GPT-6 Astra 打平，但 token 价只有其 1/10 |
| 同上，max effort | 相比 Claude Opus 5.5，token 效率 3 倍以上、单价 1/4，折算每任务成本约低 9 倍 |
| 同上，速度 | 完成任务比 GPT-6 Astra 和 GPT-6.1 Sol 都快 3 倍以上 |
| MMMU-Pro（视觉推理） | 每个推理档位都超过 GPT-5.6 Terra；接近 Astra 与 Sol |
| OSWorld 2.1（桌面 App 多步任务） | medium effort 超过 GPT-5.6 Terra 的最好成绩，每任务成本更低 |
| 内部"易错提示"基准 | 低档错误率 53.6% → 16.7%（−36.9 个百分点）；max 档 −18 个百分点至 4.3% |
| Terminal-Bench 4.0（max） | 50.3%，超过 GPT-5.6 Terra 公开成绩 21.5% 的两倍 |
| Terminal-Bench-Science 0.1（max） | 超过 GPT-6.1 Sol 且更便宜；距 Opus 5.5 不到 5 分，估算成本不到其 1/5 |

来源：[Introducing GPT-6.1 Terra](https://openai.com/index/introducing-gpt-6-1-terra/)，2026-10-26。

读这张表要守住两条：这些都是厂商自测；"每任务成本低 9 倍"是**估算**，它把单价、token 效率、重试都折进去了，不是账单实测值。

官方自己划了一条边界，值得原样记下：**最复杂的编码任务仍然应该交给 GPT-6.1 Sol 和 GPT-6 Astra**。Terminal-Bench 4.0 的 50.3% 比上代翻倍，但离同代旗舰还有距离。

## 第三方怎么看这个位置

Artificial Analysis 已经把 Terra（max）收录，几个数字能校准期待：

| 指标 | GPT-6.1 Terra (max) | 参照 |
| --- | --- | --- |
| Intelligence Index | 48（第 25 / 221） | 同价位中位数 28 |
| 每任务成本 | **$0.40**（第 32 / 121） | 明显便宜 |
| 输出速度 | 90.9 tokens/s（第 91 / 192） | 快于均值 87 |
| 输出量 | 130M tokens（第 90 / 122） | 中位数 81M，偏冗长 |
| 缓存折扣 | 95% | 与官方 $0.05/$1 一致 |

来源：[Artificial Analysis · GPT-6.1 Terra](https://artificialanalysis.ai/models/gpt-6-1-terra)，检索 2026-10-27。

翻译成一句话：**便宜、快、不小气；但不是前沿智能**。48 分落在第一梯队之外，官方博客也不主张它打前沿，只说它"推进了成本-智能边界"。这与"追平 Astra"并不矛盾——Agents' Last Exam 是特定任务集，Index 是十项评测的加权平均。

## 分派规则

把四档当四条车道，比"哪个最强"有用：

| 任务类型 | 该给谁 | 理由 | 例外 |
| --- | --- | --- | --- |
| 读屏、跨 App 点操作、填表单、看图纸 | Terra | 主卖点就是视觉理解 + computer use | 需要长时间自主决策链时换 Sol |
| 高频抽取、分类、摘要、格式化 | Terra（`none`/low 档） | 单价 $0.05 缓存 + 可关推理 | 涉及合规判断时不要关推理 |
| 复杂重构、长程 Agent、难题推理 | Sol 或 Astra | 官方明确说复杂编码归它们 | 用 Terra 先跑基线省钱做对照 |
| 极致成本的海量短任务 | Luna | $0.10/$0.50 | 需要看屏操作时退回 Terra |

还有一条隐性约束：**Terra 在 ChatGPT 的普通 Chat 里不可用**。官方 changelog 写明它出现在 ChatGPT 桌面端的 Advanced、ChatGPT Work（含移动端），不在 Chat 中，也不支持 UAE 推理驻留；企业版还取决于工作区与管理员开关。这不是模型能力问题，但会直接影响你怎么向业务方承诺。

## 选型前先算一次成本量级

不看单价看量级：假设一次典型请求输入 20k、输出 2k tokens，四档的每千次请求成本如下（按标准档、无缓存）。

| 模型 | 单次输入 | 单次输出 | 单次合计 | 每千次请求 |
| --- | --- | --- | --- | --- |
| GPT-6 Astra | $0.20 | $0.10 | $0.30 | $300 |
| GPT-6.1 Sol | $0.04 | $0.02 | $0.06 | $60 |
| GPT-6.1 Terra | $0.02 | $0.01 | $0.03 | $30 |
| GPT-6 Luna | $0.002 | $0.001 | $0.003 | $3 |

这张表能直接回答一个常见争论：“要不要为了 7 分智能多花 10 倍钱”。如果一天才几百次请求，差额是几美元，不值得纠结；如果一天几十万次，差额就是一条人力的预算。

当输入变成 100k 的长前缀且能命中缓存时，排序不变但差距拉大：Terra 的缓存输入是 $0.05，Astra 的是 $1.00，正好 20 倍。

## 三个常见误配

| 误配 | 表面症状 | 代价 | 正确做法 |
| --- | --- | --- | --- |
| 用 Terra 跑复杂重构 | 初版能写，但错得隐蔽 | 返工时间远高于省下的 token 费 | 复杂编码回 Sol/Astra，Terra 只做基线对照 |
| 用 Astra 跑批量抽取 | 账单高但质量“也就那样” | 为用不上的推理能力付费 | 降档，先用 Terra `none` 试 |
| 忽略知识截止差异 | 新旧模型给出的答案不一致 | 误归因为能力差 | 把截止日期写进提示词或搜索策略 |

## 试用与验证

先用最小请求确认模型可用、`reasoning.effort` 生效：

```bash
curl https://api.openai.com/v1/responses \
  --header "Authorization: Bearer $OPENAI_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "gpt-6.1-terra",
    "reasoning": {"effort": "medium"},
    "input": "把这张表单里的三个字段抽出来并说明依据"
  }'
```

`reasoning.effort` 的合法值以模型页为准，Terra 是 `none` / `low` / `medium` / `high` / `xhigh` / `max`。请求成功后按下面四项记录，才能判断它是否真的够用：

| 记录项 | 用途 |
| --- | --- |
| 任务通过与否 | 能力基线 |
| 推理档位 | 同一任务的成本对比基准 |
| 输入/输出 token 与缓存命中 | 换算实际单价 |
| 每任务耗时 | computer use 场景里常比 token 更影响体验 |

## 什么时候不要选它

**任务以复杂工程为主。** 官方已经把最难的编码留给了 Sol 与 Astra。用 Terra 省下的钱，可能被返工吃掉。

**需要单次超长输出的报告。** 128K 最大输出与四档一致，但"能不能写满"和"写满质量如何"是两件事，需要单独测。

**业务依赖 Chat 界面。** 它不在 ChatGPT Chat 里，只在其桌面端 Advanced / Work / Codex。

**对地区驻留有要求。** UAE 推理驻留不支持，Regional/FedRAMP 端点还有 10% 加价（2026-03-05 之后发布的模型统一适用）。

## 限制与结论

确定的事实是：Terra 单价为 Sol 的一半、Astra 的十分之一，上下文与输出上限没缩水，知识截止还比 Astra 晚一个月，独立评测把它定位在"第 25 名附近、每任务 $0.40"。

不确定的部分同样清楚：官方所有基准为自测，9 倍成本优势是估算，MMMU-Pro / Agents' Last Exam 都没有公开可复现的题目集；Terra 的 48 分意味着它不适合直接替代旗舰，只适合替代"你本来用 Sol 处理、但其实不需要旗舰智力"的那部分请求。

如果要给一个条件化结论：把请求按"是否需要长链条判断"切成两堆，不需要的那堆先迁到 Terra 并记录每任务成本，需要的那堆留在 Sol/Astra。迁移后如果通过率下降超过你的人力返工成本，再迁回去——这比看榜单可靠。
