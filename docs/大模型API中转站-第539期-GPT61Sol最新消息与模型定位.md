# GPT-6.1 Sol 最新消息：官方更新、模型定位与使用边界

模型列表里出现 `gpt-6.1-sol`，到底是正式更新，还是第三方服务商起的新名字？截至 **2026 年 9 月 30 日**，这个型号已经可以从 OpenAI 官方页面确认：API 模型页列出了 GPT-6.1 Sol，Codex 与 ChatGPT 更新页也记录了相关产品变化。不过，官方确认一个模型存在，与某个账号已经获得权限，仍然是两回事。

本文只整理当前官方能够支持的消息，再给出首次试用的方法。不把官方定位写成独立测评，不根据上下文窗口猜性能，也不把 API 价格换算成订阅额度。

## 一、最新可确认的消息

官方更新页在 **2026 年 9 月 29 日**记录了“GPT-6.1 Sol in Codex and ChatGPT Work”。这条记录把它描述为面向复杂工作、以更低成本提供接近 Astra 表现的选项，并建议用于代码、应用和文档等重复、长时间运行的工作。可用性仍取决于计划、客户端和工作区设置。[官方更新页](https://developers.openai.com/codex/changelog)

同一天，Codex CLI **0.159.1** 的更新说明把 GPT-6.1 Sol 加入捆绑模型目录，并设为该目录的默认模型，也更新了 Amazon Bedrock Mantle 与 Runtime 目录。之后的 **0.159.2** 记录的是 Windows 后台进程窗口修复。模型目录更新和客户端补丁是两件事，不能把补丁版本号当成模型版本号。[CLI 更新记录](https://developers.openai.com/codex/changelog)

日期也要分清。9 月 29 日是相关产品更新的记录日期，不应据此推断 API 的独立发布日期、所有账号的开放日期，或者各地区的上线时间。官方模型页给出了 API 规格，但本文没有把产品更新日期补写成 API 发布日期。

## 二、Sol 不是“全面替代 Astra”

官方模型选型页把当前三种定位放在一起：Astra 面向要求更高的复杂分析和交付；GPT-6.1 Sol 面向既有复杂度、又需要管理时间和成本的任务；Luna 面向边界清楚、频繁运行的工作。对 Sol，官方建议在同一个任务上与 Astra 比较质量和成本，而不是直接宣布二者等价。[模型选型指南](https://developers.openai.com/api/docs/guides/model-selection)

| 任务形态 | 首轮试用建议 | 验收重点 |
| --- | --- | --- |
| 批量抽取、分类、局部编辑 | 比较轻量模型与 Sol 低档位 | 格式、失败率、吞吐 |
| 多文件开发、应用原型、文档交付 | 从 Sol 默认档位建立基线 | 完成度、返工、耗时 |
| 证据冲突、复杂决策、高价值审查 | 保留 Astra 对照 | 漏项、证据质量、风险 |

这张表是本文提出的实验起点，不是已经测出的排名。即使任务名字相同，输入规模、工具权限和交付标准不同，也可能产生完全不同的选择。

比如“写一个网站”，可以只是做静态样稿，也可以要求登录、数据库、移动端适配和部署。前者主要看视觉与交互，后者还要看工程完整性和安全边界，不能放进同一个成功率里。

## 三、规格和限制要一起看

当前官方模型页列出的主要信息如下。[GPT-6.1 Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

| 项目 | 官方页面当前信息 |
| --- | --- |
| API 模型 ID | `gpt-6.1-sol` |
| 上下文窗口 | 1,050,000 tokens |
| 最大输出 | 128,000 tokens |
| 知识截止日期 | 2026 年 4 月 30 日 |
| 直接输入 | 文本、图像 |
| 直接输出 | 文本 |
| 推理档位 | `low`、`medium`、`high`、`xhigh`、`max` |
| 默认推理档位 | `medium` |
| 不支持的档位 | `none`、`minimal` |

“知识截止日期”不是实时信息更新时间。要处理今天的价格、新闻和政策，仍应给模型提供来源或使用搜索工具。“上下文窗口”也不是有效阅读质量的保证；装入更多内容之前，先验证它能否提取关键证据、处理冲突和保留引用。

模型页列出 Responses API 下的网页搜索、文件搜索、代码解释器、计算机操作、托管 Shell、MCP、工具搜索及其他工具支持。直接输出为文本与“可以调用图像生成工具”并不冲突，但不能因此写成模型直接输出所有媒体类型。音频、视频模态在模型页显示不支持，相关需求需要另外确认工具或其他模型。[模态与工具支持](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

## 四、接入前先检查两处变化

第一个是推理档位。旧应用如果把 `none` 或 `minimal` 写成公共默认值，换成 GPT-6.1 Sol 前必须重新配置。官方迁移指南建议，遇到不支持的旧档位时从 `low` 开始评测；其他可用档位先保留作为基线，不要同时改模型和所有推理设置。[迁移指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)

第二个是工具入口。Sol 支持不带工具的 Chat Completions 请求，但工具调用要使用 Responses API。纯聊天冒烟测试通过，不代表原有 Agent 的函数调用、状态管理、流式解析都已经兼容。[接口边界](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

因此，新闻里一句“支持编码和电脑操作”，放到工程上应该拆成多个测试：能否读文件、能否调用工具、是否在授权目录修改、修改后是否验证，以及任务失败后是否能恢复。

## 五、价格公开不等于每个任务都省钱

当前标准、短上下文的每百万 Token 价格为：普通输入 2 美元、缓存输入 0.10 美元、缓存写入 2.50 美元、输出 10 美元。超过 272K 输入 Token 的请求适用不同费率；Fast、Batch、Flex 和区域处理也有各自规则。订阅产品的额度不能直接按这张 API 价格表推算。[官方模型定价](https://developers.openai.com/api/docs/models/gpt-6.1-sol) [API 定价表](https://developers.openai.com/api/docs/pricing)

预算时至少问三件事：一次任务要生成多少输出；失败后要重跑几次；人工还要改多久。如果单次请求便宜，但结果需要重新制作，整体成本可能并没有下降。反过来，如果较高档位减少了返工，也可能值得保留。

区域也要单独核对。模型页说明支持美国和欧盟数据驻留，但欧盟驻留下不能使用 Fast 模式。数据驻留资格、实际项目设置和运行模式需要一起确认，不能把模型的区域支持理解成账号自动满足所有要求。[区域说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

## 六、一小时内完成首次核验

第一次试用不要直接切换生产默认值。先保存当前生产模型、有效推理档位、工具配置和一份脱敏样本。然后准备三项任务：一次局部代码修改、一份带引用的文档整理、一条只读工具链。每项写清楚成功标准，例如测试通过、必填字段完整、引用对应原文、无越权修改。

在 API 端记录请求 ID、响应模型字段、错误码、完整 usage 和端到端耗时。在产品端记录客户端版本、可见模型选项和工作区策略。遇到权限错误先检查权限，遇到参数错误先清理请求，不要用模型回答“我是谁”来证明身份。

试用通过后，再增加多轮任务和更长输入。如果发生工具结果丢失、引用错误、禁止操作被执行或成本超出预算，就暂停扩量，恢复原配置，并保留失败样本。成功信号应是任务通过验收，而不是回答看起来更自信。

## 七、看得到模型，却用不了怎么办

读者最容易遇到的情况，是新闻已经发布，但自己的模型选择器还没有变化。先按入口分类，而不是一上来就重装客户端。API 项目、Codex 登录态和 ChatGPT Work 工作区是不同的核验对象；产品更新页明确说可用性受计划、客户端和工作区设置影响，因此不能用其中一个入口的成功，证明另外两个入口已经开放。[可用性说明](https://developers.openai.com/codex/changelog)

对个人使用者，可以先记录客户端版本、当前登录账号和实际看到的选项，再与对应产品文档比对。对组织使用者，先询问管理员是否允许该型号，以及已有任务是否固定了旧模型。对 API 使用者，则先跑不带工具的最小请求，保留状态码和错误信息。

还要区分三种失败：型号无权限，说明需要检查账号或项目；参数被拒绝，说明请求模板可能不兼容；输出不达标，才进入质量评测。它们都表现为“用不了”，但处理方法不同。不要把参数错误当成模型能力下降，也不要把权限等待写成发布消息不可信。

首次核验可以用一句话记录结论：“在某日期、某入口、某配置下，完成了哪一种验证。”如果只确认官方文档，就写文档核验；如果只看到选择器，就写产品可见；真正调用成功后，再写接口验证通过。这样后续补充消息时，旧文章也不会和新结果混在一起。

## 八、哪些结论现在还不该写

本文没有运行付费 API 横评，因此不能说它在某个代码基准上提高多少，也不能说它已经在所有账号开放。官方的“接近 Astra”属于产品定位，必须与同条件测试结果分开。

看到 CLI 默认目录更新，也不代表用户手动固定的模型配置被改写；看到 API 页面，也不代表第三方网关已经支持同样的参数和真实路由。后续写实测文章时，应公开输入、工具环境、档位、失败样本和验收方式。

GPT-6.1 Sol 值得关注的地方，是官方已经给出明确的使用位置和接口边界。先确认权限，再做小样本对照，最后决定迁移范围，比把一条发布消息直接变成“全面升级”更稳妥。
