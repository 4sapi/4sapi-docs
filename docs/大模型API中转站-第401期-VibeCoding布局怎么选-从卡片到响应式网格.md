# Vibe Coding 布局怎么选：从卡片到响应式网格

很多人让 AI 做网页时只会说：“帮我做一个高级、简洁、有设计感的网站。”这句话的问题不是不够有审美，而是没有告诉 Agent 内容如何占据屏幕。它不知道哪些信息应该并列，哪些内容应该突出，也不知道手机端要怎样重排。

网页布局解决的不是颜色和字体，而是四个更具体的问题：内容怎么排列，主次怎么形成，页面如何适应屏幕，以及用户下一步要看哪里。布局选错以后，继续补颜色、阴影和动画，通常只会让页面更忙。

本文把常见布局拆成 10 种模式。每种模式都给出适用场景、可复制的提示词片段和验收方式，最后再说明如何把多个布局组合成一份 Vibe Coding 任务书。

## 1. 先按四个变量选布局

不要先问“哪种布局最漂亮”，先记录四个变量：

```text
内容类型：文字、项目卡片、图片、数据、表单还是工具入口？
信息层级：用户第一眼必须看到什么，第二步才需要什么？
视觉比例：图片是否需要保留原始比例，文字是否需要稳定阅读宽度？
屏幕变化：桌面、平板和手机端分别要保留哪些关系？
```

例如同样是作品集：

```text
项目数量少、需要突出一个主项目：Bento Grid。
图片比例差异大、需要浏览作品：Masonry Layout。
项目资料复杂、需要讲清过程：Case Study 结构加窄阅读列。
```

布局的选择应该由内容关系驱动，而不是由某个 CSS 技术名驱动。

## 2. Card-based Layout：稳定的重复内容

卡片式布局把内容拆成一张张独立单元。每张卡片通常包含标题、图片、简介、标签和操作按钮，边界清楚，适合快速比较。

### 适合什么

```text
作品集列表。
博客文章列表。
功能介绍。
商品或服务目录。
工具导航。
```

### 可复制提示词

```text
使用响应式 Card-based Layout 展示 6 个项目。
每张卡片包含封面、项目名称、两行简介、技术标签和“查看项目”按钮。
桌面端三列，平板端两列，手机端单列。
所有卡片保持相同的内部间距和按钮位置，不要因为简介长度不同而让按钮跳动。
```

### 验收重点

```text
卡片是否有明确边界？
标题长度变化时高度是否稳定？
按钮是否都能点击并有清晰状态？
卡片是否真的代表同一级内容？
移动端是否变成可连续滚动的单列？
```

卡片不是万能模板。如果每张卡片内容差异很大，强行统一高度会制造大量空白；如果用户需要沉浸式浏览图片，卡片也可能比画廊更笨重。

## 3. Masonry Layout：保留图片差异

瀑布流布局让卡片宽度大致一致，但高度由内容决定，适合图片原始比例不同的场景。

### 适合什么

```text
摄影集。
AI 图片作品。
插画和海报。
灵感墙。
视觉型博客。
```

### 可复制提示词

```text
使用 Masonry Layout 展示视觉作品。
保留每张图片的原始宽高比，不要裁切成统一高度。
桌面端三列，平板端两列，手机端单列。
图片设置明确的 width、height 或比例信息，进入视口附近再加载。
点击缩略图后打开可关闭的全屏预览，并为每张图片提供准确的 alt 文本。
```

### 验收重点

瀑布流最容易出现两个问题：图片加载前布局跳动，或者为了“整齐”而裁切图片。应提前设定比例占位，图片加载后不改变其他内容的位置；如果图片内容需要严格对齐比较，就不要使用 Masonry。

## 4. Bento Grid：用尺寸表达主次

Bento Grid 使用大小不同的矩形模块组合页面。它的关键不是把页面切成很多块，而是用模块尺寸表达优先级。

### 适合什么

```text
个人主页。
产品首页。
SaaS 首页。
创作者网站。
AI 工具展示页。
```

### 可复制提示词

```text
使用 Bento Grid 设计个人主页。
左侧放一张大型 Hero 模块，展示姓名、身份和主要按钮。
右侧用不同尺寸的模块展示 About、Skills、Latest Writing 和 Contact。
底部放一张横向 Featured Project。
不要做成平均九宫格，必须通过面积和位置突出主次关系。
```

### 验收重点

先问最大模块是否承载了最重要的信息。如果所有模块大小相同，Bento 只剩下“卡片拼图”的外观；如果小模块内容过多，页面会变成密集的仪表盘。

移动端尤其要明确重排顺序：主介绍、主要行动、核心项目、补充信息，而不是简单把桌面网格压成一列。

## 5. Split-screen Layout：让两种内容同场出现

分屏布局把页面分成左右两部分，常见形式是左侧文字、右侧视觉，或者一侧固定、一侧滚动。

### 适合什么

```text
个人首页。
产品介绍。
登录页。
创意作品集。
对比页面。
```

### 可复制提示词

```text
创建 Split-screen Hero。
左侧约占 45%，放姓名、身份、简介和两个操作按钮。
右侧约占 55%，展示与主题相关的真实视觉内容。
桌面端保持左右关系，手机端改为上下结构，文字在前，视觉在后。
两侧都要有稳定的最小高度，不要因为图片加载导致按钮跳动。
```

不要把分屏理解成永远固定的 50/50。比例应由文字长度和视觉内容决定。移动端如果仍然强行并排，通常会造成标题换行、按钮拥挤和视觉主体过小。

## 6. CSS Grid：管理二维关系

CSS Grid 适合处理行和列同时存在的二维布局。复杂首页、非对称作品集和 Dashboard 通常需要它。

```css
.project-layout {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: clamp(1rem, 2vw, 2rem);
}

.project-main {
  grid-column: span 8;
}

.project-meta {
  grid-column: span 4;
}

@media (max-width: 900px) {
  .project-main,
  .project-meta {
    grid-column: span 6;
  }
}

@media (max-width: 640px) {
  .project-main,
  .project-meta {
    grid-column: 1 / -1;
  }
}
```

这段代码只是一个结构示例，具体列数和断点要根据内容验证。MDN 的 [CSS Grid Layout](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_grid_layout) 文档适合核对 Grid 的行列、间距和区域能力。

### Grid 的验收

```text
是否使用 minmax(0, 1fr) 避免长文本撑破列？
是否有明确的移动端列数？
是否能在不改绝对定位的情况下重排？
不同内容长度是否会产生横向滚动？
```

## 7. Flexbox：处理一维对齐

Flexbox 更适合处理一行或一列中的对齐、间距和顺序，常见于导航、工具栏、按钮组和卡片内部。

```css
.site-header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 1rem;
}

.tag-row {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem;
}
```

### 可复制提示词

```text
顶部导航使用 Flexbox。
左侧显示 Logo，右侧显示 Work、About、Writing、Contact 和主题切换按钮。
使用 justify-content: space-between、align-items: center 和稳定的导航高度。
小屏幕隐藏文字导航，切换为可键盘操作的菜单按钮。
```

Flexbox 和 Grid 不是二选一。页面可以用 Grid 划分大区域，再在每个卡片和导航内部使用 Flexbox。MDN 的 [CSS Flexible Box Layout](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_flexible_box_layout) 可以作为属性和对齐行为的核对来源。

## 8. Sidebar Layout：把筛选和目录固定在一侧

侧边栏长期占据页面一侧，另一侧承载主要内容，适合博客、文档、后台和作品归档。

### 可复制提示词

```text
为 Journal 页面添加 Sidebar Layout。
左侧宽度在桌面端保持稳定，包含头像、简介、分类和筛选器。
右侧显示文章列表，侧边栏在桌面端保持 sticky。
手机端不要把 260px 侧栏挤进正文，改成顶部筛选按钮和可关闭 Drawer。
```

### 验收重点

侧边栏要回答“我可以按什么筛选”，不能只放装饰性内容。移动端要考虑它何时打开、如何关闭、焦点去哪里，以及关闭后页面滚动位置是否保留。

## 9. Dashboard Layout：高密度任务界面

Dashboard 通常包含侧边导航、顶部工具栏、统计卡片、图表、表格和最近活动。它的目标不是展示所有信息，而是让用户完成监控、筛选或处理任务。

### 可复制提示词

```text
创建一个创作后台 Dashboard。
左侧是 Overview、Projects、Writing、Analytics 和 Settings。
顶部有搜索、通知和用户菜单。
主区域包含 4 个统计卡片、最近项目列表和趋势图。
每个统计卡片写清时间范围和数据来源，表格支持加载、空数据和错误状态。
桌面端固定侧栏，手机端改成 Drawer，不要把桌面布局整体缩小。
```

### 验收重点

检查空数据、加载和错误状态。Dashboard 只设计默认有数据的截图，会在真实使用时暴露大量空白和不可理解的状态。

## 10. Responsive Layout：重新排列，不是整体缩小

响应式布局不是让桌面页面按比例缩小，而是根据空间重新选择列数、导航、文字宽度和内容顺序。

```text
Desktop：内容最大宽度 1200px，作品三列，完整导航。
Tablet：作品两列，部分边栏折叠，按钮仍保持横向间距。
Mobile：作品单列，导航改为菜单，正文不出现横向滚动。
```

可复制提示词：

```text
设计 desktop、tablet、mobile 三种布局状态。
不要只使用 transform 缩小桌面内容。
明确每个断点的列数、导航形态、字号、间距、图片比例和内容顺序。
在 390px 宽度下检查正文、表格、按钮和图片，不允许横向滚动。
```

MDN 的 [Responsive Design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design) 可以帮助核对媒体查询、弹性布局和移动端重排的基本概念。

## 11. Full-bleed：让视觉延伸到屏幕边缘

Full-bleed 布局让图片、视频或颜色区域突破普通内容容器，常见于 Hero、章节过渡和摄影作品。

### 可复制提示词

```text
创建一个 Full-bleed Hero。
背景视觉铺满浏览器宽度并占据稳定的首屏比例。
文字和按钮位于清晰的内容层，保证对比度。
Hero 下方的正文重新回到 1120px 的居中容器。
视觉内容设置尺寸和比例，加载过程中不能让页面跳动。
```

Full-bleed 不是把所有内容都铺满。正文、表单和长文本通常仍需要窄容器，否则阅读和交互都会变差。

## 12. 十种布局的选择矩阵

| 内容特征 | 优先考虑 | 不要直接使用 |
| --- | --- | --- |
| 同级项目、信息短且可比较 | Card | 不要让每张卡片结构完全不同 |
| 图片比例差异明显 | Masonry | 不要强制统一裁切 |
| 一个主内容加多个补充内容 | Bento | 不要平均九宫格 |
| 文字和视觉同等重要 | Split-screen | 不要在手机端硬保留并排 |
| 二维区域、非对称列宽 | CSS Grid | 不要靠绝对定位拼整页 |
| 一行或一列的对齐 | Flexbox | 不要让 Flex 承担复杂二维区域 |
| 分类、目录和筛选常驻 | Sidebar | 不要在手机端保留固定宽侧栏 |
| 监控、处理和数据密集 | Dashboard | 不要只做有数据的默认状态 |
| 所有公开网页 | Responsive | 不要把桌面页面整体缩小 |
| 图片、视频或章节沉浸 | Full-bleed | 不要让长文本也铺满全屏 |
```

## 13. 布局组合比单个术语更重要

真实网页很少只使用一种布局。例如一个个人作品网站可以这样组合：

```text
首页首屏：Split-screen Hero。
首页项目区：Bento Grid 突出精选项目。
作品归档：Card-based Layout。
AI 图片画廊：Masonry Layout。
项目详情：CSS Grid 组织正文与元信息。
导航和按钮组：Flexbox。
移动端：Responsive Layout 重新排序。
```

组合时先画出页面区域，再决定每个区域内部使用什么布局。不要在一条提示词里只列十个术语，却不说明它们分别负责什么。

## 14. 如何用模型和截图验证布局

生成代码后，可以把任务拆成两个角色：一个负责实现布局，另一个根据固定视口截图检查溢出、层级、间距、图片裁切和移动端重排；如果使用 4SAPI 作为可替换的模型入口，模型名和参数应从当前配置复制，不要把一次截图判断写成普遍性能结论。

建议固定以下验收样本：

```text
1440px 桌面端：看整体层级、列宽和首屏比例。
1024px 平板端：看断点是否提前重排。
390px 移动端：看标题、按钮、图片和导航是否溢出。
极长标题：看卡片和按钮是否被撑破。
空数据：看列表和 Dashboard 是否有解释。
```

## 15. 常见失败

### 平均九宫格

所有内容大小相同，主项目无法突出。修复方法是按信息优先级重新分配面积，不是增加阴影。

### 绝对定位硬拼

桌面截图看起来整齐，手机端一塌糊涂。优先使用 Grid、Flexbox、比例和自然文档流，只有真正需要覆盖层时才使用绝对定位。

### 图片统一裁切

视觉作品失去原始比例。先判断图片是不是需要统一比较；如果不需要，使用比例占位和 Masonry。

### 移动端只是缩小

导航、按钮和正文都变得难点。需要为手机端重新设计列数、内容顺序和交互入口。

### 只验证默认状态

加载、空数据、错误和长文本会改变布局。验收时必须加入极端内容。

## 16. 结论与限制

布局不是一组可以随意堆叠的视觉关键词。Card 解决同级内容比较，Masonry 解决图片比例差异，Bento 解决主次表达，Grid 和 Flexbox 解决结构关系，Responsive 解决屏幕变化，Full-bleed 解决视觉延展。

Vibe Coding 时，先说明内容、层级、尺寸、断点和验收，再让 Agent 选择实现方式。最终要看的不是截图是否“有设计感”，而是内容有没有稳定排列，用户能不能找到重点，页面在真实屏幕和真实数据下是否仍然可用。
