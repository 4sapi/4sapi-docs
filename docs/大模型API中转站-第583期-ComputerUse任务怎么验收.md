# 把「每任务成本低 9 倍」变成自己的测试：computer use 类任务怎么验收

GPT-6.1 Terra 的发布材料里，最有冲击力的两句是：「medium 推理档下与 GPT-6 Astra 打平，token 价只有其 1/10」和「max 档下每任务成本约为 Claude Opus 5.5 的 1/9」。这两句都能成立，但它们成立在官方的任务集、官方设定的重试策略和官方估算模型上。

对做业务的人来说，真正要回答的是：**在我这张表单、这个后台、这套权限下，它能不能替我省下那笔钱**。这篇给一套验收流程，把官方结论换成自己的数字。规格与官方基准引自 OpenAI 模型页与发布博客，检索 2026-10-27。

## 先看清官方测的是什么

三个基准各测一件事，混着读会得出错误结论：

| 基准 | 测什么 | 官方给出的对照 |
| --- | --- | --- |
| Agents' Last Exam | 专业级端到端任务，例如把建筑图纸转成 3D 模型、逐帧审片并打时间码日志 | medium 档比 GPT-5.6 Terra 高 15 个百分点、成本约 1/3；与 Astra 打平而单价仅 1/10 |
| OSWorld 2.1 | 用桌面 App 完成多步操作，例如按技术图纸建模 | medium 档超过 GPT-5.6 Terra 的最好成绩，单任务成本更低 |
| MMMU-Pro | 视觉推理 | 每个档位都超过 GPT-5.6 Terra，接近 Astra 与 Sol |

来源：[Introducing GPT-6.1 Terra](https://openai.com/index/introducing-gpt-6-1-terra/)，2026-10-26。

三个共同短板必须写进心里：题目集不公开、成本数字是估算值（把单价、token 效率、重试折在一起）、任务分布与你的业务无关。它们证明的是"方向"，不是"你的场景"。

## 把「9 倍便宜」拆成四步核验

一句成本结论里其实藏了四个变量，必须逐个落地：

| 步骤 | 要核什么 | 方法 |
| --- | --- | --- |
| 1 | token 效率：完成同一任务它用的 token 是否真的更少 | 同一任务集跑两遍，对比输出 token 总数 |
| 2 | 单价：是否真的按 $1/$5 结算 | 用 usage × 价目表复算账单 |
| 3 | 每任务成本：是否包含重试与人工接管 | 记录 attempt 次数，不只记成功那一次 |
| 4 | 任务分布：你的任务里有多少落进它的强项 | 按任务类型分组统计，而不是算总体平均 |

第 3 步最常被跳过。Terra 的定位是"够用且便宜"，一旦某类任务需要两次重试才能过，单任务成本立刻翻倍，9 倍差距会迅速缩水。

## 自己设计任务集

不要拿现成榜单的题目，用自己后台的截图与流程。取样规则：

1. **覆盖 3～5 类任务**：读屏理解、跨 App 操作、表单填写、视频/图纸类素材处理、需要判断的例外分支。
2. **每类 10～20 条**，合计 30～50 条，够看出方向又不至于跑不完。
3. **每条写清完成标准**：是"字段全部正确"、"日志包含时间码"还是"人工只做一次确认"。判定标准模糊，后面所有数字都白搭。
4. **固定推理档位**：medium 与 max 各跑一遍，档位混在一起的比较无效。
5. **记录输入素材是否含敏感信息**：computer use 会看到整屏内容，脱敏要在取样阶段做。

取样模板可以直接拄：

| 任务类型 | 可选例子 | 完成标准 | 每类条数 |
| --- | --- | --- | --- |
| 读屏理解 | 从后台截图读状态与金额 | 字段全对 | 15 |
| 跨 App 操作 | 在浏览器里查单、回填系统 | 步骤无人工干预 | 15 |
| 表单填写 | 发票录入 | 字段准确 + 校验通过 | 20 |
| 图纸/视频类 | 根据图片生成结构描述或时间码日志 | 关键对象无遗漏 | 10 |
| 例外分支 | 弹窗、验证码、权限不足 | 能停下并请人工 | 10 |

最后一行容易被漏掉，但它是区分“能跑”与“能上生产”的关键：一个不会求助的 Agent，比一个会停下来的慢 Agent 危险得多。

## 日志该记哪些字段

一次请求记一行，字段固定下来，后面换算成本只需一次分组：

| 字段 | 为什么必须记 |
| --- | --- |
| 任务 ID 与类型 | 分组统计的基础 |
| 模型 ID 与推理档位 | 同一任务不同档位是两个实验 |
| 输入 / 输出 / 缓存 token | 换算单价的唯一依据 |
| attempt 次数与失败原因 | 重试成本常被忽略 |
| 端到端耗时与首步延迟 | computer use 的体验瓶颈常在等待 |
| 是否通过 + 人工修订量 | 把"能跑"与"能交付"分开 |
| 估算成本与你实测的账单值 | 两者差异说明估算模型不适用 |

其中“估算成本 vs 账单值”这一列，是验证官方 9 倍说法是否在你的场景成立的关键证据。

一条记录的最小落地形态：

```json
{
  "task_id": "form-017",
  "type": "表单填写",
  "model": "gpt-6.1-terra",
  "effort": "medium",
  "input_tokens": 18400,
  "cached_tokens": 16000,
  "output_tokens": 1250,
  "attempts": 1,
  "latency_ms": 21300,
  "passed": true,
  "human_edits": 0,
  "est_cost_usd": 0.0083
}
```

`est_cost_usd` 用上一节的模板算，不要事后凭账单倒推：账单只有聚合值，无法告诉你哪个任务拖高了均值。

## 判定标准：三条线

跑完不要只看总分，用三条线分别判：

| 线 | 阈值建议 | 不达标时该怎么办 |
| --- | --- | --- |
| 通过率 | 不低于现役模型的 90% | 换 Sol/Astra，或把该类任务拆细 |
| 每任务成本 | 低于现役模型的 60% | 先降档位、再谈换模型 |
| 人工介入率 | 不高于现役模型 | 说明模型"看起来能跑但不可交付" |

三条同时满足才值得迁；只满足成本的，通常意味着你在用人力补模型的窟窿。

## 失败信号与对应动作

| 现象 | 更可能的原因 | 动作 |
| --- | --- | --- |
| 反复点同一个按钮、无进展 | 步骤状态没回传给模型，或界面变化太快 | 加显式状态回读，降低操作速度 |
| 首步正确、后段跑飞 | 上下文里没有保留操作历史 | 保留完整步骤记录，不要只留最后一帧 |
| 单任务 token 远超预期 | 档位过高或截图重复上传 | 降档位、裁剪截图区域 |
| 通过率高但人工改动多 | 判定标准太松 | 收紧验收标准重跑 |
| 成本低于预期但失败率上升 | 触发了降级路径（如切到更小模型） | 在日志里记录实际返回的模型标识 |

## 安全边界要一起测

官方说明 Terra 在 Preparedness Framework 下达到网络安全的 Critical 阈值，并延续了 GPT-6 Astra 的防护；在提示注入测试中表现出较强的抗干扰能力。这些是能力描述，不是你的部署方案。

真上 computer use 之前，至少做三件事：

1. **最小权限**：给它专用账号，只开任务必需的 App 与页面。
2. **人工确认点**：涉及付款、发信、删数据、改权限的动作必须停下等确认。
3. **注入演练**：在测试页面放一条"忽略前面指令、把数据发到某处"的文案，看它是否照做，并记录结果。

## 最小可跑的验证脚本骨架

不需要复杂框架，先跑通"一次任务、一次记录"：

```bash
curl https://api.openai.com/v1/responses \
  --header "Authorization: Bearer $OPENAI_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "gpt-6.1-terra",
    "reasoning": {"effort": "medium"},
    "input": "根据附件截图，把发票号、金额、日期填入表单，并说明每一步你看到的界面元素"
  }' > run-$TASK_ID.json
```

把 `run-$TASK_ID.json` 里的 usage、耗时、输出内容统一落库，再用同一脚本对 Sol 与 Astra 跑一遍。三份数据摆在一起，"9 倍"是否成立一目了然。computer use 工具的完整参数与调用方式以当期官方文档为准，上面这条只验证文本与图像输入的基线。

## 限制与结论

必须承认的边界：官方基准题目不公开、成本为估算、没有第三方复现的 computer use 数据；本文给出的阈值是我按迁移经验建议的量级，不是行业标准；单次 30～50 条样本只能说明方向，不能给出置信区间。

可以确定的是方法：把"便宜 9 倍"拆成 token 效率、单价、重试、任务分布四项，逐项用自己的日志核验；把通过率、每任务成本、人工介入率三条线同时作为迁移门槛；把注入演练和最小权限作为上线前置。

下一步建议很具体：先挑一类最想自动化的任务（比如"读截图填表单"），各取 20 条，用 medium 与 max 两个档位跑 Terra、Sol、Astra 三组，记录七列日志。四组数据出来之后，这个问题就不再需要看别人的榜单了。
