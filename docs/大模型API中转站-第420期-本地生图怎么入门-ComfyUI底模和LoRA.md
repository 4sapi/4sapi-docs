# 本地生图怎么入门：ComfyUI、底模和 LoRA 的关系

本地生图和本地聊天模型看起来都叫“下载模型、输入提示词、得到结果”，实际使用方式却完全不同。聊天模型通常围绕一个对话窗口运行；生图则把采样器、提示词编码器、底模、VAE、LoRA 和保存节点连成工作流。第一次打开 ComfyUI，满屏节点很容易让人误以为必须先学会搭建复杂流程。

入门不需要一次掌握整个生态。本文只解决一个问题：如何用 ComfyUI 跑通第一张本地图片，并理解底模、工作流和 LoRA 各自负责什么。操作前提是你已经准备好一台能运行 PyTorch 图像工作流的设备，并愿意按当前项目文档匹配驱动和依赖。

## 1. 先理解一张图是怎样生成的

一个最小的文生图工作流可以抽象成：

```text
提示词 -> 文本编码器 -> 采样器
底模 -> UNet/扩散模型 -> 采样器
VAE -> 解码潜空间 -> 图片文件
```

ComfyUI 用节点和连线把这些步骤显式表示出来。节点式界面的价值是可以看见每个阶段，固定 seed 后重复实验，也可以只替换某一个组件。代价是第一次接触时比单窗口软件更复杂。

### 底模

底模提供主要的图像生成能力，包括构图、风格和可识别的概念。不同底模需要不同的文本编码器、VAE、分辨率和工作流，不能看到一个模型文件就随便拖到任意节点。

### VAE

VAE 负责潜空间和图片空间之间的编码、解码。某些工作流使用底模自带的 VAE，某些工作流需要单独下载。VAE 不匹配时，常见表现是颜色异常、画面发灰或无法解码。

### LoRA

LoRA 是一种低秩适配方法，训练时只新增和训练一小部分权重，而不是复制一整套底模。Diffusers 官方文档说明，LoRA 通常生成比完整模型小得多的权重文件，并且需要和另一个基础模型一起使用；它可以学习特定风格、对象或角色。[Diffusers：LoRA](https://huggingface.co/docs/diffusers/main/en/using-diffusers/loading_adapters)（访问日期：2026-08-07）

所以 LoRA 不是独立画家，也不是通用画质增强包。它像一个附加适配器，必须与兼容的底模、触发词和推荐权重一起使用。

## 2. 安装前先确认三件事

### 2.1 硬件和后端

生图对显存、驱动和 PyTorch 后端比较敏感。NVIDIA、AMD、Intel 和 Apple Silicon 都有不同程度的支持，但当前项目页面对各平台的安装方式和支持范围并不完全相同。ComfyUI 官方仓库列出了 Windows、Linux、Mac、NVIDIA、AMD、Intel 等路径，并提醒不同版本的 PyTorch 和自定义节点可能存在兼容差异。[ComfyUI 官方仓库](https://github.com/comfyanonymous/ComfyUI)（访问日期：2026-08-07）

如果你只是想验证流程，先选官方提供的稳定发行方式或桌面/便携版本；只有需要自定义节点、脚本或精细控制时，再考虑手动安装。不要从不明压缩包里复制运行环境，也不要为了一个工作流随意覆盖已有的 PyTorch。

### 2.2 模型来源和许可证

模型页面至少要看四项：基础模型、适用软件、文件格式和许可证。一个 LoRA 的示例图可以说明它的风格，不等于允许任何商业用途；底模允许的范围，也不一定覆盖 LoRA 训练素材和第三方组件。

### 2.3 工作流依赖

工作流文件可能引用自定义节点、额外模型或特定版本的前端。下载工作流时，先打开文件或模型页的依赖说明，列出需要的节点和模型，再逐项安装。不要看到“缺少节点”就从搜索结果中随便下载同名插件。

## 3. 用官方说明跑通最小工作流

以下路径以 ComfyUI 官方仓库当前说明为准，具体安装命令要根据你的操作系统和 GPU 后端选择对应部分。

### 第一步：准备 ComfyUI

手动安装的基本路径是克隆官方仓库、按照平台说明准备匹配的 PyTorch 和 Python 环境、安装项目依赖，然后从项目目录启动：

```powershell
git clone https://github.com/comfyanonymous/ComfyUI.git
cd ComfyUI
pip install -r requirements.txt
python main.py
```

这段命令不是跨平台保证。官方 README 要求先根据平台准备 PyTorch，并说明不同 GPU 需要不同安装路径。Windows 用户如果使用官方便携版本，应直接按该版本附带的启动方式，不要再执行一遍手动依赖安装。

启动成功后，终端通常会显示本地 Web 服务地址；在浏览器打开该地址，确认能看到 ComfyUI 界面。如果窗口一闪而过、提示缺少 CUDA 或 PyTorch，先看终端最后几十行错误，不要继续下载模型。

### 第二步：放置底模和 VAE

ComfyUI 官方 README 说明，SD checkpoint 等模型放入 `models/checkpoints`，VAE 放入 `models/vae`。LoRA 和其他组件也应按工作流或项目文档要求放到对应模型目录。[ComfyUI：模型目录说明](https://github.com/comfyanonymous/ComfyUI)（访问日期：2026-08-07）

目录结构可以先整理成：

```text
ComfyUI/
  models/
    checkpoints/
    vae/
    loras/
```

不要只看文件扩展名。一个 `.safetensors` 文件可能是底模、VAE、LoRA 或其他组件，文件名和模型卡比扩展名更重要。

### 第三步：加载默认工作流

先使用软件自带的最小工作流，不要从复杂的角色、放大、控制网或视频工作流开始。选择已经出现在节点下拉框中的 checkpoint，输入一段简单提示词，设置一个固定 seed，运行一次。

第一次验证只关注四项：

- 节点是否全部执行完成；
- 输出目录是否出现图片；
- 图片尺寸与工作流设置是否一致；
- 生成图片的元数据是否能保存工作流信息。

ComfyUI README 说明，把生成的 PNG 拖回界面可以加载其中保存的工作流和 seed。这是一个很有用的复现验证：保存原图，再拖回界面，确认节点和参数仍然完整。[ComfyUI：工作流与 PNG](https://github.com/comfyanonymous/ComfyUI)（访问日期：2026-08-07）

## 4. 再加入 LoRA，而不是一开始堆组件

基础工作流成功后，再加入一个与底模兼容的 LoRA。推荐顺序如下：

1. 关闭其他自定义节点，只保留底模和最小工作流；
2. 把 LoRA 文件放入对应目录，重启或刷新模型列表；
3. 按模型页说明添加触发词；
4. 从较低权重开始测试，不要直接使用示例中的极端权重；
5. 固定 prompt、seed 和采样设置，比较“无 LoRA”和“有 LoRA”的差异。

如果加入 LoRA 后完全没有变化，先检查文件类型、基础模型兼容性、触发词和节点连接。如果画面出现明显变形，降低 LoRA 权重并确认底模版本是否匹配。多个 LoRA 叠加时，问题定位会变难，因此一次只增加一个变量。

## 5. 显存不足时先改哪几个参数

生图的内存压力通常会受到分辨率、批量大小、采样步骤、底模结构和附加组件影响。显存不足时可以按下面顺序排查：

1. 把 batch size 降到 1；
2. 降低图片分辨率；
3. 关闭不必要的放大、面部修复和 ControlNet；
4. 确认是否同时加载多个底模或 LoRA；
5. 检查当前后端是否真的启用了 GPU；
6. 再考虑官方支持的低显存或 CPU offload 选项。

不要把“能出一张图”写成“适合生产”。生产还要考虑重复性、显存余量、批量任务、保存路径、错误恢复和许可证。

## 6. 常见失败与排查

### 找不到 checkpoint 或 LoRA

检查目录是否是当前 ComfyUI 实例使用的目录，文件是否下载完整，模型类型是否放错目录。多套 ComfyUI 并存时，最容易把文件放到另一套安装目录。

### 缺少自定义节点

先阅读工作流作者列出的依赖，确认仓库地址、版本和安装方式。节点装好后仍然报错，检查它依赖的模型文件和 Python 包，不要只重复点击运行。

### CUDA out of memory

记录当前分辨率、batch size、底模、LoRA 数量和其他程序占用，再逐项降低负载。无法判断时，先用默认工作流和更小分辨率做基线。

### 图片颜色或结构异常

确认 checkpoint、VAE、文本编码器和工作流版本匹配。LoRA 只能在兼容的底模上测试，不能用“换一个采样器”掩盖基础组件不匹配。

## 7. 商用前必须单独检查授权

本地生成只说明计算发生在你的设备上，不代表生成结果自动获得商业授权。至少分别检查：

- 底模的许可证和限制；
- LoRA 的许可证、训练素材声明和发布者要求；
- 参考图片、人物肖像、商标和字体的权利；
- 生成结果是否会用于广告、商品、客户交付或公开发布。

如果模型卡没有说明授权范围，不能把“社区里很多人都在用”当成许可依据。对客户项目保存模型名称、版本、下载地址、文件 hash 和使用参数，后续出现争议时才有基本的追溯信息。

## 8. 结论和限制

本地生图的入门顺序应该是：先让 ComfyUI 和一个最小工作流稳定出图，再加入 LoRA 和其他节点。底模负责主要生成能力，VAE 负责潜空间和图片之间的转换，LoRA 是依赖底模的附加适配器，工作流则负责把这些组件按顺序连接起来。

真正值得优化的不是节点数量，而是变量控制和结果复现。固定 seed、记录模型版本、保存工作流、逐个加入组件，并在商用前核对每一层授权，比追求复杂工作流更能减少排错成本。
