# Nemotron 3.5 Transcribe 适用边界：转写、说话人归属与榜单数字的读法

NVIDIA 在 2026 年 10 月 28 日的博客里介绍了 Nemotron 3.5 Transcribe。它把转写、说话人归属、翻译和音频问答放进同一个检查点，并且列了一串榜单名次。读到这类文章，最容易做的事是记住"开放权重里第一"，然后直接换模型。

本文回答三个问题：它能做什么、不能做什么；榜单上的数字各衡量什么，我能核验到哪一步；拿到自己的录音后，怎么做一次最小验收。文章不含我对这个模型的实测，所有性能数字都是 NVIDIA 的自述，文中逐条标明。

信息截止日期为 2026-10-30。榜单和模型卡会更新，引用前请重新打开原页面。

## 三、它能做的任务

按博客和模型卡，同一个检查点用不同的文字指令完成不同输出：

- 转写，可选逐字（保留口头语）或书面形式（规范化数字、单位）。
- 带上下文词表的转写，例如给出可能出现的专业术语。
- 说话人归属转写。
- 语音翻译。
- 语种识别。
- 音频问答。

两个容易漏看的限制：

1. **语言支持因任务而异。** 模型卡有按任务和语言的支持矩阵，说话人归属只覆盖 13 种语言，音频问答是用英语训练的。选型前先查矩阵里你的语言那一行。
2. **它不是流式识别。** 模型卡写明：内部的音频分块不等于实时流式 ASR 服务。博客也写了"为录音音频而建，不是实时流式"。做实时字幕、电话客服实时辅助的团队，这一条是硬约束。

## 五、几个指标各自衡量什么

读榜单前先弄清每个缩写，否则数字没法比较。

| 指标 | 含义 | 容易误读的地方 |
| --- | --- | --- |
| WER | 词错误率：替换、删除、插入的总数除以参考词数 | 不区分错误的重要性，把药名错成近音词和漏掉一个"的"算同样一个错误 |
| DER | 说话人时间段错误率：谁在什么时候说话判断错了的时间占比 | 只管"谁在说"，不管说了什么 |
| cpWER | 先把说话人标签对齐，再算词错误率 | 同时受转写质量和说话人归属影响，数值通常比 WER 高很多 |

WER 的一个直接后果：同一份转写，你的业务可能只关心人名、药名、金额这些实体。整体 WER 很低，实体错误率仍然可能不低。博客自己在医疗案例里也分别报告了整体 WER、关键词 WER 和语义 WER，说明厂商也认为单一数字不够。

## 六、官方承认的局限

模型卡的局限部分列出的错误类型有：替换、删除、重复、幻觉语音、语言判断错误、说话人归属错误。它建议对下面几类情形做针对性测试：

- 长录音。
- 重叠说话。
- 噪声。
- 人名。
- 语码转换（同一句里混用两种语言）。

博客里同样提醒：和任何语音模型一样，要对照录音抽查人名、说话人切换和回答内容。

这份清单本身就是验收清单的来源，下面直接拿来用。

## 七、部署与速度的说法

| 说法 | 来源 | 注意 |
| --- | --- | --- |
| 100 小时音频在一块 RTX PRO 6000 Blackwell 上不到 3 分钟 | 博客 | 使用尚未发布的 NVFP4 版本，30 秒片段，高并发 |
| 最高 2,238 秒音频每秒；30 秒录音 0.13 秒返回 | 模型卡 | 使用 NIM 里的优化版 vLLM，加 NVFP4 与 DFlash2 推测解码 |
| 这些优化尚未进入开源版本 | 模型卡 | 开源版 vLLM 集成"预计约慢两倍" |

两处数字可以对上：100 小时是 360,000 秒，除以 180 秒约为每秒 2,000 秒音频，与 2,238 在同一量级。

但这里有一个读数字时必须记住的前提：**这是厂商优化过的、未开源的服务栈的成绩。** 你自己用开源版本部署，模型卡说预计约慢两倍。预算算力时不要直接拿 2,238 作规划依据。

模型卡给出的硬件范围包括 Ampere、Hopper、Lovelace 和 Blackwell 架构，快速开始示例是一块 H100 80GB 配 vLLM 0.32.0。官方也提到有量化版本，可在 RTX、DGX Spark、Jetson 等设备上运行，具体精度和显存占用请看各量化仓库。

## 八、用自己的录音做最小验收

榜单只能缩小候选范围，最终要用你的数据。

### 步骤

1. **收集样本。** 至少 30 段你真实场景的录音，覆盖最难的几类：噪声、重叠说话、专业术语、口音、长录音。
2. **做人工参考。** 为每段写出你想要的正确转写。逐字还是书面形式，先定好，之后保持一致。
3. **固定指令。** 用同一条文字指令跑所有样本，把指令原文记下来。博客的医疗案例表明，换一条更明确的指令（写明语言和字母表）就能让整体 WER 从 30.8% 降到 23.8%，所以指令是变量，不是细节。
4. **统一规范化。** 比较前对参考和输出做同样的处理：大小写、标点、数字写法。否则差异会被算成错误。
5. **算 WER，再单独算实体错误率。** 实体指你业务关心的名字、术语、数字。
6. **按类别分组汇总。** 看平均值会掩盖最差一类。
7. **说话人场景另测。** 如果要用说话人归属，对重叠说话的片段单独统计谁说了什么是否被归对。
8. **记录延迟与资源。** 每段耗时、显存占用、并发数。

### 一个最小的 WER 函数

下面是我写的纯 Python 版本，不依赖第三方库。我在本机跑了 4 组小输入，结果符合预期：完全相同返回 0.0；把 metformin 切成两个词，6 个词里有 2 处错误，返回 0.333；两个空串返回 0.0。

```python
def wer(ref, hyp):
    r, h = ref.split(), hyp.split()
    d = [[0] * (len(h) + 1) for _ in range(len(r) + 1)]
    for i in range(len(r) + 1):
        d[i][0] = i
    for j in range(len(h) + 1):
        d[0][j] = j
    for i in range(1, len(r) + 1):
        for j in range(1, len(h) + 1):
            cost = 0 if r[i - 1] == h[j - 1] else 1
            d[i][j] = min(d[i - 1][j] + 1, d[i][j - 1] + 1, d[i - 1][j - 1] + cost)
    return d[len(r)][len(h)] / max(len(r), 1)
```

它按空格分词，所以不适合中文、日文这类不用空格分词的语言。这些语言应该用字错误率，按字符而不是按词切分。它也不做大小写和标点处理，调用前要自己规范化。

这个函数只是帮你理解指标。正式评测可以用成熟的评测库，并核对它的规范化规则与你的参考一致。

## 九、哪些场景要谨慎

| 场景 | 原因 |
| --- | --- |
| 实时字幕、实时客服辅助 | 官方说明不是流式识别 |
| 超过 1 小时的整场录音 | 上限是 1 小时，需要自己切分，切分点可能影响说话人归属 |
| 依赖其他语言的说话人归属 | 只覆盖 13 种语言 |
| 对术语或人名要求极严 | 官方局限列了人名；需要用上下文词表并单独验收 |
| 要在小显存设备上本地运行 | 30B 总参数，需要看量化版本的实际占用 |
| 需要确定的授权条款 | 许可证正文我没读，需要自己确认 |

## 十、限制与结论

Nemotron 3.5 Transcribe 的定位很清楚：面向录音的多任务转写模型，用文字指令切换输出形式，开放权重。官方公布的榜单成绩大多是开放权重范围内的名次，差距有大有小，且主要是厂商自述。

本文的限制：没有运行过这个模型；没有打开博客引用的各个第三方榜单；没有读许可证正文；速度数字来自未开源的优化栈。

下一步建议：按第八节用 30 段自己的录音，对比你现用的方案和这个模型，分别统计整体 WER 和实体错误率。如果差距在你关心的类别上不明显，就没有必要换。
