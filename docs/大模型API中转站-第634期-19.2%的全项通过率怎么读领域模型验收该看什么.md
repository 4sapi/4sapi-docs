# 19.2% 的全项通过率怎么读：领域模型验收该看什么

一个领域模型上线前，团队通常会被一个数字卡住：官方基准的通过率。19.2% 这个数字看着低，但只凭它判断"能不能用"，结论会偏。

要读它，至少得知道三件事：这个百分比是按什么口径算的、它和谁的差距、以及这个基准离你的任务有多远。本文按这三层拆，然后给一套用自己文档做验收的方法。

数据来自 [Z.ai 官方文档](https://docs.z.ai/guides/llm/glm-5.3-flash)，检索日期为 2026-11-03。我没有调用过这个模型，也没有复现任何基准。文中不构成法律意见。

## 一、官方给的三个信息

| 项目 | 内容 |
| --- | --- |
| 基准 | Harvey LAB，官方描述为面向法务 agent 的基准 |
| 指标 | 全项通过率（all-criteria pass rate） |
| Legal 版结果 | 19.2% |
| 相对基座 | 高 12.5 个百分点 |
| 范围限定 | 官方称在该评测的开放模型中达到该水平 |

三条限定要一起读：**这是全项通过率、这是相对基座的比较、这个"达到该水平"只在开放模型范围内。**

## 二、由这两个数能推出什么

下面是我的算术，不是官方结论：

| 推论 | 计算 | 结果 |
| --- | --- | --- |
| 基座模型的全项通过率 | 19.2 − 12.5 | 约 6.7% |
| Legal 版未通过全项的比例 | 100 − 19.2 | 80.8% |
| 相对基座的提升幅度 | 12.5 ÷ 6.7 | 约 187% |

三个数字合起来才是完整画面：

1. **提升在数值上很可观。** 从 6.7% 到 19.2%，接近三倍。但我无法判断它是否显著：官方没有给任务数，任务数少于一二十个时，12.5 个百分点可能只对应一两道题。
2. **通过率本身仍然低。** 五分之四的任务至少有一项没达标。
3. **相对数字容易被误读。** "提升 187%" 听起来像质变，但它建立在 6.7% 这个小基数上。

还有一个连乘的例子能说明这个通过率的意义。把 19.2% 当成单次全项通过的概率，按独立假设（这三个数是我算的）：

| 情形 | 概率 |
| --- | --- |
| 三份里至少一份通过 | 约 47.2% |
| 三份全部通过 | 约 0.7% |
| 三份全部失败 | 约 52.8% |

第一行与第三行互为补集，加起来正好 100%；第二行那个 0.7% 才是「连着三份都全过」，这正是全项口径最容易被低估的地方。

结论：它适合"人生成、人复核"的位置，不适合"跑完就交"。

## 三、"全项通过"这个口径有多严

这是最容易被忽略的一层。全项通过意味着**所有评判标准同时满足**才算过；任何一项不达标，这份任务就算未通过。

如果一份任务有 k 个互相独立的检查项，单项通过率是 p，那么全项通过率约为 p 的 k 次方。举个纯算术的例子（与这个基准的真实设置无关）：

| 单项通过率 | 3 项全过 | 5 项全过 |
| --- | --- | --- |
| 90% | 72.9% | 59.0% |
| 70% | 34.3% | 16.8% |
| 50% | 12.5% | 3.1% |

这张表的意思是：**同样一个模型，在"看单项"和"看全项"两种口径下，得分可以差出好几倍。** 所以看到一个低的全项通过率时，不能推出"八成回答是错的"，只能推出"八成任务至少有一处不达标"。

这是我的推理，不是对该基准的核验——它的检查项数量和判定规则我都没拿到。

## 四、这个基准我核验不了

我尝试打开 Harvey LAB 的官方页面（`harvey.ai/lab`），返回 HTTP 404。所以以下信息我都没有核验：

- 检查项的数量与判定规则。
- 任务数量与领域分布。
- 评分是自动判定还是人工判定。
- 该基准是否包含"引用准确性"这类检查。

因此文中 19.2% 与 12.5 个百分点只能标为**厂商自述**。

如果你想自己核验，可行的路径是：找到该基准的官方页面或论文，确认任务数、检查项定义与判定方式，再看这个分数是在什么配置下取得的。找不到就不要把这两个数写进决策文档。

## 五、一个基准能回答与不能回答什么

| 能回答 | 不能回答 |
| --- | --- |
| 在同一套任务与判定下，Legal 版与基座谁更好 | 在你的文档上谁更好 |
| 全项达标的比例是多少 | 单项达标的比例是多少 |
| 该基准覆盖的任务类型上的表现 | 你的行业、语言、文档格式上的表现 |
| 相对提升的幅度 | 人工复核要花多少时间 |

最后一列第二行是关键：**单项通过率往往才是你真正关心的**。因为实际工作流里，人可以先扫一遍、只处理没达标的项；而全项通过率假设"一处不合格就整体不可用"。

## 六、用自己文档做验收：二十到三十题

基准只能缩小候选范围，验收必须用你自己的材料。流程如下。

### 步骤

1. **选题。** 20 到 30 个真实任务，覆盖你最常见的三到四类（例如条款风险、跨文档一致性、文书起草）。少于此数，结果会被单题波动主导（见第八节）。
2. **自定评分标准。** 每个任务列出 3 到 5 条"必须做到"的检查项，写在跑之前。这是你的标准，不是模型的。
3. **固定输入。** 同一批文档、同一提示词、同一工具配置，分别跑 Legal 版与基座版。
4. **双评。** 至少要两个人独立按第 2 步的检查项打分，再核对分歧。单人评分容易受表达风格影响。
5. **分别统计三种指标。** 单项达标率、全项达标率、以及"看起来对但引用了不存在内容"的比例。
6. **记录人工修正时间。** 每个任务修正到可用需要多少分钟。

第 5 步的第三项是这类模型专属的风险项，单独统计它比合成一个总分有用得多。

### 失败模式清单

按法务场景，我建议把失败分到下面几类分别计数：

| 失败类型 | 表现 | 危害 |
| --- | --- | --- |
| 编造条文 | 引用一个不存在的条款号或条文内容 | 最高，因为看起来最像对的 |
| 错引判例 | 案例存在但论点与判决要旨不符 | 高 |
| 漏掉关键条款 | 审阅时未点出明显风险 | 高 |
| 跨文档张冠李戴 | 把 A 文件的条款安到 B 文件上 | 中高 |
| 把"没找到"说成"没有" | 检索失败被表述为不存在 | 中高 |
| 过度保守 | 大量"建议咨询律师"式空话 | 低但降低可用性 |

第三行与第五行的区别值得注意：漏掉条款是能力问题，把检索失败说成不存在是**表述问题**，后者更难被发现，因为它给出的是一个确定性结论。

## 七、样本量决定你能看出多大差别

小样本的百分比非常不稳。按每题的权重算：

| 题目数 | 一题占多少个百分点 |
| --- | --- |
| 10 | 10.0 |
| 20 | 5.0 |
| 30 | 3.3 |
| 50 | 2.0 |
| 100 | 1.0 |

也就是说，20 题的验收里，两个模型差 3 个百分点只等于 0.6 道题——这种差异不能写进结论。

如果按比例区间的粗略估算（正态近似，未做配对设计）：20 题、通过率约 20% 时，95% 误差约 ±17.5 个百分点；30 题时约 ±14.3；50 题时约 ±11.1。

这说明两件事：

1. **50 题还看不出 5 个百分点的差别。** 按上面的粗估，n=50 时误差约 ±11 个百分点，比 5 个百分点还大一倍；单臂要把误差压到 ±5 个百分点，需要约 246 题（1.96²×0.16÷0.05²，我的算术）。
2. **如果只能做 20 题，那就不要比百分比，改比"失败类型分布"。** 类型分布比单一数字更稳，也更能指导改进。

## 八、怎么把结论写进决策文档

一份可用的验收结论应该包含这几项：

| 项 | 例 |
| --- | --- |
| 任务集 | 24 个任务，覆盖条款风险 10、一致性核对 8、文书起草 6 |
| 输入 | 自家文档 24 份，中英各半，页数 12 到 180 |
| 评分 | 每任务 4 条检查项，两人独立评分，分歧由第三人裁决 |
| 结果 | 单项达标率 x%，全项达标率 y%，编造条文 z 次 |
| 修正成本 | 中位修正时间 n 分钟/份 |
| 对照 | 与基座版、与人工起草各比一次 |
| 限制 | 样本 24，95% 误差约 ±16 个百分点，只能判断很大的差异 |

最后一行很重要：把"看不出什么"写清楚，比把"看出了什么"写更长的段落更有用。样本 24 的实际分辨率是"只能看出很大的差异"，不是"看不清 5 个百分点"——后者需要两百多题。

## 九、限制与结论

19.2% 这个数字能支持的结论是：在某个法务 agent 基准的全项口径下，Legal 版明显好于基座，但仍有约八成任务至少有一项不达标。它不能支持的结论包括"八成回答是错的"和"在你的文档上也这样"。

本文的限制：没有调用过模型；Harvey LAB 的页面 404，基准定义未核验，两个数字只能标为厂商自述；样本量误差用正态近似粗估，未做配对检验；失败模式清单是我按法务场景整理的，不是官方分类；不构成法律意见。

下一步建议：先做 20 题的小验收，只统计失败类型分布和人工修正时间。等你确认这两项可接受，再扩到 50 题以上去比百分比。
