# 【大模型API中转站】第176期 AI排查JSON输出失败 | Schema校验

本文是【大模型API中转站】系列的第176篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

很多应用接大模型，不是为了聊天。

而是为了拿结构化结果：

```json
{
  "category": "billing",
  "priority": "high",
  "summary": "用户询问发票问题"
}
```

但线上最常见的崩溃是：

```text
模型输出不是合法 JSON。
字段缺失。
字段类型错。
数组多了或少了。
多输出了一段解释。
中文引号、尾逗号、Markdown 代码块导致解析失败。
```

这类问题非常适合用 AI 排查。

但不能只靠 Prompt。

要靠：

```text
Schema。
校验。
失败样本。
有限重试。
模型路由。
```

## 1. 先收集失败样本

给 AI 的材料：

```text
目标 Schema。
模型原始输出。
解析器错误。
Prompt。
模型名称。
temperature。
是否使用 JSON mode / structured output。
失败率。
```

不要只说：

```text
JSON 坏了。
```

你要让 AI 看到坏在哪里。

## 2. 给 AI 的 JSON 排错包

```text
【目标】
- 需要输出什么结构：
- 字段类型：
- 必填字段：
- 枚举值：

【Schema】
贴 JSON Schema 或 TypeScript interface。

【失败样本】
- 原始输出：
- parse error：
- validator error：

【调用参数】
- model：
- temperature：
- max_tokens：
- 是否 JSON mode：
- prompt：

【统计】
- 总调用数：
- 失败数：
- 失败类型分布：

【边界】
- 不要求模型输出隐藏推理
- 不把错误 JSON 直接写入数据库
- 先校验再使用
```

## 3. 常见失败一：多余解释文本

模型输出：

```text
当然可以，以下是 JSON：
{ ... }
```

解析器直接炸。

修复：

```text
使用结构化输出能力。
系统提示明确只输出 JSON。
后端做严格提取和校验。
失败时重试一次。
```

但不要依赖正则硬抠所有情况。

最好让模型本身走结构化模式。

## 4. 常见失败二：字段类型不稳定

比如 schema 要：

```json
{ "score": 0.8 }
```

模型输出：

```json
{ "score": "0.8" }
```

或者：

```json
{ "score": "高" }
```

解决方式：

```text
字段说明写清类型和范围。
使用枚举。
后端校验并拒绝。
低风险字段可做类型转换。
关键字段不自动猜。
```

AI 可以分析失败样本，找出最常错的字段。

## 5. 常见失败三：枚举值跑偏

你要求：

```text
priority: low | medium | high
```

模型输出：

```text
urgent
critical
一般
高优
```

修复：

```text
枚举写进 schema。
Prompt 里强调只能选枚举。
校验失败时让模型基于错误信息重试。
```

不要让业务代码默默把所有未知值映射成 medium。

那会污染数据。

## 6. 常见失败四：数组长度不可控

比如你要 5 个选题，模型输出 7 个。

或者你要逐条分类，模型漏了 2 条。

解决：

```text
输入每条加 id。
要求输出必须包含所有 id。
后端校验 id 集合一致。
失败时只重试缺失项。
```

这比“请认真不要遗漏”稳得多。

## 7. 4SAPI 路由策略

结构化输出不一定要用最贵模型。

建议：

| 场景 | 模型 |
| --- | --- |
| 简单分类 | 低成本模型 + 严格 schema |
| 中等抽取 | 中等模型 |
| 复杂多字段判断 | Fable 5 |
| 高失败率任务 | Fable 5 或专门结构化模型 |
| 校验失败修复 | 原模型重试一次，仍失败再升级 |

4SAPI 记录：

```text
schema_name
schema_version
model
parse_success
validation_error
retry_count
fallback_model
```

这样你能知道哪个模型在结构化任务上最稳。

不是凭感觉选。

## 8. AI Prompt

```text
你是结构化输出排查助手。

请根据 Schema、Prompt、模型原始输出和 validator error，判断 JSON 输出失败原因。

重点检查：
1. 是否输出多余文本
2. 是否字段缺失
3. 是否类型错误
4. 是否枚举值不合法
5. 是否数组长度或 id 对不上
6. 是否 max_tokens 截断
7. 是否需要改用结构化输出或更强模型

要求：
- 不要建议直接信任模型输出。
- 给后端校验和重试策略。
- 给 Prompt 最小修改建议。
```

## 9. 修复策略不要只靠“再说一遍”

很多人遇到 JSON 坏了，会在 Prompt 里加：

```text
请务必输出合法 JSON。
一定不要输出其他内容。
如果不输出 JSON 你会受到惩罚。
```

这类话有时有用，但不是工程方案。

更稳的是四层：

```text
第一层：使用结构化输出或 JSON mode。
第二层：后端用 schema validator 校验。
第三层：校验失败时，把错误信息发回模型修复一次。
第四层：仍失败就 fallback 或转人工。
```

重试 Prompt 可以这样写：

```text
你的上一次输出没有通过 JSON Schema 校验。
错误是：[validator error]。
请只修正 JSON，使其符合 Schema。
不要新增解释，不要改变业务含义。
```

注意：

```text
不要无限重试。
```

结构化输出失败多次，往往说明任务太复杂、Schema 太模糊，或者模型不适合。

## 10. 结构化输出验收表

上线前建议跑一张表：

| 检查项 | 标准 |
| --- | --- |
| 解析成功率 | 连续样本达到目标 |
| 必填字段 | 不缺失 |
| 枚举字段 | 不出现非法值 |
| 数字字段 | 类型正确 |
| 数组字段 | 数量和 id 对齐 |
| 截断 | max_tokens 足够 |
| 重试 | 最多 1-2 次 |
| fallback | 有降级或人工处理 |

4SAPI 可以按 `schema_name` 和 `model` 记录成功率。

这样你会发现：

```text
某个便宜模型做简单分类很稳。
某个强模型做复杂抽取更稳。
某个 Prompt 版本失败率突然升高。
```

这比拍脑袋选模型可靠得多。

## 11. 线上治理：不要等解析器炸了才知道

结构化输出上线以后，最怕的是失败被吞掉。

比如代码里写了：

```text
try parse。
失败就返回空对象。
```

用户看到的是“结果为空”，团队以为系统正常。

所以结构化输出一定要把失败变成指标。

建议至少做三张表：

```text
按 schema_version 看失败率。
按 model 看失败率。
按字段看 validator error。
```

如果你通过 4SAPI 统一调用模型，可以把这几类指标都串起来：

```text
request_id
schema_name
schema_version
model
temperature
json_mode
parse_success
validator_error_path
retry_count
fallback_model
final_status
```

这里最有用的不是总失败率，而是变化。

比如：

```text
昨天 parse_success 99.2%，今天掉到 93%。
某个 schema_version 上线后，枚举字段错误翻倍。
某个低成本模型在长文本抽取里失败率明显高于 Fable 5。
```

这些都能直接指导你：

```text
回滚 Prompt。
固定 schema。
缩短输入。
升级模型。
把复杂字段拆成两步。
```

再补一个很实用的策略：

```text
普通字段失败，可以重试。
关键字段失败，宁愿转人工也不要瞎猜。
```

比如发票金额、用户权限、合同状态、支付结果，这些字段不要靠模型“猜一个最接近的值”。

结构化输出的底线是：

```text
不确定，就不要写入核心业务表。
```

这也是企业用 4SAPI 做中转的价值。

它不只是帮你换模型，而是把每次结构化失败都记录下来，让你知道到底是模型问题、Schema 问题，还是业务边界没写清。

## 12. 总结

JSON 输出失败，不是单纯 Prompt 写得不够凶。

要靠：

```text
Schema。
Validator。
失败样本分析。
有限重试。
模型路由。
日志统计。
```

4SAPI 可以帮你记录不同模型的结构化成功率。

Fable 5 适合处理复杂抽取和高价值判断。

低成本模型适合简单分类，但必须配校验。

一句话：

```text
结构化输出不是让模型听话，而是让系统会验货。
```
