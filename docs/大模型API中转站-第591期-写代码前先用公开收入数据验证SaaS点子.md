# 写代码前先算账：用公开收入数据验证一个 SaaS 点子的方法与陷阱

用 Codex 或 Claude Code 写一个能收款的 SaaS，现在一个周末就够了。代码变快的副作用很直接：做出一个"没人买"的产品，也只要一个周末。

所以顺序很重要：**先想清楚商业模式和获客渠道，最后才写代码**。这个顺序本身没什么争议。真正值得展开的是下一层——"先看同行赚不赚钱"这一步，用的是什么数据、怎么读、会在哪里读错。

本文的产品数据均取自公开收入平台 TrustMRR，检索时间 2026-10-28 至 10-29。

## 数据从哪来

验证一个点子，最直接的办法是看同赛道的产品赚不赚钱。这类数据目前最常见的来源是公开收入平台：产品方把 Stripe 或 Polar 的只读 API Key 接进去，平台按真实流水展示收入。

它比"有人发帖说自己月入多少"可靠，但有三个先天限制：

| 限制 | 含义 |
| --- | --- |
| 自愿登记 | 只有愿意公开的产品才在上面，天然偏向赚钱的那批 |
| 只看支付渠道 | 不经过 Stripe 或 Polar 的收入（企业合同、应用商店）看不到 |
| 只有收入 | 没有成本、没有退款细节、没有获客花费 |

第一条最要紧。在一个"自愿晒收入"的平台上找同行，看到的永远是幸存者。

## 5 个样本产品

下面这组产品都与"给开发者或创作者提供模板与设计能力"有关，正好可以用来演示读法：

| 产品 | 卖什么 | 近 30 天收入 | MRR | 累计收入 | 活跃订阅 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| Skillry | 风格化 Agent Skill | $12,808 | $4,111 | $13,090 | 417 | 2026 年成立 |
| ShipFast | Next.js 代码样板（买断） | $1,694 | 无 | $1,272,892 | 无 | 2023 年成立 |
| Sleek | 对话生成 App 界面设计 | $16,216 | $18,932 | $184,661 | 551 | 挂牌出售，要价 $500,000 |
| TypeUI | 给 AI 编程工具的 UI 风格 | $3,319 | $3,409 | $22,811 | 156 | 收入经 Polar 验证 |
| Low Content AI | 亚马逊 KDP 低内容图书生成 | $15,114 | $14,388 | $651,381 | 328 | 挂牌出售，要价 $800,000 |

来源：[TrustMRR · Skillry](https://trustmrr.com/startup/skillry)、[ShipFast](https://trustmrr.com/startup/shipfast)、[Sleek](https://trustmrr.com/startup/sleek)、[TypeUI](https://trustmrr.com/startup/typeui)、[Low Content AI](https://trustmrr.com/startup/low-content-ai)。

这张表里每一列都有用，但最容易出错的地方恰恰是把列混着读。

## 陷阱一：30 天收入不等于 MRR

看 Skillry 的两个数字：近 30 天收入 $12,808，MRR $4,111。前者是后者的 3 倍多。

差额从哪来？看它在平台上登记的定价就明白了：

| 方案 | 价格 | 计入 MRR 的方式 |
| --- | --- | --- |
| 月付 | $9.99/月 | 全额计入 |
| 年付 | $79/年 | 折成约 $6.58/月 |
| 终身版 | $169 一次性 | **不计入 MRR** |

上线初期，大量早期用户会买年付或终身版。这部分钱当月一次性到账，所以"近 30 天收入"会远高于 MRR。

这不是问题，是早期产品的正常形态。但它意味着：**"月入一万美元"如果指的是 30 天流水，就不等于每月稳定进账一万美元**。真正代表"每月稳定进账"的是 MRR。

这个区别对判断"订阅制是否跑通"非常关键：终身版卖完就没了，年付要等一年后才知道续费率。

## 陷阱二：新产品的增长率没有意义

一个上线一两个月的产品，在平台上显示环比增长几千个百分点，并不说明它增长有多猛，只说明上个月的基数几乎为零。

任何上线不到三个月的产品，环比增长率都可以忽略。要判断趋势，至少看三个完整月的 MRR 曲线。

## 陷阱三：累计收入是历史，近 30 天才是现在

ShipFast 是个典型例子：累计 $1,272,892，近 30 天 $1,694，而且没有活跃订阅（它是买断制）。

只看累计榜，会以为这是个正在印钞的模式；看近 30 天才知道销售已经大幅回落。这个例子可以说明"纯买断制在后期会很难看"，但样本只有一个，不能推广到所有买断产品。

## 陷阱四：挂牌出售是个信号

表里收入最高的两个产品，Sleek 和 Low Content AI，平台页面同时显示它们都**挂牌出售**，要价分别是 $500,000 和 $800,000。

出售有很多理由（团队转型、套现、精力分配），不一定意味着生意变差。但它是一个"产品方自己怎么看未来"的信号，判断赛道时应该一起看，而不是只取收入那一栏。

## 一个常见误读：用收入差推转化率

常见的推理是：A 产品收入是 B 产品的几倍，所以 A 的定位更好、转化率更高。拿表里的 Skillry 和 TypeUI 来看，这个推理为什么站不住：

| 对比项 | Skillry | TypeUI |
| --- | --- | --- |
| 月价 | $9.99 | $30 |
| 活跃订阅 | 417 | 156 |
| 近 30 天访客 | 平台未公开 | 4,105 |
| 一次性收入 | 有 $169 终身版 | 只看到月付 |

转化率等于付费用户除以访客。只要其中一方的访客数没有公开，就无法计算转化率，更无法比较。收入差异可能来自终身版的一次性收入、定价结构、分发渠道，也可能来自场景定位——这几个因素混在一起，单凭收入拆不开。

## 一套可执行的验证流程

| 步骤 | 做什么 | 看哪个数 |
| --- | --- | --- |
| 1 | 找 5～10 个同赛道产品 | 不只在一个平台找，包括没公开收入的 |
| 2 | 分别记录近 30 天收入、MRR、累计收入、活跃订阅 | 四个数分开记 |
| 3 | 算"30 天收入 ÷ MRR" | 明显大于 1，说明一次性收入占比高 |
| 4 | 看定价页 | 月付、年付、买断各占什么位置 |
| 5 | 看成立时间 | 不到 3 个月的增长率不算数 |
| 6 | 看是否挂牌出售 | 记下来，作为风险信号 |
| 7 | 找一个失败案例 | 同赛道里做了但没赚到钱的 |

第 7 步最容易被跳过。只看赚钱的同行，你得到的是"这个赛道能赚钱"，而不是"我进去能赚钱"。

## 用这套流程走一遍

把 7 步套到上面这组样本上：

| 步骤 | 结果 |
| --- | --- |
| 1. 找同行 | 5 个，都在同一个平台上 |
| 2. 记四个数 | 见上方样本表 |
| 3. 30 天收入 ÷ MRR | Skillry ≈ 3.1；TypeUI ≈ 0.97；Low Content AI ≈ 1.05；Sleek ≈ 0.86 |
| 4. 看定价 | 只有 Skillry 有终身版，所以只有它的比值明显大于 1 |
| 5. 看成立时间 | Skillry、Sleek、TypeUI 都是 2026 年成立，趋势还看不出来 |
| 6. 看出售状态 | 5 个里有 2 个挂牌出售 |
| 7. 找失败案例 | 这组样本里没有，需要另外去找 |

读出来的结论比较保守：这个赛道里**有能做到每月几千美元 MRR 的订阅产品**，但多数很年轻；一次性收入在早期占比很高；收入最高的两家都在出售。这些信息不足以说"赛道不行"，但足以说明"月入一万美元"不是一个稳定的基准线。

## 常见问题

**Q：公开收入平台的数据会不会被刷？**
收入通过只读 API Key 从支付平台拉取，比截图可靠。但它只能证明"钱进了支付账户"，不能证明钱从哪里来，也不排除退款发生在统计窗口之外。

**Q：同行收入高，是不是说明我也能做到？**
不能。同行的收入里包含了它的品牌、分发渠道、时机和团队。你能复制的是模式，复制不了这些条件。

**Q：找不到同行的公开收入怎么办？**
看定价页、招聘信息、社交账号的更新频率、应用商店的评论数。这些都是间接信号，组合起来能判断一个产品是否还活着。

## 适合与不适合

这套方法适合：订阅制 SaaS、开发者工具、面向海外的小产品，这些品类在公开收入平台上样本够多。

不适合：B2B 大客户（收入不走 Stripe）、应用商店产品（收入不在支付渠道里）、刚出现的新品类（没有可参照的同行）。最后一类恰恰是机会最大的地方，但这类判断靠的不是数据。

## 限制与结论

本文的产品数据只代表检索当天，公开收入平台每天更新；5 个样本都来自同一个平台，存在明显的幸存者偏差；收入数字不包含成本，不能推出利润。

可以确定的是方法：先看同行再写代码的顺序是对的，但读法要对——分清 30 天收入和 MRR，忽略新产品的增长率，把挂牌出售当作信号，不用收入差去推转化率，并且主动找一个失败样本。

这些数据都能在公开页面上直接查到，不需要任何付费工具。做完这七步，"做不做"的判断会更有依据。
