# WhatsApp 线索自动化怎么做：人工审批与风控边界

分类：营销自动化、Agent、安全治理

标签：#WhatsApp自动化 #线索管理 #AI安全

摘要：把广告、落地页和 WhatsApp 接起来并不难，难的是让自动化流程在权限、同意、频率和人工接管上可控。本文给出一套适合中小团队的最小架构：广告或内容带来线索，落地页完成说明和授权，自动化负责分类与草稿，人工负责报价、承诺和敏感操作。

## 开头：自动回复不等于自动成交

很多“全自动获客”方案会把流程描述成：投广告、跳转 WhatsApp、AI 自动回答、最后成交。

这个叙事忽略了几个关键问题：

- 用户是否明确同意被联系。
- 自动回复是否准确表达了产品边界。
- 价格、交期和库存由谁确认。
- 对话记录里是否包含个人或商业敏感信息。
- 账号被限制、消息失败或模型答错时谁来接管。

Meta 关于 Muse 的安全说明强调，Agent 可以在云端电脑和连接器中执行多步骤任务，但安全边界仍然需要由产品和用户共同设计。[官方安全说明](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)

本文只解决一个问题：如何把 WhatsApp 线索流程做成“自动化整理 + 人工确认”，而不是把高风险承诺交给无人值守机器人。

## 一、先画出最小链路

建议把链路拆成六个节点：

1. 广告、官网或内容页面。
2. 说明页和授权入口。
3. 线索收集与去重。
4. AI 分类、摘要和问题补全。
5. 人工审批与正式回复。
6. CRM 记录、跟进和退出。

每个节点都要定义输入、输出和负责人。

如果一个节点没有负责人，出了问题就只能靠“再让 AI 试一次”。

## 二、授权页面要说清楚三件事

用户提交号码前，至少应知道：

1. 谁会联系他。
2. 会通过什么渠道联系。
3. 联系内容大致是什么。

如果后续会使用自动化辅助，也应在隐私说明中解释数据用途、保存周期和退出方式。

不要把“点击咨询”当成无限期营销许可。

如果用户只请求一次报价，就不要默认加入长期群发名单。

## 三、线索数据的最小字段

一个基础线索对象可以是：

```json
{
  "lead_id": "L-20260928-001",
  "source": "landing_page",
  "consent_at": "2026-09-28T10:30:00+08:00",
  "consent_scope": "product_inquiry",
  "phone": "stored_in_provider_system",
  "country": "AU",
  "product_interest": "example_product",
  "budget_range": "unknown",
  "timeline": "unknown",
  "status": "needs_review",
  "owner": "sales_team"
}
```

这里的重点不是字段多，而是能回答三个问题：

- 线索从哪里来。
- 用户同意了什么。
- 当前由谁负责下一步。

不要在提示词、日志或表格中明文复制不必要的身份证件、银行卡、密码或完整支付信息。

## 四、让 AI 做分类，不让它做最终承诺

适合交给 AI 的任务包括：

- 识别咨询主题。
- 提取预算、地区和时间要求。
- 判断是否缺少关键信息。
- 把对话整理成 CRM 摘要。
- 生成待人工确认的回复草稿。

不适合无人值守执行的任务包括：

- 确认最终价格。
- 承诺交付日期。
- 修改合同条款。
- 判断退款、赔付或合规例外。
- 向客户发送未经审批的技术指标。

一个好的系统会明确输出“未知”，而不是逼着模型猜答案。

## 五、回复状态机

可以用一个简单状态机控制对话：

```text
NEW
  -> CONSENT_CHECK
  -> QUALIFYING
  -> NEEDS_HUMAN_REVIEW
  -> APPROVED_REPLY
  -> WAITING_CUSTOMER
  -> CLOSED
```

异常状态单独处理：

```text
ERROR
BLOCKED
OPT_OUT
```

### NEW

刚收到线索，只做去重和来源校验。

### CONSENT_CHECK

确认用户是否提交了明确授权，授权范围是否覆盖当前回复。

### QUALIFYING

只询问完成初步判断所需的信息。

### NEEDS_HUMAN_REVIEW

遇到价格、合同、技术承诺或敏感信息时暂停。

### APPROVED_REPLY

人工确认草稿后发送。

### OPT_OUT

用户拒绝、退订或投诉后停止后续营销触达。

状态机的价值，是让每条消息都有可解释的下一步。

## 六、人工审批界面至少要显示什么

审批人不应该重新翻完整聊天记录。

审批界面至少显示：

1. 用户原始问题。
2. AI 提取的关键信息。
3. 信息来源和时间。
4. AI 草稿。
5. 草稿中可能是推断的句子。
6. 发送渠道和收件人。
7. 一键修改、批准、拒绝和转人工按钮。

如果审批人不知道模型为什么这样回答，就很难承担审核责任。

## 七、消息频率和退出机制

自动化系统必须有频率限制。

至少设置：

- 单个用户的每日消息上限。
- 连续无回复后的停止条件。
- 退订后的永久或长期抑制列表。
- 发送失败后的重试次数。
- 高风险词命中后的人工转接。

不要用多个号码、多个账号或变体文案去规避平台限制。

这会把一个可修复的流程问题，变成账号信誉和数据合规问题。

## 八、对话知识库怎么写

知识库应该优先放可核验资料：

- 当前产品说明书。
- 已批准的价格表版本。
- 服务区域和营业时间。
- 交付流程和售后规则。
- 常见问题与明确的“不知道”答案。

每份资料标记版本和生效时间。

模型回答时要求输出来源字段：

```text
answer: 当前可确认的交期为 7 至 10 个工作日。
source: delivery-policy-v3
valid_from: 2026-09-01
needs_human_confirmation: true
```

如果知识库没有答案，就返回“需要人工确认”，不要从相似产品猜测。

## 九、广告和落地页的验证

自动化上线前，至少准备五类测试输入：

1. 正常产品咨询。
2. 缺少预算或交期的信息。
3. 询问不存在的功能。
4. 要求承诺最低价格的请求。
5. 明确退订或投诉的消息。

每类输入都要写预期状态、允许回复和禁止回复。

还要检查落地页：

- 表单提交后是否显示授权说明。
- 是否能撤回或修改联系请求。
- 是否收集了不必要的字段。
- 是否能在移动端正常完成。
- 是否对隐私政策和数据用途做了可见说明。

## 十、失败处理和人工接管

一个可靠的流程不会把所有失败都转成“稍后再试”。

建议区分：

### 平台错误

例如发送失败、接口超时或权限失效。

处理：停止重试风暴，记录错误码，转人工检查配置。

### 数据错误

例如号码格式异常、产品名称不存在或线索重复。

处理：回到数据校验节点，不要让模型猜测。

### 内容错误

例如模型生成了未经批准的价格或承诺。

处理：阻断发送，保存草稿和触发规则，人工修订后再发。

### 用户风险

例如投诉、威胁、敏感事件或法律问题。

处理：停止营销话术，转交指定负责人并保留完整记录。

## 十一、如何算是否真的省人

不要只统计机器人发送了多少条消息。

建议记录：

| 指标 | 计算方式 |
| --- | --- |
| 有效线索率 | 通过授权和去重后的线索 / 总提交数 |
| 自动整理率 | 无需人工重新整理的线索 / 有效线索 |
| 审批通过率 | 直接可批准草稿 / 进入审核草稿 |
| 人工接管率 | 转人工会话 / 总会话 |
| 误发率 | 未授权或错误发送 / 总发送 |
| 退订率 | 退订用户 / 被联系用户 |
| 成交贡献 | 可归因成交金额 / 自动化总成本 |

误发率和退订率比消息数量更值得关注。

如果自动化让销售每天多花一小时清理错误线索，它就没有真正省人。

## 十二、常见高风险做法

### 1. 批量导入未经同意的号码

号码能被找到，不代表可以直接营销触达。

### 2. 把竞品广告原样下载再投放

竞品广告可以用于研究市场表达，但复制素材、商标、案例和客户评价可能涉及版权、商标和不正当竞争风险。

### 3. 让 Agent 自己修改投放预算

预算调整属于可产生真实费用的动作，应设置额度上限和人工审批。

### 4. 把客服机器人接到所有后台系统

连接器越多，误操作面越大。

先用只读权限和沙箱数据验证，再逐步开放写入权限。

## 结尾：自动化的底线是可撤回

WhatsApp 线索自动化最适合做三件事：整理信息、补齐问题、准备草稿。

真正影响收入和责任的动作，仍然应该由明确的人来确认。

一个能暂停、能追溯、能退订、能人工接管的系统，通常比“全自动成交”更容易长期运行。

先把授权、状态机、知识库版本和审批界面做好，再考虑是否接入更复杂的云端 Agent。
