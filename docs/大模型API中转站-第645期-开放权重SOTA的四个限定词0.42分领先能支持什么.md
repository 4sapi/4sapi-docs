# 开放权重 SOTA 的四个限定词：0.42 分领先能支持什么结论

一个新模型发布时，"SOTA"是最容易被截取的三个字。但 SOTA 从来不是无条件的名次，它总带着范围：哪些模型参与比较、用什么评测、哪个版本、什么条件下。

Ricursive 在 2026 年 11 月 4 日发布了 [Ripple-65B Preview](https://www.ricursive.com/ripple)，宣称达成"美国开放权重模型在 agentic coding 上的 SOTA"（模型卡见 [Hugging Face](https://huggingface.co/ricursiveAI/Ripple-65B-Preview)）。这句话里有四个限定，每一个都会缩小它的适用范围。

本文按"限定词拆解 → 两种口径的差距 → 成本口径 → 该用它做什么"的顺序读一遍。所有分数都是厂商自测，我没有复现；每个数字我都会标明出处与检索日期（2026-11-06）。

## 一、先把四个限定词拆开

原文的说法是"U.S. open-weight state-of-the-art on agentic coding"。四个限定分别是：

| 限定 | 含义 | 排除掉了什么 |
| --- | --- | --- |
| 美国 | 只跟美国机构的模型比 | 中国、欧洲的开放权重模型不在比较集里 |
| 开放权重 | 只跟可下载权重的模型比 | 闭源 API 模型不在比较集里 |
| agentic coding | 只在这个任务族上比 | 知识问答、数学、长上下文另有排名，且它并非都领先 |
| Preview | 这是个预览版 | 正式版可能变化，历史成绩不保证稳定 |

第三项最关键。**在 agentic coding 上第一，不等于各任务都第一。** 同一个模型卡里的基座对照表显示，它的 MMLU 是 83.7，而对照的 Nemotron 3 Ultra 550B 是 89.1；HumanEval 是 70.9 对 83.8（模型卡原文，检索日期 2026-11-06）。这一点我在另一篇讲架构取舍的文章里展开。

## 二、0.42 分：领先是真的，但幅度要说清

被拿来对照的四个模型与分数（模型卡与发布页，厂商自测）：

| 模型 | 总参数 | 架构 | TerminalBench 2.1（自报） |
| --- | --- | --- | --- |
| Ripple-65B Preview | 65B | dense | 80.52 |
| Reflection Beam 501B | 501B | MoE | 80.1 |
| Meta Muse Spark Open 816B | 816B | MoE | 76.4 |
| Thinking Machines Inkling 975B | 975B | MoE | 63.8 |
| NVIDIA Nemotron 3 Ultra 550B | 550B | MoE | 56.4 |

与最接近的对手相比，差距是 **0.42 分**（我按 80.52−80.1 算的，相对高约 0.52%）。与其余三家相比分别是 4.12、16.72、24.12 分。

这组数字要分两层读：

1. **"65B 打赢 500B 到 975B"这个说法成立**——在同一张表、同一口径下，它确实比四个更大的 MoE 模型分高。
2. **"领先"的幅度在第一名那里只有 0.42 分**。在一个 0 到 100 的百分比指标上，这个差距小于单题波动带来的影响量级；说它"与 Beam 并列第一梯队"比说它"第一"更准确。

第二层不是贬低，而是读取规则：0.42 分的差距需要重复测量才能说显著，而模型卡没有给多次运行的方差。

## 三、同一张表里的两种口径，是这份卡最值得读的地方

模型卡做了一件多数发布稿不做的事：它把 **Terminal-Bench 2.1 的两种 harness 口径并列**。

| 模型 | 自报 | 官方 Terminus 2 口径 | 变化 |
| --- | --- | --- | --- |
| Ripple-65B Preview | 80.5 | 80.5 | 0 |
| Reflection Beam 501B | 80.1 | 70.8 | **−9.3** |
| Meta Muse Spark Open 816B | 76.4 | 78.7 | +2.3 |
| Thinking Machines Inkling 975B | 63.8 | 56.2 | −7.6 |
| NVIDIA Nemotron 3 Ultra 550B | 56.4 | 55.1 | −1.3 |

模型卡自己的解释是：用官方 Terminus 2 harness、128K 序列、带摘要时，Terminal-Bench 2.1 的分数**普遍更低**（Muse Spark Open 是例外）。所以两种口径下的排名并不一样：

- 自报口径：Ripple 80.52 > Beam 80.1 > Muse 76.4
- Terminus 2 口径：Ripple 80.5 > Muse 78.7 > Beam 70.8

**换成统一 harness 后，第二名从 Beam 换成了 Muse。** 这直接改变了"谁是最接近的对手"这个判断，也改变了"这 0.42 分意味着什么"——Terminus 2 口径下它对 Muse 的领先是 1.8 分（80.5−78.7），比对 Beam 的 9.7 分小得多。

顺带一个精度提醒：发布页与模型卡导语写的是 80.52，卡里表格行写的是 80.5。我标题里用的 0.42 是把 80.52 减 80.1 得到的；只用卡里的三位数，差值就是 0.4。两者都可，但不要混着当同一个来源。

这一段值得所有读模型卡的人学：**同一份文档里同时给两种口径，比只给一个漂亮数字诚实得多。** 它同时提醒你，看到别家只报一个数时，那个数未必与这里的数是同一种东西（模型卡说明：斜体表示他们自测、非斜体表示官方卡上的成绩。但注意这条只对别家成立——Ripple 自己那一列是非斜体加粗，却同样是自测，因为不存在"官方卡"可引）。

## 四、参数倍数：说法与表格并不完全一致

模型卡（不是发布页）写它"匹配或超过参数多 10 倍以上的美国开放权重模型"。按表里的总参数算（我算的倍数）：

| 模型 | 相对 65B 的倍数 |
| --- | --- |
| Inkling 975B | 15.0 倍 |
| Muse Spark Open 816B | 12.6 倍 |
| Nemotron 3 Ultra 550B | 8.5 倍 |
| Reflection Beam 501B | 7.7 倍 |

也就是说，**四个对照里只有两个超过 10 倍**。这句宣传语在"存在这样的模型"这个意义上成立，但不能读成"所有对手都比它大 10 倍"。

另一组更有意义的对照是激活参数占比：

| 模型 | 激活占比 |
| --- | --- |
| Ripple-65B（dense） | 100% |
| Nemotron 3 Ultra 550B | 10% |
| Muse Spark Open 816B | 5.1% |
| Reflection Beam 501B | 4.6% |
| Inkling 975B | 4.2% |

这就把"dense 与 MoE"的差别量化了：它每个 token 都要动用全部 65B 参数，而那些 MoE 模型每个 token 只用 4% 到 10%。所以"参数少但分高"这句话，比的是**总参数**；按**每 token 计算量**比，两者的差距要小得多——65B dense 的计算量大致相当于一个激活 65B 的模型，而那些 MoE 的激活只有 23B 到 55B。

Ripple 在这一列的对比里其实是"每个 token 更贵"的一方。这不否定它的成绩，但解释了为什么它强调 dense 的另一个好处：部署简单（模型卡的部署说法见第六节）。

## 五、3200 万美元：要连限定一起读

发布页称从零开始的全部研发投入是 **3200 万美元**，并说这约为"上一个开放权重 agentic coding SOTA 成本的十分之一，据我们所知（to the best of our knowledge）"。

三个要点：

1. **口径是"全部 R&D"**，原文列举包含预训练阶梯开发、数据配比、评测、调试、合成数据生成、后训练配方开发，以及最终的正式训练。这与"单次训练算力成本"不是一回事。
2. **对照对象的成本无法独立核验**。"上一个 SOTA 的十分之一"是个自述估算；发布页脚注提到对手曾公开的算力承诺规模，但那是承诺而非实际支出。
3. **训练效率的另一个数字更可核**：它在 1.4M rollouts 内把 TerminalBench 2.1 推到 80.5，并称比 Reflection Beam 少约 70 倍 rollouts。这个对比的前提是两家的 rollout 定义与任务难度一致——发布页没有展开，所以我把它当作"厂商自述的相对量"。

成本数字对读者真正的用处，是提示一件事：**一个 65B dense 模型在 NVIDIA 硬件上、无自定义 kernel、无量化的情况下能把 MFU 维持到 40%**（模型卡自述）。它不能直接换算成"3200 万美元"——那个数含预训练阶梯、数据、评测、调试、合成数据与后训练配方等七项开支，不只是算力。但 MFU 是判断"这套配方能否在中小规模复现"的关键。

## 六、拿到权重之后，它能干什么

模型卡与发布页给出了几条与工程直接相关的信息：

| 项 | 内容 |
| --- | --- |
| 许可证 | Apache-2.0，HF 仓库未设访问门槛 |
| 权重形态 | BF16 指令模型（本仓库）、NVFP4 版、BF16 基座版 |
| 上下文 | 宣称支持最长 1M |
| 本地运行 | 称可在 NVIDIA DGX Spark 这类桌面硬件上运行，并提供 NVFP4 与 colab |
| 吞吐 | 2×B200、batch=8、未量化、无自定义 kernel 时达 250 tok/s |
| 分发 | Hugging Face、Together AI、GMI Cloud、OpenRouter、Fireworks |

"能在桌面上跑"这句要按精度读：65B 的 BF16 权重大约 130GB，桌面设备跑得动的是 NVFP4 版本，不是 BF16。这一点模型卡没有直接写显存数字，我按参数量推算，属推断。

## 七、什么时候值得考虑，什么时候别急

| 你的情况 | 判断 |
| --- | --- |
| 要一个可自托管的 agentic coding 模型，且已有 GPU | 值得试：Apache-2.0、有 NVFP4 与基座权重、官方称可跑在桌面上 |
| 只看 agentic coding 且要替换闭源前沿 | 谨慎：0.42 分的领先不足以支撑"更好"，要自己跑 |
| 需要强世界知识 | 谨慎：基座对照里它落后于更大的 MoE 模型（MMLU 83.7 对 89.1）；已发布的指令版是 89.6，仍低于 Muse 的 92.6 与 Nemotron 的 92.0 |
| 需要强数学 | 反而不错：指令版的 AIME 2025 是 98.3、GSM8K 88.5，与表内最高分差距很小；落后的是**基座**版的 MATH（59.1 对 82.0） |
| 需要长上下文 | 要单独测：1M 是宣称值，模型卡里长上下文基准（AA-LCR 75.0）并非表内最高 |
| 团队没人维护推理栈 | 先算成本：dense 65B 每 token 全激活，吞吐与显存都要自己压 |

结论表里"需要长上下文"那一行值得展开：AA-LCR 上它的 75.0 低于 Muse Spark Open 的 80.7、Inkling 的 78.3，也低于 Beam 的 78.2——三家都比它高。**"支持 1M"和"在长上下文任务上领先"是两件事。**

## 八、四个限定词换成一句可复核的话

把整篇的读法压成一句：**在被测的四个美国开放权重模型里，这个 65B dense 模型在 TerminalBench 2.1 上排名第一，自报口径领先 0.42 分；换成统一 harness 后排名第一不变，但最接近的对手换人；权重可下载，许可证是 Apache-2.0。**

这句话里的每个分句都能回到公开页面核对，而"它是 SOTA"这四个字做不到。差别就在这里。

## 九、限制与结论

这份发布材料里可核验的部分不少：Apache-2.0、参数量、训练阶段表、两种 harness 口径并列、基座对照的落后项都写在公开页面上。能支持的结论是：**一个 65B dense 模型在 agentic coding 上进入了与 500B 以上 MoE 模型同一梯队，并且权重可下载。**

不能支持的结论包括："各任务都第一"、"领先于所有参数大十倍的对手"、"0.42 分代表稳定优势"。

本文的限制：没有下载权重、没有跑任何基准；80.52 等分数全部是厂商自测；Terminus 2 的具体设置（128K + 摘要）只有模型卡一句描述，未核验；3200 万美元与 70 倍 rollouts 的对照口径无法独立验证；"桌面可跑"与显存的推断基于参数量，未实测。

下一步建议：如果你在评估它，先只做一件事——用你自己的 20 到 30 个 agentic 任务，把它和现用模型在同一 harness 下各跑一遍。这比争论 0.42 分有没有意义更省时间。
