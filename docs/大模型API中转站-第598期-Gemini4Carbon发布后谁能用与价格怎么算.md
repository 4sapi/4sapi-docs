# Gemini 4 Carbon 发布后：现在谁能用、价格怎么算、开发者何时能接入

2026 年 10 月 28 日，Google 发布了 Gemini 4 Carbon。发布稿给出了价格，也说了它已经向一部分用户开放。但稿子里的"开放"和"价格"各有几层含义，直接读标题很容易得出"可以接入了"这个结论。实际情况是，截至 2026 年 10 月 30 日，开发者还没有办法在 Gemini API 里调用它。

本文只回答三个问题：谁现在能用，价格怎么算，开发者怎么判断它什么时候开放。文章不评价模型能力，也不提供接入教程，因为目前没有可以验证的调用方式。读完你能得到一份"已确认、未公布、需自己核验"的清单，以及一个在它开放后几分钟内确认可用的检查方法。

信息截止日期为 2026-10-30，引用前请重新打开文中的官方页面核对。

## 一、先分清"可用"的三层含义

发布稿用了多个与"可用"相关的说法，它们对应不同的人群。

| 层级 | 含义 | 当前状态（2026-10-30） |
| --- | --- | --- |
| 已发布 | 模型已经公开宣布，有名字、价格和评测数字 | 是 |
| 受限开放 | 一部分经过筛选的机构可以使用 | 是，对象是部分网络防御者 |
| 开发者可调用 | 普通开发者拿 API 密钥就能在 Gemini API 中调用 | 否，官方文档中没有它 |


## 二、官方已经确认的事实

下面的内容都来自 Google 的发布稿，原文见
[Gemini 4 Carbon: our next frontier model](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)
（发布于 2026-10-28，检索于 2026-10-30）。

1. **开放范围。** 发布稿写明，从发布当周起，Carbon 会提供给一部分网络防御者，之后通过 Fairwind Program 逐步向更多受信任的伙伴开放。
2. **开放节奏。** 稿子说在收集反馈、迭代防护措施，之后"尽快"通过产品入口向开发者、企业和消费者开放。没有给出日期。
3. **发布前测试。** Google 称正在参与美国政府的自愿式发布前模型测试。
4. **价格。** 发布价与 Argon 的介绍期价格相同：每百万输入 token 2 美元，每百万输出 token 10 美元，缓存输入 token 比输入价便宜 95%。
5. **价格脚注。** 脚注写明介绍期结束后，价格变为每百万输入 4 美元、每百万输出 20 美元。

第 2 点是关键。"尽快"不是日期，也不是承诺，不能据此排期。

## 三、官方没有说的事

读发布稿时，下面几项容易被默认为"已经有"，但原文没有给出：

- 开发者开放的具体日期。
- Carbon 的介绍期在哪天结束。
- Carbon 在 Gemini API 中的模型名称（端点 ID）。
- 免费层是否可用。Argon 的定价页写明免费层不可用，Carbon 没有对应说明。
- 输出价格是否像 Argon 一样包含思考 token。Argon 的定价页明确写了"包含思考 token"，Carbon 的发布稿没有写。
- 缓存存储等其他计费项的价格。
- 区域可用性和数据保留条款。

这些空白可能随时被补上，开放当天建议逐项核对。

## 四、Fairwind Program 说明了什么，没说明什么

发布稿提到的开放通道是 Fairwind Program。官方页面
[Fairwind Program](https://deepmind.google/fairwind-program/)
（检索于 2026-10-30，页面无日期）提供了这些信息：

- 目前合作的伙伴超过 650 家。
- 优先对象是政府、关键基础设施运营方（医疗、通信、能源、金融）和核心技术平台。
- 只允许防御和学术研究范围内的两用任务，例如授权的威胁模拟、逆向工程和恶意软件分析。创建恶意软件明确不允许。
- 参与机构需要做到用户级认证、防钓鱼的多因素认证，只能把访问权限给内部的安全、应急响应或渗透测试团队，并且要记录员工的使用情况。
- 不允许转让、转售或共享访问权限。
- 申请方式是联系 Google Cloud 客户团队。

需要注意的是，这个页面描述的模型是 Gemini 4 Argon，没有提到 Carbon。发布稿说 Carbon 会通过这个计划逐步扩大范围，但页面上的准入条款是否原样适用于 Carbon，目前只能算推断。

这对普通开发者的含义很直接：Fairwind 是面向防御场景的受限通道，不是开发者开放前的"候补名单"。如果你的团队做的不是安全防御，这条路径本来就不适用。

## 五、两套价格怎么对上

发布稿里出现了两组价格，看起来矛盾，其实是同一价格表的两个阶段。

| 阶段 | 输入（每百万 token） | 输出（每百万 token） | 缓存输入 |
| --- | --- | --- | --- |
| 介绍期 | $2 | $10 | 比输入价低 95%，即 $0.10 |
| 介绍期结束后 | $4 | $20 | 比输入价低 95%，即 $0.20 |

缓存价格是按"低 95%"推算出来的，发布稿没有直接写出 $0.10 和 $0.20。Argon 的定价页确实写了介绍期缓存价为 $0.10，两者吻合。

第三方评测机构 Artificial Analysis 在
[Gemini 4 Carbon is the new #1 on the Artificial Analysis Intelligence Index v5](https://artificialanalysis.ai/articles/gemini-4-carbon-new-number-1)
（2026-10-28，检索于 2026-10-30）里把同一件事描述为"标准价 $4 / $20，外加 50% 的发布折扣，折扣没有确认结束日期"。它的所有图表都按标准价计算。

两种说法对应关系如下：

- Google 说"介绍期价 $2 / $10，之后 $4 / $20"。
- Artificial Analysis 说"标准价 $4 / $20，现在打五折"。


### 介绍期什么时候结束

Carbon 没有公布。Argon 的
[定价页](https://ai.google.dev/gemini-api/docs/pricing)
写的是：输入 $2.00 和输出 $10.00 持续到 2026 年 11 月 30 日，从 12 月 1 日起变为 $4.00 和 $20.00。

Carbon 的发布稿说"与 Argon 相同的介绍期价格"，因此很可能也在 11 月 30 日前后结束。但这只是推断。发布稿没有写这一点，而 Carbon 还没有向开发者开放，它的介绍期完全可能从开放日起重新计算。做预算时，应该用 $4 / $20 作为保守假设。

## 六、一个用来估算的例子

下面是用公布的单价算出来的示例，不是实测账单。假设一次请求输入 200k token、输出 20k token。

| 场景 | 计算 | 合计 |
| --- | --- | --- |
| 介绍期，无缓存 | 0.2 × $2 + 0.02 × $10 = $0.40 + $0.20 | $0.60 |
| 标准价，无缓存 | 0.2 × $4 + 0.02 × $20 = $0.80 + $0.40 | $1.20 |
| 介绍期，150k 命中缓存 | 0.15 × $0.10 + 0.05 × $2 + 0.02 × $10 | $0.315 |
| 标准价，150k 命中缓存 | 0.15 × $0.20 + 0.05 × $4 + 0.02 × $20 | $0.63 |

从这张表可以读出两点：

1. 介绍期结束后，同样的请求价格翻倍。按介绍期价格做出的成本预测，在结束日之后会整体偏低一半。
2. 在输入很长且前缀稳定的任务里，缓存把输入侧的成本压得很低，剩下的主要是输出费用。

这个计算假设输出价包含思考 token（Argon 是这样）、没有缓存存储费、缓存命中 75%。前两项在 Carbon 上没有官方说明，所以只能用来看量级。

## 七、怎么自己确认它是否对开发者开放

不要靠新闻判断，直接查官方接口。Gemini API 提供模型列表接口，文档见
[Models（API reference）](https://ai.google.dev/api/models)
（检索于 2026-10-30）：

- 请求方式：`GET https://generativelanguage.googleapis.com/v1beta/models`
- 每页数量：默认 50，最多 1000，用 `pageSize` 调整。
- 分页：响应里有 `nextPageToken` 时说明还有下一页。
- 返回的每个模型含 `name`、`displayName`、`inputTokenLimit`、`outputTokenLimit`、`supportedGenerationMethods` 等字段。

不带密钥的请求会返回 HTTP 403，提示需要 API 密钥，说明接口存在。带密钥的调用没有实测，下面的命令按文档写成。

在 Bash 中：

```bash
# 密钥放在环境变量里，不要写进脚本或提交到仓库
curl -s "https://generativelanguage.googleapis.com/v1beta/models?pageSize=1000&key=$GEMINI_API_KEY" \
  | grep -i '"name"' | grep -i carbon
```

在 PowerShell 中：

```powershell
$u = "https://generativelanguage.googleapis.com/v1beta/models?pageSize=1000&key=$env:GEMINI_API_KEY"
(Invoke-RestMethod $u).models | Where-Object { $_.name -match 'carbon' } |
  Select-Object name, displayName, inputTokenLimit, outputTokenLimit
```

### 怎么读结果

- **没有任何输出**：当前这个密钥可见的模型里没有 Carbon。可能是还没开放，也可能是你的项目没有权限。
- **有输出**：记下 `name` 字段的完整值，后续调用以它为准。不要凭 Argon 的命名习惯去猜 Carbon 的端点 ID。
- **返回 403 或 401**：检查密钥是否有效，以及项目是否启用了 Gemini API。

没有输出时有一个容易漏掉的情况：列表接口只显示你有权限的模型。所以"没有输出"只能证明"对我不可用"，不能证明"对所有人不可用"。要判断后者，还需要看
[模型文档页](https://ai.google.dev/gemini-api/docs/models)
是否已经出现 Carbon。2026-10-30 我对该页面全文检索，没有找到它。

## 八、开放之前可以做的准备

下面这些事不依赖 Carbon 本身，开放前就能做，而且和具体模型无关。

1. **模型名做成配置项。** 把模型 ID 放在环境变量或配置文件里。开放当天只改一处，不用改代码。
2. **预算用保守价。** 用 $4 / $20 估算，介绍期的差价当作额外余量，而不是前提。
3. **准备一组自己的评测任务。** 选 20 到 50 个真实任务，记录输入长度、期望输出和判定标准，并统计单任务成功率、平均输出 token 和单任务总成本。榜单分数不能替代这一步。
4. **先拿 Argon 跑通流程。** Argon 已经对开发者开放，价格结构和 Carbon 相同。用它把调用、缓存、日志和成本统计这些环节验证一遍，换模型时就只剩模型本身的差异。

第 4 点要加一个限定：Argon 与 Carbon 的价格结构相同，不代表两者的输出长度、思考消耗和延迟相同。这些必须在 Carbon 开放后重新测。

## 十、限制与结论

截至 2026 年 10 月 30 日，Gemini 4 Carbon 属于"已发布、受限开放、开发者不可调用"。价格已经公布，但介绍期结束日、输出计费口径和开放日期都没有公布。

这篇文章的结论有明确的适用条件。如果你的团队做网络安全防御，并且属于 Fairwind 优先对象，可以通过 Google Cloud 客户团队了解准入。如果你是普通应用开发者，现在能做的是准备配置、预算和评测任务，等模型出现在官方模型列表中再测。

下一步的验证建议很简单：每隔几天用上面的列表接口查一次，同时关注 Gemini API 的模型页和定价页。一旦出现 Carbon，先核对价格页的介绍期结束日和输出计费说明，再决定要不要把它放进生产流量。
