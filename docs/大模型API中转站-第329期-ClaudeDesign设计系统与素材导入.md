# Claude Design 设计系统如何从素材提炼可执行规则
设计系统不是一张色板，而是一组能够约束页面变化的规则：颜色、字体、网格、间距、组件、图表、图片和禁用项都要有明确写法。本文说明如何从品牌手册、旧 PPT、PDF 和截图提炼规则，并用代表性页面检查系统是否真的被执行。文中只讨论可复现的步骤，不把单次结果扩展成产品承诺；每个结论都标注前提、证据和无法覆盖的边界。读者可以先完成最小验证，再按自己的版本、权限和数据补充实验。


用 AI 做演示文稿，最常见的问题不是没有内容，而是每一页都像来自不同的模板：封面有一套颜色，正文换了一种字体，图表又突然变成另一种风格，最后一页像一张独立海报。

这类问题通常不是“审美不够高级”，而是没有给生成系统一套可执行的设计规则。

Design System，也就是设计系统，负责把颜色、字体、间距、组件、页面结构和禁用项写成一套可重复使用的约束。Claude Design 可以从既有品牌素材中提取这些规则，也可以根据你的文字说明先建立一个轻量版本。

## 一、设计系统不是一张色板

很多人准备设计规范时只给一句：

~~~text
请使用蓝色，整体高级一点。
~~~

这句话没有规定标题和正文的层级，没有说明重点怎么强调，也没有告诉模型哪些视觉元素不能出现。

一套够用的 PPT 设计系统，至少包含：

| 规则层 | 需要说明什么 |
| --- | --- |
| 颜色 | 主色、辅助色、强调色、背景色和风险色 |
| 字体 | 中文字体、英文字体、标题和正文字号层级 |
| 网格 | 页面边距、列数、对齐线和内容安全区 |
| 间距 | 标题与正文、卡片与卡片、图表与注释之间的距离 |
| 组件 | 卡片、按钮、标签、数字、引用和页脚如何呈现 |
| 图表 | 颜色使用、坐标轴、数据标签和来源说明 |
| 图片 | 图片比例、裁切、边框和使用场景 |
| 文字 | 每页信息量、行长、术语和标点规则 |
| 禁用项 | 渐变、阴影、发光、复杂背景或其他不希望出现的元素 |

设计系统的作用不是让每页完全一样，而是让变化发生在规则允许的范围内。

## 二、哪些材料可以用来提取设计系统

Claude Design 可以从多种资料中理解视觉风格。资料越接近真实使用场景，提取出来的规则通常越有参考价值。

### 1. 品牌手册和 Logo

品牌手册适合提供正式颜色、字体、Logo 安全区、用法和禁用规则。Logo 本身只能说明识别元素，不能单独代表完整页面风格。

### 2. 现有 PPT 或 PDF

旧的演示文稿最能反映团队实际使用的版式：标题放在哪里，数字如何突出，页脚怎样处理，图表和文字之间留多少空间。

不要只上传一张最漂亮的封面，最好提供几页不同类型的页面：

~~~text
封面页
目录或章节页
文字说明页
数据图表页
案例页
总结或行动页
~~~

这样系统提取的是一套页面语言，而不只是一个封面颜色。

### 3. 网站截图和设计稿

网站截图可以补充网页端的按钮、卡片、导航和信息层级。截图中如果包含广告、用户头像或无关文字，导入前最好先裁切或脱敏。

### 4. 产品代码库和组件库

企业有前端组件库时，可以提供颜色变量、字号、间距和组件文档。代码库不应该整体上传；只提供与视觉规范有关的公开或已授权文件，避免把密钥、业务数据和内部逻辑混入设计上下文。

### 5. 已完成的品牌素材

海报、社交媒体卡片、宣传单页和产品截图都可以作为参考，但要说明它们是“风格参考”还是“必须复用的组件”。否则模型可能把一张活动海报中的特殊排版扩展到所有页面。

## 三、先把参考素材分成三类

上传素材前，建议按用途分类：

~~~text
硬规则：必须遵守的品牌、字体、颜色和Logo规范
软参考：希望接近的版式、节奏、图片和氛围
内容材料：文章、数据、案例和业务事实
~~~

三类材料的优先级不同。硬规则约束视觉边界，软参考帮助系统理解方向，内容材料决定页面到底要表达什么。

如果一份旧 PPT 和品牌手册出现冲突，应先确认哪一份是当前生效版本，而不是让模型自动选择“看起来更好”的那个。

## 四、没有品牌手册时，先写一个轻量设计系统

个人创作者和小团队通常没有完整品牌手册，可以先写一份能直接执行的说明：

~~~text
项目主题：AI 与效率工具
目标受众：普通职场人士和内容创作者
使用场景：公开分享和线上课程

整体风格：简洁、现代、专业，避免过度科技感。
主色：深蓝色，用于标题、主要结构和核心导航。
辅助色：浅蓝色、浅灰色，用于背景和次要信息。
强调色：橙色，只用于重点数字、警示和行动提示。
背景：白色或浅灰色，不使用复杂纹理。
字体：常见中文无衬线字体，标题和正文保持清晰层级。
页面规则：每页只表达一个核心观点，避免密集小字。
组件规则：卡片边界克制，圆角和阴影只在确有层级需要时使用。
禁用项：蓝紫发光、无意义装饰、夸张阴影、过度渐变和堆叠图标。
~~~

这份说明不需要写成设计师规范书，但必须包含颜色用途、字体层级、信息密度和禁用项。明确“橙色只用于什么”，比单纯说“加入一些亮色”更容易保持一致。

## 五、让 Claude 先提取规则，再开始设计

上传参考素材后，可以先要求 Claude 输出设计系统摘要，不要立刻生成整套 PPT：

~~~text
请阅读我提供的品牌资料和参考页面，先输出一份可执行的 Design System。

请按以下结构整理：
1. 主色、辅助色、强调色和背景色，以及各自的使用场景。
2. 中文和英文字体建议，标题、正文、注释的层级。
3. 页面网格、边距、对齐方式和常用版式。
4. 卡片、数字、引用、图表和页脚的表现方式。
5. 图片和图标的使用规则。
6. 参考素材中可以复用的规律。
7. 只适合原页面、不能全局复用的特殊效果。
8. 明确列出当前无法确认的规则。

请区分“资料中明确出现的规则”和“根据样式推测的建议”，不要把推测写成品牌规范。
~~~

输出后检查两件事：一是规则是否来自真实素材，二是规则之间有没有冲突。例如主色既被规定为深蓝，又被另一份生效手册规定为绿色时，应该暂停并让负责人确认。

## 六、把设计系统变成页面级约束

全局设计系统还不够，制作 PPT 时需要把它转成页面规则：

~~~text
封面：标题、主题说明和日期，保留足够留白。
章节页：只承担分段，不塞进完整正文。
内容页：标题说明观点，正文提供证据或步骤。
数据页：数字、单位、来源和结论必须同时出现。
案例页：背景、做法、结果和限制分开呈现。
总结页：只保留行动建议和下一步。
~~~

这样可以避免每页都套同一种卡片布局。统一风格不等于所有页面只有一个模板，真正的统一是：不同页面承担不同任务，但使用同一套字号、颜色、间距和对齐规则。

## 七、检查“统一”是否变成“僵化”

AI 很容易把设计系统执行得过头：所有页面都有同样的三栏卡片、同样的圆角和同样的标题位置。

可以用 4 个问题检查：

~~~text
这一页的版式是否服务于它的内容？
核心数据能否在 3 秒内被找到？
不同页面有没有合理的节奏变化？
变化是否仍然遵守颜色、字体和对齐规则？
~~~

如果答案是否定的，不要直接要求“换一种高级设计”，而要说清楚哪一种页面关系需要改变：比较、流程、时间线、案例、数据或行动建议。

## 八、素材导入的隐私和权限边界

设计项目经常会混入不该公开的资料：客户 Logo、内部产品路线图、销售数据、未发布截图和团队评论。

上传前至少确认：

- 当前 Claude 工作区是否属于公司或个人账户。
- 团队成员是否都能看到 Design 项目。
- 原始素材和生成结果会保存多久。
- 客户资料是否允许交给外部模型服务。
- 截图中是否包含账号、手机号、价格和内部链接。
- 设计系统中是否包含不宜公开的品牌资料。

如果素材必须经过企业模型服务处理，可以先由业务后端完成权限过滤和脱敏，再通过 上游 API 调用摘要、OCR、视觉分析或知识库检索模型，最后把允许进入设计工作区的结果交给 Claude Design。

## 九、上游 API 如何承接企业内容和设计素材

在企业里，Design System 往往不是一次上传就结束。它可能需要从知识库、产品系统、品牌资产库和历史项目中持续获取内容。

可以设计成：

~~~text
品牌资产库 / 产品资料库
  -> 业务权限和脱敏
  -> 上游 API 统一调用检索、文本和视觉模型
  -> 输出已授权的事实与设计上下文
  -> Claude Design 生成和编辑视觉页面
  -> 人工审核与版本归档
~~~

上游 API 适合统一管理：

- 哪些团队能调用素材理解和视觉检查模型。
- 资料检索、OCR、摘要和 Embedding 的路由。
- 不同项目的 API Key、额度和成本。
- 失败、超时、重试和请求日志。
- 设计素材被调用的项目、版本和时间。

Claude Design 负责视觉画布，上游 API 负责企业多模型调用治理。两者可以协作，但不要在文章中宣称 Claude Design 已经原生集成 上游 API。

## 十、设计系统发布前验收清单

### 规则完整性

- [ ] 已写明颜色及其使用场景。
- [ ] 已定义标题、正文、注释和数字层级。
- [ ] 已说明边距、网格、对齐和间距。
- [ ] 已说明图表、图片、卡片和页脚规则。
- [ ] 已列出明确的禁用项。

### 素材质量

- [ ] 参考文件来自当前生效版本。
- [ ] 至少包含两种以上页面类型。
- [ ] 个人信息、客户数据和密钥已经脱敏。
- [ ] 已区分硬规则、软参考和内容材料。
- [ ] 规则冲突已经由负责人确认。

### 生成效果

- [ ] 封面、正文、数据和总结页风格统一。
- [ ] 页面之间有节奏变化，而不是全部套同一模板。
- [ ] 颜色没有被滥用成装饰。
- [ ] 内容密度不会因为遵守风格而变得难读。
- [ ] 设计系统中的推测没有被当成正式品牌规则。

## 总结

Design System 的价值，不是让 AI 每次都生成同一张页面，而是让它知道哪些地方可以变化、哪些地方不能变化。

没有品牌手册时，先用文字写清楚颜色用途、字体层级、页面密度和禁用项；有旧 PPT、PDF、网站或组件库时，提供多个页面类型，让系统提取真实规律。企业场景还要把素材权限、脱敏、调用日志和模型成本纳入流程，必要时通过 上游 API 统一管理外围模型服务。
