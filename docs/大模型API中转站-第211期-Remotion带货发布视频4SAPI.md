# 【大模型API中转站】第211期 Remotion批量素材 | 发布会带货视频

本文是【大模型API中转站】系列的第211篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

上一篇讲了 Codex + Remotion 的 4 类模板。

这一篇只拆两个最容易商业化的场景：

```text
产品发布视频。
电商带货素材。
```

它们有一个共同点：

```text
追速度。
追变体。
追批量。
```

产品发布要抢热点。

电商带货要测素材。

这两类视频都不适合每条从零剪。

更适合用 Remotion 做模板，再让 Codex 按数据生成变体。

4SAPI 则放在模型调用层，解决：

```text
哪一步用什么模型。
每条素材成本多少。
失败重试多少次。
谁触发了高成本任务。
哪些素材需要人工审查。
```

## 1. 产品发布视频的模板结构

产品发布视频不要一上来追求花哨。

先固定结构。

30 秒短片可以这样拆：

| 时间 | 画面 | 内容 |
| --- | --- | --- |
| 0-3 秒 | 标题冲击 | 产品名 + 发布事件 |
| 3-8 秒 | 主视觉 | 产品图 / 发布会图 |
| 8-20 秒 | 三个亮点 | 功能、性能、场景 |
| 20-26 秒 | 用户价值 | 谁该关注 |
| 26-30 秒 | 结尾 | 一句话判断 + CTA |

这套结构够用了。

后面换产品、换主题、换素材，不用重写整个视频。

## 2. 给 Codex 的输入不要太空

差的 Prompt：

```text
帮我做一条某产品发布视频，要科技感。
```

问题是它会自己补事实。

更好的输入是结构化资料：

```text
视频类型：产品发布快讯
比例：16:9 或 9:16
时长：30 秒
产品名：
发布日期：
发布方：
核心亮点：
- 
- 
- 
素材目录：
官方链接：
禁止编造：
- 价格
- 参数
- 发布时间
- 用户量
```

再让 Codex 做：

```text
1. 先生成视频分镜表。
2. 再生成 Remotion 组件。
3. 所有素材路径必须来自 assets manifest。
4. 不能使用没有来源的事实。
5. 输出预览和导出命令。
```

这样比一句话生成稳很多。

## 3. 产品发布最怕事实幻觉

产品发布类视频有三个坑：

```text
日期编错。
功能夸大。
产品图错配。
```

这类错误非常伤账号信任。

所以必须加事实审查。

可以让一个独立 reviewer 模型检查：

```text
视频字幕里的日期是否来自输入资料。
产品名是否一致。
功能点是否有来源。
是否出现“首个”“最强”“唯一”等夸张词。
素材是否和产品一致。
```

这一步可以通过 4SAPI 路由到强模型。

而普通字幕润色、标题改写，用低成本模型就够。

不要所有环节都用一个模型。

## 4. 发布视频的 4SAPI 字段

建议每条发布视频记录：

```text
workflow_id: remotion_launch_video
project_id:
source_url:
product_name:
template_id:
model_script:
model_reviewer:
cost_bucket: launch_video
render_status:
review_status:
error_type:
```

这样后面可以查：

```text
哪类发布视频最贵。
哪一步失败最多。
哪个模板成片最快。
哪个模型审查最稳。
```

如果你要做 AI 新闻号，这些数据很重要。

热点内容不是靠激情长期跑。

靠流程和日志跑。

## 5. 电商带货视频先做字段表

带货素材的核心不是“做一条好看视频”。

而是做很多可测试版本。

先把商品拆字段：

```text
商品名：
类目：
主图：
细节图：
目标人群：
痛点：
卖点：
价格锚点：
使用场景：
禁用词：
CTA：
```

再把视频拆结构：

```text
开头 3 秒：痛点或场景。
中间 15 秒：商品展示 + 3 个卖点。
后段 8 秒：价格/活动/信任点。
结尾 4 秒：行动提示。
```

这就可以模板化。

Remotion 负责画面结构。

Codex 负责把字段接到组件里。

模型负责生成变体。

## 6. 一件商品可以生成哪些变体

不要只生成一条。

可以一次生成：

```text
痛点开头版。
价格开头版。
场景开头版。
人群开头版。
细节展示版。
对比展示版。
评论口吻版。
```

每条都用同一套 Remotion 模板。

变化的是：

```text
字幕。
图片顺序。
开头钩子。
卖点排序。
BGM 类型。
CTA。
```

这就是代码视频的优势。

模板写好以后，变体是数据问题。

## 7. 带货视频必须有合规审查

带货素材不能只看好不好看。

还要看能不能投。

至少检查：

```text
是否夸大功效。
是否出现绝对化词语。
是否虚构用户评价。
是否误导价格。
是否使用无授权素材。
是否字幕遮挡商品主体。
```

4SAPI 可以在这里做两层：

```text
低成本模型：初筛禁用词和夸张词。
强模型：审查高风险素材和最终文案。
```

不要把所有素材都交给强模型审。

先批量初筛。

高风险再升级。

## 8. 批量任务怎么控成本

如果一天生成 100 条视频，成本要提前设上限。

建议：

```text
每个商品最多生成 10 条变体。
每条最多 3 次模型调用。
同一错误最多重试 2 次。
强模型只用于首版模板和高风险审查。
批量任务必须带 cost_bucket。
超过预算自动停止。
```

4SAPI 日志字段：

```text
product_id
template_id
variant_id
task_type
agent_role
model
cost
status
retry_count
review_required
```

这些字段比“感觉成本还行”靠谱。

## 9. 推荐工作流

产品发布：

```text
资料收集 -> 人工核事实 -> Codex 生成分镜 -> Remotion 出模板 -> reviewer 审字幕 -> 导出 MP4
```

电商带货：

```text
商品图入库 -> 模型提卖点 -> 生成 5-10 个文案变体 -> Remotion 批量渲染 -> 合规审查 -> 投放测试
```

4SAPI 贯穿其中：

```text
模型路由。
Key 权限。
调用日志。
成本统计。
失败排查。
```

## 10. 总结

产品发布和带货素材，最适合 Codex + Remotion。

因为它们结构稳定、重复需求高、对速度敏感。

但真正能长期跑起来，需要三层：

```text
Remotion 模板层：沉淀画面结构。
Codex 编排层：生成代码、调试、批量改模板。
4SAPI 模型治理层：管模型、Key、日志、预算和审查。
```

一句话：

```text
发布视频抢速度，带货视频抢变体。
4SAPI 负责让这两件事跑得可控。
```
