# 用自己的文档测状态跟踪：同序列四级对照与最小验收脚本

看到一个基准说"前沿模型在最难的长文档状态题上掉到 13% 或更低"，接下来该问的是：我的任务算难还是简单，我的模型在我用的那种表述下表现如何。这两个问题，公开基准都答不了。

自己测并不复杂，但有一个前提容易做错：**不同难度的题必须来自同一条序列**，否则你比的是长度、变量数、位置这些混杂因素。本文给一套最小做法，含一个我本机跑过的生成脚本。

四级难度的定义来自 AllenAI 在 2026-11-03 发布的 StateBench 博客（[链接](https://huggingface.co/blog/allenai/statebench)），检索日期为 2026-11-04。脚本是我写的，不是官方代码；我没有跑过任何模型。

## 一、为什么要"同一条序列派生四级"

如果把"简单题"和"难题"分别独立生成，两者在长度、变量数量、赋值出现的位置上都会不同。于是模型在难题上变差，你无法判断是难度造成的，还是"输入更长""变更更多"造成的。

StateBench 的做法是反过来：先生成一条最复杂的序列，再从它派生出三个更简单的版本。派生时保持三件事不变——

| 保持不变 | 允许变化 |
| --- | --- |
| 变量个数（取值集合在 r-trivial、aperiodic、general 三级一致；soluble 会溢出，见第二节说明） | 赋值的类型 |
| 赋值出现的位置与总步数 | 每个位置上做什么操作 |
| 最终要回答的变量范围 | — |

这样四份题唯一不同的就是难度本身。这是整套方法里最容易被忽略、也最值钱的一点。

## 二、生成与派生：一个可跑的最小脚本

下面的脚本做两件事：生成一条 General finite 级别的序列；从它派生出三个更简单的级别。

```python
import random

def gen_general(names, n_steps, seed):
    rnd = random.Random(seed); vals = list(range(1, len(names)+1)); seq=[]
    for _ in range(n_steps):
        k = rnd.random()
        if k < 0.4: seq.append(("set", rnd.choice(names), rnd.choice(vals)))
        elif k < 0.7:
            x,y = rnd.sample(names,2); seq.append(("copy", x, y))
        else:
            x,y = rnd.sample(names,2); seq.append(("swap", x, y))
    return seq

def first_values(names, seq):
    """每个变量在序列里第一次被 set 到的值；没有则用域内值兜底。
    r-trivial 是“值定了就不改”，所以用它当不可变初值，这样这一级才携带序列信息。"""
    vals = list(range(1, len(names)+1))
    init = {n: None for n in names}
    for op in seq:
        if op[0] == "set" and init[op[1]] is None:
            init[op[1]] = op[2]
    return {n: (init[n] if init[n] is not None else vals[i]) for i, n in enumerate(names)}

def to_level(names, seq, level, seed=0):
    rnd = random.Random(seed)
    vals = list(range(1, len(names)+1))
    if level == "rtrivial":
        fv = first_values(names, seq)
        return [("set", n, fv[n]) for n in names] + [("noop",)] * len(seq)
    out = [("set", n, v) for n, v in zip(names, vals)]
    for op in seq:
        if level == "aperiodic":
            out.append(("set", op[1], rnd.choice(vals)))
        elif level == "soluble":
            out.append(("add", op[1], rnd.choice([1,2,3])))
        else:
            out.append(op)
    return out

def solve(names, seq):
    """参考解：按语义逐步执行"""
    st = {n: None for n in names}
    for op in seq:
        if op[0]=="set": st[op[1]] = op[2]
        elif op[0]=="copy": st[op[1]] = st[op[2]]
        elif op[0]=="swap": st[op[1]], st[op[2]] = st[op[2]], st[op[1]]
        elif op[0]=="add": st[op[1]] = (st[op[1]] or 0) + op[2]
    return st
```

我在本机用 5 个变量、40 步、`seed=7` 跑过，结果如下（`to_level` 的派生用 seed=0）：

| 级别 | 步数 | 真实赋值条数 | 全部变量有值 | 最终状态（节选） |
| --- | --- | --- | --- | --- |
| rtrivial | 45 | 5（其余 40 条为空操作） | 是 | a=5, b=4, c=5 |
| aperiodic | 45 | 45 | 是 | a=5, b=5, c=3 |
| soluble | 45 | 45 | 是 | a=20, b=22, c=22 |
| general | 45 | 45 | 是 | a=4, b=2, c=5 |

两点要说明。第一，r-trivial 这一级只有 5 条真实赋值：它是"值定了就不改"，所以这 5 个初值直接取自原序列里每个变量第一次被赋到的值——这样这一级仍然携带序列信息，而不是所有题都一样的固定初值。第二，**soluble 这一级的取值会溢出初始域**（表里的 20、22 已经超出 1 到 5），因为累加操作本来就会往上走，所以"四个级别取值集合相同"只在 r-trivial、aperiodic、general 三级成立。

四个级别的步数都是 45（5 次初始化加 40 步），变量数一致，差别主要在赋值类型。**取值集合只有三级一致**：soluble 的累加会突破初始的 1 到 5，这一点上面刚说过，不要当成"四级完全相同"来理解。要的对照是"同一条序列、同样步数、同样变量"，而赋值类型正是被允许变化的那一维。

第一版脚本我写错过两次，都值得记下来。第一次：r-trivial 变体里可能出现某个变量从未被赋值（它在原序列里第一次出现时是"引用赋值"或"交换"，在简单级别被替换成了空操作）。第二次更隐蔽：我为了修第一个错，把初始化写成"先给全部变量 1 到 5，再用 `seen = set(names)` 过滤后续赋值"——结果过滤条件永远为假，r-trivial 这一级变成"只有初始化、零真实赋值"，所有题都是同一组固定值，任何策略都能拿满分，这一级就失去了鉴别力。现在的写法是让初值取自序列本身（见上面的 `first_values`），这样它既不可变、又携带信息。

## 三、指标：全变量正确率

最直接的指标是"最终每个变量的值是否都对"，全部正确才算这道题做对。

为什么不按变量算部分分？因为实际任务里你关心的是"这个结论能不能用"，一个变量错就意味着结论错。博客里那些"13% 或更低"的数字，我按全对才算对来理解——但博客没有明说它的评分口径，这一条是我的推断。

如果你想看得更细，可以额外记录：

| 指标 | 用途 |
| --- | --- |
| 全变量正确率 | 主指标，对齐基准口径 |
| 错误步数最低位 | 只错了一步还是错了很多，反映"敏感度" |
| 错误类型 | 用了初始值、用了倒数第二次、张冠李戴 |

第三行最能指导改进：如果错误集中在"用了初始值"，说明模型把任务当成不可变；如果集中在"用了上一步"，说明它只回退了一步。

## 四、接你自己的模型

契约很简单：输入是一条序列，输出是每个变量的最终值。

提示词要写清三件事：变量名与初始值、赋值规则（四种操作的语义）、输出格式（例如 JSON，键是变量名）。要求它只输出结果，不要解释——解释会掩盖错误，也会让自动评分变难。

一个可用的流程：

1. 用 `to_level` 生成四份同源题，写成一个 JSON 数组，每题带标准答案。
2. 逐题调用你的模型，把返回的 JSON 与标准答案比对，命中记为 1。
3. 每个级别至少 20 题，报"全对题数 ÷ 总题数"。

第 3 条的分母不要太小：20 题时一道题就是 5 个百分点，两级的差异小于这个数时不能下结论。

## 五、叠加长度梯度

单点测一次没有意义，因为这类能力的失效是随长度发生的。做法是：把同一条序列按步数切几个档位，例如 50、200、1000、5000 步，每档各测一遍。

作为参照，博客里的从零训练实验是：训练序列最长 256 次赋值，测试拉到 64,000 次。博客原文自己写了这是"训练长度的 250 倍"（64,000÷256=250，我复算一致）。你不需要这么极端，但至少要让最长的一档明显超过你实际任务的长度。

如果资源有限，优先测两档：**你任务的平均长度**与**你任务的 p95 长度**。前者判断日常可用性，后者判断最坏情况。

## 六、叠加格式矩阵

这一步最容易被跳过，但它可能让结论反转。博客记录了一个具体现象：参数量 2.75 亿的 hybrid 模型与 Gated DeltaNet 模型，在"RULER 风格"的 R-trivial 题上接近满分，但同一个问题改成"表格编辑"的表述后接近随机。

所以同一批题至少用三种表述各跑一遍：

| 表述 | 长什么样 | 适用场景 |
| --- | --- | --- |
| 代码式 | `x = 4`、`x = y` 一行一条 | 你在处理代码或配置 |
| 表格式 | 每行一次变更：变量、操作、值 | 你在处理审阅记录、台账 |
| 自然语言 | "约翰把刀递给了玛丽" | 你在处理合同、纪要、叙事 |

**用你生产里的那种表述做最终判断**，其余两种作为对照。如果三者的差距很大，说明你的结论高度依赖表述方式，这时候"换模型"未必比"换表述"有效。

## 七、四个常见错误

| 错误 | 后果 | 修正 |
| --- | --- | --- |
| 四级题分别独立生成 | 比的是长度与变更数，不是难度 | 同一条序列派生 |
| 只测一种表述 | 可能高估或低估 | 至少三种格式 |
| 只测窗口内的长度 | 看不到拐点 | 加一档超过窗口的 |
| 每题只跑一次 | 采样波动被当成能力差异 | 同题多次，或增大题量 |

第四行常被忽略：如果模型有随机性，一道题的对错本身就不稳定。要么每题跑三次取多数，要么把题量加大到 50 以上。

## 八、怎么读结果并用起来

把结果整理成一张表：行是难度级别，列是长度档位，格子是全变量正确率。然后按下面的方式判断：

| 现象 | 含义 | 动作 |
| --- | --- | --- |
| 只在第四级掉 | 架构或训练的通用限制 | 加外部状态表，别指望换模型 |
| 所有级别随长度一起掉 | 可能是"长输入处理"问题，不特指状态跟踪 | 先查检索与分段 |
| 只在某种格式上掉 | 表述敏感 | 换表述，或在提示里固定格式 |
| 简单级别都不稳 | 提示词或输出契约有问题 | 先修提示词再谈模型 |

第二行和第三行是最容易被误判成"模型不行"的两种情况：一个是长度问题，一个是格式问题，而它们的解法都不是换模型。

## 九、限制与结论

这套方法的要点只有一个：**同一条序列派生四级**，其余都是围绕它加维度（长度、格式、重复次数）。脚本不到 50 行，一次能跑完，比读一份基准结论更能回答"我的任务行不行"。

本文的限制：脚本是我写的，只在本机用一个种子验证过，不是官方实现；四级语义按博客描述实现，可能与官方数据集的细节不同（例如它假设变量数固定，我照这个假设做的）；没有跑过任何模型，所以文中没有模型准确率数字；"250 倍"是我用两个数算的。

下一步建议：先用脚本生成 20 题、两个长度档、三种格式，各跑一次。如果第四级在你生产的表述下准确率低于一半，就把外部状态表排进日程——这比继续比模型更省时间。
