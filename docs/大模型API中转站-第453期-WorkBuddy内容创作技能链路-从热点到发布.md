# WorkBuddy 内容创作技能链路：从热点、长文到发布

内容创作是最容易被技能市场吸引的场景。一个技能找热点，一个技能写文章，一个技能做封面和插图，最后再用排版技能生成发布格式，看上去像是把一篇文章交给 Agent 后就能自动出街。

真正做过内容的人知道，最耗时间的部分并不只是打字。选题有没有读者、材料是否可靠、观点是否站得住、图片有没有误导、排版是否适合渠道，任何一步都可能让“产出很快”变成“返工更多”。用户提供的 WorkBuddy 素材给出了 `aihot`、`khazix-writer`、`baoyu-cover-image`、`baoyu-article-illustrator`、`gzh-design-skill` 等不同环节的例子。它们可以组成一条链路，但每个环节的责任边界必须先划出来。

本文不把这些技能包装成全自动发文方案，而是给出一条从热点到发布的可审核工作流。技能名称、来源和功能状态会变化，具体使用请以 WorkBuddy 当前入口与相应开源仓库的说明为准。

## 一、先把内容生产拆成五个不该混在一起的阶段

一篇文章的发布可以拆成：

```text
选题：决定要讨论什么，读者为什么现在要看。
取材：收集来源，确认日期、主体、数字和限制条件。
写作：形成有观点、有结构、能被读懂的正文。
视觉：用封面、插图、图表帮助理解，而不是掩盖信息不足。
发布：按渠道处理标题、格式、链接、版权与最终检查。
```

这些阶段可以由不同技能辅助，但不能跳过。比如热点技能能告诉你“今天哪些话题出现得多”，不等于它已经证明这个话题值得写；写作技能能组织段落，不等于它替你确认了新闻事实；排版技能能生成 HTML，不等于平台审核、链接和图片版权已经没有问题。

最初就把阶段拆开，会让每一轮输出都能被检查，也会让你知道出问题应回到选题、资料还是表达，而不是笼统地说“AI 写得不行”。

## 二、热点是信号，不是选题结论

素材中的 `aihot` 用于获取 AI 资讯和按时间、类别、关键词筛选事件。它适合做选题雷达：快速知道今天发生了什么、哪些主体持续被讨论、哪些词开始升温。但热度往往混杂转发、争议、标题党和重复报道，不能直接变成文章结论。

一次稳妥的热点筛选可以这样设计：

```text
请整理指定时间范围内与“AI Agent 办公”相关的公开动态。

输出表格：
- 事件标题；
- 原始来源链接与发布时间；
- 事件主体；
- 已确认事实；
- 尚未确认或存在争议的说法；
- 与目标读者的关联；
- 适合写成快讯、教程、评论还是不建议跟进。

不要把二手报道中的评价写成事实；同一事件合并去重。
```

这张表的作用，是让编辑先看到材料质量。选题判断还要加两个问题：我是否能提供新的解释或实用信息？读者读完后能得到什么，而不只是知道“发生了一件事”？如果两个问题都回答不上来，再热的事件也很难写出有价值的长文。

## 三、取材阶段要做一份小型事实账本

写作前先把必须保真的信息锁住。对产品更新、开源项目、行业数据和人物观点，至少记下：

| 类别 | 需要记录的内容 |
| --- | --- |
| 事件 | 原始公告、发布时间、主体和链接 |
| 数字 | 数值、单位、统计时间、来源页或表格 |
| 引语 | 原话、说话人、上下文与出处 |
| 产品能力 | 当前文档中的功能、限制、配置条件 |
| 判断 | 作者自己的分析，与事实分开标记 |

这份账本不需要公开，但它会约束后面的写作和配图。没有来源的数字不进正文；版本、价格、排名和支持范围等变化快的信息要标注时间；来自二手文章的引用尽量回到原始来源。若无法核实，宁可写“尚待确认”，不要让流畅的叙述替代证据。

对于用户提供的资料、访谈记录或内部文档，还要先确认是否有发布权限。AI 能读取不代表作者有权对外公开；内容技能不应该被当成绕过版权、保密或平台规则的工具。

## 四、写作技能负责组织，不负责替你拥有立场

素材提到 `khazix-writer` 这类写作技能会带有特定的表达规则与节奏。风格技能可以减少陈词滥调，也能让长文的节奏更统一，但它不该让文章都长成同一种腔调。

更实用的做法，是在调用前给清楚五项内容：

```text
读者：谁会读，已经知道什么。
问题：文章真正要回答什么，不回答什么。
材料：允许使用的来源与事实账本。
观点：作者的判断及其证据强度。
表达：希望的语气、长度和禁用表达。
```

例如：

```text
请基于已核对的事实账本写一篇面向开发者的教程。
核心问题：技能数量增加后，为什么 Agent 反而更容易选错工具？
观点：不要把技能市场当应用商店，应按任务、权限和验收选技能。
要求：事实与作者判断分段表达；未核实内容不补写；避免夸张承诺；正文要给出一个可执行的选择流程。
```

这比“写一篇爆款文章”更容易得到可用稿件。好文章不是把信息全部塞进来，而是找到一条读者跟得上的主线，删掉不能支撑主线的材料。

## 五、用两轮编辑代替一次性定稿

长文最不适合一次生成后直接发布。建议把编辑分成两轮，每轮只做一类判断。

### 第一轮：事实与结构

```text
检查标题是否兑现了文章承诺。
检查开头是否说明读者的问题和文章范围。
逐项核对数字、日期、产品名、命令、引用和链接。
将事实、推断、意见和待确认内容分开。
确认每个章节都在推动主线，而不是重复换句话说。
```

### 第二轮：节奏与表达

```text
删掉空泛的评价、口号和不提供信息的过渡句。
把长句拆开，保留必要的条件与限制。
用具体场景替代抽象形容，但不虚构案例。
让标题、列表和表格真正帮助扫描阅读。
检查是否存在同一套模板式段落反复出现。
```

写作技能在第二轮很有用，例如帮助找出重复表达、统一标题层级、调整句子节奏。但事实核对必须以第一轮确认的账本为准，不能为了“更像人写的”而弱化来源、条件或不确定性。

## 六、封面和配图先服务理解，再服务点击

素材中的封面和插图技能可以根据文章内容选择视觉方向。对内容创作者来说，这能减少空白画布的时间，但有三条底线：图片不能伪造事实、不能误导为真实现场、不能使用没有授权的受保护标识或人物形象。

给配图技能的需求最好说清楚图的功能：

| 图的位置 | 它该解决什么 | 不该做什么 |
| --- | --- | --- |
| 封面 | 让读者一眼知道主题与情绪 | 用与正文无关的夸张视觉骗点击 |
| 流程图 | 解释步骤、角色或信息流 | 把猜测画成确定的系统架构 |
| 对比图 | 让读者看见两种方案的边界 | 偷换指标或省略关键条件 |
| 氛围插图 | 调节阅读节奏、承托主题 | 伪装成真实新闻照片或产品截图 |

发布前核对图片中的文字、标识、数字和关系箭头。图片里的一个错误年份或错误产品名，比正文里的错字更容易被忽略，也更容易被传播。涉及真实产品界面时，优先使用合法截图或自行制作的示意图，并明确它是示意。

## 七、排版技能的价值在最后一公里

素材提到 `gzh-design-skill` 可以将 Markdown 转为适合公众号编辑器的 HTML。这类技能最适合处理重复的样式劳动：标题、引用、列表、表格、提示块、目录和移动端间距。但排版必须排在事实与内容确认之后。

发布前可以给排版任务一个明确边界：

```text
请将已审定的 Markdown 转为发布格式。

保留：标题层级、代码块、链接、引用来源和免责声明。
检查：长链接、窄屏表格、图片宽度、代码换行、引用块和列表缩进。
不要改写正文事实，也不要替换链接或删除限制说明。
输出：发布用 HTML 与一份预览检查清单。
```

生成后务必在目标平台预览。不同编辑器会重置样式、过滤标签或改变图片宽度；能粘贴不等于能发布。标题、封面、摘要、链接、图片授权和文末来源都应由发布人再过一遍。

## 八、一个两小时内可跑完的内容工作流

如果你刚开始搭这条链路，不必一次做日报、封面、插图和自动发布。可以先选一个小题目，按下面步骤完成一篇可审核的文章：

```text
第 1 步：用热点或检索技能收集候选事件，人工选一个问题。
第 2 步：建立事实账本，给每个关键事实留来源。
第 3 步：先生成大纲，确认读者、主线、观点和非目标。
第 4 步：写出正文初稿，事实与判断分开。
第 5 步：人工做事实与结构审阅，再做表达调整。
第 6 步：为真正需要解释的地方制作封面、流程图或插图。
第 7 步：转换为目标平台格式，预览后再发布。
```

前几次最好保留每一步的材料：选题表、事实账本、大纲、初稿、审阅意见和最终稿。等某类文章连续跑通三次，再把它沉淀成自己的内容技能。那时固化的不是“让 AI 写文章”这句愿望，而是你已经验证过的选题规则、事实标准和交付格式。

## 九、发布前清单

```text
[ ] 选题有明确读者问题，不只是复述热点。
[ ] 关键事实、数字、时间和引用都能回到来源。
[ ] 事实、推断、意见和待确认事项没有混写。
[ ] 素材、截图、图片和引用具备适当的使用权限。
[ ] 正文没有为了顺口而承诺未验证的能力或结果。
[ ] 封面与插图服务理解，文字和数据已核对。
[ ] 排版后在目标平台或窄屏环境预览过。
[ ] 标题、摘要、链接、来源与免责声明已由发布人确认。
[ ] 未经确认的自动化发布、外部发送和评论回复仍保持关闭。
```

## 十、不同类型内容，链路也应不同

不是每篇内容都需要同样长的生产线。把快讯、教程、观点文章和资料型长文混用一套流程，要么拖慢发布，要么降低准确性。可以先按内容类型分流：

| 类型 | 重点 | 最不能省的一步 |
| --- | --- | --- |
| 快讯 | 时效、原始来源、事实边界 | 事件主体、时间和原始公告核对 |
| 教程 | 可复现、条件、失败分支 | 自己或可信环境中的步骤验证 |
| 观点文章 | 论点、证据、反例 | 区分事实、推断和个人判断 |
| 资料型长文 | 结构、来源、读者路径 | 事实账本和章节级审阅 |
| 案例复盘 | 过程、限制、责任边界 | 不把个案结果夸大成通用结论 |

技能选择也跟着变。快讯需要检索和去重，但未必需要复杂插图；教程需要可复现的步骤和截图核对，而不是华丽文风；资料型长文更需要文档提取、引用整理和结构审阅。先确定内容类型，才能避免为了“技能全都用上”而制造多余环节。

## 十一、给选题做一个轻量评分，不跟热点赛跑

热点出现后，最容易发生的是马上开写，写到一半才发现没有一手资料、没有独特角度，或者读者已经被同类文章淹没。可以用一个简单评分表，十分钟内决定是否投入：

```text
读者相关性：目标读者是否正在遇到这个问题？
资料可靠性：是否拿到原始来源或足够的可核实材料？
新意：能否给出新解释、可执行步骤或不同视角？
时效：晚一天发布是否仍有价值？
成本：核实、写作、视觉与审阅是否值得投入？
风险：是否涉及敏感数据、未确认消息、版权或品牌误导？
```

不必把每项都量化成精确分数，但若资料可靠性和读者相关性都很低，就应该放弃或改为内部笔记。内容技能能让写作速度变快，也会让低质量选题更快地变成成品；因此，选题阶段反而需要故意慢一点。

## 十二、把“人审”写成具体的编辑动作

“最后人工看一眼”通常无法发现关键问题，因为没有人知道该看什么。更有效的方式是指定审阅角色与动作：

```text
作者：确认论点、材料取舍、案例边界和最终语气。
事实编辑：核对日期、数字、引语、链接、产品能力和不确定性。
视觉编辑：核对封面、插图、图表文字、版权与是否误导。
发布人：核对平台格式、标题、摘要、标签、跳转链接和发布时间。
```

个人创作者也可以一人兼任四个角色，但最好分轮进行。先只看事实，再只看表达，再只看视觉与发布；一次从头读到尾，往往会被流畅的文字掩盖错误。

对于允许 Agent 使用浏览器或发布接口的工作流，建议仍保留人为发布动作。自动生成草稿、准备图片、生成排版都是可逆的；误发、发错账号、贴错链接或附带未公开资料，往往不是。只有在流程稳定、权限分层、失败通知和回退方式都清楚后，才考虑极小范围的自动发布。

## 十三、素材沉淀比单篇爆发更有价值

一条内容发布后，不要只保存最终稿。将可复用的资产放回自己的资料库，下一篇会更快也更可靠：

```text
选题表：记录为什么写、目标读者和发布时间窗口。
事实账本：保存来源、引语、数据口径和核实日期。
结构模板：保留真正有效的章节顺序，而不是固定句式。
视觉规范：封面比例、字体、色彩和示意图规则。
复盘记录：哪些段落被读者追问、哪些链接失效、哪些步骤最花时间。
```

等一类文章重复出现，再把这一套资产打包为个人 Skill。此时，Skill 的内容应该包含事实核对和发布前检查，而不是只包含“写得吸引人”。内容产出越快，越需要把质量标准也一起固化。

## 十四、结论

内容技能可以让选题、取材、写作、视觉和排版彼此接上，但它们不会替代创作者的判断。热点只负责提示方向，来源决定事实边界，写作技能负责组织表达，视觉和排版负责降低理解成本，发布责任仍然在人。

先把一篇文章按这条链路完整跑通，再考虑把其中的重复步骤自动化。这样积累下来的不是一批自动生成的稿件，而是一套能复核、能迭代、也能长期使用的内容生产方法。
