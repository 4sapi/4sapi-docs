# 用 DeepTutor 做学习平台前：数据落在哪里、哪些会外发、文档没说什么

把一个个性化辅导平台用于班级、培训机构或家庭，数据问题会比功能问题更早出现：学生的对话记在哪里，谁能看，删了是不是真的没了，用到的外部服务会拿走什么。DeepTutor 是自托管项目，听上去数据都在自己手里，但自托管不等于不外发。

本文依据仓库里的数据存储文档和 README，回答三个问题：数据落在磁盘的哪些位置；哪些功能按设计必然把内容发给外部服务；文档没有回答什么。文章不是法律意见。涉及未成年人或教育机构的合规要求，请找有资质的人确认。我没有安装或运行过项目，也没有抓包，所以"外发"的判断是从功能设计推断的。

信息截止日期为 2026-10-30。

## 一、数据落在哪里

来源：[本地数据持久化文档](https://github.com/HKUDS/DeepTutor/blob/HEAD/docs-for-dev/DATA_STORAGE.md)（检索于 2026-10-30，文档无日期）。

文档开头说明：默认安装不需要 PostgreSQL、MySQL 之类的数据库服务，持久状态都在一个运行时目录下，部分在 SQLite 里，设置、生成物、知识库索引、缓存和导入的源文件是普通文件。

默认管理员范围的布局如下：

| 路径 | 内容 |
| --- | --- |
| data/user/settings/ | JSON 和 YAML 设置，以及模型提供方的凭据 |
| data/user/chat_history.db | SQLite：会话、消息、轮次、题库条目、练习数据 |
| data/user/.runtime/ | 私有运行时状态，如 workspaces.sqlite3 |
| data/user/workspace/ | 默认内容工作区和生成物 |
| data/user/logs/ | 应用日志 |
| data/knowledge_bases/ | 知识库索引和带版本的源数据 |
| data/parse_cache/ | 共享的文档解析缓存 |
| data/users/<user-id>/ | 启用本地多用户认证时，每个用户的工作区根 |
| data/partners/<partner-id>/ | 合成的 Partner 工作区 |
| data/system/ | 账号、授权、审计记录、索引和所有者凭据 |

几个要点：

1. **凭据和对话在同一棵目录树里。** 设置里有提供方的 API 密钥，system 下有账号和所有者凭据，chat_history.db 里有对话。拷走整个目录，等于拷走全部。
2. **内容工作区可以在 data/user 之外。** 此时它的私有学习状态在 <工作区>/.deeptutor/data/ 下，而账号设置、凭据、记忆和工作区注册仍留在运行时目录。要备份就得两处都备份，包括隐藏的 .deeptutor 文件。
3. **不同类型的数据分开存。** 题库条目在 SQLite 的 notebook_entries 表（遗留的名字），收藏集合和笔记块是文件，不在这张表里。

### 数据库支持的边界

文档明确：SQLite 是受支持的本地后端；没有受支持的 PostgreSQL 或 MySQL 连接设置；设置 DATABASE_URL 之类的环境变量不会重定向存储。PocketBase 是可选集成，只存受支持的会话集合，不会把全部状态搬进去，当前模式是单用户。

## 二、备份与泄露面

文档给的备份要求有两条，都值得照做：

1. **先停止 DeepTutor 和 Partner 进程再复制。** SQLite 可能有未合并的预写日志，运行中只拷 .db 文件会丢最近的事务。
2. **把每份拷贝都当作敏感数据。** 它可能含凭据、私人对话文本和上传的学习材料。

### 一个清点脚本

下面这个脚本帮你在备份前看清目录里有什么，并检查有没有非空的 -wal 或 -shm 文件（那说明可能还有未落盘的写入）。我在本机用一个按文档布局伪造的假目录测过：它正确汇总了每个子目录的大小和文件数，发现了我故意放的非空 chat_history.db-wal 并给出警告；对空目录则不输出任何内容。它没有在真实的 DeepTutor 数据上跑过。

```python
import pathlib, sys

def human(n):
    for unit in ("B", "KB", "MB", "GB"):
        if n < 1024 or unit == "GB":
            return f"{n:.0f} {unit}" if unit == "B" else f"{n:.1f} {unit}"
        n /= 1024

root = pathlib.Path(sys.argv[1])
for child in sorted(root.iterdir()):
    files = [f for f in child.rglob("*") if f.is_file()] if child.is_dir() else [child]
    print(f"{human(sum(f.stat().st_size for f in files)):>10}  {len(files):>4} files  {child.name}")

live = [p for p in root.rglob("*")
        if p.is_file() and p.name.endswith(("-wal", "-shm")) and p.stat().st_size > 0]
if live:
    print("WARNING: non-empty WAL/SHM files found; stop the app before copying:")
    for p in live:
        print("  ", p.relative_to(root))
```

用法：`python inventory.py <你的 data 目录>`。这个脚本只读，不修改任何文件。它不能代替"先停应用再复制"，只是帮你发现你忘了停。

## 三、哪些功能会把内容发给外部服务

下面是我根据 README 的功能清单做的推断。文档没有给出一份"外发清单"，我也没有抓包。

| 功能 | 为什么可能外发 | 依据 |
| --- | --- | --- |
| 对话、测验、解题、研究等所有生成功能 | 内容要发给你配置的大模型提供方才能得到回答 | 设置里要配置模型提供方和 API 密钥；这是这类系统的基本工作方式 |
| 联网搜索 | 查询词发给搜索提供方 | README 提到多家搜索提供方 |
| 咨询外部智能体工具 | 对话内容交给你连接的工具及其背后的服务 | README 列出 Claude Code、Codex 等可被咨询 |
| Partner 的 IM 渠道 | 消息经过聊天平台 | 发布记录提到 Partner 接入多个即时通讯渠道 |
| 视频学习 | 请求到视频平台；字幕和浏览可经管理员配置的 Invidious 实例 | README 说明；YouTube 播放使用官方的隐私增强播放器 |
| MCP 服务和 CLI 应用 | 取决于具体服务 | README 列出 |
| 文档解析与嵌入 | 取决于你选的引擎是本地还是云端 | 设置中可选多种解析和嵌入引擎 |

结论的逻辑是：**数据存储在本地，不意味着内容不出本机。** 只要你配置的是云端模型，学生的提问就会发给那家提供方。要做到内容不离开内网，需要把模型、嵌入、搜索和解析都配成本地服务，并确认没有启用上面那些外联功能。

容器化文档里提到，宿主机上的 Ollama、LM Studio 等可以作为模型提供方接入。这说明纯本地的配置在设计上是可行的，但我没有验证这套组合在实际运行时有没有其他外联。

## 五、删除：文档说了一半

两条线索来自发布记录：

- v1.6.8：已删除对话的回收站。
- v1.6.9：可恢复的归档，以及"显式的永久删除"。

这意味着删除分两步：先进回收站或归档，再显式永久删除。对隐私的含义是，用户点了"删除"，数据可能仍在磁盘上。

README 里还有一段卸载说明：先复制启动横幅里 Workspace 的路径，确认其中的 data 子目录是预期的 DeepTutor 数据目录，需要时备份，再把这个目录移到系统回收站；不要对它执行递归删除命令。

文档没有回答的：永久删除是否同时清理 SQLite 的空闲页、预写日志、解析缓存、知识库索引和日志里的残留；删除一个学生的账号会不会连带删除其全部数据。需要自己做一次删除测试：创建一个测试账号，产生一些对话和上传，再删除，然后用上面的清点脚本和文本搜索看是否还有残留。

## 六、文档没有回答的隐私与合规问题

我对 README 全文做了关键词检索（COPPA、FERPA、GDPR、telemetry、analytics、privacy 等）。结果是：README 里没有出现 COPPA、FERPA、GDPR、遥测或分析的字样，"privacy"只出现在 YouTube 隐私增强播放器那一处。

这个检索只覆盖 README，我没有检索其他文档。所以准确的说法是"README 没有提"，而不是"项目没有"。

下面这些问题，我没有在读过的文档里找到答案：

| 问题 | 为什么重要 |
| --- | --- |
| 项目本身会不会收集使用数据或崩溃报告 | 决定是否有除你配置的服务之外的外发 |

## 七、部署前的最小核查

在一台一次性的机器上按下面顺序做，每一步都记录结果：

1. 用出站代理或系统网络监视记录一次完整使用，列出所有外部域名。
2. 对照第三节的表，判断每个域名对应哪个功能，关闭不需要的。
3. 把模型、嵌入、搜索、解析逐个换成本地或你信任的服务，再抓一次包。
4. 创建测试账号，产生对话、上传、记忆，然后走一遍删除，再用清点脚本和搜索查残留。
5. 测试备份与恢复：停止应用，复制，恢复到另一台机器，确认账号和对话完整。
6. 如果启用学习者/监护人账号，用两个测试账号确认各自能看到什么。
7. 把第六节的问题发给项目维护者或自己读更多文档，记录答复。

## 八、限制与结论

DeepTutor 的数据布局透明：一个运行时目录、SQLite 加普通文件、不依赖外部数据库。这对备份和审计是优点。但同一棵目录里放着凭据和学生对话，备份要当作敏感数据处理。

内容是否外发取决于你配置的模型、搜索和连接的工具，而不是取决于"自托管"这个事实。文档没有给出遥测、隐私政策、保留期限和监护人权限的说明。

本文的限制：没有安装或运行项目；没有抓包；外发判断是推断；关键词检索只覆盖 README；学习者/监护人账号的实际行为未验证；清点脚本只在假目录上测过；不构成法律意见。

下一步建议：不要先问"它合规吗"，先做第七节的前三步，拿到自己环境里的真实外联清单，再带着清单去问你的法务或数据保护负责人。
