# 【大模型API中转站】第178期 AI排查模型成本暴涨 | Token和重试

本文是【大模型API中转站】系列的第178篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

企业接入大模型以后，最容易让老板皱眉的问题是：

```text
账单怎么突然涨了？
```

很多人第一反应：

```text
模型是不是涨价了？
```

其实更多时候不是单价问题。

而是：

```text
上下文变长。
输出变长。
重试变多。
强模型被低价值任务调用。
Loop 空转。
工具返回太大。
缓存失效。
批量任务和实时任务混在一起。
```

这类问题特别适合 AI。

因为它要分析调用日志、账单、任务类型和模型路由。

4SAPI 在这里就是成本治理核心。

## 1. 成本暴涨先看公式

粗略公式：

```text
总成本 = 调用次数 × 单次 token × 模型单价 × 重试倍率
```

所以成本上涨可能来自四个变量：

```text
调用次数变多。
单次 token 变多。
模型变贵。
重试变多。
```

先别争。

先让 AI 分解。

## 2. 给 AI 的成本排查包

```text
【现象】
- 成本上涨时间：
- 上涨比例：
- 哪个项目：
- 哪个 Key：
- 哪个模型：

【4SAPI日志】
- 按天调用次数：
- input_tokens：
- output_tokens：
- retry_count：
- fallback_count：
- top task_type：
- top prompt_version：

【最近变更】
- 是否换模型：
- 是否上线新功能：
- 是否新增 Loop / Agent：
- 是否改 Prompt：
- 是否增加上下文：
- 是否关闭缓存：

【边界】
- 不直接停生产服务
- 先找成本来源
- 区分短期止血和长期优化
```

## 3. 辅助模型先做账单聚合

低成本模型适合：

```text
按天聚合。
按模型聚合。
按 Key 聚合。
按 task_type 聚合。
按 prompt_version 聚合。
```

Prompt：

```text
请根据这批 4SAPI 调用日志，输出成本归因表。
维度包括 date、project、key_group、model、task_type、input_tokens、output_tokens、retry_count、estimated_cost。
不要给优化建议。
```

再让 Fable 5 判断：

```text
哪个变量导致成本上涨。
```

## 4. 常见根因一：上下文变长

Prompt 改了一版，把：

```text
用户全部历史。
完整知识库。
所有日志。
所有文件。
```

都塞进去了。

调用次数没变，但成本翻倍。

修复：

```text
上下文包。
检索。
摘要缓存。
材料索引。
只传证据。
```

这时不是降模型。

是减上下文。

## 5. 常见根因二：强模型滥用

例如：

```text
标题改写走 Fable 5。
日志摘要走 Fable 5。
客服分类走 Fable 5。
批量标签走 Fable 5。
```

这肯定贵。

4SAPI 路由应该改成：

```text
low_value -> low_cost_model
medium_value -> medium_model
critical_reasoning -> Fable 5
review -> Fable 5
```

Fable 5 是高级专家。

不是默认打印机。

## 6. 常见根因三：重试太多

如果某个接口错误率升高，重试会放大成本。

尤其是：

```text
JSON 解析失败重试。
429 后无退避重试。
Tool Call 参数错反复重试。
上游 500 无限重试。
```

要看：

```text
retry_count。
error_code。
失败前后 token。
重试是否换模型。
```

有些重试比原请求还贵。

所以要设置：

```text
最大重试次数。
错误类型白名单。
退避策略。
失败后降级或转人工。
```

## 7. 常见根因四：Loop 空转

自动化 Loop 很容易烧钱。

表现：

```text
同一个 task_id 多轮调用。
每轮没有新文件变化。
每轮没有新证据。
状态一直 continue。
```

AI 可以帮你检测空转：

```text
请找出过去 24 小时里，iteration 超过 5 轮但 evidence_ids 没变化的任务。
```

空转任务要：

```text
停止。
生成复盘。
改停止条件。
限制预算。
```

## 8. 常见根因五：工具返回太大

Agent 调工具时，工具返回：

```text
完整 HTML。
几万行日志。
全量数据库查询。
完整文件树。
```

这些都进入模型上下文。

成本会暴涨。

解决：

```text
工具分页。
工具过滤。
先摘要。
返回证据编号。
限制单次结果大小。
```

这属于 Agent 工具设计问题。

不是模型价格问题。

## 9. AI Prompt

```text
你是大模型成本治理分析助手。

请根据 4SAPI 调用日志和账单聚合，判断成本上涨来自：
1. 调用次数增加
2. input tokens 增加
3. output tokens 增加
4. 模型路由变贵
5. 重试次数增加
6. fallback 放大
7. Loop 空转
8. 工具返回过大

要求：
- 用数据排序贡献度。
- 区分短期止血和长期优化。
- 不建议简单停掉所有强模型。
- 给 Key 分组、预算、模型路由和告警建议。
```

## 10. 4SAPI 告警建议

建议设置：

```text
单日预算告警。
单 task_id 成本告警。
单 Key 成本告警。
Fable 5 调用次数告警。
重试率告警。
平均 input_tokens 告警。
Loop iteration 告警。
```

企业场景里，成本治理不是月底看账单。

是当天就知道哪里不对。

## 11. 成本复盘报告模板

当成本暴涨时，让 AI 输出一份复盘报告。

模板：

```text
# 模型成本异常复盘

时间范围：
影响项目：
总成本变化：
主要贡献因素：
证据：
短期止血：
长期治理：
需要调整的 Key：
需要调整的模型路由：
需要补充的告警：
负责人：
```

要求它必须用数据说话：

```text
不要只写“调用变多”。
要写哪个项目、哪个 Key、哪个模型、哪个 task_type 变多。
```

这类复盘用低成本模型先写草稿即可。

如果涉及路由策略和预算调整，再让 Fable 5 审查。

## 12. 降本不是一味降模型

很多人看到成本高，就想：

```text
全部换便宜模型。
```

这可能适得其反。

如果便宜模型成功率低，重试和人工返工会更贵。

更合理的是：

```text
简单任务降模型。
复杂任务保留 Fable 5。
长上下文先压缩。
失败率高的任务先改 Prompt。
重试多的任务先修错误处理。
Loop 空转先改停止条件。
```

成本治理的目标不是少用好模型。

是把好模型用在值得的地方。

## 13. 总结

模型成本暴涨，别只盯单价。

先拆：

```text
调用次数。
输入 token。
输出 token。
模型路由。
重试。
Loop。
工具返回。
缓存。
```

4SAPI 的价值就是让这些维度可见。

辅助模型做账单聚合。

Fable 5 做策略判断。

最后落到：

```text
Key 分组。
预算。
路由。
告警。
停止条件。
```

一句话：

```text
成本治理不是少用 AI，而是别让 AI 在低价值地方空转。
```
