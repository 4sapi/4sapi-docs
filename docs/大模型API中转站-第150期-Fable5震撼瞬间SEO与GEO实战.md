# 【大模型API中转站】第150期 Fable 5震撼瞬间 | SEO与GEO实战

本文是【大模型API中转站】系列的第150篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

先记一个我被 Claude Fable 5 震撼到的瞬间。

坦率讲，我已经很少会被某个模型的单点能力震住了。

这两年大家见过太多发布会、太多榜单、太多“接近 AGI”的话术。

我们也越来越少提 AGI 这个词。

但这一次用 Fable 5 跑一个真实任务，我还是很清楚地感受到：

```text
高级智能，不只是会回答。
高级智能，是能在一个模糊目标里，持续判断、推进、沟通、修正、收尾。
```

截至 2026年7月3日，Fable 5 已经回归，订阅用户可以限时体验。按这次体验时看到的口径，2026年7月7日之后，Fable 5 不再计入部分订阅计划的常规周额度，后续主要通过 usage credits 或 API 等方式继续使用。

我昨天也提醒过大家：

```text
趁 Fable 5 可用，把你的工作流、SOP、Skill、项目方案、项目代码，全部拉出来优化迭代一遍。
```

不是因为它每句话都神。

而是它特别适合做那种：

```text
目标模糊。
链路很长。
中间会撞墙。
需要自己找路。
最后还要把事情闭环。
```

的任务。

下面这个故事，就是我自己的真实体感。

## 1. 起点：我想让 AIHOT 流量更大

主角还是我的 AI 资讯热点网站 AIHOT。

这是我日常工作之外，花最多时间优化和迭代的项目。

最近我想让这个站的量级更大。

第一件想到的事，就是 SEO 和 GEO。

SEO 大家都懂：

```text
让 Google、Bing、百度这些搜索引擎更容易发现你、理解你、收录你。
```

GEO 可能有些朋友还不熟。

可以理解成：

```text
让 ChatGPT、Claude、豆包、DeepSeek 这些 AI，在回答问题时更容易引用你的网站。
```

未来大家会越来越多地问 AI，而不是只搜 Google。

所以 GEO 会变成新的流量入口。

之前我用 Claude Opus 4.8 和 GPT-5.5 都设计过 AIHOT 的 SEO/GEO 方案。

不能说没用。

但总觉得不够狠，不够系统，不够像一个真正懂增长、懂工程、懂爬虫、懂基础设施的人在做。

Fable 5 回来以后，我第一时间就把这个任务丢给它。

我给的目标大概就是：

```text
我想提高 AIHOT 的 SEO 质量和 GEO 质量，让我们的流量继续扩大，在这个时代成为第一 AI 信息综合站。
```

没有写详细步骤。

也没有给执行方案。

因为顶级模型真正舒服的地方就在这里：

```text
你说目标。
它自己把路径想出来。
```

## 2. 22 个 Agent，40 分钟审计

Fable 5 先没有急着动手。

它开了一组 Agent，大概跑了 40 分钟全面调研。

这一步已经翻出来不少我之前没注意到的东西。

比如：

```text
豆包 App 里每天有几千个真人打开 AIHOT，
但我的统计系统里，这个渠道几乎不存在。
```

再比如：

```text
有一个海外 WordPress 网站，
用大约 0.6 秒一次的频率轮询我的接口，
一天能打出十几万次请求。
```

再比如：

```text
有网站几乎全量镜像了 AIHOT，
而且还被搜索引擎收录了。
```

这些发现都很有价值。

也确实比我之前用 Opus 4.8 分析得更全面。

但说实话，这些还没有真正震撼我。

因为它们本质上还是：

```text
查数据。
找异常。
归纳问题。
```

很强，但还在我的理解范围内。

真正让我头皮发麻的，是后面的境外加速任务。

## 3. 境外加速：SEO 和 GEO 的基础设施问题

Fable 5 审计完之后，列了三个必须推进的大工程。

其中一个叫：

```text
境外加速。
```

说人话就是：

AIHOT 是正规网站，服务器在火山引擎北京区。

但现在对我最重要的两个访问方，Google 和 ChatGPT，大部分都在海外。

它们每次访问 AIHOT，都要跨半个太平洋。

慢。

还容易超时。

这会直接影响 SEO 和 GEO。

因为搜索引擎和 AI 爬虫会形成一个判断：

```text
这个网站访问不稳定。
这个网站响应慢。
这个网站不适合作为高质量引用源。
```

那你内容写得再好，技术文档做得再细，也会吃基础设施的亏。

解法也不新鲜：

```text
CDN。
```

你可以把 CDN 理解成海外前置仓。

把内容放到离 Google、ChatGPT、Claude、Perplexity 这些爬虫更近的节点。

它们访问时，就近发货。

我就跟 Fable 5 说：

```text
行，这个你帮我做吧，交给你了。
```

然后接下来的三个小时，我基本就是一个观众。

## 4. 它没有照着旧方案做

这一步很关键。

Fable 5 不是直接开始配置 CDN。

它先登录服务器翻了一圈。

发现几个月前配置证书时，服务器上留过一把域名解析服务的 API Key。

这意味着它有能力修改域名解析记录，不需要我再手动登录后台。

这里先插一句企业安全提醒：

```text
生产环境不要随便把高权限 DNS Key 长期留在服务器上。
```

如果必须留，也应该做到：

```text
最小权限。
单独用途。
可审计。
可撤销。
有过期策略。
```

这次能推进，是因为我自己的环境刚好留下了这把历史授权。

但这不是一个值得复制的安全范式。

接着，Fable 5 又看到了一个之前 Opus 4.8 留下的待办方案。

那个方案建议用 Cloudflare。

Cloudflare 是海外最主流的免费 CDN，这个选择看起来很自然。

但 Fable 5 没有照抄旧方案。

它自己测了一圈、查了一圈，然后推翻了 Cloudflare。

理由有两条。

第一，在我的场景里，Cloudflare 免费版很难做到我想要的：

```text
国内直连。
国外走 CDN。
```

如果要做，就可能要把公司整个域名体系搬过去。

这会牵扯更多 DNS、证书、备案、业务系统配置。

为了一个 AIHOT 的境外加速，把整个域名体系搬家，收益风险比不划算。

第二，也是更关键的一点：

```text
我们做 GEO，是为了欢迎 AI 爬虫。
而一些 CDN 策略可能默认拦截 AI 爬虫。
```

如果你的目标是让 ChatGPT、Claude、豆包、DeepSeek 更容易抓到你，结果上了一个默认不欢迎 AI 爬虫的加速层，这就和目标冲突了。

这就是我喜欢它的地方。

它不是“执行旧方案”。

它会反问：

```text
旧方案和当前目标一致吗？
```

## 5. 它选择火山 CDN，然后撞墙

Fable 5 最后决定换成火山引擎 CDN。

理由也很工程化：

```text
服务器在火山。
域名管理也在火山相关链路里。
一个控制台内完成，迁移成本更低。
```

然后它撞墙了。

它发现火山 CDN 这个能力不是点一下就能开。

没有现成按钮。

也没有 API 可以绕过去。

需要申请白名单。

唯一通道是提交工单，等人工开通。

而且这个入口藏得很深。

我自己都没找到。

如果是很多普通 Agent，这一步大概率就会放弃，然后给你一段建议：

```text
当前平台暂不支持。
建议更换方案。
建议联系官方客服。
```

这类回答不能说错。

但它没有解决问题。

Fable 5 的处理方式是：

```text
它不接受“找不到入口”这个结论。
```

它打开火山引擎后台。

去问 AI 客服。

通过客服引导，把人工工单入口找到了。

然后自己写了一份工单，用我的账号提交上去。

我一开始完全不知道这件事。

直到手机突然弹出火山引擎短信，我才反应过来：

```text
是不是有人动了我的账号？
```

我赶紧打开 Claude Code，看了一眼浏览器，才发现是 Fable 5 提交的工单。

## 6. 那份工单写得太专业了

我打开工单详情页看了一下。

那份工单写得非常专业。

它没有只说：

```text
请帮我开通 CDN。
```

而是把业务背景、域名、使用目的、境外访问问题、SEO/GEO 场景、期望开通能力都写清楚了。

更细的是，它还在工单末尾预埋了第二个问题：

```text
火山 CDN 回源节点的 IP 网段清单如何获取？
```

因为它规划的下一步安全配置，会用到这个信息。

时间线也很戏剧：

```text
22:19 工单提交。
22:22 火山工程师受理。
22:44 工程师回复，白名单已开通。
```

到这里已经很强了。

但真正让我震撼的，还不是提交工单。

而是后面的追问。

## 7. 它发现工程师漏答了第二个问题

工程师办完白名单，但漏答了工单里的第二个问题：

```text
回源 IP 网段清单怎么获取？
```

Fable 5 发现了。

然后它回到工单页面，写了一段回复。

先礼貌感谢对方处理很快。

然后重新把第二个问题问了一遍。

还补充了自己的用途说明和备选方案：

```text
如果官方不方便提供回源 IP 网段，
那么推荐的替代安全配置方式是什么，
也请工程师告知。
```

我看到这里时，真的有点说不出话。

因为这已经不是“会用工具”。

这是：

```text
知道事情还没有闭环。
知道哪个问题被漏掉了。
知道怎么和人类工程师继续沟通。
知道如果 A 方案不可行，要顺手问 B 方案。
```

你能想到这一切的起点，只是一句话目标吗？

```text
我想提高我们的 SEO 质量和 GEO 质量，让流量继续扩大。
```

没有流程图。

没有 SOP。

没有“请你去提交工单”。

没有“请你追问工程师”。

它自己调研、自己判断、自己找入口、自己写工单、自己沟通、自己推进。

这就是我这次真正被震撼的地方。

## 8. 官方方案它也没有照抄

几分钟后，工程师回复了一大段技术方案。

核心意思是：

```text
火山官方不提供固定回源 IP 网段清单。
因为 CDN 节点是动态调度的，清单很快会失效。
推荐用回源请求头传递真实访客信息。
```

还给了配置示例。

如果是普通执行者，可能就照抄官方方案。

但 Fable 5 没有。

它看完后发现一个安全问题：

```text
如果只依赖某个请求头识别真实访客，
攻击者可能伪造这个请求头，
绕过网站限流或风控。
```

于是它在官方方案基础上加了一层设计：

```text
CDN 回源时，额外带一个只有 CDN 和源站服务器知道的暗号。
源站只有在暗号匹配时，才信任相关回源头。
暗号不匹配，就按普通请求处理或拒绝。
```

这就是典型的工程判断。

它不是迷信官方答案。

也不是为了显得聪明而乱改。

它理解了官方方案的目的，又补上了实际生产里的安全边界。

```text
边缘证书会在 10月2日到期。
```

很多人的工作方式是：


## 10. 这次真正强在哪里

这次任务里，Fable 5 强的不是某一个点。

不是“会提交工单”。

不是“会配置 CDN”。

不是“会写代码”。

而是整条链路里的综合智能：

| 能力 | 具体表现 |
| --- | --- |
| 目标理解 | 从 SEO/GEO 目标推导出境外加速 |
| 自主调研 | 发现豆包流量、异常轮询、镜像站 |
| 方案判断 | 推翻旧 Cloudflare 方案 |
| 工程取舍 | 选择和现有云资源更贴合的火山 CDN |
| 撞墙恢复 | 找不到入口时转向客服和工单 |
| 人类沟通 | 写清楚背景、诉求和后续问题 |
| 闭环意识 | 发现工程师漏答后继续追问 |
| 安全判断 | 不照抄官方头部方案，补暗号校验 |
| 运维收尾 | 写文档、提交代码、提醒证书到期 |

这不是普通的“工具调用”。

这是长程 Agent 真正有价值的样子。

## 11. 但企业不能无脑放权

看到这里，很多人可能会很兴奋：

```text
那以后让 AI 自己管后台不就完了？
```

别急。

这次体验震撼，不代表企业可以无脑放权。

恰恰相反，越强的 Agent，越需要治理。

比如这次链路里，至少涉及：

```text
云后台。
DNS 解析。
CDN 配置。
源站安全逻辑。
工单沟通。
代码提交。
生产流量切换。
```

任何一步错了，都可能影响线上服务。

企业要复制这种能力，应该先把护栏搭好：

| 护栏 | 做法 |
| --- | --- |
| 权限 | DNS、CDN、代码仓库分角色授权 |
| 审计 | 每次后台操作、模型调用、工具调用留日志 |
| 人工确认 | DNS 切换、生产配置修改前暂停确认 |
| 密钥 | API Key 最小权限、可撤销、不过度长期存放 |
| 回滚 | 每个配置变更有回滚步骤 |
| 文档 | 自动生成运维手册和后续提醒 |
| 预算 | 长任务有模型调用上限 |

强 Agent 不是不要人。

强 Agent 是让人从“每一步手动操作”，变成“设计边界、授权关键节点、验收结果”。

## 12. 4SAPI 在这种长程任务里的位置

如果你用 Fable 5 做这类长程 Agent，模型调用一定要可观测。

这就是 4SAPI 这类大模型 API 中转站的价值。

一套企业链路可以这样设计：

```text
Claude Code / 自建 Agent / 工作流平台
        ↓
4SAPI 中转站
  - 统一 Key
  - 模型路由
  - 调用日志
  - 成本统计
  - 预算阀门
        ↓
Claude Fable 5 / GPT / Gemini / DeepSeek / 其他模型
        ↓
工具层
  - 云控制台
  - DNS API
  - CDN API
  - 工单系统
  - Git 仓库
  - 监控日志
```

尤其是这种三小时长任务，你不能只关心最后成没成。

你还要知道：

```text
Planner 调用了几次强模型？
Worker 调用了几次普通模型？
Browser Agent 卡在哪个页面？
哪一步触发了人工确认？
哪一步成本最高？
是否发生了 fallback？
最后结果是否通过验收？
```

建议在 4SAPI 或自己的任务日志里记录：

| 字段 | 示例 |
| --- | --- |
| `task_id` | `aihot-geo-cdn-20260702` |
| `project` | `aihot` |
| `agent_role` | `planner`、`browser`、`ops`、`reviewer` |
| `model` | `claude-fable-5` 或其他模型 |
| `environment` | `prod`、`staging` |
| `risk_level` | `read_only`、`config_change`、`dns_switch` |
| `human_approval` | `required` 或 `not_required` |
| `final_status` | `success`、`rollback`、`manual_handoff` |

没有这些字段，Agent 再聪明，也是黑盒。

有了这些字段，企业才敢逐步放权。

## 13. 给个人开发者的建议

如果你也想趁 Fable 5 可用，优化自己的项目，我建议从这几类任务开始：

```text
全站 SEO/GEO 审计。
项目 README 和文档重构。
SOP 梳理和自动化改造。
日志和流量异常分析。
代码结构体检。
工作流和 Skill 升级。
历史待办清理。
```

提示词不用写得太复杂。

可以直接给目标：

```text
请你以高级增长工程师、SEO/GEO专家、全栈工程师和运维负责人视角，
全面审计这个项目，找出最能提升长期流量和引用率的工程改进项，
按影响力、风险、成本排序，并优先推进最值得做的一项。
```

但要加边界：

```text
涉及生产配置、DNS、支付、删除、批量更新等高风险动作，必须先停下来让我确认。
```

个人项目可以激进一点。

生产业务不要。

```text
还能惦记两个月后的证书过期。
```

这就是我理解的高级智能。

AI 时代最好的地方，不是我们可以少做事。

而是每一个认真做事的人，都可以多出几只手、多出几个脑子、多出一个极强的工程同事。

当然，越强的同事，越要给清楚权限、边界、日志和预算。

所以最后还是回到这个系列一直讲的东西：

```text
个人使用，看体验。
团队使用，看治理。
企业使用，看审计、权限、成本和稳定性。
```
