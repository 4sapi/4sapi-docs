# 长文档里的状态跟踪：四级难度与一个容易被忽略的格式敏感

长上下文经常被当成"记得住"的同义词。但"记住"和"跟得住"是两件事：把一百页材料塞进窗口，模型能读到每一句；可如果材料里某个东西中途易手、某个值被反复改写，它未必能在最后答出"现在归谁""现在等于几"。

这类能力叫状态跟踪。AllenAI 在 2026 年 11 月 3 日发布了一个专门测它的基准 StateBench，把问题按难度分成四级，并给了不少具体结论。

本文回答三个问题：四级难度各是什么、为什么同一道题换个写法结果会差很多、以及这些发现对你判断自己的长文档任务有什么用。信息来自该项目的[官方博客](https://huggingface.co/blog/allenai/statebench)（Hugging Face 上的 allenai 组织页，2026-11-03），检索日期为 2026-11-04。我没有跑过这个基准。

## 一、先看它测的是什么

博客给的例子很直白：如果推理小说写到"约翰把刀递给玛丽"，紧接着发生凶案，那么读的人必须知道每个角色的状态已经变了。

再难一档的例子是：如果写的是"约翰把背包里的东西给了玛丽"，而前面交代过"爱德华把刀放进了约翰的背包"，那么要判断刀在谁手上，就得跟住一条依赖链——中间漏一步，结论就错。

这正是编程里每天都在发生的事：

| 场景 | 状态变化 |
| --- | --- |
| 读代码 | 变量被赋值、重新赋值、相互引用 |
| 读小说 | 物品易手、人物移动 |
| 读合同 | 条款被修订、主体变更、金额调整 |

所以这不是"学术玩具"，而是"你到底能不能信任模型读完这段材料后的结论"。

## 二、四级难度各是什么

StateBench 用四种赋值操作来区分难度，博客把它们分别对应到代码写法与日常类比：

| 级别 | 允许的赋值 | 代码类比 | 生活类比 |
| --- | --- | --- | --- |
| R-trivial | 不可变赋值，值定了就不改 | `let x = 4` | 出生日期 |
| Aperiodic | 按值重新赋值，只需找最新一次 | `x = 4` 之后 `x = 2` | 恒温器的当前设定 |
| Soluble | 自引用更新，要基于当前值往下算 | `x = x + 5` | 游戏分数累加 |
| General finite | 按引用赋值，一个变量取另一个变量的当前值 | `x = y`、交换两变量 | 三仙归洞：球在五只杯子间反复换位 |

最后一级那个"三仙归洞"的例子里，博客点明它对应的是五个物体的连续置换，属于四档里最难的一类。

这四档不是随手分的。博客说明它们对应代数理论中状态跟踪问题的分层，每一级由不同的原子操作构成。这一点我只按原文说明概念，不展开推导——对你的实际用途来说，重要的是这四级**确实对应不同的推理负担**：

- 前两级只要"找到最新那一次"或"记住初始值"。
- 第三级要往前累加，漏一步就偏。
- 第四级要跨更新维护依赖关系，一次交换会同时改变两个变量的状态。

## 三、几个可以直接用的结论

博客给出了三组实验，结论比"谁强"更有用。

### 前沿模型：简单的能过，难的随长度崩

被测的四个前沿模型是 Gemini 3.8 Flash、Claude Opus 5.5 与 GPT-6 Sol 和 Luna。结果是：

- 在 R-trivial 与 Aperiodic 上，四个都表现良好。
- 在 Soluble 与 General finite 上，随着输入变长，准确率急剧下降；**在最长的 General finite 问题上掉到 13% 或更低**。

博客给了一个可能的原因：这两级里"能影响最终答案的步骤"多得多，模型可容忍的漏步空间更小。

### 同一道题换个写法，结果会差很多

这一条我认为是全篇最该记住的。博客写到：参数量 2.75 亿的 hybrid 模型与 Gated DeltaNet 模型，在"RULER 风格"表述的 R-trivial 题上接近满分，但把**同一个问题**改写成"表格编辑"的形式后，却接近随机。

正因如此，StateBench 才要把同一个底层问题用多种格式测一遍。

这里要小心外推：博客的这个发现只针对 2.75 亿参数的 hybrid 与 Gated DeltaNet 在 r-trivial 题上的表现，不是对全部模型的普遍结论。基于它，我的判断是：**测长文档能力时只用一种表述形式，有高估的风险。** 你在生产里用的是哪种形式，就该用那种形式测。

### 架构差异：训练补不齐的部分才是架构的上限

第三组实验从零训练了若干 2.75 亿参数的模型，训练序列最长 256 次赋值，测试拉到 64,000 次赋值。博客原文自己写了这是"训练上限的 250 倍"（我复算 64,000÷256=250，一致）。

| 架构 | 结果 |
| --- | --- |
| Gated DeltaNet 与 hybrid | 在前三级上泛化几乎完美，能撑到数万次赋值 |
| Transformer | 学得会较简单的级别，长序列上退化；**最难一级始终学不会** |

博客的解读是：对 Gated DeltaNet 与 hybrid 来说，预训练与直接训练之间的差距指向训练不足；而对 transformer 来说，那是架构的限制。

顺带说一句预训练模型的设置：被测的开源预训练模型包括两个 70 亿参数模型（一个纯 transformer，一个是加了 Gated DeltaNet 层的 hybrid），以及 2.75 亿与 27 亿的较小模型；它们用同一批数据预训练，训练时都没见过超过 64,000 token 的上下文，而测试时多数模型被喂了远超这个长度的输入。另外博客说明：这批预训练模型只测了 r-trivial、aperiodic、general finite 三级，没有测 soluble。

## 四、为什么"记得住"不等于"跟得住"

把上面的发现合起来，可以给出一条对工程有用的区分：

| 能力 | 表现 | 常见误解 |
| --- | --- | --- |
| 检索 | 能在长文里找到某句话 | 找到了就等于理解了它的后果 |
| 状态跟踪 | 能按时间顺序推出"现在是什么" | 上下文装得下就能推对 |

第二行的误解特别常见，因为两者在短输入上几乎无法区分：一份 5 页的材料里，找到那句和推出结果都毫无难度。差异只在长度拉开、变更次数变多之后才显现。

而实际任务里，长度和变更次数往往同时增长——一份 200 页的合同，修订次数可能几十处。

## 五、这个基准还没覆盖什么

博客列出的开放问题里有两条对使用者有直接意义：

1. **变量数量是固定的。** 现实任务里会出现新实体：一段长对话里不断有新的人、新的物件出现，模型得从出现那一刻开始跟踪。当前框架没有覆盖这个设定。
2. **部分理论位置未定。** 博客提到一项新证明关于某种受限内存更新的能力边界，但精确归属仍是开放问题。

第一条尤其值得记住：**你在真实场景里遇到的，往往比基准更麻烦。** 基准给出的分数是下限性质的信息，不是上限。

## 六、这对你的长文档任务意味着什么

| 你的任务 | 对应级别 | 需要警惕的 |
| --- | --- | --- |
| 从材料里找一条事实 | 接近检索 | 基本不受状态跟踪影响 |
| 读代码答"这个变量最后是几" | Aperiodic | 变更多、长度长时会掉 |
| 跟进累加与计数器逻辑 | Soluble | 漏一步就错，且错得安静 |
| 追一条跨对象的依赖链（谁把谁的东西给了谁） | General finite | 前沿模型在最难情形下准确率很低 |

最后一行不是危言耸听：博客给的数字是"最长问题上 13% 或更低"。这意味着在这类问题上，模型的答案**不能单独作为结论使用**，必须配可核对的中间状态。

### 三个问题快速定级

下面这套问法是我根据四级定义拟的，不是博客提供的方法。不必读论文，三个问题就能大致判断你的任务落在哪一级：

1. **同一个量会不会被改写？** 不会（例如查一条固定事实）→ 接近检索，第一级。
2. **改写是"覆盖成新值"，还是"基于当前值继续算"？** 覆盖 → 第二级；累加、自增、状态机转移 → 第三级。
3. **会不会出现"A 取 B 的当前值"这种跨对象依赖？** 会（物品易手、变量交换、主体变更）→ 第四级。

三题都答"不会"的任务，长上下文基本够用；只要第三题答"会"，就该假设模型会错，并提前准备核对手段。

这个定级的意义在于：它决定了你该花力气在"换模型"还是"加外部状态"。第四级的问题，换更强的模型只能改善概率，不能消除失败。

## 七、工程上的三个补救方向

以下是我的建议，不是博客的结论：

1. **把状态搬到外面。** 与其让模型在长文里自己跟踪，不如让程序维护一张状态表，每次变更后更新表、把表发给模型。表是确定性的，模型只负责解释。
2. **分段并显式交接。** 把长材料切成段，每段处理完输出"当前状态摘要"，下一段以这份摘要为起点，而不是重新读全文。
3. **要求引用中间步骤。** 让它给出"第几步改变了什么"再给结论。这样错在哪一步可以被发现，而不是只有一个错答案。

第三条的代价是输出变长、成本上升，但它把"可验证性"换回来了。

## 八、限制与结论

StateBench 的价值在于把"长上下文里的状态跟踪"拆成四级，并给出两组容易被忽略的发现：前沿模型在较难级别上随长度急剧退化；而在 2.75 亿参数的 hybrid 与 Gated DeltaNet 上，同一道 r-trivial 题换表述形式，结果可能从接近满分掉到接近随机。

本文的限制：没有运行该基准，所有数字来自官方博客；四级难度的理论背景只按原文说明，我未读技术报告；"250 倍"是博客原文的说法，我复算过；第七节的补救方向是我的建议，未经验证；基准的变量数固定这一限制意味着真实场景可能更难。

下一步建议：先判断你手上的任务属于哪一级。如果是第三、第四级，不要先比较模型，先加一层外部状态表——那比换模型更可能解决问题。
