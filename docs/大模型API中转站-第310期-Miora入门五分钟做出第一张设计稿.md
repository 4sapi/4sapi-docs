# Miora 如何从一个 brief 开始完成首张设计稿
第一次使用 Miora 时，界面里的模型、画布和素材选项很容易让人跳过最重要的 brief。本文从一个小任务开始，逐步完成注册、场景选择、需求描述、首张设计稿和人工验收，说明哪些信息必须写清楚，哪些视觉结果需要继续迭代。文中只讨论可复现的步骤，不把单次结果扩展成产品承诺；每个结论都标注前提、证据和无法覆盖的边界。读者可以先完成最小验证，再按自己的版本、权限和数据补充实验。


如果你第一次打开 AI 设计工具，最容易遇到的不是不会生成，而是不知道从哪里开始。

输入框里只写一句“做一张好看的海报”，出来的东西往往只能看一眼。换个主题，风格就漂了；想改一个字，整张图又重新抽；想做一套品牌物料，还得在生图、视频、排版和 3D 工具之间来回切换。

腾讯的 Miora 解决思路不太一样。

它把自己定位为 `The Agentic Creative Studio`，也就是智能体创意工作室。你给它一个创意 brief，它会先理解目标，再调用不同的创意专家，把图像、视频、3D、UI 和文字资产放到同一张画布上继续修改。它最值得单独学习的地方，是 Agent Memory：它可以把你的品牌色、排版习惯、禁用项和创作规则沉淀下来。

这篇不是把官网按钮逐个翻译一遍，而是按“第一次打开 Miora，我建议你怎么用”的顺序，跑通一个完整任务。

项目入口：[Miora](https://miora.design/)

官网当前公开定位包含四个关键词：Agent Memory、Creative Specialists、Skills + Community，以及从 brief 到 delivery 的完整创意流程。注册福利、模型列表、积分和具体场景会随产品运营变化，以下涉及活动的地方以当前页面实际显示为准。

## 一、Miora 到底是什么

先用一句话理解：Miora 不是一个只负责“抽一张图”的输入框，而是一张可以持续工作的 AI 创意画布。

它大致由四部分组成：

~~~text
Agent：理解你的目标，拆解任务，组织创作流程
Specialists：分别负责品牌、插画、分镜、UI/UX、视频、3D 等领域
Canvas：承载图片、视频、3D、界面和文字节点的工作台
Memory / Skills：保存你的风格规则和可重复的工作流
~~~

普通生图工具的流程通常是：

~~~text
输入 Prompt -> 选择模型 -> 生成一张图 -> 下载
~~~

Miora 更接近：

~~~text
描述目标 -> Agent 拆任务 -> Specialists 执行 -> 画布组织资产
       -> 局部修改 -> 记住稳定规则 -> 复用成下一次项目
~~~

这并不代表它在每一个单点模型的画质、视频时长或 3D 精度上都一定胜过专业工具。Miora 的优势更像是“把一段创意流程串起来”，尤其适合需要多种物料、风格一致和持续修改的任务。

## 二、第一次打开先看懂四个入口

登录后，左侧导航通常可以看到四个主要入口。不同版本的页面名称和布局可能会调整，但功能逻辑基本可以这样理解。

### 1. Creation，真正开始创作

这是你提交 brief、选择场景和启动任务的地方。不要把它当成普通聊天框，因为你选的场景会影响 Agent 采用哪一套工作流。

常见场景包括：

- 品牌设计：Logo、品牌视觉、IP 形象、VI 全案。
- 影视创意：分镜、概念图、宣传视觉。
- 电商广告：主图、海报、卖点图和活动物料。
- 互动游戏：角色、世界观、卡牌和游戏视觉。
- 网页应用：网页、App 界面和落地页原型。

### 2. Inspiration，解决“我不知道怎么写”

灵感库里通常会展示社区案例。看到合适的案例后，可以使用它的提示词，再根据自己的品牌、用途和素材修改。

对新手来说，这个入口的价值不只是找灵感，而是观察一条完整需求是怎样写出来的。先拆解别人的目标、风格和交付物，再把模板换成自己的任务，比对着空白输入框硬想有效得多。

### 3. Skills，把一次流程变成可复用资产

Skill 不是一句 Prompt，而是一套可重复的工作流。

比如品牌视觉 Skill 可能包含：

~~~text
确定品牌定位
  -> 生成 Logo 方向
  -> 建立主色和辅助色
  -> 设计应用场景
  -> 生成社交媒体和宣传物料
~~~

你跑通一套流程后，可以把它保存下来，下一次直接复用。第312期会具体讲 Skills 和团队协作。

### 4. Memory，管理它对你的长期理解

Memory 是 Miora 和一次性生图工具拉开差异的地方。它不是只记住某张临时图片，而是尝试保存你稳定的创作规则，例如：

- 主色和辅助色。
- 标题、留白和构图习惯。
- 品牌语气和视觉气质。
- 不希望出现的风格、元素和装饰。
- 某个项目长期沿用的视觉设定。

不要把 Memory 当成无需检查的黑箱。后面的文章会专门说明为什么要查看、编辑和测试记忆。

## 三、第一条需求不要只写“做得好看”

AI 设计工具的结果上限，往往先被 brief 的清晰度限制。

一个可用的需求至少回答六个问题：

| 信息 | 需要说明什么 | 示例 |
| --- | --- | --- |
| 目标 | 要做什么资产 | 一张品牌开业海报 |
| 对象 | 给谁看 | 城市白领和周末消费者 |
| 用途 | 发布在哪里 | 小红书、公众号和门店海报 |
| 风格 | 希望呈现什么感觉 | 极简、温暖、现代 |
| 约束 | 哪些东西不要出现 | 不要霓虹、不要复杂贴纸 |
| 交付 | 需要哪些尺寸或变体 | 横版头图、竖版海报、方形封面 |

可以直接套用这个模板：

~~~text
我在做一个[品牌/产品/活动]的视觉设计。

目标：请帮我完成[具体任务]。
受众：主要给[目标人群]使用。
用途：会发布在[平台/场景]。
需要的资产：[列出图片、视频、Logo、UI 或尺寸]。
风格：希望整体是[风格关键词]，画面感觉[补充形容]。
限制：不要出现[禁用颜色、元素、字体或视觉风格]。
请先给我 2 到 3 个方向，确认后再继续完整制作。
~~~

例如，不要只写：

~~~text
做个咖啡品牌 Logo。
~~~

可以写成：

~~~text
我在做一个植物基轻食外卖品牌的视觉。
先给我 3 个 Logo 方向，再根据选定方向生成一套基础品牌视觉。
目标用户是 20 到 35 岁、关注健康和效率的城市白领。
主色偏米白、深绿和浅棕，整体干净、现代、有一点自然感。
需要后续用于微信公众号、小红书和外卖包装。
不要复杂插画、不要廉价渐变、不要过多装饰。
请先说明每个方向的设计逻辑，不要直接铺满所有物料。
~~~

如果你不擅长把口语整理成设计需求，可以使用对话框附近的“增强提示词”能力，把大白话先整理成结构化指令，再检查它有没有改变你的真实目标。

## 四、五分钟跑通第一个任务

下面以“植物基轻食品牌开业海报”为例。第一次不要挑战完整 VI，也不要同时要求海报、视频、3D 店铺和 App 全部完成。先把一张可用海报跑通。

### 第一分钟：选择场景

进入 Creation 后，选择“品牌设计”或“电商广告”这类接近目标的场景。

选场景不是为了给作品加标签，而是告诉 Agent：

~~~text
这次是品牌资产，不是随机插画
这次需要考虑传播和版式，不只是画面
这次可能会有文案、Logo 和后续物料
~~~

如果选择完全不相关的场景，Agent 可能会采用不适合你交付目标的拆解方式。发现方向不对时，重新开一个正确场景，往往比在错误流程里不断补 Prompt 更快。

### 第二分钟：写清楚 brief

把上一节的例子粘进去，再补充开业时间、文案、尺寸和必须出现的元素：

~~~text
请为“青芽轻食”做一张开业海报。
主文案是“开业第一周半价”，副文案是“植物基轻食，十分钟吃得更轻松”。
画面用于小红书竖版发布，也要能裁切成门店立牌。
主色是米白、深绿和浅棕，整体极简、清爽、留白充足。
标题要大、清晰、居中，品牌名不要被装饰遮挡。
不要霓虹、不要二次元、不要复杂食物堆叠、不要难以识别的小字。
请先给出两个构图方向，说明各自适合的传播场景。
~~~

“先给方向”很重要。第一次就让系统直接生成全部物料，你很难知道是策略错了还是执行错了。

### 第三分钟：选择 Agent 档位

素材中的当前配置可以这样理解：

| 档位 | 适合任务 | 新手建议 |
| --- | --- | --- |
| Standard | 单张图、改一段文字、简单小调整 | 任务很简单时使用 |
| Pro | 日常品牌、电商和社交媒体任务 | 默认优先选择 |
| Max | 多步骤全案、复杂品牌系统和大量资产 | 需求已经说清楚再使用 |

第一次建议选 Pro。它通常能覆盖大部分日常任务，也能让你先理解工作流，而不是一上来把积分消耗在不确定的复杂任务上。

执行模式可以先选 Ask。Ask 会在真正执行前确认方向，适合你还在判断方案的时候；自动执行适合已经明确 brief、想连续推进的任务。

### 第四分钟：让它生成并观察拆解

不要只看最终图片，还要看 Agent 是怎样拆任务的：

~~~text
是否先理解了受众和用途？
是否保留了品牌名和主文案？
是否把竖版海报和门店立牌的关系说清楚？
是否提出了两个可比较的方向？
是否擅自增加了你禁止的元素？
~~~

如果方向不对，不要马上写一大段新的 Prompt。先明确指出一件事：

~~~text
保留第一个方向的构图，不要更换整体风格。
请把标题区域增加 20% 的留白，并让“开业第一周半价”成为唯一视觉焦点。
其他元素先不动。
~~~

这样更容易判断修改是否生效。

### 第五分钟：在画布上继续改

生成结果会进入画布。画布不是只用来展示图片的预览区，它是后续工作的主要位置。

在画布上，你可以把图像、视频、3D、UI 和文字作为节点组织起来，拖动位置、建立关系、继续描述修改方向。对于多资产任务，画布能让你看到：

- 哪个节点是原始方向。
- 哪个节点是修改版本。
- 哪些资产来自同一套品牌规则。
- 哪张图是主视觉，哪些是衍生物料。

如果你只在对话里来回发指令，容易忘记每一版的差异；把结果放在画布上，创作过程会更接近一个可回看的设计工作台。

## 五、局部编辑要说清楚“只改哪里”

AI 设计中最浪费时间的情况，是你只想改标题，系统却把背景、人物和色彩全部换了。

Miora 的画布支持圈选、框选或标记区域，再用自然语言说明修改对象。修改指令最好同时包含三件事：

~~~text
目标区域：我指的是哪一个位置
修改动作：要改什么内容
保持不变：其他哪些元素不能动
~~~

例如：

~~~text
只修改画面上方的标题文字为“开业第一周半价”。
保持背景、主色、Logo 位置、人物和食物图片不变。
文字要清晰可读，不要增加新的装饰。
~~~

再比如修改画面关系：

~~~text
黄色标记线是蝴蝶的飞行路径。
请让蝴蝶沿着这条路径移动，保持主体大小和背景光线不变。
~~~

你还可以把局部编辑用于：

- 擦除不需要的元素。
- 去除背景或替换背景。
- 调整局部打光和角度。
- 扩展画布边缘。
- 把几张图统一成同一尺寸。
- 放大已经确认的局部细节。

“只改这块，其他全部不动”不是多余的话，而是给 Agent 划定修改边界。对于有品牌规范的团队，这种边界描述还可以后续沉淀成 Memory。

## 六、模型怎么选，先别被模型名带着跑

Miora 的底部配置通常有两层：

第一层是 Agent 底模，也就是负责理解需求、拆任务和调度专家的“大脑”；第二层是生成模型，也就是实际负责图像、视频、3D 或 UI 的执行层。

两者不要混淆：

~~~text
Agent 底模决定：理解、规划、分工和迭代
生成模型决定：具体资产的视觉或多模态执行
~~~

素材中提到的当前模型选项包括图像、视频和 3D 等不同专家模块。模型列表和价格会变化，实际使用时建议先看页面显示的积分或费用，再决定是否自动选择。

新手的起步配置可以是：

~~~text
场景：品牌设计或电商广告
Agent：Pro
生成模型：自动
执行模式：Ask
第一个任务：单张海报或封面
~~~

当你已经知道自己需要什么，再逐步尝试指定模型。不要用一次失败就判断整个产品，也不要把某个模型的一次好结果当成稳定生产能力。先用固定 brief 做三次对照，记录质量、速度和积分消耗，再决定默认模型。

## 七、上游 API 在企业创意流程里的位置

如果只是个人在 Miora 页面里做设计，先使用站内提供的模型和积分体系即可。

企业通常还会有另一条链路：品牌团队在 Miora 里探索方向，产品、运营和 Agent 系统需要把同一套视觉规则接到自己的业务里。这时 上游 API 可以作为企业级大模型接入的统一入口，把图像理解、文案生成、Embedding、视频脚本和客服/知识库等模型调用放进同一套 API 网关治理。

典型架构是：

~~~text
Miora：创意探索、画布协作、方案确认
    -> 导出已确认的品牌规则和资产
企业应用 / Agent / 内容流水线
    -> 上游 API 企业API网关
    -> 图像、文本、Embedding、视频等模型
    -> 统一 Key、路由、预算、日志和失败告警
~~~

需要注意的是，不能因为 Miora 页面有模型选择，就直接推断它支持把任意 上游 API endpoint 填进去。上游 API 的营销重点应该放在企业自有应用和工作流的多模型统一接入：Miora 负责前端创作体验，上游 API 负责企业 API 入口和后续生产链路的成本治理。

## 八、第一次使用的安全和成本边界

### 1. 不要把积分当成无限试用

注册赠送的积分或当前活动会变化。第一次体验时，不要直接上传一整套客户素材或高分辨率批量任务。用一张公开或脱敏素材验证：

- 生成质量是否符合预期。
- 局部修改是否真的只影响目标区域。
- 导出格式和尺寸是否满足用途。
- 一次完整任务消耗多少积分。
- 失败重试是否会再次计费。

### 2. 企业素材先分级

合同、未发布产品、客户肖像、内部品牌手册和营销计划，不要在没有确认数据处理条款前直接上传。即便工具能理解画布，也不代表企业可以绕过数据分类和合规审批。

### 3. 生成结果仍要人工验收

重点检查文字、Logo、人物手指、产品结构、价格、尺寸和版权风险。AI 生成的视觉资产适合加速探索和制作，不代表自动获得商用权利，也不代表每一个文字和产品细节都准确。

## 九、第一次上手验收清单

### 操作验收

- [ ] 能打开 [Miora](https://miora.design/) 并完成登录。
- [ ] 能在 Creation 中选择品牌设计或电商广告场景。
- [ ] 能写清目标、受众、用途、风格、限制和交付物。
- [ ] 能用 Ask 模式先确认方向，再执行生成。
- [ ] 能在画布上找到生成结果并继续发起修改。
- [ ] 能用圈选或框选只修改一个区域。

### 质量验收

- [ ] 第一张作品的标题、Logo 和关键文案可读。
- [ ] 修改局部时，背景、配色和主体没有无故漂移。
- [ ] 同一个任务至少保留两个方向，能说清取舍原因。
- [ ] 已记录本次任务的积分、耗时和失败重试次数。

### 企业验收

- [ ] 未上传未经授权的敏感客户资料。
- [ ] 站内模型能力和价格以当前页面为准，没有把宣传语当成 SLA。
- [ ] 后续生产工作流需要统一模型时，已评估用 上游 API 做企业 API 网关和成本治理。
- [ ] 导出的品牌规则、资产和后续模型调用都有版本与权限记录。

## 总结

第一次使用 Miora，不要把目标定成“让它替我完成整个品牌”。更有效的路径是：

~~~text
选对场景
  -> 写清 brief
  -> 用 Pro + Ask 先确认方向
  -> 在画布上完成一张小作品
  -> 用局部编辑修正细节
  -> 记录哪些规则值得长期保留
~~~

Miora 最适合的不是一次性抽卡，而是让创意从一张图逐渐变成一套可以继续迭代的资产。下一篇我们专门讲它最有辨识度的能力：Memory 如何把“我喜欢高级感”变成真正可执行的设计规则。

如果你要把 Miora 里确认的创意继续接到企业内容生产、Agent 或 SaaS 产品里，上游 API 可以作为后续多模型统一接入、Key 权限管理、调用追踪和成本治理的基础设施。
