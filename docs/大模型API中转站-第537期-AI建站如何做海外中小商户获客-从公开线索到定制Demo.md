# AI 建站如何做海外中小商户获客：从公开线索到定制 Demo

分类：AI 应用、独立开发、出海实践

标签：#AI建站 #客户开发 #独立开发者

摘要：AI 建站降低了制作网站的时间，但不会自动带来客户。本文围绕一个具体问题展开：个人开发者如何利用公开商业信息，筛选有明确网站需求的海外中小商户，制作可验证的定制 Demo，并用合规、低打扰的方式完成第一次触达。

## 开头：不要从“我会做网站”开始

很多建站服务的第一封开发信，开头都是“我们可以帮你做一个现代化网站”。

这句话的问题是，客户没有理由相信你，也没有理由现在回复。

更有效的切入点通常是一个可以被观察的问题：

- 手机上的导航是否难以使用。
- 联系方式是否藏在多层菜单里。
- 预约入口是否无法在移动端完成。
- 旧网站是否没有清楚展示服务范围。
- 广告或社交主页是否把用户带到一个失效页面。

AI 的作用，是把“发现问题、制作演示、整理沟通材料”这条链路压缩得更短。

它不是替你发明客户需求，也不是自动获得客户授权。

本文只解决一个独立问题：如何从公开商业线索出发，做一份不夸大、不冒充、不侵犯隐私的定制网站 Demo。

## 一、先定义理想客户画像

不要一开始就搜索“所有海外商家”。

先写一张理想客户画像：

| 维度 | 示例 | 说明 |
| --- | --- | --- |
| 地区 | 某个城市或州 | 控制样本规模 |
| 行业 | 汽车美容、牙科、家政 | 便于复用页面结构 |
| 规模 | 1 至 20 人团队 | 预算和决策链相对短 |
| 公开信号 | 营业中、评价持续更新 | 排除长期停业商家 |
| 网站问题 | 无官网、移动端体验差 | 定义改造价值 |
| 联系方式 | 商家公开邮箱或联系表单 | 确保触达合规 |

画像越窄，Demo 越容易做得具体。

## 二、只使用必要的公开信息

线索收集应围绕商业判断，而不是围绕“能挖出多少个人资料”。

建议保留这些字段：

1. 商家名称。
2. 官方网站或公开商家页面。
3. 服务类别。
4. 营业地点或服务区域。
5. 公开的通用联系入口。
6. 网站问题的客观描述。
7. 公开页面链接和检查时间。

不建议收集店主个人主页、家庭信息、私人号码或与业务无关的社交关系。

如果商家只提供联系表单，就使用联系表单。

不要把公开可见理解成可以无限制复制和再利用。

不同平台的服务条款、隐私政策和当地法律可能对自动抓取、批量联系和数据保存有额外要求。

## 三、给线索打分，而不是凭感觉筛选

可以使用一个简单的五项评分表，每项 0 到 2 分：

| 评分项 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 网站可用性 | 正常 | 有小问题 | 明显不可用 |
| 移动端体验 | 正常 | 局部拥挤 | 关键流程无法完成 |
| 服务展示 | 清晰 | 不完整 | 无法判断卖什么 |
| 转化入口 | 清晰 | 需要寻找 | 没有预约或联系入口 |
| 更新状态 | 持续更新 | 不确定 | 明显过期 |

总分达到 6 分以上，才值得制作 Demo。

评分必须附证据，不要只写“网站很旧”。

可以记录：

```text
检查页面：https://example.com
检查时间：2026-09-28
问题：移动端首屏横向溢出，预约按钮在 390px 宽度下不可见
证据：截图或录屏文件名
```

## 四、制作 Demo 前先写内容合同

AI 建站最容易出问题的地方，不是代码，而是内容胡编。

制作前先列出内容合同：

- 哪些信息来自商家公开页面。
- 哪些文案是通用占位符。
- 哪些图片可以使用。
- 哪些评价只能引用原文，不能改写成夸张承诺。
- 哪些字段必须由客户确认。

如果没有获得授权，不要把商家的商标、客户评价、员工照片或第三方图片直接用于公开发布。

Demo 可以使用“仅供预览”的标识、占位图片和待确认文案。

这样既能展示设计能力，也不会让收件人误以为你已经代表其品牌上线了网站。

## 五、一个十分钟 Demo 的最小结构

针对本地服务商家，Demo 不需要堆很多页面。

一个可验收的最小版本通常包括：

1. 首屏：服务类型、服务区域和一个主要行动按钮。
2. 服务卡片：列出 3 至 5 个核心服务。
3. 信任区：只放经授权或明确标注来源的内容。
4. 流程区：说明预约、咨询或上门服务流程。
5. FAQ：回答价格范围、营业时间、服务区域等常见问题。
6. 联系区：使用官方邮箱、电话或联系表单。
7. 移动端布局：至少检查 320px、390px 和 768px 宽度。

页面的目标不是展示你会多少技术，而是让商家一眼看到一个具体改进。

## 六、让 AI 编程工具按验收条件工作

给 AI 的任务不要写成“做一个漂亮网站”。

可以改成下面这种形式：

```text
为一家本地汽车美容店制作一个静态 Demo。

输入：商家公开服务列表、服务区域、公开联系方式。
限制：不新增未提供的价格、评价、认证和客户案例。
页面：首页、服务区、流程区、FAQ、联系区。
响应式：320px、390px、768px、1440px。
验收：移动端无横向滚动；主要按钮在首屏可见；表单字段不超过 5 个；
所有事实文案附来源或标记为待确认。
输出：源代码、截图、待确认内容清单。
```

如果使用 Codex、Claude Code 或其他编码 Agent，建议让它先输出内容清单，再生成页面。

先锁定事实，能减少返工。

## 七、Demo 的验证清单

发送给客户前，至少检查以下项目：

- 页面标题和商家名称没有拼写错误。
- 电话、邮箱、地址和营业时间来自公开来源。
- 所有图片有明确授权或使用许可。
- 移动端没有横向滚动。
- 预约按钮不会提交到真实生产系统。
- 表单不会收集不必要的敏感信息。
- 代码中没有硬编码密钥。
- 页面加载失败时有清晰提示。
- Demo 链接不会暴露目录列表或调试信息。

可以把“待客户确认”的内容单独列在页面底部，而不是藏在代码里。

## 八、第一封邮件怎么写

冷邮件的目标不是一次成交，而是确认对方是否愿意看 Demo。

邮件应短、具体、可退出。

一个可改写的结构如下：

```text
Subject: A small mobile website idea for [Business Name]

Hi [Name],

I was looking at [public page] and noticed one small mobile usability issue:
[one factual observation].

I made a private preview to show one possible fix:
[demo link]

It is only a concept, and I have not published or connected it to your systems.
If this is not relevant, no reply is needed. If you would like to discuss it,
I can send a short scope and fixed estimate.

Best,
[Name]
```

不要声称“你的转化率会提高多少”。

不要伪装成平台官方、现有供应商或商家客户。

不要在没有授权的情况下把 Demo 发布成正式网站。

## 九、发送节奏和退出机制

一次只联系少量、经过人工核验的商家。

建立退订和停止联系的记录。

如果收件人表示不感兴趣，就停止发送。

如果邮箱退信或平台提示投诉风险，就暂停该批次，检查来源和模板。

不要通过更换域名、变体拼写或多个账号规避平台限制。

这不是效率问题，而是信誉和合规问题。

## 十、如何判断这条路径是否值得继续

不要只看发送数量。

建议记录：

| 指标 | 含义 |
| --- | --- |
| 有效线索率 | 通过人工核验且存在明确网站问题的比例 |
| Demo 完成率 | 从线索到可预览页面的时间和成功率 |
| 正向回复率 | 收到具体反馈的比例 |
| 会议转化率 | 愿意进一步沟通的比例 |
| 返工时长 | 每个 Demo 的平均修改时间 |
| 交付毛利 | 收入扣除工具、人工和维护成本后的结果 |

如果 Demo 很快，但后续沟通几乎没有回应，问题可能不在建站速度，而在客户选择和价值表达。

## 十一、常见反例

### 反例一：把所有行业套同一个模板

牙科、汽车美容和屋顶维修的决策信息完全不同。

模板可以复用，但首屏信息、案例结构和预约流程必须贴近行业。

### 反例二：拿客户的好评改写成营销承诺

评价是第三方内容，不应被改成“保证效果”或“本地第一”。

保留原意，标注来源，并让客户确认是否允许展示。

### 反例三：先建站，再问对方是否需要

先做一个轻量 Demo 没问题，但不要投入数小时制作完整站点。

先用评分表确认需求信号，再决定投入深度。

## 结尾：AI 降低的是制作成本，不是信任成本

AI 建站确实能把页面制作压缩到更短时间，但客户最终购买的是清晰的问题判断、可信的内容和可维护的交付。

一条稳妥的路径是：只用必要的公开商业信息，先记录客观问题，再做带边界的定制 Demo，最后用低打扰的方式触达。

当对方确认需求后，再讨论域名、部署、表单、分析和维护。

这比批量抓取个人资料、复制竞品素材或承诺“几乎零成本获客”更慢一点，但更容易形成长期可交付的服务。
