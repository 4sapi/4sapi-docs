# 用任务交接包在新会话中继续长任务

软件开发、研究和长文写作可能跨越多个会话。把完整聊天复制到新窗口，会把错误答案、废弃方案和无关工具输出一起迁移；只写一段摘要，又容易丢失文件位置、测试结果、禁止事项和下一步。本文只解决会话接力：旧会话生成结构化任务交接包，人核对事实与状态；新会话先复述目标、指出矛盾并验证关键资料，再执行一个明确动作。涉及发送、删除或生产变更时，还要记录操作状态，防止换会话后重复执行。

## 1. 交接包保存工作状态，不保存全部聊天

普通聊天摘要回答“讨论过什么”，任务交接包回答“下一步如何继续”。它只保留会影响后续工作的内容：

```text
最终目标和当前范围。
当前阶段与已完成结果。
已确认事实及来源。
关键决策及理由。
待核实内容和已否决方案。
未完成任务与依赖。
文件、资料和验证索引。
禁止事项与授权边界。
下一步动作和验收标准。
```

旧会话原文仍可保留用于追溯，但不应默认进入新上下文。

## 2. 区分完成、待验证和推测

交接最常见的错误是把“模型说已修复”写入已完成。状态至少分为：

```text
已完成：存在文件、命令输出或人工检查证据。
待验证：工作已执行，但没有取得要求的验证结果。
待处理：尚未开始或明确未完成。
推测：可能的解释，尚无证据。
阻塞：缺少权限、资料或外部状态。
```

每个“已完成”项应附证据位置，例如文件路径、测试命令与实际结果、审核记录或来源链接。没有证据就不能升级状态。

## 3. 可直接使用的交接模板

```text
# 任务目标
[最终交付物与范围]

# 当前状态
[所处阶段，以及为什么停在这里]

# 已确认事实
- [事实]；依据：[文件、输出或来源]

# 待核实与推测
- [内容]；需要：[验证方法]

# 关键决策
- [决定]；理由：[证据与取舍]

# 已完成
- [结果]；证据：[路径、命令和输出]

# 未完成与阻塞
- [动作]；依赖：[前置条件]

# 已否决方案
- [方案]；原因：[失败证据或决策]

# 禁止事项与授权边界
- [不得执行或需要确认的操作]

# 资料索引
- [路径或链接]；用途：[为什么需要]

# 下一步
[一个可执行动作]

# 验收标准
[通过、失败和停止条件]
```

路径、命令、数字和引用只能从现有材料原样提取。模型无法核对的内容要放入待验证，不要补全。

## 4. 关闭旧会话前先人工检查

至少检查：

```text
目标和范围是否仍然有效。
已完成项是否都有证据。
测试结果是否来自当前代码或数据版本。
错误事实和废弃方案是否明确标出。
下一步是否依赖缺失权限或资料。
敏感信息是否不应进入新会话。
```

交接包是派生文档，不是新的事实来源。发现它与原文件、日志或用户决定冲突时，以可验证的一手材料为准并修正交接包。

## 5. 新会话先做接收验收

不要粘贴后只说“继续”。可以使用：

```text
下面是上一会话的任务交接包。

执行前：
1. 复述当前目标、范围、状态和下一步。
2. 列出交接包中的矛盾、缺失信息与无法验证项。
3. 核对下一步依赖的文件和当前工作区状态。
4. 不要把待验证内容当成事实，也不要扩大范围。
5. 完成检查后只执行交接包中的下一步。

[交接包]
```

若代码、文档或外部数据在会话之间发生变化，先更新状态；不要强行沿用已经过期的测试和结论。

## 6. 不同任务需要不同证据

### 编程任务

记录仓库、分支、工作区改动、复现步骤、实际测试命令和结果，以及不可破坏的接口。不要只写“测试通过”，要写运行了什么和结果是什么。

### 研究任务

记录研究问题、资料时间范围、事实来源、冲突材料和待核实结论。来源文章的观点不能自动升级为已确认事实。

### 写作任务

记录读者问题、核心主张、章节状态、已用案例、引用来源和禁止重复的表达。草稿用文件路径索引，不必全部塞入交接包。

### 自动化任务

记录工具调用、外部写入、重试和人工审批状态。尤其要区分“准备发送”“已发送”和“发送失败”，避免新会话重复操作。

## 7. 为外部操作设置幂等标识

会话切换可能发生在任务执行中途。对于发送消息、创建工单、付款、删除和生产变更，交接包需要记录：

```text
操作目标和业务标识。
请求是否已经提交。
外部系统返回的状态或编号。
是否允许重试。
重试前需要核对什么。
人工批准人或批准状态。
```

没有外部证据时，不要假设操作成功，也不要自动重试。先查询当前状态，确认不会重复执行后再决定。

## 8. 用文件保存长期状态

小型项目可以维护：

```text
PROJECT.md：目标、范围和长期约束。
STATUS.md：当前阶段、已完成、未完成和下一步。
DECISIONS.md：关键决策、理由与替代方案。
```

文件名不是强制标准，可以沿用仓库已有约定。新会话只加载当前任务需要的片段；状态更新必须基于实际修改和验证，而不是从聊天语气推断。

## 9. 结论与限制

可靠的会话连续性来自结构化状态，而不是无限历史。旧会话负责整理目标、证据、决策和未完成项；人负责核对；新会话先验收交接，再执行一个具体步骤。这样能减少错误前提和无关上下文被继续放大。

交接包不能替代源码、原始资料、测试输出和外部系统状态。它也可能过期或总结错误；高风险信息必须在新会话重新核对，外部操作必须通过业务标识和实际状态防止重复执行。
