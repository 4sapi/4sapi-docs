# Vibe Coding 导航怎么设计：让用户知道在哪里

很多人让 Agent 做网页时，会在提示词末尾补一句：“顶部加一个漂亮的导航栏。”结果往往是 Logo、几个文字链接和一个菜单按钮被排在一行，看起来像导航，实际却没有回答用户最关心的几个问题：我现在在哪一层？还能去哪里？刚才打开的菜单怎么关？刷新页面后当前位置还在不在？

导航不是页面上的一条装饰线，而是一套帮助用户定位、切换和返回的方向系统。它至少要处理四种关系：全局页面之间怎么走，当前页面内部怎么跳，列表内容怎么翻页，以及在小屏幕上如何把同样的路径压缩成可操作的入口。

本文把视觉词典里常见的 10 种导航模式拆开说明，再给出一份可以直接交给 Agent 的实现提示词。重点不在于一次把所有模式都放上页面，而在于根据用户任务选择最少、最清楚的导航层级。

## 1. 先回答三个导航问题

开始写代码前，先把页面路线写成文字。每一个页面或区块至少要回答：

```text
当前位置：用户现在位于哪个页面、哪个分类或哪个步骤？
可去位置：从这里最可能继续访问的三个地方是什么？
返回方式：用户如何回到上一级、首页或刚才的滚动位置？
```

例如一个 AI 工具作品集可以先写成：

```text
全局：Home / Work / Notes / About / Contact
作品集：Work -> Project Detail
详情页内部：Overview -> Problem -> Process -> Outcome
移动端：顶部菜单负责全局，页面内目录负责详情区块
```

这份路线图决定了导航类型。全局页面适合 Navbar，详情页区块适合 Anchor Link，层级关系适合 Breadcrumb，内容很多时再使用 Sidebar。不要因为某个组件流行，就把它放进所有页面。

## 2. Sticky Navbar：让全局入口一直可见

Sticky Navbar 固定在视口顶部或在滚动到顶部后吸附。它适合页面较长、用户经常需要切换全局页面的场景，例如作品集、文档站、产品介绍页和内容站。

### 适合什么

```text
需要频繁跳转到其他一级页面的站点。
页面内容较长，但全局入口不能丢失的站点。
需要在滚动后继续提供主要行动的产品页。
```

### 可复制提示词

```text
创建一个 Sticky Navbar。
左侧放品牌名称，桌面端显示 Work、Notes、About、Contact 四个真实链接。
导航高度稳定，滚动时只改变背景不改变布局高度；当前页面使用 aria-current="page"。
右侧保留一个主要行动按钮和一个主题切换按钮。
小于 760px 时隐藏文字导航，显示可键盘操作的菜单按钮。
不要用绝对定位把导航盖在正文上，页面顶部为导航预留空间。
```

### 验收重点

滚动到页面中段时，导航是否仍可见？导航出现阴影或背景变化时，内容是否发生跳动？当前页是否有文本、颜色之外的可识别状态？链接是否真的指向页面，而不是用点击事件模拟跳转？

固定导航要留意移动端的可视高度。手机浏览器的地址栏会变化，导航不能把首屏主体和关闭按钮压到视口之外；如果导航高度较大，也不要为了“始终可见”牺牲正文阅读空间。

## 3. Hamburger Menu：移动端的压缩入口

Hamburger Menu 适合把桌面端的一组全局链接收进移动端面板。汉堡图标本身不是完整的交互说明，按钮需要有可访问名称，并且要明确打开后的面板范围。

### 一个完整菜单至少有这些状态

```text
closed：按钮显示，正文正常滚动。
open：菜单面板显示，按钮状态变为关闭，背景是否锁定要有明确规则。
focus：打开后焦点进入菜单，键盘可以按顺序访问链接。
escape：按 Esc 关闭菜单，焦点回到打开菜单的按钮。
outside click：点击面板外是否关闭，要与产品风险和表单内容保持一致。
```

### 可复制提示词

```text
为移动端创建一个 Hamburger Menu。
使用 button 作为触发器，提供 aria-label 和 aria-expanded，面板用 aria-controls 关联。
打开后把焦点移动到面板里的第一个可操作元素；按 Esc 关闭并把焦点还给触发按钮。
菜单链接使用真实 href，点击链接后关闭面板并保留目标 URL。
如果锁定背景滚动，要确保菜单内容可以独立滚动，底部不被手机安全区域遮挡。
```

不要只验收“点开后能看见菜单”。需要用 Tab、Shift+Tab、Enter、Space 和 Esc 走完一轮，并检查关闭后焦点有没有跑到页面开头。

## 4. Breadcrumb：说明层级，不是复制标题

Breadcrumb 面包屑适合文档、分类、作品详情和后台页面，用来表达“首页 / 作品 / 项目详情”这样的层级关系。它的价值是帮助用户回到上级，而不是把当前页面标题在顶部再显示一遍。

### 可复制提示词

```text
在项目详情页顶部添加 Breadcrumb：Home / Work / Project Name。
Home 和 Work 使用真实链接，当前项目只显示为文本并标记 aria-current="page"。
桌面端完整显示层级，手机端保留上一级和当前页，过长的项目名使用可读的截断方式。
分隔符只作为视觉装饰，不要让屏幕阅读器重复读出无意义符号。
```

如果页面没有稳定的父子层级，就不要强行制造面包屑。标签筛选、搜索条件和浏览历史不是层级关系，适合用筛选条、返回按钮或搜索结果状态来表达。

## 5. Anchor Link：让长页面可以被定位

Anchor Link 页面内锚点适合长文档、案例研究、产品说明和政策页面。它解决的是“我想直接去某个区块”，不是“我想切换到另一个页面”。

### 设计要点

```text
每个目标区块有稳定且有意义的 id。
目录链接使用 href="#section-id"，刷新后 URL 可以复现当前位置。
标题滚动到视口后不被 Sticky Navbar 遮挡。
当前区块可以在目录里显示 active 状态，但不要只靠颜色区分。
手机端目录可以折叠，打开后要有明确的关闭和返回行为。
```

可以用 CSS 处理固定导航遮挡：

```css
section[id] {
  scroll-margin-top: 5rem;
}

@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}
```

`scroll-margin-top` 的具体值要和真实导航高度一致。平滑滚动是增强效果，不应影响键盘用户定位；对减少动态效果的用户，要尊重 `prefers-reduced-motion`。可以参考 MDN 的 [scroll-margin-top](https://developer.mozilla.org/en-US/docs/Web/CSS/scroll-margin-top) 和 [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion) 文档。

## 6. Tabs：切换同一层级的内容

Tabs 适合在同一页面、同一上下文中切换几组互斥内容，例如“概览 / API / 示例”或“月度 / 年度”。它不适合拿来代替全局页面导航，也不适合承载用户必须同时比较的内容。

### Tabs 和导航链接的区别

```text
Tab：切换当前页面的一组面板，通常不离开当前上下文。
Link：前往另一个 URL，可以复制、刷新和分享。
Accordion：展开或收起同一页面中可能同时查看的内容。
```

### 可复制提示词

```text
创建一组可访问 Tabs：Overview、API、Examples。
使用 tablist、tab 和 tabpanel 的语义关系，当前 tab 具有 aria-selected="true"。
左右方向键切换 tab，Tab 键进入当前面板；每个面板有稳定 id，并通过 aria-controls 关联。
移动端允许横向滚动但不能出现页面级横向滚动，或在标签很少时改为下拉选择。
如果切换状态需要被分享，使用 URL 参数恢复当前 tab，并支持浏览器刷新后保持。
```

Tabs 的键盘行为应在实现前确定是自动激活还是手动激活。内容切换很快时可以方向键移动即激活；内容需要加载或计算时，最好让用户按 Enter 或 Space 确认，避免每次移动都触发请求。

## 7. Sidebar Navigation：为深层内容提供地图

Sidebar Navigation 适合文档、管理后台、知识库和多层级作品归档。它要承担分类和层级，不是单纯在左边放一列链接。

### 可复制提示词

```text
创建一个文档站 Sidebar Navigation。
左侧显示 Getting Started、Guides、API Reference、Changelog 四个一级分组。
当前页面高亮，并使用 aria-current="page"；可展开分组使用 aria-expanded 和 aria-controls。
桌面端侧栏宽度稳定，长列表独立滚动；手机端改为顶部“目录”按钮和可关闭 Drawer。
收起侧栏后仍保留可识别的图标和 tooltip，但不能只靠图标判断页面。
```

侧栏固定时要检查正文是否仍有足够阅读宽度。侧栏内的 active 状态、展开状态和页面 URL 要一致；用户刷新或直接打开深层 URL 时，相关父级分组应该自动展开，否则当前页面会被“藏”起来。

## 8. Mega Menu：处理大量的一级入口

Mega Menu 是展开后包含多列分组、说明和精选入口的大型菜单，适合内容多、分类稳定的网站。它不是把普通菜单放大，而是给用户一张更完整的入口地图。

### 适合什么

```text
产品线和解决方案较多的企业站。
文档、资源和案例分组明显的平台站。
分类层级稳定、用户需要先浏览再选择的站点。
```

### 状态要求

```text
closed：只显示一级入口。
open：当前一级入口被标记，面板有明确标题和分组。
focus：焦点能在面板中的链接之间顺序移动。
escape：关闭面板并回到触发入口。
resize：从桌面切到移动端时，不保留溢出的多列面板。
```

不要把所有链接、推广卡片和搜索框都塞进 Mega Menu。列数应服从分类关系，链接标题要能脱离视觉分组独立理解；如果菜单只包含五六个入口，普通 Navbar 更清楚。

## 9. Bottom Navigation：移动端的高频切换

Bottom Navigation 把几个最高频的一级入口放在手机屏幕底部，适合工具型应用、社区和移动后台。它不适合内容详情页里放十几个动作，也不能同时和一个很高的浮动按钮争夺底部空间。

### 可复制提示词

```text
为移动端工具应用创建 Bottom Navigation，包含 Home、Projects、Activity、Settings 四项。
每项使用图标和可见文本，当前项同时有颜色、文本和 aria-current="page" 状态。
底部固定区域适配 env(safe-area-inset-bottom)，不遮挡最后一条内容和表单提交按钮。
桌面端隐藏 Bottom Navigation，恢复顶部或侧边的全局导航。
不要把不常用的操作放进底部栏，也不要用图标替代所有文字。
```

底部导航的最大风险是遮挡内容。验收时把页面滚动到底，打开键盘，进入表单错误状态，再看底部最后一个控件是否仍能看见并操作。

## 10. Pagination：让列表的范围可预测

Pagination 分页适合搜索结果、文章列表、数据表格和目录。它需要表达当前页、总页数或下一步是否存在，不能只放两个没有说明的箭头。

### 可复制提示词

```text
为文章列表添加 Pagination。
显示上一页、当前页、相邻页码和下一页；当前页使用 aria-current="page"。
第一页禁用上一页，最后一页禁用下一页，并提供可读的 aria-label。
页码写入 URL 的 page 参数，刷新和复制链接后能恢复相同列表。
移动端减少页码数量，保留上一页、当前页、下一页和总范围说明。
加载期间保持分页区域尺寸稳定，错误时提供重试而不是把分页按钮消失。
```

如果列表适合连续浏览，也可以选择“加载更多”或无限滚动，但要考虑用户是否需要回到固定位置、复制结果链接和使用屏幕阅读器。分页是一种产品决策，不只是把数组切片。

## 11. Back to Top：给长页面一个明确出口

Back to Top 返回顶部按钮适合长文章、案例研究和数据页面。它应该在用户滚动到一定距离后出现，而不是一打开页面就占据注意力。

### 验收重点

```text
页面顶部时按钮隐藏或不可用。
滚动超过阈值后按钮出现，并有可见或屏幕阅读器可读的名称。
点击后焦点和视觉位置都回到顶部，不只改变滚动条。
按钮不会遮挡客服、提交、播放或 Bottom Navigation。
减少动态效果的用户不会被强制播放长距离动画。
```

如果页面很短，Back to Top 只是噪音。对于有目录的长文档，顶部按钮和目录返回入口可以同时存在，但要让两者承担不同任务：一个回到页面起点，一个回到内容层级。

## 12. 用一张状态表验收导航

导航最容易被遗漏的不是默认样式，而是状态。至少为每个组件写出下面这张表：

| 导航模式 | 默认状态 | 交互状态 | 键盘要求 | URL 或层级要求 |
| --- | --- | --- | --- | --- |
| Sticky Navbar | 当前页明确 | 滚动、主题、菜单 | Tab 可到达全部入口 | 真实页面 URL |
| Hamburger | closed | open、focus、close | Enter、Space、Esc | 打开不改变目标页面 |
| Breadcrumb | 当前层级 | 返回上级 | Tab 访问父级链接 | 父子关系稳定 |
| Anchor Link | 目录可见 | active、跳转 | Tab、Enter | hash 可复现位置 |
| Tabs | 一个面板显示 | selected、loading、error | 方向键或确认键 | 必要时使用 query 参数 |
| Sidebar | 当前页高亮 | 分组展开收起 | Tab、Enter、Esc | 深层 URL 能恢复父级 |
| Mega Menu | closed | open、focus | Esc 回到触发器 | 一级分类清楚 |
| Bottom Navigation | 当前项明确 | pressed、disabled | 触摸和键盘均可用 | 一级页面可分享 |
| Pagination | 当前页明确 | loading、error | 页码可到达 | page 参数可复现 |
| Back to Top | 隐藏 | visible、focus | Enter、Space | 焦点回到顶部 |

至少测试四条路径：鼠标路径、触摸路径、纯键盘路径、直接打开深层 URL 的路径。如果只能在默认首页截图里证明“导航存在”，还不能证明它真的工作。

## 13. 一份可直接复制的导航提示词

下面这份提示词适合交给能够读写项目文件、启动开发服务并观察页面的 Agent：

```text
目标：为一个个人 AI 工具作品集设计并实现清晰的响应式导航系统。
用户路径：用户先了解身份，再浏览项目，再进入项目详情，最后发起联系。
全局页面：Home、Work、Notes、About、Contact；详情页有 Overview、Process、Outcome 三个内部区块。

桌面端：使用 Sticky Navbar，显示品牌名称、五个真实页面链接和一个主要行动按钮。
详情页：在正文顶部显示 Breadcrumb，在右侧显示 Anchor Link 目录；目录随滚动更新当前区块。
移动端：全局链接收进 Hamburger Menu，打开后管理焦点，Esc 关闭并恢复触发按钮焦点；详情页目录改为可关闭的 Drawer。
长列表：Work 页面使用 Pagination，当前页写入 page URL 参数；页面较长时提供 Back to Top。

实现约束：
1. 使用语义 HTML 和真实 href，不用 div 模拟所有按钮和链接。
2. 为 current、active、open、close、focus、disabled、loading、error 定义视觉和行为状态。
3. 当前页面使用 aria-current，菜单和折叠区域正确使用 aria-expanded、aria-controls。
4. 键盘可完成全部任务：Tab、Shift+Tab、Enter、Space、方向键和 Esc。
5. 手机宽度至少测试 390px，桌面宽度至少测试 1280px；适配 safe-area，避免横向滚动和底部遮挡。
6. 尊重 prefers-reduced-motion；滚动动画只作为增强，不能阻止定位和阅读。
7. 先输出导航树、状态表和文件修改计划，确认后再实现；完成后启动服务并提供桌面和移动端截图。
8. 根据截图逐项修复重叠、截断、焦点丢失、URL 不可复现和按钮被遮挡的问题。
```

如果项目需要通过 4SAPI 这类可替换模型入口生成第一版文案或检查提示词，先核对当前配置、实际模型清单和调用能力，再把模型输出当作草稿，导航状态仍需在浏览器中逐项验证。

## 14. 常见失败：看起来像导航，实际不能带路

### 只有装饰，没有当前位置

所有链接都是同一种颜色，当前页面没有 `aria-current` 或其他可识别状态，用户只能靠记忆判断自己在哪。修复时先补信息层级，再决定高亮颜色。

### 菜单打开了，但焦点留在背景

键盘用户按 Tab 后继续访问被菜单遮住的正文，按 Esc 也没有回到触发按钮。修复要把打开、关闭、焦点进入和焦点恢复当成一个完整流程。

### 移动端只是缩小桌面导航

五个链接被挤成两行，按钮换行后把首屏推开，或者页面出现横向滚动。移动端需要重新选择入口和优先级，而不是只降低字体。

### URL 无法复现状态

Tabs、筛选、分页和详情区块只存在于内存里，刷新后全部回到默认值。对于用户需要分享、返回或复查的状态，应使用 path、hash 或 query 参数表达。

### 图标代替了所有文字

图标可能节省空间，但无法稳定表达“项目”“活动”“设置”这些概念。高频且关键的入口优先保留文字，工具提示只能补充，不能替代可见标签。

## 15. 结论：导航的目标是降低迷路成本

Sticky Navbar 负责全局入口，Hamburger Menu 负责移动端收纳，Breadcrumb 负责层级，Anchor Link 负责长页面定位，Tabs 负责同一上下文切换，Sidebar 和 Mega Menu 负责复杂信息架构，Bottom Navigation 负责移动端高频页面，Pagination 负责列表范围，Back to Top 负责长页面出口。

这些模式没有必要全部同时出现。先画出用户路径，再选能表达路径的最少组件；然后把默认、打开、关闭、焦点、禁用、加载和错误状态写进提示词，最后用桌面、移动端和键盘走一遍真实流程。

一个导航是否“有设计感”，最终不由它有多少动画决定，而由用户能不能随时回答“我在哪里、下一步去哪、怎么回来”。
