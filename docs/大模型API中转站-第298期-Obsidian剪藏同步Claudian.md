# Obsidian 如何把网页剪藏、同步与 AI 整理分开
网页剪藏、跨设备同步和 AI 整理解决的是三类不同问题，把它们混在一起容易造成重复文件、覆盖冲突或越权修改。本文以 Obsidian 为例，把 Web Clipper、同步工具和 Claudian 的职责分开，建立收件箱、同步检查、来源保留和只读整理的可验证流程。文中只讨论可复现的步骤，不把单次结果扩展成产品承诺；每个结论都标注前提、证据和无法覆盖的边界。读者可以先完成最小验证，再按自己的版本、权限和数据补充实验。




这三个工具的职责不一样：

~~~text
Web Clipper：从浏览器保存网页
Remotely Save：同步本地 Vault
Claudian：在 Obsidian 中和 AI 对话
~~~

先把这个边界记住：同步不是备份，剪藏不是整理，AI 对话也不是授权它随便改整个 Vault。

## 一、Obsidian Web Clipper 是浏览器扩展

Obsidian Web Clipper 不是 Obsidian 社区插件，它是浏览器扩展。官方入口可以从 [Obsidian Web Clipper](https://obsidian.md/clipper) 页面进入，再按当前支持的浏览器和安装说明操作。

### 安装步骤

1. 打开官方 Web Clipper 页面。
2. 进入当前浏览器对应的扩展安装入口。
3. 安装完成后，打开浏览器右上角扩展菜单。
4. 把 Web Clipper 固定到工具栏，方便使用。
5. 确认浏览器工具栏出现扩展图标。

不要在 Obsidian 的社区插件市场里搜索 Web Clipper。那里找不到它是正常的，因为它不属于同一类工具。

## 二、把微信文章剪进 00-收件箱

### 第一步：准备收件箱

如果还没有收件箱，在 Vault 根目录创建：

~~~text
00-收件箱/
~~~

它只负责接收未经整理的资料。不要一剪藏就立刻把文章分到十几个主题目录，否则入口会越来越慢。

### 第二步：打开网页

用默认浏览器打开要保存的微信文章或其他网页。确认页面已经完整加载，必要时先展开全文、图片或折叠内容。

### 第三步：点击 Web Clipper

点击浏览器右上角 Web Clipper 图标。第一次使用时，通常需要选择目标 Vault 和保存位置。选择当前的本地知识库，再把目标文件夹设置为：

~~~text
00-收件箱
~~~

也可以使用：

~~~text
00-收件箱/微信剪藏
~~~

### 第四步：回到 Obsidian 验收

切回 Obsidian，打开左侧的 `00-收件箱`，确认出现新的 Markdown 文件。打开文件检查：

- 标题是否正确
- 正文是否完整
- 来源链接是否保留
- 保存时间是否存在
- 图片和附件是否按当前设置处理

剪藏成功的标准不是浏览器弹出“Saved”，而是 Vault 里真的出现了能打开的 Markdown 文件。

### 剪藏失败先检查三件事

1. Obsidian 是否正在运行。
2. Web Clipper 是否选择了正确 Vault。
3. 保存位置是否仍然指向 `00-收件箱`。

如果文件出现了但内容不完整，先检查网页结构和剪藏模板，不要马上责怪 Vault 或同步插件。

## 三、给剪藏文章保留最少元信息

建议每篇剪藏至少保留：

~~~markdown
---
title: "网页文章标题"
source: "原始链接"
saved: 2026-07-24
status: inbox
---

# 网页文章标题

原始内容……
~~~

字段名称可以按你的习惯调整，但至少要保留标题、来源、时间和状态。后面让 AI 整理时，它才能区分原始资料、已读资料和已经生成的知识页。

## 四、Remotely Save 解决什么问题

Remotely Save 是同步插件，目标是把同一个本地 Vault 接到云端或其他设备。它不是写作插件，也不是 AI 插件。

它可能支持 WebDAV、OneDrive、S3、Dropbox 等同步方式，具体选项取决于当前插件版本和你的存储服务。

典型链路是：

~~~text
电脑上的 Vault
  -> Remotely Save
  -> 云端存储
  -> 手机或另一台电脑的 Vault
~~~

## 五、配置同步前先做备份

第一次同步前，先完整复制一份 Vault。可以放到外置硬盘或另一个明确的本地目录：

~~~text
AI产品知识库-backup-2026-07-24/
~~~

同步软件可能把删除、冲突或错误路径传播到其他设备。备份的意义是让你能回到同步前状态，而不是让你在云端继续找被覆盖的文件。

### 同步前确认清单

- [ ] Obsidian 已关闭或当前没有大量写入。
- [ ] Vault 已经复制出独立备份。
- [ ] 本地 Vault 路径确认正确。
- [ ] 远程目录确认是专用目录。
- [ ] 云端已有文件不会覆盖本地重要笔记。
- [ ] 手机端和电脑端不会同时大规模修改同一个文件。
- [ ] 已经知道如何停止同步。

## 六、Remotely Save 的配置步骤

### 第一步：打开插件设置

进入 **Settings**，找到 Remotely Save。首次配置先只选择一种同步方式，不要同时填写 WebDAV、OneDrive 和 S3。

### 第二步：选择同步方式

选择你实际拥有并理解的存储方式。不同方式需要的字段可能不同，常见包括：

- 服务地址
- 远程路径或 Bucket
- 本地 Vault
- 账户或授权方式
- 加密/冲突策略
- 测试连接
- 手动同步按钮

登录信息、访问令牌、授权文件和私密路径由你自己填写。不要把这些内容粘贴到公开文章、群聊或 AI 对话中。

### 第三步：先手动同步

保存配置后，不要直接开启全天候自动同步。先点击测试连接或手动同步，观察：

- 是否连接成功
- 远程目录是否出现预期文件
- 本地文件是否发生意外变化
- `.obsidian` 和插件设置是否按预期同步
- 是否有冲突提示

### 第四步：第二台设备只读验证

另一台设备安装 Obsidian 和 Remotely Save，使用相同同步方式。第一次可以先观察文件列表，打开一篇测试笔记，不要立即在两台设备同时编辑同一篇文章。

## 七、同步冲突怎么处理

同步不是版本控制。常见冲突包括：

| 现象 | 处理方法 |
| --- | --- |
| 同一文件两台设备同时修改 | 停止继续编辑，保留两份内容后人工合并 |
| 文件被移动后重复出现 | 检查远程路径和同步规则 |
| 图片在一台设备不显示 | 检查附件路径和大小限制 |
| 插件设置来回变化 | 不要盲目同步全部 `.obsidian`，确认同步范围 |
| 大量文件突然消失 | 立即暂停同步，从本地备份恢复检查 |

如果你说不清同步插件的冲突策略，就先关闭自动同步，保留手动同步。慢一点比把错误传播到所有设备更容易恢复。

## 八、Claudian：在 Vault 里直接和 AI 对话

Claudian 的作用是把 AI 对话面板放进 Obsidian。安装并启用后，通常可以在右侧看到对话面板或通过命令面板打开。

它适合做：

- 总结当前笔记
- 整理收件箱
- 提取标题、来源、主题和摘要
- 生成文章大纲
- 根据笔记提出问题
- 辅助生成图表描述
- 检查指定文件夹里的重复资料

它不应该默认拥有整个 Vault 的无限修改权限。每次任务都要说清楚范围、允许的动作和完成后的回报格式。

## 九、让 Claudian 整理收件箱

可以复制下面这段：

~~~text
请读取当前 Vault 的 AGENTS.md 和 00-索引.md。
然后只整理 00-收件箱 里的新资料。

允许的动作：
- 提取标题、来源、主题、摘要和可用场景
- 在 00-知识库 中生成新的知识笔记
- 在 00-索引.md 中补充新增入口

禁止的动作：
- 删除任何文件
- 覆盖已有正文
- 移动已发布内容
- 读取、展示或记录登录信息、授权信息和私密配置
- 处理 00-收件箱 之外的文件

完成后请按以下格式回复：
- 读取了哪些文件
- 新增了哪些文件
- 修改了哪些文件
- 哪些内容没有处理
- 下一步建议做什么
~~~

### 为什么要先读规则文件

AI 看到的是文件和任务，不一定知道你的知识库约定。`AGENTS.md` 和 `00-索引.md` 提供范围、入口和底线；没有这些文件，AI 可能把临时资料直接改成正式文章，或者把一个简单任务扩展成全库整理。

## 十、Claudian 任务的三条安全线

### 第一条：限定目录

把 `00-收件箱` 写出来，不要只说“整理我的资料”。

### 第二条：限定动作

明确“只读、摘要、生成新文件、更新索引”，不要把删除、移动和覆盖默认为允许。

### 第三条：限定回报

要求 AI 最后告诉你处理了哪些文件、改了什么、哪些没处理。你才能在左侧文件列表里逐项检查。

## 十一、每天怎么用

可以把日常流程压缩成六步：

1. 看到微信文章，先用 Web Clipper 剪进 `00-收件箱`。
2. 看到课程或 PDF，先保存原始文件和来源。
3. 需要画正式流程图，用 Diagrams。
4. 需要讲概念或发散，用 Excalidraw。
5. 需要整理资料，先让 Claudian 只处理收件箱。
6. 确认内容和文件无误后，再手动同步。

这个流程的关键不是每个插件都研究得很深，而是让资料经过明确的入口：

~~~text
网页/课程/对话
  -> 00-收件箱
  -> AI 提炼
  -> 02-知识库
  -> 文章草稿或项目输出
~~~

## 十二、给 AI 检查同步配置的 Prompt

~~~text
请帮我检查 Remotely Save 的配置思路。
不要读取、展示或记录我的个人登录信息、授权信息、密码、Token、远程私密路径和完整配置。

只告诉我应该在界面中确认哪些项目：
1. 同步方式
2. 远程路径
3. 本地 Vault
4. 测试连接
5. 手动同步按钮
6. 同步完成提示
7. 冲突处理策略
8. 备份是否存在

不要建议我删除本地文件，也不要让我把敏感配置粘贴到聊天里。
~~~

## 总结

Web Clipper、Remotely Save 和 Claudian 组成的是一个资料流：

~~~text
浏览器负责进货
Vault 负责保存
AI 负责整理
同步负责多设备可用
~~~

但同步前先备份，AI 处理先限定范围，插件配置里的授权信息永远自己填写。

## 结论

本文给出了问题定位、配置或创作流程的可执行路径。实际结果仍取决于当前版本、权限和运行环境，提交前应按官方文档复核可变字段，并保留失败证据和回滚边界。
