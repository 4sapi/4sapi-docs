# WorkBuddy 技能怎么选：别把技能市场当应用商店

技能市场最容易带来一种错觉：看到一个功能就装一个，装得越多，Agent 就越能干。现实通常相反。技能数量不断增加后，模型要在更多定义、更多工具和更多相似名字之间做选择；用户自己也很难记住每个技能到底改了什么、会读取什么、出了问题去哪里排查。

用户提供的素材把技能解释得很准确：专家决定“谁来干活”，技能规定“这件事怎么干得更专业”。前者偏角色和任务分工，后者偏流程、限制和输出格式。理解这层关系，才知道为什么一个表格技能能让结果更稳定，也知道为什么不该把所有技能长期打开。

这篇不再罗列一长串“必装技能”。重点是建立一套选择方法，让你在 WorkBuddy 或其他支持 Agent Skills 的工具里，能判断一个技能该不该装、该不该开，以及什么时候该把自己的流程写成技能。

## 一、技能到底替 Agent 补了什么

模型可以生成文本，也可以在已有工具的帮助下做计划。但真正的办公或开发任务往往有固定的细节：Excel 需要保留 Sheet 和公式，Word 需要处理样式，PDF 可能需要分页识别，网页需要点击和提取，文件整理需要先预览再执行。技能的价值，是把这些经验组织成可执行的操作说明。

一个质量合格的技能，至少应把以下内容说清楚：

| 项目 | 需要回答的问题 |
| --- | --- |
| 目标 | 它具体解决哪类任务，不解决什么 |
| 输入 | 接受哪些文件、参数、目录或链接 |
| 步骤 | 读取、处理、校验和交付如何进行 |
| 输出 | 产物格式、保存位置和字段要求是什么 |
| 边界 | 是否读写文件、联网、执行命令或调用外部服务 |
| 失败处理 | 信息缺失、格式异常或权限不足时怎样停止 |

如果一个技能只有“帮你更高效地完成工作”这类描述，却没有输入、输出和边界，它的实际作用通常很难验证。它也许会带来更长的提示词，但未必会带来更可靠的结果。

## 二、先按任务链路选，不要按热度选

素材中提到的 `xlsx`、`pptx`、`docx`、`pdf`、浏览器控制、磁盘分析、内容写作与公众号排版，覆盖的并不是同一类需求。把它们放进一次真实任务，会更容易看出各自的位置。

例如做一份行业汇报，流程可能是：

```text
收集网页和报告
  -> 提取 PDF、表格和文档里的事实
  -> 清洗数据并形成图表
  -> 写出报告大纲与正文
  -> 生成演示文稿
  -> 人工核对事实、格式和受众表达
```

这里，浏览器或检索能力解决的是资料获取；`pdf`、`docx`、`xlsx` 解决的是不同文件类型的结构化处理；写作技能解决的是表达；`pptx` 解决的是交付格式。把一个写作技能当成全流程解决方案，或让一个浏览器技能替你判断统计口径，都会让任务边界变得含混。

挑选时先写下自己的高频任务链路，再找其中真正缺的环节。不是“这个技能看起来厉害，所以安装”，而是“这一步每周都会卡住，现有流程没有可靠做法，所以试用”。

## 三、给每个候选技能过四道门

下面四个问题足够淘汰大部分不值得长期保留的技能。

### 3.1 它解决的是高频且具体的问题吗

“帮助办公”“提升开发效率”不算具体问题。可以写成：

```text
每周合并五份同结构的销售表，统一日期与金额格式，输出异常记录。
每月把会议录音转写为行动项，并对比上次承诺是否完成。
每次发布前检查 README、docs 和 Agent 记忆是否与代码改动一致。
```

任务出现频率不高、输入又每次完全不同，先用普通提示词更经济。相反，只要一项任务反复出现，且输出结构稳定，技能就能把口径、检查项和保存方式固定下来。

### 3.2 输入和输出能验收吗

好的技能不会只交出一段看起来不错的文字。它应该让你知道读取了什么、生成了什么、哪些地方没把握。例如表格清洗应给出异常记录；资料整理应给出来源文件与字段；文件归档应先列出预览表；写作任务应区分素材事实和待确认判断。

可以用一个最小验收模板：

```text
输入：这次允许读取的文件、目录、链接。
输出：文件名、格式、字段和保存位置。
不做：不能修改、删除、发送或推断的内容。
检查：由谁核对哪些结果，失败时如何回退。
```

连这个模板都填不出来的技能，不适合直接接进重要工作流。

### 3.3 权限与副作用是否匹配

读取一个 PDF 和清理磁盘、控制浏览器、整理发票不是同等级风险。用户提供的 `storage-analyzer` 素材之所以强调先只读扫描、删除前二次确认，正是因为这类任务一旦越过边界，后果不只是“答案不好用”。

把技能按副作用分成三档，能帮助你安排试用顺序：

| 档位 | 例子 | 推荐做法 |
| --- | --- | --- |
| 低风险 | 文档摘要、生成大纲、只读分析 | 可用脱敏样例直接试用 |
| 中风险 | 创建新文件、批量重命名、受限网页操作 | 先输出预览或草稿，再人工确认 |
| 高风险 | 删除文件、发送表单、访问业务系统、长期自动化 | 最小权限、隔离环境、明确 Owner 和回退方式 |

“能做”与“应该自动做”是两回事。技能如果涉及文件写入、浏览器会话、网络请求或外部系统，首次不要把它放进真实生产目录，更不要同时给它一组无关权限。

### 3.4 你能维护它吗

社区技能往往依赖脚本、第三方包或服务，后续还会更新。安装前至少看清来源、近期维护状态、所需权限、安装脚本和卸载后的残留。一个只在演示里好用、升级后没人能排查的技能，不会因为开源就自动变成团队资产。

最简单的维护记录可以放在一个 Markdown 文件里：

```text
技能名：
来源与版本：
用途与使用人：
读取/写入/联网权限：
试用任务与验收结果：
已知限制：
升级日期与回退方式：
```

这看起来像多做了一步，却能避免几个月后面对一个失效技能时，只能靠猜测它当初为什么被装上。

## 四、三套足够起步的技能组合

不需要等到收集完所有技能才开始干活。对大部分用户，下面三套组合比“全开”实用得多。

### 办公资料组合

```text
文档处理：PDF、Word 或 Markdown 读取与输出。
表格处理：Excel 清洗、合并、公式与图表。
演示交付：PPT 大纲或可编辑演示文稿生成。
```

适合周报、方案、报销明细、调研材料和汇报。先让它读资料和生成草稿，再处理格式；先保留原文件，再生成新版本。不要把“生成了一个文件”当成最终验收，数据口径、数字和版式都需要人看。

### 开发收尾组合

```text
项目文件与 Git 状态读取。
文档和记忆一致性检查。
受控的浏览器或自动化验证。
```

素材里的 `neat-freak` 关注的是一次开发工作结束后的文档、README、规则文件与 Agent 记忆同步。它值得借鉴的不是某个名称，而是“把收尾列为独立步骤”。代码改了七轮，文档仍停在第一版，后续无论人还是 Agent 都会被旧信息误导。

这类技能最适合在提交前运行，并且应先输出候选改动和差异，而不是直接删除或覆盖项目文件。

### 内容生产组合

```text
热点或资料检索。
长文写作与事实复核。
封面和配图生成。
Markdown 到发布格式的排版。
```

内容生产不等于连续点四个技能。它仍然需要一个人做选题判断、事实确认和最终发布审核。写作技能可以加快把资料组织成文章，封面与配图技能可以提高交付完整度，排版技能可以减少重复劳动，但任何一个环节都不该替代来源核对和发布责任。

## 五、为什么同类技能只留一个

用户提供的素材建议同类型技能只留一个，这条建议值得保留。两个功能重叠的技能同时打开，模型未必能知道该选哪个；不同技能又可能给出相反的格式、命名和工具调用方式。用户以为自己增加了选择，实际增加的是不确定性。

可以这样处理重叠技能：

```text
先为同一个小任务准备相同输入与验收条件。
分别运行候选技能，记录产物、错误、人工修改量和权限请求。
保留一个默认技能；其余关闭，而不是立即删除。
遇到特殊任务再临时启用第二个，并重新记录结果。
```

这比凭介绍页或单次体感做选择可靠。尤其是处理文档、表格和发布格式的技能，最后要比较的是“能否交付”，不是生成过程看起来多热闹。

## 六、重复三次后，再把流程沉淀为自己的技能

素材提出“重复三次以上就考虑封装”，这是个很好的阈值。一次任务可能只是偶然；连续三次都要修改同一段提示、核对同一批字段、纠正同一种错误，才说明这里存在稳定流程。

把流程写成技能时，不必追求很长的文档。先把最容易遗漏的内容固定下来：

```text
触发条件：什么时候使用。
输入检查：需要哪些文件、字段和权限。
执行顺序：先清点、再处理、最后自检。
输出规范：格式、命名、保存位置和来源标注。
禁止事项：不得覆盖原件、不得编造、不得外发。
异常处理：缺字段、冲突、权限不足时停止并报告。
```

比如“客户反馈周报”可以把分类规则、优先级、原文证据和待确认项固定下来；“内容发布”可以把事实核对、标题、封面、排版和发布前清单固定下来。技能沉淀的是你已经验证过的判断，不是把一段模糊愿望包装成自动化。

## 七、安装、启用与停用的日常规则

下面的规则适合个人和小团队长期使用：

```text
安装前：明确任务、来源、权限和验收样例。
试用时：只在隔离目录或脱敏材料上运行一次小任务。
启用后：记录版本、默认输入范围和已知限制。
每月：关闭近期不用或重复的技能，检查异常权限。
升级前：重跑原来的验收任务，必要时保留旧版回退。
下线时：确认缓存、配置、后台任务和访问令牌是否需要清理。
```

这个流程的重点不是让技能管理变成审批会，而是让新增能力有出处、有边界、有退出路径。技能市场的规模、热门排名和兼容范围会不断变化，具体安装方法请以 WorkBuddy 当前页面和技能仓库说明为准；选择方法本身不会过时。

## 八、Skill、工具、MCP 与专家，不要混成一件事

很多技能管理混乱，不是因为技能本身不好，而是把几种不同层次的能力混在了一起。可以先做一个简单区分：

| 概念 | 解决的问题 | 例子 |
| --- | --- | --- |
| 专家或角色 | 由谁负责判断和推进任务 | 数据分析助手、内容编辑、项目经理 |
| Skill | 按什么流程完成一类任务 | 表格清洗、发票归档、发布前检查 |
| 工具 | 具体做哪一个动作 | 读取文件、执行命令、创建图表 |
| MCP 或连接器 | 如何接入外部系统和数据 | 数据库、网盘、浏览器、内部知识库 |

它们可以组合，但不能互相替代。以“整理发票”为例：角色可以是财务助理，Skill 规定提取字段、重命名规则和异常检查，工具负责读取 PDF 或图片、创建表格，连接器决定是否有权访问网盘。把一个连接器当成 Skill，只会得到“能访问数据但不知道怎么做”；只写 Skill 又没有工具和授权，最终仍然停在纸面上。

这也解释了为什么有些斜杠命令没有达到预期。显式调用一个技能，通常能让 Agent 使用更明确的工作流，但前提是它处于启用状态、当前会话已经加载，而且所需的工具和权限也可用。具体调用格式、缓存行为与安装目录会因版本和工具而不同，遇到问题时优先检查当前产品说明和技能状态，而不是反复改提示词。

## 九、为技能准备一张小型测试卡

没有测试任务的技能，很难知道是“它不适合”，还是“这次输入刚好不适合”。每安装一个准备长期使用的技能，给它留一张很小的测试卡，内容不需要复杂：

```text
任务：例如合并两份结构相同的销售表，输出按月份汇总。
样例：两份脱敏文件，包含一行重复数据和一行缺失日期。
预期：不改原文件；生成合并表与异常表；重复和缺失均被标记。
限制：不得联网、不得读取工作区外文件。
记录：耗时、工具错误、人工修改和权限请求。
```

有了这个测试卡，升级后只要重跑一次，就能知道规则是否还有效。它也能帮助团队新人理解技能的实际边界，而不是只看到一段市场介绍。

不同类型的技能，测试重点不同：

| 类型 | 最该测试的内容 |
| --- | --- |
| 文件技能 | 原件是否保持不变、字段和格式是否正确 |
| 浏览器技能 | 访问范围、登录状态和外部提交前的确认 |
| 写作技能 | 来源是否保留、禁用表达和结构是否遵守 |
| 自动化技能 | 重复执行是否幂等、失败是否停止、通知是否可控 |
| 开发技能 | 修改范围、测试命令、文档同步与回退方式 |

测试卡的目的不是证明技能永远正确。它只是在你扩大使用范围前，提供一条能重复跑的基线。

## 十、个人和团队的管理方式不同

个人使用时，技能管理的目标主要是减少干扰。保留少量高频技能，关闭不常用的，给文件和网页任务留预览步骤，已经能解决大部分问题。

团队使用则多了几个必须回答的问题：谁有权安装第三方技能，谁审核它的权限，是否允许读取共享资料，更新后谁重跑回归，出现异常由谁停用。一个实用的最小分工可以是：

```text
使用者：提出场景、提供脱敏样例、检查业务结果。
维护者：记录来源、版本、依赖和升级情况。
资料 Owner：决定数据范围和敏感资料是否可访问。
负责人：批准高风险技能进入真实工作流，并保留停止权。
```

不需要把每个低风险写作技能都拉进正式审批，但涉及文件删除、对外发送、浏览器账号、公司数据或长期定时任务时，必须有人能说清它的权限和责任归属。技能越能行动，越不能只按“好不好用”来管理。

## 十一、什么时候应该停用或删除

技能并不是装上后永久保留。出现下列情况时，优先关闭并复查：

```text
它已经被更稳定的同类技能替代。
连续几次都要靠手工修正才能交付。
维护者不明，来源或依赖无法确认。
升级后新增了不需要的权限或外部请求。
它的工作流与当前项目规则发生冲突。
```

关闭通常比立即删除更稳，因为你还能在旧任务复盘时查看原配置。但如果技能保存了访问令牌、后台任务或本地缓存，下线时也要检查这些残留。把无用技能留在环境中并不完全无害，它会占用上下文，也可能在未来被误调用。

## 十二、结论

真正有效的技能管理，目标不是搭出最全的工具箱，而是让 Agent 在当前任务中少走弯路、少碰不该碰的东西，并稳定产出能验收的结果。

先按任务链路找缺口，再用频率、验收、权限和维护成本筛选；同类技能只保留一个默认项；重复三次的流程再沉淀为自定义技能。做到这几步，技能才会成为工作流的一部分，而不是积灰的收藏夹。

资料说明：本文基于用户提供的 WorkBuddy Skills 素材整理。素材涉及的市场规模、具体技能状态、安装入口和跨工具兼容性可能随版本变化，使用前请以对应产品与开源仓库的当前说明为准。
