# 从义理、考据到辞章，搭建一套 AI 写作工作流

很多人使用 AI 写作时，第一句话就是“帮我写一篇文章”。如果结果不满意，第二句话往往变成“更有深度一点”“少一点 AI 味”“写得像真人”。

这样的要求并没有错，但它们都集中在最后一层：辞章，也就是句子怎么写、段落怎么排、语气是否自然。问题是，如果作者还没有想清楚自己究竟要说什么，也没有把事实和经验整理出来，模型就只能替作者填补前面的空白。它会给出一个听起来正确的观点，再用一些概率上合理的细节把文章撑起来。

古人谈文章，常把义理、考据、辞章放在一起。换成今天的 AI 写作，可以把它理解成三个连续的问题：

- 义理：我究竟想说什么，为什么必须由我来说？
- 考据：我的判断建立在什么事实、经历和证据上？哪些地方只是推断？
- 辞章：怎样把已经想清楚、查明白的内容写得准确、克制、有力量？

本文把这三个词改造成一套可以执行的工作流。它适合写技术文章、产品复盘、行业观察、个人经历和知识分享，也适合与不同模型协作。核心原则只有一句：先让人完成思想和材料，后让模型提高表达效率。

## 一、先定义文章要回答的那一个问题

一篇文章最容易失控的原因，不是资料不够，而是问题太大。

“写一篇关于 AI 的文章”没有明确输入，也没有可验收输出。模型当然可以写，但它只能把所有相关概念排列起来：效率、变化、机会、风险、未来。这样的内容看似全面，读者却不知道自己读完以后应该解决什么问题。

开始写作前，先把题目压缩成一个具体问题：

```text
这篇文章只回答一个问题：________。

目标读者是谁：________。
读者当前遇到的具体困难：________。
读者读完后应该能够完成什么动作或形成什么判断：________。
文章不讨论哪些相关问题：________。
```

例如，“AI 会不会取代程序员”太大，可以改成“在一个已有代码库里，怎样判断 Coding Agent 生成的改动是否值得合并”。前一个题目只能产生观点，后一个题目可以产生流程、证据和验收标准。

问题一旦清楚，后面的义理、考据和辞章才有边界。

## 二、第一层：义理是自己的判断，不是漂亮口号

义理不是文章里的金句，也不是最后一段的总结。它是作者对问题的真实判断，包括立场、依据、范围和代价。

### 1. 先写一句不适合直接发表的话

很多作者一开始就要求模型把观点写得成熟，结果把最重要的犹豫删掉了。更好的做法是先自己写一段不必漂亮的内部笔记：

```text
我真正想说的是：________。
我之所以这样想，是因为我亲自遇到过：________。
过去我曾经以为：________。
后来哪件事让我改变了看法：________。
我最担心别人误解成什么：________。
即使有人反对，我仍然愿意坚持的部分是：________。
```

这一阶段不需要让模型代写。可以让模型提问，但不能让它替你决定立场。

### 2. 把观点拆成“主张、范围、反例”

一个可用的观点至少要包含三部分：

- 主张：我认为 X 比 Y 更适合某个场景；
- 范围：这个结论只在什么条件下成立；
- 反例：什么时候它可能失效。

比如，“写作 Skill 能去除 AI 味”是一个过大的主张。改成“写作 Skill 可以帮助模型先采访作者、整理事实和检查过度解释，因此在作者愿意提供真实材料时，能减少模板化表达；它不能替作者生成真实经历，也不能突破模型的事实核验能力”，就有了范围和边界。

这类限定不会削弱文章，反而会让读者知道你到底承担了什么判断。

### 3. 让模型做反方，不要只做扩写器

在义理阶段，可以使用下面的提示：

```text
下面是我的初步判断：
________。

请不要帮我扩写，也不要替我润色。
请分别输出：
1. 这段判断里最核心的可争议主张；
2. 我可能偷换了哪些概念；
3. 哪些地方把个人经验写成了普遍规律；
4. 一个有道理的反方观点；
5. 为了让结论成立，我还需要补充哪些事实。

如果材料不足，请提问，不要自行补造经历。
```

模型在这里的价值，是扩大你的判断范围，而不是生产一个你自己也不确定是否相信的结论。

## 三、第二层：考据是事实边界，不只是添加链接

考据常被误解成“文章里放几个网址”。实际上，它首先要求作者知道自己说的每句话属于哪一种材料。

### 1. 建立事实账本

写作时可以把材料分成五类：

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| 亲身经历 | 我在某次任务中遇到的失败 | 写清时间、场景和可观察结果 |
| 一手资料 | 官方文档、标准、源码、原始公告 | 给出紧邻事实的来源 |
| 他人陈述 | 演讲、采访、文章中的观点 | 标明说话者和材料出处 |
| 作者推断 | 根据多个事实得出的判断 | 明确写“我推测”或“这意味着” |
| 未确认信息 | 传闻、印象、待查数据 | 不写成确定事实 |

可以让模型先生成一个事实账本，而不是直接写稿：

```text
请把下面的材料整理成事实账本，不要写文章。

每条材料包含：
- 内容
- 类型：亲身经历 / 一手资料 / 他人陈述 / 作者推断 / 未确认
- 证据或来源
- 可以支持的结论
- 不能支持的结论
- 是否需要我补充或核验

严禁把推测升级成事实，也不要为缺失的来源编造链接。
材料如下：
________。
```

### 2. 区分“我记得”和“真的发生过”

个人写作也需要事实边界。记忆很重要，但记忆不是自动准确的数据库。你可以说“我记得那天一直在下雨”，也可以说“在我的印象里，那次经历从这里开始改变了我”，但不要在无法确认时写出精确日期、对话和数字。

真实感不等于精确到每一个细节。诚实地标明不确定性，本身就是可靠的写法。

### 3. 事实核验不能被辞章掩盖

技术文章尤其容易出现一种问题：模型把不确定的配置、版本或兼容性写得非常肯定。句子越流畅，读者越难意识到它可能未经验证。

在进入成稿前，可以要求模型执行一次“事实闸门”：

```text
逐句检查下面的文章材料。

对于每个可验证陈述，标记为：
- 已有一手来源
- 有作者亲身记录
- 仅为合理推断
- 尚未核验

涉及版本、模型能力、接口路径、错误码、日期、性能、价格和兼容性时，必须单独列出。
没有来源的内容不要补链接，也不要写成确定结论。
```

这一步可能会让文章变短，却能减少把不确定内容包装成知识的风险。

## 四、第三层：辞章是准确表达，不是表面装饰

当义理和考据完成后，AI 才真正适合大量介入。它可以帮助你调整结构、压缩重复、解释术语、改变读者层级，也可以模拟反对者来检查段落是否自洽。

但辞章仍然有几个需要由人把关的原则。

### 1. 用动作和结果替代情绪标签

“我非常焦虑”“这件事让我深受触动”是情绪结论。它们不是不能使用，但通常不如一个可观察的动作有力量。

例如，与其写“我意识到自己已经被工作消耗”，不如写“我打开旧文档，发现连续三周的周报里，最后一段都是同一句话”。

动作不是为了制造文学性，而是把判断交给读者。读者看到事实之后，可以自己得出情绪。

### 2. 一段只完成一个动作

一个段落可以负责提出问题、提供证据、解释含义或转向下一步，但不要让它同时承担所有功能。

让模型检查段落时，可以这样要求：

```text
请为每个段落标注它主要完成的动作：提出问题、讲述事实、解释原因、提出判断、承认限制或推进结论。
如果一个段落承担了两个以上互相冲突的动作，请指出具体句子，不要直接重写。
```

### 3. 让句子有长短变化，但不要追求随机

“去 AI 味”不等于把每句话写成不同长度。真正自然的节奏，来自思想的推进：一个短句落地，一个长句解释，一个停顿留下未说完的部分。

如果每段都严格按照“观点、解释、例子、总结”的四句结构，读者会感觉到模板；如果所有句子都短，文章又会像提纲。节奏应该服从内容，而不是独立成为装饰。

### 4. 把漂亮句子放回上下文

模型很擅长生成可以截图的结尾，但单独漂亮的句子不一定能支撑文章。检查一句话是否值得保留，可以问：

- 它是否推进了主张？
- 它是否来自前文的事实或判断？
- 如果删掉它，文章是否损失信息或方向？
- 它是不是只负责让读者觉得“很有道理”？

最后一种句子最需要警惕。它可能好听，但如果没有来处，文章就会从经验重新滑回公共表达。

## 五、把三层方法串成一条可执行流程

完整流程可以拆成七步。

### 第一步：人先写问题和立场

用几句话回答“为什么现在写”“我想纠正什么误解”“我愿意承担什么判断”。不追求完整，只追求真实。

### 第二步：模型进行事实访谈

让模型一次只问一个问题，追问时间、场景、动作、结果、原话和变化。回答中没有出现的内容，不允许模型自行补齐。

### 第三步：整理材料板

把事实、判断、证据、反例和待核验内容分栏。此时不要写长段落，避免过早进入辞章。

### 第四步：完成事实核验

对外部事实查官方文档、标准、源码或原始材料。对个人经历标记记忆范围，对不能确认的内容直接删掉或保留不确定表达。

### 第五步：设计读者路径

确定读者先遇到什么问题，再看到什么证据，最后得到什么结论。文章不是材料仓库，而是一条让读者逐步理解的路径。

### 第六步：让模型生成初稿

初稿提示里要明确：哪些内容来自事实账本，哪些是作者判断，哪些地方不能扩写；要求模型在缺材料处留出标记，而不是自动填空。

### 第七步：人做失真审查

不要只看有没有语病。逐段问：这还是我的判断吗？这个细节真的发生过吗？这个结论是否超过证据？这句话是否只是模型替我表达感动？

## 六、一个可以直接复用的总提示

```text
你是我的写作协作者，不是代替我生活和判断的作者。

任务主题：________。
目标读者：________。
文章要回答的问题：________。

请严格分四个阶段工作：

阶段一：采访
- 一次只问一个问题；
- 优先追问真实场景、动作、原话、时间和结果；
- 不替我补写没有提供的经历；
- 如果我只有抽象观点，要求我给出一个具体例子。

阶段二：材料整理
- 输出事实、个人判断、外部来源、推断和待核验项；
- 标明每条材料可以支持什么，不能支持什么；
- 等我确认后再进入下一阶段。

阶段三：结构设计
- 只围绕一个读者问题组织文章；
- 给出主张、证据、反例、限制和结论；
- 不使用空泛的行业趋势段落填充篇幅。

阶段四：成稿与审查
- 保留具体事实和必要的不确定性；
- 少做情绪解释，不重复总结已经成立的意思；
- 不编造数字、引用、对话、经历和来源；
- 成稿后单独列出可能需要我确认的句子。
```

## 七、这套方法的限制

第一，它不能替作者获得没有经历过的经验。如果你没有案例，正确做法是写成观察、假设或方法论，而不是让模型编一个案例。

第二，它不能替作者完成价值判断。模型可以提出反方，可以指出论证漏洞，但“我愿意坚持什么”仍然要由人决定。

第三，三层工作流会增加前期时间。它不一定让第一版更快，却往往能减少后期返工，尤其适合需要署名、需要核验或需要长期积累的内容。

第四，辞章层的效果仍然受模型能力影响。更好的模型可能更会理解复杂材料，但它也可能更擅长把不确定内容说得完整，因此事实闸门和人工审查不能省略。

## 结语：先把自己的话想明白，再让模型替你说得更清楚

AI 写作的价值，不应该只是让人更快得到一篇像文章的东西。更理想的协作，是模型帮助你发现自己的论点、追问你忽略的事实、指出你没有意识到的反例，然后把这些已经属于你的内容组织得更清楚。

义理决定文章为什么值得写，考据决定它能不能被相信，辞章决定读者能不能读懂。三者缺一不可。

如果只在辞章上反复修饰，最后得到的可能只是更流畅的空话；如果先把自己的判断和材料交给写作，再让 AI 负责结构和表达，文字才有机会既清楚，又确实像一个人在这里说话。
