# LFM3 六个模型怎么选：文本、视觉、音频、全模态与 d1 的适用边界

LFM3 一次发布了六个 2B 级模型。它们共用同一个骨干，输入输出却各不相同。第一次看的人容易问：我只要做语音转命令，该下哪一个？要不要直接上全模态那个？d1 又是什么？

本文按"我有什么输入、要什么输出"来选型，给出各模型的适用和不适用场景，列出官方示例要求的依赖版本，最后说明怎么用最小成本验证一个微调是否有效。

需要先说明：本文所有命令和代码都来自官方博客与模型卡，我没有在本机运行，因此都属于"按官方示例、待你自行验证"。性能数字是厂商自报。信息截止日期为 2026-10-30。

## 一、六个模型的输入输出

来源：[Build specialized multimodal models with LFM3](https://huggingface.co/blog/LiquidAI/lfm3)（2026-10-27，检索于 2026-10-30）。

| 模型 | 输入 | 输出 | 基于 |
| --- | --- | --- | --- |
| LFM3-1.7B | 文本 | 文本 | LFM3-1.7B-Base |
| LFM3-VL-2B | 文本、图像、视频 | 文本 | LFM3 骨干加视觉编码器 |
| LFM3-Audio-2B | 文本、音频 | 文本、语音 | LFM3 骨干加音频编码器、音频解码器和 LiquidCodec |
| LFM3-Omni-2B | 文本、图像、视频、音频 | 文本、语音 | LFM3 骨干加视觉和音频编码器、音频解码器 |
| d1-2B | 文本、图像、视频 | 校准后的答案 | LFM3-VL-2B |
| d1-omni-2B | 文本、图像、视频、音频 | 校准后的答案 | LFM3-Omni-2B |

六个模型都从 LFM3-1.7B-Base 衍生。官方还提供 Base 权重，用于自己做后训练。

## 二、按需求选

### 流程图式判断

1. 需要生成文字或语音，还是只需要做判断？
   - 只做判断（是否、选哪个、打几分）：看 d1。
   - 需要生成：继续。
2. 有没有图像或视频输入？
   - 没有：看文本和音频模型。
   - 有：看 VL 或 Omni。
3. 有没有语音输入或需要语音输出？
   - 有：Audio 或 Omni。
   - 没有：文本或 VL。

### 各模型的适用与不适用

**LFM3-1.7B（文本）**

- 官方建议场景：本地智能体、工具调用、结构化输出，或作为领域微调的基座。官方称它经过后训练，可在 Hermes Agent、Pi、OpenClaw 等智能体框架中运行。
- 不适用：任何需要看图或听音的任务；需要很强通用知识的开放问答（容量有限）。

**LFM3-VL-2B（视觉）**

- 官方建议场景：设备端视觉理解。它是 LFM 系列里第一个接受视频输入的模型，会先分步推理再回答，并能定位物体、推理摆放关系。
- 官方数字：1.9B 参数，在 62 项视觉基准上的平均分从 LFM2.5-VL-3B（3.1B）的 57.6 提高到 71.4，称与 Gemma 4 12B 相当。这是厂商自报。
- 不适用：需要语音交互的场景；要求高精度文字识别的场景应单独评测，官方没有给出这类专项数字。

**LFM3-Audio-2B（音频）**

- 官方建议场景：语音对话、语音识别、语音合成、翻译，覆盖 18 种语言，可在笔记本或边缘设备运行，也能把口头请求转成工具调用。
- 官方数字：语音质量指标 UTMOSv2 为 3.83（上一代 LFM2.5-Audio-1.5B 为 3.22）。
- 不适用：需要看图的任务。

**LFM3-Omni-2B（全模态）**

- 官方建议场景：一个模型同时看、听、说，替代分开的语音识别、视觉语言模型、语言模型和语音合成。可以回答关于图像的口头问题，也可以同时看和听视频。
- 官方数字：在 Daily-Omni、WorldSense、AV-SpeakerBench 上，称超过最大 10.7B 参数的模型（例如 Qwen2.5-Omni-7B）。厂商自报。
- 不适用：只有文本或只有图像的任务，用它是浪费算力；对延迟极敏感且不需要多模态时，更小的单模态模型更合适。

**d1-2B 与 d1-omni-2B（决策）**

- 官方建议场景：需要快速、结构化的决策而不是生成文字。给它一个情境（工单、发票、应用截图、照片、语音备忘）和一组问题，它在一次前向计算中回答全部问题，每个答案带校准后的概率。
- 题型：是非、选项、打分，也可以指向物体、读取文档里的数值、估计带范围的数字、选出所有适用的选项。
- 官方数字：d1-2B 在 ImajevBench 上 75.5，上一代 d1-3B 为 64.0。厂商自报。
- 选择：输入含音频用 d1-omni-2B，官方称用语音提问时它几乎不损失精度；只有文本、图像、视频用 d1-2B。
- 不适用：需要生成长文本、需要多轮对话的场景。

## 三、依赖版本

官方示例对 transformers 版本的要求不同，混装容易出错。

| 模型 | 官方示例的依赖 |
| --- | --- |
| LFM3-1.7B | 最新版 transformers |
| LFM3-VL-2B | transformers>=5.21.0，torch，torchvision，pillow |
| LFM3-Audio-2B | transformers>=5.20.2，torch，accelerate，librosa，soundfile |
| LFM3-Omni-2B | transformers>=5.20.2，torch，torchvision，torchcodec，accelerate，pillow，librosa，soundfile |
| d1-2B | transformers>=5.19，torch，torchvision，pillow |

几点提醒：

- 所有示例都带 `trust_remote_code=True`，会执行仓库里的自定义代码。使用前应阅读代码，并固定到具体提交版本。
- 用独立的虚拟环境，不同模型的版本下限不同，先装最高下限的那个通常能满足其他几个，但这是推断，不是官方说明。
- 视觉模型的示例里 `max_new_tokens=16384`，官方注释写明"推理过程可能很长"。VL 会先推理再回答，输出长度和延迟都要预留。

## 四、最小运行示例（文本模型）

下面是模型卡中的文本模型示例。命令按官方原样列出，我没有在本机运行。

```bash
pip install -U transformers
```

```python
from transformers import pipeline

generator = pipeline(
    "text-generation",
    model="LiquidAI/LFM3-1.7B",
    trust_remote_code=True,
)
messages = [{"role": "user", "content": "What is C. elegans?"}]
output = generator(
    messages,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=2048,
)
print(output[0]["generated_text"][-1]["content"])
```

运行位置：已安装 Python 和 PyTorch 的环境，首次运行会从 Hugging Face 下载权重。

预期现象：终端打印一段关于秀丽隐杆线虫的回答。具体文字不固定，因为 `do_sample=True`。

验证成功的标准：能加载、能生成非空文本、没有报错。若报告缺少自定义类，先确认 transformers 版本和网络是否能访问仓库。

采样参数按模型卡：通用场景 `temperature=0.1, top_k=50, repetition_penalty=1.1`；数学与 STEM `temperature=1.0, top_p=0.95, top_k=20`。

## 五、官方给出的微调路线

官方提供 10 个 Colab 笔记本，覆盖文本、视觉、音频、全模态，每个模型都声称可以在单张 GPU 上微调。

| 模型 | 方法 | 任务 |
| --- | --- | --- |
| LFM3-1.7B | SFT | 从杂乱文档中抽取结构化 JSON |
| LFM3-1.7B | DPO | 基于检索到的文档回答，或拒答 |
| LFM3-1.7B | GRPO | 在含 108 个工具的手机应用里调用正确的工具 |
| LFM3-1.7B | CPT | 用原始文本学习新语言（土耳其语） |
| LFM3-VL-2B | SFT | 把收据照片读成 JSON |
| LFM3-VL-2B | GRPO | 把公式图片转写为 LaTeX |
| LFM3-Audio-2B | SFT | 把口述的智能家居命令映射为函数调用 |
| LFM3-Audio-2B | SFT | 教模型一种新声音 |
| LFM3-Omni-2B | SFT | 把口述的智能家居命令映射为函数调用 |
| LFM3-Omni-2B | SFT | 回答关于医学图像的口头问题 |

这张表的用处是：你的任务如果和其中一行相似，可以直接从对应笔记本改起，不必从零写训练脚本。

官方没有在博客里写：单卡指哪种显存规格，训练需要多少数据，要跑多久。这些要自己估。

## 六、微调前后怎么验证有没有用

微调最常见的失败不是训练报错，而是"看起来好了，其实没好"。下面是最小验证流程，适用于任何一行笔记本。

1. **先划出测试集，再开始训练。** 从你的真实数据里留出 50 到 100 条，训练过程中不接触它们。
2. **先测基线。** 用未微调的同一个模型，在测试集上跑一遍，记下指标。没有基线就无法判断提升。
3. **指标要对应任务。** 抽取 JSON 就看字段级准确率和格式合法率；工具调用就看函数名和参数的完全匹配率；拒答类任务要分别统计该答没答和不该答却答了的比例。
4. **微调后在同一个测试集上重测。** 用相同的采样参数和提示词。
5. **看退化。** 随机抽一些与微调任务无关的通用提问，确认模型没有明显变差。小模型在窄任务上微调后，丢失通用能力是常见现象。
6. **多跑几次。** `do_sample=True` 时结果有随机性，同一输入跑 3 次看稳定性。
7. **记录成本。** 训练时间、显存占用、推理时的首 token 时间和吞吐。

失败信号与排查方向：

| 现象 | 可能原因 | 排查方向 |
| --- | --- | --- |
| 训练集指标很高，测试集很低 | 过拟合或数据泄漏 | 检查测试集是否混入训练数据，减少训练轮数 |
| 输出格式偶尔不合法 | 数据里格式不一致 | 统一标注格式，加强后处理校验 |
| 通用问答明显变差 | 学习率过高或训练过久 | 降低学习率，混入通用数据 |
| 工具名拼错 | 工具列表太长或描述含糊 | 精简工具描述，检查训练样本覆盖度 |

## 七、关于 d1 的使用提醒

d1 的输出是"校准后的概率"。校准意味着概率应该和真实正确率对应，例如它说 0.8 的那批答案，实际约 80% 正确。官方强调这一点，但没有给出校准曲线。

如果你要依赖这个概率来决定是否人工复核，需要自己验证：

1. 在你的数据上收集 d1 的概率和真实标签。
2. 按概率分桶（例如 0.5 到 0.6、0.6 到 0.7 等）。
3. 统计每个桶的实际正确率。
4. 若偏差明显，在业务阈值上做修正，而不是直接信任原始概率。

另外，官方 d1 示例代码里有一处 `"type": "noul"`，看起来像是笔误。我没有核实这是不是该库接受的取值，所以本文不转载 d1 的示例代码。使用前请以 d1-2B 的模型卡为准。

## 八、部署形态

LFM3-1.7B 的模型卡列出了多种格式：GGUF（可用于 llama.cpp、Ollama、LM Studio）、ONNX（ONNX Runtime）、MLX 4-bit（苹果芯片）、FP8（GPU 推理），以及 BF16 权重（vLLM、SGLang、Transformers）。

选择思路：

- 笔记本或桌面本地跑：GGUF 或 MLX。
- 跨平台集成到应用里：ONNX。
- 服务器上批量推理：BF16 或 FP8 配合 vLLM 或 SGLang。

官方称文本模型 4-bit 约 1 GB，这一条你可以直接下载文件核对。

## 九、限制与结论

选型可以压缩成一句话：输入决定模型。纯文本用 LFM3-1.7B；要看图用 VL；要听和说用 Audio；既看又听又说用 Omni；只要结构化判断用 d1。

本文的限制：所有性能数字来自厂商自报；命令和代码没有在本机运行；微调所需硬件、数据量、耗时官方没有给出；d1 的概率校准没有公开曲线；协议是否允许你的商用场景需要另行确认。

下一步建议是，选一个与你任务最接近的官方笔记本，按第六节先测基线，再决定要不要投入微调。
