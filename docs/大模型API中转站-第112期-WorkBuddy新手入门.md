# 【大模型API中转站】第112期 WorkBuddy入门 | 先养成AI同事

本文是【大模型API中转站】系列的第112篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

我第一次认真看 WorkBuddy，想到的是一个很具体的场景。

周五下午 5 点半。

桌面上有截图、Excel、会议纪要、还没改完的 PPT。

老板问周报，客户催表格，晚上还有材料要发。

这时候你打开一个普通 AI 聊天框，说：

```text
帮我写周报。
```

它能写。

但问题是：

```text
它不知道你这周做了什么。
它不会主动读你的文件。
它不知道哪份表格是最新版。
它不会检查会议纪要里的行动项。
它也不会把输出文件放到你指定的位置。
```

所以 WorkBuddy 的价值，不是“更会聊天”。

它更像一个围绕办公任务执行的 AI 工作台。

你给它文件夹，给它目标，给它输出格式，给它边界，它才能更像一个 AI 同事。

这篇先讲入门路线。

重点不是把 WorkBuddy 讲得很玄。

而是回答三个问题：

```text
新手第一天应该怎么用？
哪些任务适合先交给它？
什么时候需要 4SAPI 做企业级大模型接入和企业级 API 治理？
```

## 1. WorkBuddy 不是聊天框，是办公 Agent 工作台

普通聊天工具最擅长的是回答、改写、生成一段内容。

WorkBuddy 更适合做“从材料到交付物”的过程。

比如你要周报，不应该只说：

```text
写一份周报。
```

而是给它：

```text
本周任务清单
会议记录
项目文档
客户反馈
输出模板
保存位置
```

然后让它读完材料，再整理成：

```text
本周完成
关键进展
风险问题
需要协助
下周计划
```

这就是 WorkBuddy 和普通聊天框的差别。

它不只是生成内容，而是可以接住一个具体办公流程。

我会把 WorkBuddy 拆成四个核心能力：

```text
本地文件处理
远程助理入口
Skills 工具调用
Automations 自动化
```

这四个能力组合起来，WorkBuddy 才真正像办公 Agent。

## 2. 它最适合的不是大而空任务

很多人第一次用这类工具，会直接让它处理整个桌面、整个网盘、整个项目。

这通常会翻车。

因为输入太散，目标太虚，输出也不好验收。

WorkBuddy 更适合从这种任务开始：

```text
高频重复
输入明确
输出可检查
风险可控
能沉淀模板
```

比如：

```text
整理会议纪要
生成周报草稿
合并几份 Excel
提取发票信息
把长文改成推特提纲
把视频转成知识卡片
整理客户反馈
生成项目待办表
```

这些任务都有一个共同点：

结果能检查。

你能看它有没有漏文件、有没有编造、有没有字段错误、有没有把负责人和截止时间写清楚。

新手不要一上来追求“全自动办公”。

先把一个低风险流程跑稳。

## 3. 第一件事：建一个干净工作区

我建议先建一个专门目录。

```text
WorkBuddy/
  01-input/
  02-working/
  03-output/
  04-archive/
  99-prompts/
```

这个目录结构很朴素，但非常有用。

```text
01-input：放本次任务的输入材料。
02-working：放处理中间文件。
03-output：放最终交付物。
04-archive：放跑完后的历史材料。
99-prompts：存跑通过的提示词。
```

为什么要这样分？

因为 Agent 最怕两件事：

```text
到处找文件。
到处改文件。
```

你把输入、过程、输出、历史、提示词分开，WorkBuddy 的行为就更容易控制。

它不会在整个桌面里乱翻。

你也能快速验收结果。

## 4. 新手第一周只做低风险任务

低风险任务有三个特点：

```text
只读资料
生成新文件
结果容易检查
```

第一周我会先跑这六类任务。

```text
1. 整理一个杂乱文件夹，先输出归档预览表。
2. 读取一份会议记录，生成会议纪要和待办表。
3. 根据本周任务清单生成周报草稿。
4. 合并几份 Excel，统一字段格式。
5. 把一篇长文改成推特 article 提纲。
6. 整理项目文档里的更新，生成项目周报。
```

第一条指令可以这么写：

```text
请读取 01-input 里的会议记录，整理为会议纪要。

输出包括：
1. 主要结论
2. 行动项
3. 负责人
4. 截止时间
5. 待确认问题

要求：
- 不要修改原文件
- 不要凭空补充没有出现在材料里的信息
- 如果负责人或截止时间缺失，请标记为“待确认”
- 把结果保存到 03-output
```

这条指令的重点不是“会议纪要”四个字。

重点是：

```text
读取哪里
输出什么
不能做什么
缺信息怎么处理
保存到哪里
```

这才是把 AI 当同事用，而不是当聊天框用。

## 5. 批量任务前一定要先预览

文件整理、表格清洗、批量重命名、归档移动，这些都属于容易出事的任务。

不要一上来就让它执行。

先让它输出预览表。

```text
请先不要实际移动或修改文件。

请扫描 01-input 目录，输出一张归档预览表。

字段包括：
- 原文件路径
- 建议新文件名
- 建议新目录
- 操作类型
- 分类理由
- 风险提示

等我确认后，再执行移动或重命名。
```

这个习惯非常重要。

因为 WorkBuddy 再强，也可能误判文件名、日期、版本号。

预览表就是你的人工确认点。

## 6. WorkBuddy 和 4SAPI 怎么配合

个人用 WorkBuddy，重点是效率。

企业用 WorkBuddy，重点就不只是效率。

一旦你开始把它接到团队工作流里，就会遇到企业级大模型接入问题：

```text
谁能用哪些模型？
不同项目能不能拆 Key？
员工调用成本怎么统计？
失败请求怎么追踪？
客户资料有没有被越权读取？
自动化任务有没有日志审计？
预算超了谁负责？
```

这时就不能只靠一个个人 API Key 硬撑。

更合理的方式，是把模型调用统一走 4SAPI。

你可以把 4SAPI 理解成企业API网关：

```text
WorkBuddy 负责办公任务执行。
Skills 负责具体工具能力。
4SAPI 负责企业级 API、Key 权限、日志审计、调用追踪和成本治理。
```

如果你的 WorkBuddy 工作流支持自定义模型 API，或者你把它和 n8n、Dify、Coze、脚本、内部系统联动，可以统一配置：

```text
Base URL: https://4sapi.com/v1
API Key: 从 4SAPI 后台创建
Model: 从 4SAPI 模型广场复制
```

企业里建议不要只建一个 Key。

更稳的是按用途拆：

```text
4SAPI-WorkBuddy-WeeklyReport
用途：周报、会议纪要、项目总结。
```

```text
4SAPI-WorkBuddy-DataClean
用途：表格清洗、字段合并、数据摘要。
```

```text
4SAPI-WorkBuddy-Research
用途：搜索摘要、竞品调研、行业简报。
```

```text
4SAPI-WorkBuddy-Automation
用途：定时自动化任务。
```

这样做的好处是：

```text
成本能按任务拆。
权限能按场景控。
日志能按项目查。
异常能快速定位。
预算能提前限制。
```

这就是企业级 API 和个人 API 最大的区别。

个人 API 是“能不能调用”。

企业级 API 是“调用以后能不能管住”。

## 7. 第一周提示词模板

新手可以先把这套模板放到 `99-prompts`。

```text
角色：
你是我的办公流程助理，负责把输入材料整理成可交付结果。

目标：
[这次最终要交付什么]

输入：
[你可以读取哪些文件、目录、链接或材料]

过程：
1. 先列出你准备读取的材料
2. 再说明输出结构
3. 等我确认后再处理
4. 处理完成后做一次自检

约束：
- 不修改原文件
- 不删除文件
- 不对外发送
- 不编造材料中没有的信息
- 缺失信息标记为“待确认”

验收：
- 输出是否覆盖所有输入材料
- 表格字段是否完整
- 是否列出待确认问题
- 是否保存到指定目录

输出：
保存到 03-output，文件名使用“日期-任务名-版本号”。
```

这套模板可以改成周报、纪要、表格、调研、内容改写。

它的核心是让 WorkBuddy 先有边界。

边界清楚了，效率才会稳定。

## 8. 入门路线：别急着自动化

我建议按这个节奏来。

```text
第一天：
建工作区，只授权一个测试目录。
跑会议纪要、文件整理、文档摘要。

第一周：
固定 5 条提示词。
周报、会议纪要、表格清洗、长文改写、项目周报。

第二周：
安装基础 Skills。
先补搜索、浏览器、文档、表格、PPT。

第三周：
把重复任务放进 99-prompts。
每条提示词都要求输出到 03-output。

第四周：
挑一个低风险任务做自动化。
比如每日资讯简报、每周周报草稿、固定目录资料归档。
```

不要一上来就做长期定时任务。

一个流程还没手动跑稳，就把它自动化，只是在定时制造混乱。

## 9. 三档风险边界

我会把 WorkBuddy 任务分成三档。

```text
L1：只读文件、摘要、改写、生成草稿。
适合新手直接试。
```

```text
L2：创建新文件、整理目录、生成表格、发送到自己邮箱。
需要人工检查输出。
```

```text
L3：修改原文件、批量移动或删除、对外发送、长期定时自动化。
必须先预览，再确认，最好留备份。
```

涉及法律、医疗、投资、财务重大判断、公司战略方向，我只建议让 WorkBuddy 做：

```text
资料整理
选项生成
风险清单
初稿撰写
```

最后判断一定留给人。

企业场景还要加一层：

```text
权限审计
日志审计
预算控制
敏感数据脱敏
项目级 Key 管理
```

这也是为什么我建议企业把 WorkBuddy 相关模型调用放到 4SAPI 这种企业级 API 网关后面。

## 10. 最后总结

WorkBuddy 的正确打开方式，不是把它当聊天机器人。

而是把它当一个需要训练、需要约束、也值得调度的 AI 同事。

新手先记住这条路线：

```text
建工作区
只授权测试目录
先跑低风险任务
输出预览
沉淀提示词
再做自动化
最后接企业级 API 治理
```

个人使用，看的是省时间。

团队使用，看的是能不能管住。

如果你的 WorkBuddy 只是帮你写一份周报，用默认能力就够。

如果它开始进入企业知识库、项目周报、客户反馈、自动化任务和 Agent 工作流，就建议用 4SAPI 做统一模型入口：

```text
WorkBuddy 负责办公执行。
4SAPI 负责企业级大模型接入、企业API网关、权限审计和成本治理。
```

这才是把一个 AI 办公工具真正养成 AI 同事的开始。
