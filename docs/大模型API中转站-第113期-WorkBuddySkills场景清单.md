# 【大模型API中转站】第113期 WorkBuddy Skills | 25个高频办公场景

本文是【大模型API中转站】系列的第113篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

上一篇讲 WorkBuddy 入门。

核心就一句话：

```text
先把它当一个可约束的 AI 同事，而不是万能聊天框。
```

这一篇继续往下走。

WorkBuddy 真正变强，不只靠模型。

还靠 Skills。

模型负责理解任务，Skills 负责把事情做完。

如果没有 Skills，很多任务只能停在“帮你想一想”。

有了 Skills，才可能进入：

```text
搜索资料
打开网页
读取 PDF
处理 Excel
生成 PPT
下载视频字幕
语音转写
整理知识库
批量生成报告
```

但新手最容易犯的错，是一上来乱装。

我的建议是：

```text
先装基础工具箱。
再按场景扩展。
跑通三次，再沉淀成模板或自定义 Skill。
```

如果是企业使用，还要再加一层：

```text
通过 4SAPI 做企业级大模型接入、企业级 API、Key 权限、日志审计和成本治理。
```

## 1. Skills 不要乱装，先按任务选

我判断一个 Skill 值不值得装，会看三件事：

```text
它是不是解决高频任务？
它是不是补上模型做不了的能力？
它的输出能不能验收？
```

比如搜索 Skill 有价值，因为模型本身拿不到最新信息。

表格 Skill 有价值，因为真实办公数据需要清洗、合并、计算。

语音转写 Skill 有价值，因为会议录音不先转文字，后面没法做纪要和待办。

反过来，如果一个 Skill 只是换个话术生成内容，使用频率又低，就不用急着装。

## 2. 第一组：搜索和网页类 Skills

涉及最新信息，先用搜索。

适合：

```text
行业动态
竞品更新
新闻简报
调研报告
写文章前事实核查
```

提示词可以这样写：

```text
请搜索最近 1 个月 AI 办公工具领域的重要动态。

按四类整理：
1. 产品更新
2. 融资动态
3. 企业应用
4. 争议风险

要求：
- 附来源链接
- 标注发布时间
- 去掉重复信息
- 不要混入 1 个月以前的旧新闻
```

如果网页需要滚动、点击、展开折叠内容，就用浏览器类 Skill。

```text
请打开这个网页，阅读需要滚动和展开后才能看到的内容。

输出：
- 页面核心信息
- 关键截图说明
- 适合引用到报告里的 5 条要点
- 需要人工复核的位置
```

搜索类任务要特别注意时间范围。

没有时间范围，AI 很容易把旧资料混进新报告。

## 3. 第二组：PDF、Word、Markdown 文档类 Skills

办公资料大量存在文档里。

最适合 WorkBuddy 的任务不是“总结一下”，而是结构化提取。

```text
请读取 01-input 中的 3 份 PDF。

提取每份文档的：
1. 核心观点
2. 关键数据
3. 风险提示
4. 可引用原句
5. 待确认问题

最后合并成一张对比表，保存到 03-output。
```

文档任务建议分两步：

```text
先提目录和摘要。
再处理细节和字段。
```

长文档一步到位，很容易漏信息。

多文档任务一定要明确输出结构。

否则它会写成一段看起来很顺的摘要，但你很难验收。

## 4. 第三组：表格处理类 Skills

表格是 WorkBuddy 最值得榨干的场景之一。

因为很多表格任务很烦，但规则很清楚。

适合：

```text
多表合并
字段清洗
日期格式统一
金额格式统一
客户名去重
发票明细提取
数据透视
图表分析
异常记录表
```

模板：

```text
请读取 01-input 中所有 Excel。

任务：
1. 合并为一张总表
2. 统一字段名称
3. 统一日期格式
4. 统一金额格式
5. 标记缺失值和异常值
6. 输出一张异常记录表

要求：
- 不修改原文件
- 异常记录表必须说明问题原因
- 保存到 03-output
```

表格任务要写清口径。

比如：

```text
销售额是否含税？
利润率怎么算？
时间按订单日期还是付款日期？
客户名是否允许模糊合并？
重复记录以哪个字段判断？
```

这些口径不写清楚，结果就会看起来很专业，但实际上不可用。

## 5. 第四组：PPT 和演示文稿类 Skills

我更愿意让 WorkBuddy 先做 PPT 大纲。

页面美化可以后置。

逻辑先跑通。

模板：

```text
请根据这份产品说明文档，生成一份 10 页以内的汇报 PPT 大纲。

受众：
业务负责人。

重点：
1. 市场机会
2. 用户痛点
3. 产品方案
4. 落地计划
5. 风险和资源需求

要求：
- 每页只保留一个核心观点
- 每页给出建议图表或素材
- 先不要生成最终 PPT
```

先验收每页标题和观点。

再让它继续生成页面。

很多 PPT 不好，不是设计问题，而是逻辑顺序和页内观点没有先定住。

## 6. 第五组：视频、语音和知识卡片

视频和音频资料非常适合进入 WorkBuddy。

你可以用视频下载、字幕提取、语音转写类 Skill 做前置处理。

比如外文视频：

```text
请下载这个视频的字幕和音频。

输出：
1. 800 字中文摘要
2. 10 条关键观点
3. 10 张知识卡片
4. 适合发推特线程的提纲

每张知识卡片包含：
- 观点
- 例子
- 可延展选题
```

会议录音：

```text
请把这段会议录音转成文字。

再整理成会议纪要：
1. 主要结论
2. 行动项
3. 负责人
4. 截止时间
5. 待确认问题
```

长音频建议先转写，再摘要。

一步到位容易漏信息。

## 7. 第六组：知识库和本地笔记

如果你用 Obsidian、本地 Markdown、腾讯文档或其他知识库，WorkBuddy 可以做 inbox 整理。

模板：

```text
请读取本周 inbox 目录的笔记。

任务：
1. 按主题归类
2. 生成 5 条永久笔记候选
3. 保留原文链接
4. 标记可以转成文章或视频的选题
5. 不要修改原笔记
```

知识库场景的重点不是让 AI 替你决定知识结构。

而是让它帮你做：

```text
摘要
归类
打标签
提取待办
保留链接
生成候选笔记
```

结构规则最好由你先定。

## 8. 最值得榨干的 25 个场景

我把 WorkBuddy 的高频场景分成六类。

### 文档类

```text
1. 会议纪要
2. 周报和月报
3. 调研报告
4. 项目文档汇总
5. 多文档合并
6. 合同或方案结构化
```

会议纪要模板：

```text
请读取这份会议记录，生成会议纪要。

输出结构：
1. 背景
2. 主要结论
3. 关键讨论
4. 行动项表格
5. 待确认问题

行动项表格包含：
- 任务
- 负责人
- 截止时间
- 依赖条件
```

周报模板：

```text
请读取 01-input 里的本周任务清单和会议纪要，生成项目周报。

结构包括：
1. 本周完成
2. 关键进展
3. 风险问题
4. 需要协助
5. 下周计划

语气简洁，适合发给直属上级。
```

### 表格类

```text
7. 多表合并
8. 数据清洗
9. 发票和报销明细
10. 数据分析和可视化
```

发票模板：

```text
请读取 01-input 中的发票图片或 PDF。

提取：
- 发票日期
- 销售方
- 购买方
- 金额
- 税额
- 发票号码

输出报销明细表，并标记信息缺失或疑似重复的发票。
```

### 会议类

```text
11. 会议预约
12. 会后资料沉淀
13. 会议行动项追踪
```

会议行动项追踪很容易被低估。

你不用只让 WorkBuddy 写纪要。

更应该让它对比：

```text
上一场会承诺了什么？
这一场会兑现了什么？
哪些事项延期？
哪些事项没人负责？
```

这比漂亮摘要更有用。

### 内容类

```text
14. 推特 article 或线程
15. 小红书和短视频选题
16. 外文视频翻译和摘要
17. 标题和摘要批量改写
```

内容类任务要防止一个问题：

```text
它很容易写出“看起来像内容”的内容。
```

所以你要给：

```text
素材来源
平台语气
禁用表达
事实边界
目标读者
```

尤其是产品评测、行业分析、工具教程，不要让它为了顺口而夸大。

### 远程与自动化

```text
18. 远程找文件
19. 远程继续低风险任务
20. 每日资讯简报
21. 每周周报自动化
```

远程找文件模板：

```text
我不在电脑前。

请查找名称包含“项目汇报”的 PPT，确认最新修改时间。

把最新版本复制到 WorkBuddy/03-output，并告诉我文件路径。

不要删除或覆盖任何文件。
```

远程任务不要做删除、覆盖、批量发送。

远程只适合低风险动作。

### 产品、研发、企业

```text
22. PRD 和用户故事
23. 零代码本地应用
24. 客户反馈分类
25. 企业知识资产整理
```

客户反馈分类模板：

```text
请读取这些客户反馈。

按五类归档：
1. 功能问题
2. 价格异议
3. 体验问题
4. 竞品比较
5. 购买意向

输出：
- Top 10 高频问题
- 建议处理优先级
- 每类附原文证据
```

企业知识资产整理，要特别重视权限、审计和复核。

个人使用看效率。

企业使用看治理。

## 9. 什么时候要沉淀成自定义 Skill

一个流程只跑一次，写提示词就够了。

一个流程每周都跑，就值得存进 `99-prompts`。

一个流程跑通三次，就可以考虑做成自定义 Skill。

比如：

```text
客户反馈分类
视频转知识卡片
竞品周报
销售数据清洗
项目周报生成
会议行动项追踪
```

自定义 Skill 的价值，是把你的判断标准固定下来。

你不用每次重新写：

```text
分类规则
输出字段
风险边界
自检清单
保存路径
```

跑得越多，越应该沉淀。

## 10. 4SAPI 在 Skills 工作流里的位置

WorkBuddy + Skills 解决的是“能不能干活”。

4SAPI 解决的是“模型调用能不能管住”。

当你把 WorkBuddy 用在团队里，尤其是下面这些场景：

```text
企业知识库接入
客服系统接入
Agent 工作流接入
SaaS 接入大模型
自动化定时任务
跨部门办公助手
```

就建议统一走 4SAPI。

配置思路：

```text
Base URL: https://4sapi.com/v1
API Key: 按团队、项目、环境拆分
Model: 从 4SAPI 模型广场复制
日志：以 4SAPI 后台调用记录为准
预算：按项目设置成本上限
```

企业里不要把所有 Skill 共用一个 Key。

可以按能力拆：

```text
4SAPI-WorkBuddy-Search
用于搜索摘要、资讯简报、竞品调研。
```

```text
4SAPI-WorkBuddy-Docs
用于 PDF、Word、Markdown 文档处理。
```

```text
4SAPI-WorkBuddy-Sheets
用于表格清洗、数据摘要、异常解释。
```

```text
4SAPI-WorkBuddy-Content
用于文章、视频脚本、社媒改写。
```

```text
4SAPI-WorkBuddy-Automation
用于定时任务和长期运行工作流。
```

这样一来，你能看到：

```text
哪个 Skill 最耗钱？
哪个项目调用最多？
哪类任务失败率最高？
哪个成员在高频调用高价模型？
自动化有没有异常放大成本？
```

这就是企业级 API、企业API网关、权限审计、日志审计和成本治理的价值。

## 11. 最后总结

WorkBuddy 的上限，不只取决于模型。

更取决于你有没有把 Skills 用在正确场景里。

新手按这个顺序来就够：

```text
搜索和网页
文档处理
表格处理
PPT 大纲
视频语音
知识库整理
自动化
自定义 Skill
```

每个 Skill 都先回答三个问题：

```text
输入是什么？
输出怎么验收？
失败时怎么回滚？
```

个人用 WorkBuddy，是把重复任务从注意力里移出去。

企业用 WorkBuddy，则要同时考虑：

```text
权限
审计
成本
模型路由
团队协作
生产环境接入
```

所以我的建议很直接：

```text
WorkBuddy 负责办公流程。
Skills 负责工具能力。
4SAPI 负责企业级大模型接入和企业级 API 治理。
```

这套组合，才更接近一个能长期跑的 AI 办公系统。
