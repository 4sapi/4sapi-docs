# 如何用 A/B 测试选择模型推理档位

支持推理配置的模型往往提供多个计算档位，但把档位直接调到最高并不能证明结果更好。简单任务可能只增加延迟和用量，复杂任务失败也可能源于输入证据不足、工具错误或验收标准缺失。要判断额外推理是否值得，应在同一模型、同一任务和同一运行环境下做配对比较，一次只改变推理配置。本文给出任务集、随机顺序、自动验证和人工复核的完整实验协议，使结论限定在实际测量条件内。

## 实验前先确认接口事实

从所用模型的当前官方文档确认：

- 支持哪些推理配置及其准确参数值；
- 该参数是否与当前接口、模型和账号组合兼容；
- 用量响应包含哪些字段；
- 流式、工具调用和结构化输出是否受配置影响；
- 请求未被接受时返回什么错误。

不要把另一模型的参数名或档位值复制过来。实验记录保存请求值和响应中的实际模型标识。

## 先修复任务定义再比较档位

每个任务必须具备：

```text
明确交付物
固定输入材料
允许使用的工具
禁止动作与权限边界
自动或人工验收标准
信息不足时的停止条件
```

如果目标模糊，提高推理配置只是让模型对同一个缺口做更多推断。任务合同在所有实验组保持不变。

## 使用配对任务设计

对每个任务分别运行配置 A 和配置 B，这样两组面对完全相同的任务难度。任务集应覆盖实际流量，而不是只选择最困难样例：

| 类型 | 示例 | 主要验收 |
| --- | --- | --- |
| 结构化任务 | 分类、字段提取 | Schema 与字段对照 |
| 日常开发 | 边界明确的缺陷修复 | 目标和回归测试 |
| 复杂开发 | 跨模块根因分析 | 证据链与复现 |
| 研究任务 | 多来源决策简报 | 引用、事实与限制 |
| 工具工作流 | 多步只读任务 | 状态、停止与权限 |

如果某类任务在真实使用中占比很低，汇总时不要让它与高频任务拥有相同权重，或直接按任务类型分别报告。

## 固定除推理配置外的变量

两组必须使用相同的：

```text
模型标识
提示词与示例版本
上下文文件快照
工具定义和顺序
输出上限及其他参数
运行时与依赖版本
验证命令
```

网络和上游服务会产生波动，可以交错运行 A、B，并随机每个任务先运行哪一组，减少时间顺序造成的偏差。

## 预先定义指标

### 硬性通过

任务是否满足全部阻断条件，例如 Schema 可解析、目标测试通过、没有越权工具调用、关键事实有来源。任一阻断项失败即不通过。

### 人工质量

人工评审使用固定量表，且在不知道配置标签的情况下评分。记录事实一致、范围遵守、完整性和可操作性，不以文字长度判断质量。

### 资源指标

保存接口实际返回的输入和输出用量、端到端耗时、重试次数与错误类别。若接口不提供某项精确用量，标记缺失，不自行估算。

### 返工指标

记录达到发布标准所需的人工修改时间和修改类型。生成结果很长但需要大量删除，不应被视为质量提升。

## 保存逐任务原始记录

```text
experiment_id
task_id
task_type
model_id_requested
model_id_returned
reasoning_config
prompt_version
dataset_version
started_at
duration
usage_fields
validation_result
human_review
retry_count
error_category
```

日志使用标识和版本，不默认保存敏感代码、完整提示词或用户数据。原始响应按数据分类存放在受控位置。

## 先看配对差异，再看平均值

对每个任务比较 A 和 B：

```text
A、B 都通过：比较耗时、用量和返工
只有 B 通过：检查 B 是否确实修复了同一失败类型
只有 A 通过：确认高档位是否引入范围扩张或格式退化
都失败：先检查任务、工具和环境，不据此判断档位
```

按任务类型汇总通过数和中位数等描述统计，并保留样本量。样本很少时只报告观察，不使用“显著更好”之类统计结论。

## 写成条件化路由结论

实验结果不应变成“所有请求默认使用配置 B”。可以写成：

```text
结构化提取：A 与 B 的硬性通过相同，默认 A。
跨模块调试：B 在当前样例中减少验证失败，作为该任务类型候选。
安全评审：样本不足，不自动路由，继续人工选择。
```

每条结论标注模型、配置、任务集版本和测试日期。模型或工具更新后重新执行相关样例。

## 检查回退是否改变实验条件

如果调用链会在失败时切换模型，必须记录实际模型并将回退样本排除或单独分析。否则比较的可能不是两个推理配置，而是不同模型。

高风险任务不应在无提示情况下自动回退到未评估的配置。失败后保留错误和证据，由控制层决定是否重试。

## 结论与限制

推理档位选择应采用同模型、同任务、同工具的配对 A/B 测试。预先定义阻断条件，保存实际模型与用量，盲化人工评分，并按任务类型输出条件化结论，才能判断额外推理是否换来可接受的质量变化。

本文不提供任何具体模型档位、价格或通用最佳配置。接口参数和计费会变化，测试结果也只适用于记录的模型版本、任务集、提示词、工具权限和运行环境。
