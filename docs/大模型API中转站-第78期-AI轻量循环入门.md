# 【大模型API中转站】第78期 AI轻量循环 | 少敲10倍提示词

本文是【大模型API中转站】系列的第78篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

你有没有想过一个问题：

```text
AI 都出来好几年了，为什么很多人用它的方式，和第一天几乎一模一样？
```

打开 ChatGPT。

敲一句话。

等回复。

不满意，再敲一句。

让它改。

再让它改。

再补一句要求。

再复制到别的地方。

这当然比完全不用 AI 快。

但你有没有发现，最累的那个人还是你。

你一直在做三件事：

```text
提醒它下一步做什么。
判断它哪里不好。
催它继续改。
```

这就像你雇了一个很聪明的助手，但每 30 秒都要拍一下他的肩膀：

```text
继续。
不对。
再改。
这句太长。
这里加案例。
这里重写。
```

问题不是 AI 不强。

问题是你还在用“手动挡”的方式使用 AI。

这篇讲一个更省力的用法：

```text
轻量循环。
```

不用写代码。

不用搭服务器。

不用懂自动化。

你只要把目标、标准、检查方式和停止条件写清楚，AI 就可以自己多跑几轮：

```text
写 -> 自评 -> 找问题 -> 修改 -> 再评 -> 再修改 -> 达标停止
```

这就是很多人说的 Agent Loop 的最轻量版本。

它不能替你接管全世界。

但它可以马上减少你反复敲提示词的次数。

## 1. 你现在的用法，像一直在点外卖

想象一下，你想吃一顿饭。

你现在的用法是：

```text
打开外卖 App
点一个菜
等送来
不满意
再点一个
再等
还不满意
再点一个
```

每个菜都要你亲自点。

每一步都要你判断。

你不是不会吃饭。

你只是一直在当传菜员。

更高效的人怎么做？

他会说：

```text
我要一桌三菜一汤。
预算 100。
口味清淡。
至少一个素菜。
做好后先自己尝一遍。
太咸就重做。
达标再端上来。
```

这时候你做的不是“点菜”。

而是设定目标和标准。

AI 也是一样。

普通用法是：

```text
帮我写一段文案。
```

轻量循环是：

```text
围绕这个产品写 5 版文案。
每版按“痛点、卖点、可信度、行动建议”打分。
低于 8 分就重写最差的部分。
最多迭代 5 轮。
最后给我最优版本。
```

普通用法是：

```text
帮我改文章。
```

轻量循环是：

```text
请按标题、开头、案例、结构、结尾清单五项评分。
每项 1 到 10 分。
先修最低分项。
全部达到 8 分以上再停止。
最多 5 轮。
```

差别在这里：

```text
普通提示词：你推一步，它动一步。
轻量循环：你定规则，它自己往前跑几步。
```

## 2. 循环到底是什么？

不用讲复杂术语。

循环就是：

```text
目标
  -> 行动
  -> 检查
  -> 修正
  -> 再检查
  -> 达标或停止
```

更简单一点：

```text
定目标，设标准，让它自己改到过关。
```

你每天都接触循环。

闹钟就是循环。

你设定：

```text
每天早上 7 点叫我。
```

闹钟负责到点响。

你不需要每天早上 6:59 手动提醒闹钟：

```text
快到 7 点了，你准备响一下。
```

AI 轻量循环也是这个逻辑。

你不再一句一句催。

你直接告诉它：

```text
目标是什么。
怎么判断好坏。
每轮怎么改。
什么时候停。
```

剩下的让它自己跑几轮。

## 3. 轻量循环的四个零件

一个能用的轻量循环，需要四个零件：

```text
任务
成功标准
每轮动作
停止条件
```

少一个都容易跑偏。

### 3.1 任务：到底要它做什么

任务不能太虚。

不要写：

```text
帮我优化一下。
```

这个太空。

AI 不知道优化哪里。

更好的写法是：

```text
请把下面这篇文章改成适合公众号发布的长文。
目标读者是独立开发者。
主题是 AI Agent 如何提升日常工作效率。
```

或者：

```text
请把下面产品说明改成 3 条短视频口播稿。
每条 30 秒以内。
面向小红书用户。
```

任务越具体，循环越稳。

### 3.2 成功标准：什么叫做好

这是最关键的一块。

没有成功标准，AI 会很快说：

```text
已经优化好了。
```

但你一看，还是不行。

成功标准要尽量可判断。

比如写文章：

```text
- 开头必须有具体场景。
- 正文至少 3 个小标题。
- 至少有 1 张表格。
- 必须解释成本和风险。
- 结尾必须有可执行清单。
```

比如写短视频脚本：

```text
- 开头 3 秒有钩子。
- 每段不超过 80 字。
- 语气口语化。
- 不使用夸张承诺。
- 结尾有收藏或行动建议。
```

比如写代码：

```text
- 测试通过。
- 不删除现有测试。
- 不做无关重构。
- 修改后说明根因。
```

标准越清楚，AI 越知道怎么自查。

### 3.3 每轮动作：不要让它瞎改

每轮动作可以固定成四步：

```text
规划
行动
验证
决策
```

也就是：

```text
先说这轮改哪里。
然后直接改。
再按标准打分。
最后决定停还是继续。
```

这样 AI 不容易变成“整篇重写机器”。

很多人让 AI 改稿，最大的问题是它每次都推倒重来。

你明明只想改开头，它把全文都改了。

轻量循环里要写清楚：

```text
每轮优先修最低分项。
不要每轮重写全部内容。
```

这句话非常管用。

### 3.4 停止条件：什么时候别再跑

停止条件有两种：

```text
成功停止。
失败停止。
```

成功停止：

```text
所有标准达到 8 分以上，就输出最终版。
```

失败停止：

```text
最多迭代 5 轮。
连续 2 轮同一个问题没改善，就停止并告诉我原因。
```

为什么要失败停止？

因为 AI 有时候会卡住。

它不会崩。

它会继续“努力”。

继续改。

继续解释。

继续消耗你的时间和 token。

所以必须有刹车。

## 4. 什么时候值得用轻量循环？

不是所有事都要循环。

如果只是问一句：

```text
今天上海天气怎么样？
```

没必要。

如果是需要多轮打磨的任务，轻量循环就很适合。

| 场景 | 为什么适合 |
| --- | --- |
| 写文章 | 需要结构、案例、语气多轮打磨 |
| 写短视频脚本 | 需要钩子、节奏、结尾反复优化 |
| 写邮件 | 需要语气、清晰度、礼貌程度平衡 |
| 做周报 | 结构固定，质量可检查 |
| 改简历 | 可按岗位匹配度反复评分 |
| 写提示词 | 可以按输出质量逐轮改 |
| 代码修复 | 有测试反馈，适合迭代 |

不适合：

- 一次性小问题
- 完全主观审美
- 重大决策
- 需要实时数据但 AI 没联网
- 涉及付款、删除、外发承诺

轻量循环最适合这种任务：

```text
你原本就会让 AI 改 3 到 5 次。
```

现在把这 3 到 5 次，提前写进规则里。

你不用每轮手动催。

## 5. 直接复制：通用轻量循环提示词

下面这段可以直接复制。

```text
你将以循环方式工作，直到任务达到标准，或触发停止条件。

任务：
[写清楚你要什么]

成功标准：
- [标准 1]
- [标准 2]
- [标准 3]
- [标准 4]

每一轮按这个流程：
1. 规划：说明本轮要优先解决什么。
2. 行动：直接完成本轮修改或产出。
3. 验证：逐条对照成功标准打分，1 到 10 分，并说明扣分原因。
4. 决策：如果所有标准都达到 8 分以上，停止并给最终结果；否则继续下一轮，优先修最低分的问题。

停止条件：
- 所有标准达到 8 分以上。
- 最多迭代 5 轮。
- 如果连续 2 轮同一个问题没有改善，停止并说明需要我介入的地方。

规则：
- 没达到标准，不要说完成。
- 不要每轮都重写全部内容，优先修最差项。
- 如果信息不足，做合理假设并注明，不要停下来反复问我。

现在开始。
```

这段提示词的重点不是“字多”。

重点是它把 AI 的工作方式从：

```text
一次回答
```

变成了：

```text
多轮自查。
```

这就是轻量循环的核心。

## 6. 示例一：写文章循环

假设你要写一篇公众号文章。

普通提示词是：

```text
帮我写一篇关于 AI Agent 的文章。
```

这太宽。

轻量循环应该这样写：

```text
你将以循环方式写一篇公众号文章。

任务：
写一篇面向独立创作者的文章，主题是“为什么不要再手动敲 AI，而要让 AI 自己循环工作”。

成功标准：
- 开头必须有一个生活类比。
- 必须用大白话解释什么是循环。
- 必须讲清楚检查机制、记忆、停止条件。
- 至少包含 1 张表格。
- 至少给 3 个普通人可用的例子。
- 结尾给出可复制的提示词模板。
- 语气像独立科技博主，不要像教科书。

每一轮：
1. 先列出本轮要修的最低分项。
2. 修改文章。
3. 按每条标准打分。
4. 所有标准达到 8 分以上才停止。

最多迭代 5 轮。
```

你会发现，它会主动做几件事：

- 先搭结构
- 自评哪里不足
- 补案例
- 补表格
- 调整语气
- 最后输出终稿

你不需要每轮说：

```text
再加案例。
再口语化。
再补个表格。
```

这就是效率差。

## 7. 示例二：短视频脚本循环

短视频最适合轻量循环。

因为它需要反复打磨：

- 开头
- 节奏
- 分镜
- 口语化
- 结尾行动

可以这样写：

```text
你将以循环方式生成短视频口播稿。

任务：
围绕主题“普通人怎么用 AI 少加班”写一条 60 秒口播稿。

成功标准：
- 分成 3 个分镜。
- 第一段 3 秒内要有具体痛点。
- 每段不超过 80 字。
- 语气像真人口播，不要书面腔。
- 不使用夸张承诺。
- 结尾引导收藏。

每轮：
1. 生成或修改口播稿。
2. 按钩子、清晰度、口语化、可信度、行动建议打分。
3. 优先修最低分项。
4. 全部达到 8 分以上停止。

最多 4 轮。
```

这比你一句“帮我写个爆款脚本”稳得多。

尤其适合搭配数字人、短视频、图文内容工厂。

如果你后面要批量生成脚本，可以把不同模型放进 4SAPI 统一调用：

```text
低成本模型出 10 个方向。
中等模型写 3 版脚本。
强模型做最终审查。
```

这就是从轻量循环走向模型分工。

## 8. 示例三：代码修复循环

代码是最适合循环的领域。

因为它有硬标准：

```text
测试过没过。
构建成没成功。
lint 报不报错。
```

提示词可以这样写：

```text
你将以循环方式修复代码问题。

任务：
修复当前项目中失败的测试。

成功标准：
- 所有相关测试通过。
- 不删除现有测试。
- 不做无关重构。
- 修改后说明根因和影响范围。

每一轮：
1. 运行测试或读取测试结果。
2. 只选择一个最明确的失败点。
3. 修改相关代码。
4. 重跑相关测试。
5. 记录本轮做了什么。

停止条件：
- 测试全部通过。
- 最多 8 轮。
- 连续 2 轮同一个错误没有改善，就停止并报告。
```

这类循环在 Codex、Claude Code、Cursor 里都很实用。

注意一点：

不要让 AI 一次修 10 个问题。

每轮修一个最明确的。

这比“全局优化一下”靠谱得多。

## 9. 示例四：周报和邮件循环

轻量循环不只适合写作和代码。

也适合日常事务。

比如周报：

```text
你将以循环方式整理周报。

任务：
根据下面的零散记录，整理成一份本周工作周报。

成功标准：
- 分成已完成、进行中、风险、下周计划四部分。
- 每条都要有具体动作或结果。
- 不要写空话。
- 风险部分必须有应对建议。
- 总长度控制在 800 字以内。

每轮：
1. 整理周报。
2. 检查是否有空话和重复。
3. 检查每条是否有动作或结果。
4. 修最低分项。

最多 3 轮。
```

再比如邮件：

```text
你将以循环方式改写邮件。

任务：
把下面这封邮件改得清楚、礼貌、能推动对方回复。

成功标准：
- 第一段说明背景。
- 第二段说明需要对方做什么。
- 语气礼貌但不卑微。
- 不超过 300 字。
- 结尾有明确截止时间。

最多 4 轮。
每轮先自评，再修最低分项。
```

这些任务的共同点是：

```text
结构固定，质量能检查，人工最后看一眼就能用。
```

这就是普通人最值得先试的地方。

## 10. 轻量循环为什么比普通提示词更省钱？

很多人会问：

```text
让 AI 多跑几轮，会不会更贵？
```

会。

但你要比较的不是“一次调用价格”。

你要比较的是：

```text
完成一个可用结果的总成本。
```

普通手动提示词看起来便宜。

但你可能要：

```text
问 1 次
改 1 次
再改 1 次
补案例 1 次
调语气 1 次
再让它整理格式 1 次
```

实际上也是 5 到 6 轮。

轻量循环只是把这几轮提前写进规则里。

区别是：

```text
手动模式：每一轮都要你回来指挥。
循环模式：它自己按标准推进。
```

如果你后面把这套方法用到高频任务里，就要开始关心模型成本。

这时 4SAPI 的价值就出来了。

你可以用统一入口管理不同模型：

| 阶段 | 适合模型 |
| --- | --- |
| 发散方向 | 低成本模型 |
| 初稿生成 | 性价比模型 |
| 精修改写 | 中高质量模型 |
| 审查挑错 | 强模型 |
| 摘要归档 | 低成本模型 |

一次两次手动用，随便哪个平台都行。

但如果你每天用循环写文章、脚本、邮件、周报、代码 review，模型调用就会变成一笔真实成本。

这时候，把它放进 4SAPI 这类大模型 API 中转站统一看日志、控额度、切模型，会比每个平台各用各的舒服很多。

## 11. 轻量循环的常见坑

### 11.1 标准太虚

错误写法：

```text
写得高级一点。
```

更好写法：

```text
减少空话。
每段都要有具体信息。
至少加入 2 个真实场景。
不要使用“赋能、闭环、颠覆”等空泛词。
```

### 11.2 没有停止条件

错误写法：

```text
一直改到最好。
```

更好写法：

```text
最多迭代 5 轮。
全部标准达到 8 分以上停止。
连续 2 轮同一问题没改善就停止。
```

### 11.3 让 AI 自己给自己满分

AI 很容易自我感觉良好。

所以你要写：

```text
评分要严格。
如果有明显问题，不能给 8 分以上。
必须说明扣分原因。
```

### 11.4 每轮都全文重写

这会浪费上下文，也会把原本好的部分改坏。

要写：

```text
每轮优先修最低分项。
不要无理由重写已经达标的部分。
```

### 11.5 没有人类最后确认

轻量循环不是让你闭眼发布。

尤其是：

- 商业文案
- 医疗健康
- 金融投资
- 法律建议
- 对外邮件
- 客户承诺

这些都必须人工看一遍。

AI 可以帮你多轮打磨。

最终责任还是在人。

## 12. 一张判断表：这事该不该循环？

你可以用这张表判断：

| 问题 | 是 | 否 |
| --- | --- | --- |
| 这事是否经常重复？ | 可以考虑循环 | 手动即可 |
| 成功标准是否清楚？ | 可以循环 | 先写标准 |
| AI 能否自己完成大部分步骤？ | 可以循环 | 不适合自动化 |
| 失败是否容易发现？ | 可以循环 | 风险较高 |
| 结果是否需要人工确认？ | 加人工关卡 | 可直接输出 |

简单说：

```text
重复、可检查、低风险，最适合轻量循环。
```

第一次别选太难的。

你可以从这些开始：

- 改文章
- 写短视频脚本
- 整理周报
- 改邮件
- 检查提示词
- 归纳会议纪要
- 修一个小测试错误

跑顺了，再上更复杂的。

## 13. 轻量循环使用前检查清单

每次准备让 AI 循环工作前，先过这张清单：

```text
[ ] 任务已经写清楚，不是“优化一下”
[ ] 成功标准至少有 3 条
[ ] 成功标准能被判断，不全靠感觉
[ ] 每轮流程包含规划、行动、验证、决策
[ ] 要求 AI 严格打分，并说明扣分原因
[ ] 要求 AI 优先修最低分项
[ ] 设置了最大迭代轮数
[ ] 设置了失败停止条件
[ ] 明确哪些内容不能编造
[ ] 商业、医疗、金融、法律等高风险内容会人工复核
```

这张清单过不了，就先别循环。

先把任务和标准写清楚。

AI 循环不是魔法，它只是把清楚的规则执行得更稳定。

## 14. 从轻量循环到自动化循环

轻量循环有一个限制：

```text
它还需要你打开聊天窗口。
```

网页关了，它就停。

它不会自己每天早上 7 点跑。

它不会自己读邮件。

它不会自己建工单。

它不会自己发 Telegram 消息。

真正自动化的循环，还需要：

- 定时器
- 工具连接器
- 任务状态
- 日志
- 权限
- 预算
- 人工关卡

这就是下一篇要讲的内容。

轻量循环解决的是：

```text
少敲提示词。
```

自动化循环解决的是：

```text
让任务自己在后台跑。
```

两者不是一回事。

普通人先学轻量循环。

团队和高频工作流，再上自动化循环。

## 15. 结尾：三句话记住轻量循环

第一句：

```text
AI 不只是问答框。
```

你可以让它按目标和标准自己改几轮。

第二句：

```text
循环的核心不是复杂工具，而是清楚标准。
```

没有标准，AI 只会“看起来很努力”。

第三句：

```text
轻量循环先跑起来，重型自动化以后再说。
```

你今天就能复制那段提示词，把文章、脚本、邮件、周报先跑起来。

如果后面你发现自己每天都在重复这些循环，再考虑接 4SAPI 做多模型分工和成本治理。

因为一旦循环多了，问题就不再是“会不会写提示词”。

而是：

```text
哪个模型负责初稿？
哪个模型负责审查？
谁在消耗 token？
哪些结果真的被采纳？
怎么防止循环空转？
```

这些，就是下一篇要讲的。
