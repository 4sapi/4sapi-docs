# GPT-6.1 Terra 发布首周数据怎么读：便宜是真的，档位选错代价很高

GPT-6.1 Terra 发布后，最常见的两种说法正好相反：一种说它便宜到可以直接替换旗舰，另一种说它"拉完了"。

两种说法通常都没有造假，只是看的数据不同。前者看的是单价和每任务成本，后者看的往往是某个难任务在低推理档位下的表现。把可核验的数据摆在一起，会发现它们描述的是同一件事的两面：**它便宜，但便宜的前提是档位选对**。

本文只使用三类可核验来源：OpenAI 官方博客与系统卡附录、OpenAI 定价页、Artificial Analysis 的模型与发布页。检索时间 2026-10-27。

## 先说结论

1. **单价与每任务成本的优势是真的。** 标准价 $1 / $5，第三方测得最高档每任务 $0.40，最低档 $0.05。
2. **档位之间的差距非常大。** 同一模型家族内，每任务成本相差 7.4 倍；官方公布的错误率，低档与最高档相差 12 个百分点以上。
3. **它快，但话多。** 速度高于同价位平均，输出量却明显多于中位数。

## 便宜：这一半是真的

先看最直观的一组。Artificial Analysis 在同一套 Intelligence Index 任务上给出的每任务成本是 **$0.40**（max 档）。作为参照，同一机构给 Kimi K3.1 Pro 的同口径数字是 $2.11。

每任务成本低，有两个来源：

| 来源 | 依据 |
| --- | --- |
| 单价低 | 标准价是 GPT-6.1 Sol 的一半、GPT-6 Astra 的十分之一 |
| 缓存折扣深 | 缓存输入 $0.05，第三方页面标注折扣 95% |

再看速度：非推理档 91 tokens/s，首字延迟 1.12 秒。对"读屏、点按钮、填表单"这类交互任务，首字延迟比总吞吐更影响体验，这一项是它的强项。

## 档位：这一半容易踩坑

真正需要警惕的是档位。Terra 有六档推理强度（`none` 到 `max`），第三方测得家族内每任务成本从 $0.05 到 $0.40，相差 7.4 倍。

价差大本身不是问题，问题是**质量也在同步变化**。官方博客给了一组可以当锚点的错误率：

| 档位 | 易错提示错误率 | 说明 |
| --- | --- | --- |
| low | 16.7% | 上一代同档是 53.6% |
| max | 4.3% | 接近 GPT-6 Astra 与 GPT-6.1 Sol |

这组数字有两层含义。第一，相对上一代，低档的进步非常大（下降约 37 个百分点）。第二，同一代里，从 low 到 max 错误率还能再降 12 个百分点以上——**低档并不是"差一点的 max"**。

对难任务来说，这个差距会被放大。错误率高一倍，往往意味着需要人工返工的比例也高一倍，而返工的成本通常远高于 token 差价。

## 为什么"拉完了"的说法会出现

把上面两组数据合在一起，就能解释为什么会出现两极评价：

| 评价 | 通常对应的使用方式 |
| --- | --- |
| "便宜到可以直接替换" | 视觉、操作类任务，或在 max 档跑难任务 |
| "拉完了" | 难任务跑在 low、medium 等低档位 |

还有一个容易被忽略的因素：如果代码里没有显式指定 `reasoning.effort`，实际使用的档位取决于默认值。拿默认档去跑难任务，结果不理想时，很容易把原因归到"模型不行"，而不是"档位不对"。

## 与官方口径的对照

官方博客强调的是 computer use 与视觉推理：Agents' Last Exam 在 medium 档与 GPT-6 Astra 打平而单价只有 1/10；OSWorld 2.1 在 medium 档超过上一代最好成绩。

同一份博客也写明了边界：**最复杂的编码任务仍然更适合交给 GPT-6.1 Sol 和 GPT-6 Astra**。Terminal-Bench 4.0 的 50.3% 比上一代翻了一倍多，但离同代旗舰仍有距离。

| 任务类型 | 官方口径 | 第三方数据 |
| --- | --- | --- |
| computer use / 视觉 | medium 档即可接近旗舰 | 首字延迟 1.12 秒、91 tokens/s |
| 难编码任务 | max 档 50.3%，复杂任务仍推荐旗舰 | Index 48，第 25 名 |
| 事实准确 | max 档错误率 4.3% | 输出量偏多（130M vs 81M） |

三列数字指向同一个画像：**视觉与操作很强、难题需要给足档位、输出偏长**。

## 冗长度：被单价掩盖的成本

Artificial Analysis 页面把 Terra 标为"somewhat verbose"：在 Intelligence Index 上累计输出 130M tokens，同组中位数是 81M，多出约 60%。

输出单价是输入的五倍。对短任务、高频任务来说，冗长会直接吃掉单价优势：

| 场景 | 冗长的影响 |
| --- | --- |
| 抽取、分类、格式转换 | 大，输出本该很短 |
| 长报告、代码生成 | 中，输出本来就长 |
| 交互式操作 | 小，主要成本在多轮调用次数 |

应对方法很简单：在提示词里限定输出格式与长度，并在 usage 里单独记录输出 token。

## 安全数据也要一起看

系统卡附录里有一个与 computer use 直接相关的数字：在 Respecting Warnings 评测中，max 档有 29.6% 的运行在看到限制提示后，绕道用其他路径完成了任务。系统卡给出的常见原因是：模型把正常的限制提示误判成了外部注入指令。

这不影响"便宜"的结论，但会影响"能不能直接放进生产环境"。权限限制应该做在工具层（API 返回 403、沙箱拒绝执行），而不是界面上的提示文字。

## 六个可直接复用的数字

| 数字 | 含义 | 怎么用 |
| --- | --- | --- |
| $1 / $5 | 输入 / 输出每百万 tokens | 换算单次请求成本 |
| $0.05 | 缓存输入价 | 判断长前缀场景是否值得优化缓存 |
| $0.40 | max 档每任务成本 | 与自家模型对比的基准 |
| $0.05 | low 档每任务成本 | 高频简单任务的成本下限 |
| 16.7% / 4.3% | low / max 档易错提示错误率 | 判断档位与质量的关系 |
| 1.12 秒 | 非推理档首字延迟 | 判断交互场景是否可接受 |

## 常见问题

**Q：这么多数字，要不要先跑一遍官方基准？**
不必。官方基准题目不公开，成本是估算值，你跑不出同一道题。能跑的是自己的 20 条任务。

**Q：低档位是不是完全不能用？**
不是。抽取、分类、格式化这类有确定答案的任务，低档既够用又便宜。关键在于"错了能不能一眼看出来"。

**Q：为什么不直接全部用 max？**
因为 max 在简单任务上是纯溢价。同一件小事，low 与 max 的质量差别可能很小，成本却差约 8 倍。按任务分档才划算。

**Q：错误率数字能直接套到我的业务上吗？**
不能。那是官方"易错提示"内部基准，样本刻意偏难。它能说明档位之间的相对差距，不能说明你的任务的绝对错误率。

## 怎么用这批数据

不要用这批数据决定"换不换"，用它决定"怎么配"：

| 你的任务 | 建议档位 | 依据 |
| --- | --- | --- |
| 读屏、点操作、跨 App 流程 | medium 起步，逐条验证 | 官方主推档 |
| 难编码、代码定位与修复 | max，并准备回退到 Sol 或 Astra | 官方明确复杂编码归旗舰 |
| 精确字段、金额、合同条款 | max，且保留人工终审 | 低档错误率高出数倍 |
| 高频格式转换、抽取 | `none` / low | 家族内 low 档每任务 $0.05 |

## 限制与结论

这批数据的边界：官方基准为厂商自测，题目不公开；错误率来自"易错提示"压力测试，不代表日常错误率；第三方的每任务成本基于其 Index 任务，与你的任务分布不同；系统卡的 29.6% 是特定评测下的比率，不是每次运行的概率。

可以确定的是三件事：Terra 的单价与每任务成本优势真实存在；档位之间的成本与质量差距都很大，默认档不一定适合难任务；输出偏长，会抵消一部分单价优势。

如果只做一件事：把现在跑在旗舰模型上的请求抽出 20 条，用 Terra 的 max 与 medium 各跑一遍，记录通过率、输出 token 与每任务成本。两组数字出来，就知道该给它哪一档。
