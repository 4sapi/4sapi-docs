# 【大模型API中转站】第190期 AI成本日报 | 模型调用经营报表

本文是【大模型API中转站】系列的第190篇。本系列致力于用最低的成本、最清晰的方法，帮你打通多模型API的任督二脉。建议先收藏，随用随查。

企业接入大模型以后，最应该每天自动生成的一张表是：

```text
模型调用成本日报。
```

不是月底看账单。

而是每天知道：

```text
谁在用。
用什么模型。
花了多少钱。
失败多少。
有没有重试风暴。
Fable 5 有没有被滥用。
哪个项目需要降本。
```

这件事特别适合 AI 做。

## 1. 成本日报看什么

字段：

```text
date
project
key_group
model
task_type
request_count
input_tokens
output_tokens
cost
error_count
retry_count
fallback_count
avg_latency
```

再加管理字段：

```text
budget_used_percent
top_risk
recommended_action
owner
```

这样日报就不是账单。

而是经营报表。

## 2. 模型分工

| 阶段 | 模型 |
| --- | --- |
| 日志聚合 | 程序或低成本模型 |
| 异常解释 | 中等模型 |
| 成本策略判断 | Fable 5 |
| 高管摘要 | 中等模型 |

不要让 Fable 5 每天读原始日志。

先聚合。

再让它判断异常。

## 3. 日报模板

```text
# 模型调用成本日报

日期：
总成本：
环比：
请求数：
失败率：
重试率：

Top 项目：
Top 模型：
Top Key：
异常任务：
预算风险：
建议动作：
```

异常任务要写清：

```text
原因。
证据。
建议。
负责人。
```

## 4. 常见告警

```text
单日成本超过预算 80%。
Fable 5 调用次数异常。
某 Key 失败率超过 10%。
某 task_type 重试率超过 20%。
平均 input_tokens 突然翻倍。
fallback 频率异常。
```

这些告警不复杂。

但非常有用。

## 5. 异常归因示例

日报里不要只写：

```text
今日成本上涨 38%。
```

要写原因。

例如：

```text
成本上涨主要来自 project=content-agent。
该项目 Fable 5 调用次数从 18 次增加到 74 次。
平均 input_tokens 从 6k 增加到 22k。
同一 task_type=article_review 出现 3 次重试。
```

这种写法才有行动价值。

对应建议可以是：

```text
article_review 先用低成本模型做材料摘要。
Fable 5 只做最终审查。
限制单任务最大上下文。
重试超过 1 次转人工。
```

## 6. 自动化流程

可以每天凌晨跑：

```text
拉取 4SAPI 调用日志。
按项目和模型聚合。
低成本模型生成日报草稿。
Fable 5 审查异常归因。
发送到飞书/企业微信。
```

日报不是给技术炫耀。

而是给业务负责人看：

```text
哪条 AI 工作流真的在花钱。
花钱有没有换来结果。
哪些地方需要降本。
哪些地方应该升级模型。
```

## 7. Prompt

```text
你是模型调用成本分析助手。

请根据 4SAPI 调用聚合表生成成本日报。

要求：
- 先给总览。
- 找出成本 Top 项目、Top 模型、Top Key。
- 找出异常：成本突增、失败率高、重试率高、Fable 5 滥用、input tokens 异常。
- 给短期处理建议和长期治理建议。
- 不要只说“减少调用”，要指出具体任务类型。
```

## 8. 4SAPI 的位置

这篇其实就是 4SAPI 的核心价值之一：

```text
统一入口。
统一 Key。
统一日志。
统一预算。
统一模型路由。
```

如果每个业务各自直连模型供应商，你很难生成日报。

统一进 4SAPI 后，才能看清：

```text
项目维度。
团队维度。
模型维度。
任务维度。
成本维度。
```

## 9. 成本日报和业务结果要连起来

只看成本还不够。

最好把成本和结果放一起：

```text
内容生成：花了多少钱，产出了多少篇，发布了多少篇。
客服摘要：花了多少钱，节省多少人工时间。
代码审查：花了多少钱，发现多少 P1 风险。
RAG 问答：花了多少钱，解决率多少。
```

这样才能判断：

```text
贵但值得。
便宜但没用。
看似便宜但返工多。
看似贵但节省人工多。
```

Fable 5 可以帮你做这类经营判断。

低成本模型负责每天整理数据。

## 10. 月度复盘问题

每个月问 AI：

```text
哪些任务应该继续用 Fable 5？
哪些任务应该降到低成本模型？
哪些 Prompt 版本成本更低？
哪些 Key 经常超预算？
哪些项目的模型成本没有对应业务产出？
哪些失败重试最浪费钱？
```

这才是企业级大模型接入的长期价值。

不是只接通 API。

而是把模型能力变成可运营资产。

## 11. 成本日报里的三种动作

成本日报最后一定要落到动作。

我一般分三类：

```text
止血动作。
优化动作。
投资动作。
```

止血动作是今天就要做的：

```text
暂停异常 Key。
限制某 task_type 的并发。
把重试从 3 次降到 1 次。
给 Fable 5 调用加人工确认。
```

优化动作是一周内做的：

```text
把长上下文先摘要。
把高频低价值任务降到低成本模型。
把 Prompt 中无用上下文删掉。
把批量任务改成异步队列。
```

投资动作是值得继续花钱的：

```text
代码 Review 发现了真实 P1 风险。
客户成功摘要节省了大量人工。
RAG 问答提升了工单解决率。
Fable 5 在关键方案审查上减少返工。
```

不要把成本日报写成“少花钱日报”。

它应该告诉你：

```text
哪些钱浪费了。
哪些钱花得值。
哪些钱应该换模型花。
```

## 12. 日报字段示例

一条异常记录可以这样写：

```text
date: 2026-07-03
project: content-agent
key_group: prod-batch
task_type: article_review
model: Fable 5
request_count: 74
cost_change: +312%
input_tokens_change: +246%
retry_count: 21
main_reason: 上游把整篇资料包重复放入每次请求
action: 先用低成本模型压缩资料包，Fable 5 只审最终方案
owner: 内容系统负责人
deadline: 今日
```

这比一句“成本上涨”有用得多。

如果 4SAPI 日志字段足够完整，低成本模型每天就能生成这种异常卡片。

Fable 5 只需要审查最贵、最危险、最影响业务的几条。

## 13. 和预算系统联动

成本日报最好不是孤立文档。

它要反过来推动预算系统。

比如日报发现：

```text
某项目连续 3 天超过日预算 80%。
某 Key 的失败重试消耗超过正常调用。
某低价值任务长期调用高级模型。
```

就应该触发：

```text
预算告警。
Key 限流。
模型路由降级。
负责人确认。
SOP 更新。
```

4SAPI 的优势是这些动作可以在同一个中转层里完成。

如果每个业务系统各自直连模型，日报最多只能提醒。

统一到 4SAPI 后，日报可以变成治理入口：

```text
看见问题。
定位责任。
调整路由。
限制预算。
复盘效果。
```

这才是企业级大模型接入从“能用”走向“可运营”的关键。

## 14. 总结

模型调用成本日报，是 AI 落地后的仪表盘。

它能让你每天知道：

```text
哪里在创造价值。
哪里在浪费 token。
哪里需要降级模型。
哪里需要升级 Fable 5。
哪里需要人工介入。
```

一句话：

```text
大模型成本治理，不是少用模型，而是每天知道模型用到哪里去了。
```
