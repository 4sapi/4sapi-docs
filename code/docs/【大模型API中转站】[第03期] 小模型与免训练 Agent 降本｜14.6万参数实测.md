# 【大模型API中转站】[第03期] 小模型与免训练 Agent 降本｜14.6万参数实测

降本不一定要换供应商。作为 4sapi 团队的接入实战记录，这一篇记录小模型与技能库两条降本路线的成本逻辑、接入示例与验证方法。

## 一、开篇：账单上最刺眼的两个数字

接入大模型 API 久了，账单上最刺眼的两个数字是：**token 消耗**和**训练/微调成本**。

- 业务量一上来，每次对话都过千 token，月账单跟着涨；
- 想给 Agent 调优，一听说要微调模型，成本直接劝退；
- 更隐蔽的是"重复劳动"：同一个任务反复让大模型从头推理，每次都付全价。

这一期讲两条我实测过、不用动大模型也能明显降本的路线：

1. **小模型路线**：用极小参数量的专用模型扛住高频、结构化的任务；
2. **免训练路线**：让 Agent 把跑通的工作流沉淀成技能，越用越省，全程不训练。

## 二、原理速览：两条路线的降本逻辑

### 小模型路线：算周期，不学周期

绝大多数时序预测、格式化输出类任务，背后的结构其实很"机械"——比如预测周期性数据，周期是能算出来的，根本不需要用几十亿参数去"背"。

实测里有个典型案例：一个只有 **146,505 个参数**（约 14.65 万）的零样本预测器，用零参数的谱检测器先算出主周期，再按相位折叠上下文，最后用卷积编码器 + 分位数解码器输出预测分布。它比 GIFT-Eval 榜单上所有能确认参数量的零样本模型都小，却在概率精度上定义了"小模型-精度前沿"。

```text
传统路线：大模型 → 硬背模式 → 每 token 都贵
小模型路线：算周期 → 折叠上下文 → 只算必要参数
```

### 免训练路线：把流程变成技能

Agent 在推理时能构造工作流，但跑完就丢，下次同样的任务又要从头推理一遍——这就是重复付钱。

免训练框架的思路是：**成功的流程编译成可调用技能，存进持久技能库**，下次直接检索复用：

```text
第一次跑通 → 编译成技能 → 存入技能库
再次遇到同类任务 → 检索技能 → 直接执行或作为上下文参考
```

模型没动一个参数，但同一个任务的推理成本断崖式下降。更进一步，还可以把"可进化的脚手架"按任务族维护，底层模型保持冻结，用环境反馈持续重写外层 harness——依然全程免训练。

## 三、方案一：小模型扛高频任务

### 适用场景

- 周期性数据预测（销量、流量、水位）；
- 固定格式抽取（日志解析、字段提取）；
- 高频低难度的批量任务。

### 接入示例

```python
import requests

# 假设已部署 14.65 万参数的预测模型服务（本地或经网关转发）
BASE = "https://4sapi.com/v1"   # 中转网关，统一管理多模型路由

def forecast(context: list[float], horizon: int = 12) -> list[float]:
    r = requests.post(f"{BASE}/predict", json={
        "context": context,      # 历史序列
        "horizon": horizon,      # 预测长度
    }, timeout=10)
    r.raise_for_status()
    return r.json()["quantiles"]["p50"]

# 高频调用：每条序列一次预测，token 开销接近零
series = [120, 131, 128, 142, 155, 149, 163, 171, 168, 182]
print(forecast(series))
```

### 成本对比

| 方案 | 参数量 | 单次成本 | 适用任务 |
| --- | --- | --- | --- |
| 通用大模型 | 数十亿–数千亿 | 高（按 token） | 强推理、开放生成 |
| 专用小模型 | 14.65 万 | 极低 | 预测、抽取、结构化输出 |
| 规则/查表 | 0 | 最低 | 完全确定性的逻辑 |

实测经验：**凡是能写清楚"规则"的任务，都不该让大模型按 token 计费**。小模型把这类任务的单位成本压到接近零，且延迟更低。

## 四、方案二：免训练 Agent 技能库

### 工作流

```text
任务 A 跑通
   ↓
提取成功步骤 → 编译为技能（含参数签名与调用方式）
   ↓
写入技能库（持久化）
   ↓
任务 B 触发 → 检索技能库
   ├── 命中 → 直接执行技能（零推理或低推理成本）
   └── 未命中 → 正常推理 → 成功后再次沉淀技能
```

### 接入示例

```python
import json

class SkillLibrary:
    def __init__(self, store_path: str = "skills.json"):
        self.store_path = store_path
        try:
            with open(store_path, encoding="utf-8") as f:
                self.skills = json.load(f)
        except FileNotFoundError:
            self.skills = {}

    def save_skill(self, name: str, workflow: dict):
        """把跑通的工作流编译成可复用技能"""
        self.skills[name] = {
            "steps": workflow["steps"],
            "signature": workflow.get("signature", {}),
            "hit_count": self.skills.get(name, {}).get("hit_count", 0),
        }
        with open(self.store_path, "w", encoding="utf-8") as f:
            json.dump(self.skills, f, ensure_ascii=False, indent=2)

    def get_skill(self, name: str) -> dict | None:
        skill = self.skills.get(name)
        if skill:
            skill["hit_count"] = skill.get("hit_count", 0) + 1
        return skill

lib = SkillLibrary()
# 第一次：跑通后沉淀
lib.save_skill("weekly_report", {"steps": ["拉数据", "汇总", "生成 MD"], "signature": {"weeks": 1}})
# 之后：直接命中，不再整段推理
skill = lib.get_skill("weekly_report")
print(skill)
```

### 成本曲线

```text
第 1 次调用：完整推理（贵）
第 2–10 次：命中技能，直接执行（近乎免费）
长期：技能库越用越厚，重复推理越来越少
```

配合"冻结模型 + 进化 harness"的思路，任务族专属的脚手架还能持续吸收反馈，模型参数始终不动——训练成本为零，只有推理成本。

## 五、方案三：组合拳——按任务路由到最便宜的执行路径

最优配置往往是混合的，我按这个决策树路由：

```text
任务进来
 ├─ 确定性逻辑？→ 规则/查表（0 成本）
 ├─ 高频结构化？→ 小模型（极低成本）
 ├─ 技能库命中？→ 直接执行技能（近零成本）
 └─ 复杂开放任务？→ 大模型 + 成功后沉淀技能
```

## 六、成本与风险提示

- **小模型有边界**：14.65 万参数扛不动开放生成、多步推理，硬上会牺牲质量；
- **技能库要验证**：沉淀技能前必须确认流程真的成功，错误流程入库会放大错误；
- **技能漂移**：环境变了（API 升级、字段变化），旧技能要能失效回退到完整推理；
- **监控命中率**：技能命中率长期偏低说明任务在变，需要重新沉淀。

## 七、实施清单

1. 梳理现有任务，标出"高频、结构化、低难度"三类；
2. 对这类任务跑小模型 POC，对比质量与成本；
3. 给 Agent 加技能库，跑通流程即沉淀；
4. 设置技能命中率与成本监控看板；
5. 每季度复查技能库，清理失效技能。

## 八、效果怎么验证

降本改造有没有效，别凭感觉，按三个指标验收：

| 指标 | 看什么 | 达标线 |
| --- | --- | --- |
| 单任务成本 | 每次任务实际消耗（元） | 改造后下降 ≥50% |
| 任务成功率 | 技能/小模型输出可用比例 | 与大模型基线持平 |
| 技能命中率 | 命中技能库的任务占比 | ≥40% 才算沉淀有效 |

监控脚本示例：

```python
def report_metrics(cost_before, cost_after, hit_rate, success_rate):
    print(f"单任务成本: {cost_before:.2f} -> {cost_after:.2f}")
    print(f"技能命中率: {hit_rate:.0%}  成功率: {success_rate:.0%}")
    if cost_after > cost_before * 0.5:
        print("警告: 降本未达标，检查路由与技能质量")
```

## 九、避坑提示

- **别为省 token 牺牲质量**：先验证质量持平，再切小模型；
- **别把所有流程都入库**：一次性的、低价值的流程不值得占库位；
- **别让技能库变成黑盒**：每次沉淀都记录来源任务与验证结果；
- **别忽略失败重试成本**：小模型成功率不足时，重试会把省下的钱吃回去。

## 总结

降本不一定要换更便宜的供应商，先把"任务该由谁来执行"想清楚：确定性逻辑走规则，高频结构化走小模型，跑通的工作流走技能库，只有真正复杂的开放任务才值得付大模型的 token 钱。两条路线叠加，账单能明显瘦一圈。
