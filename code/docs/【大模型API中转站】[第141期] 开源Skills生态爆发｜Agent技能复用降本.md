# 【大模型API中转站】[第142期] 开源Skills生态爆发｜Agent技能复用降本

OpenAI 官方发布了 openai/skills，把 Codex 的 Skills Catalog 开源出来，技能生态第一次被官方化。今天我在 4sapi（https://4sapi.com）上核对调用账单时，正好想借这个话题，把"方法论重复贴进 prompt"这笔账算清楚。

## 一、痛点：方法论每次贴进 prompt，成本高还总忘

我过去用 Agent 干活，最大的浪费不是模型选贵了，而是同一段方法论被一遍遍重贴。

每次让 Agent 处理任务，都要先把机构规范、编码约定、输出格式、验收标准写进 prompt。几百行规则就是几千 token，每贴一次就烧一次钱。贴得少，Agent 就按自己的默认行为来，质量飘忽；贴得全，上下文膨胀，成本直线上升。两头都是亏。

更麻烦的是"忘"。经验写在某个会话里，会话一关就找不到了。同一个坑，过两周再踩一遍；同一套规范，新任务里又要重新写一次。人脑靠记忆，Agent 靠上下文，上下文不持久，方法论就永远是临时工。

这个痛点的根源在于：我把知识写在了"每次都会过期"的地方（prompt），而不是"可以长期复用"的地方（文件）。只要换个落点，成本和质量的问题可以一起解决。

## 二、生态爆发：今天的 GitHub 趋势榜

今天我的 GitHub 趋势榜上，Skills 相关仓库挤成一团，这是以前没见过的情况。

- **openai/skills**：OpenAI 官方把 Codex 的 Skills Catalog 开源，技能生态第一次被官方化。官方下场意味着文件格式、触发机制、目录约定正在变成事实标准。
- **superpowers**（约 28 万星）：Agent 技能框架与软件开发方法论，把一整条工程纪律打包成可加载的技能集合。
- **ECC**（约 25 万星）：Agent Harness 性能优化系统，覆盖技能、直觉、记忆、安全四块，目标是把 Agent 跑得更稳更快。
- **andrej-karpathy-skills**（约 21 万星）：一个 CLAUDE.md 文件改善编码行为，用最小改动约束 Agent 的编码习惯。
- **marketingskills**：营销场景的技能集合。
- **diagram-design**：图表与架构图设计的技能。
- **i-have-adhd**：面向 ADHD 人群的任务管理技能，把大任务拆成可执行的小步。

一条清晰的信号：技能正在从"个人提示词技巧"变成"开源基础设施"。方法论只要写进文件，全世界都能复用，成本被摊薄，质量被反复打磨。

## 三、原理速览：Skills 到底是什么

Skills 的实质，是把一段方法论打包成一个可加载、可匹配、可执行的文件单元。拆开看是三部分：

- **触发描述（front matter）**：一段写给 Agent 看的说明，告诉它"什么任务该加载这份技能"。只占几百字符，用于匹配，不参与执行。
- **指令正文**：真正的方法论。检查顺序、输出格式、验收标准、注意事项，全部写在这里。
- **可执行脚本（可选）**：把可以自动化的部分（校验、格式化、查重）写成脚本，Agent 按需调用。

一次调用的完整链路：

```text
任务
  |
  v
匹配 skill（Agent 读触发描述，判断是否命中）
  |
  v
注入指令（命中则把指令正文放进上下文，脚本挂载为可用工具）
  |
  v
执行（Agent 按指令干活，必要时调用脚本）
```

关键在"匹配"这一步：Agent 只需要读几百字符的触发描述就能决定要不要加载，而不是把全部方法论都塞进上下文。这就是 Skills 在原理层面就能省 token 的原因。

## 四、为什么是 token 成本与质量的双赢

同样一套方法论，贴进 prompt 和装成 skill，账完全不一样。

**技能文件替代长提示词。** 方法论写一次，之后每次调用只付触发描述那几百字符的匹配成本，正文按需注入。重复十次的任务，提示词只写一次，省的是九次完整重贴。

**复用机构知识。** 团队规范、代码风格、上线检查单、客服话术，这些本该是资产的知识，从"每次手写"变成"一次编码"。新人接手、换模型、换工具链，知识都不丢。

**压缩每次调用的上下文。** 上下文越短，单次调用越便宜、越不容易遗忘、输出越稳定。短上下文还有一个被低估的好处：模型在短上下文里注意力更集中，质量波动更小。省成本和质量提升，是同一件事的两面。

## 六、自建技能：目录结构与 front matter

自己搭技能库，我从一个最小目录开始：

```text
skills/
└── code-review/          # 一个技能一个目录
    ├── SKILL.md          # 触发描述 + 指令正文
    └── scripts/          # 可执行脚本（可选）
        └── check.py
```

SKILL.md 的 front matter 只做一件事：让 Agent 在低开销下判断要不要加载。

```yaml
---
name: code-review
description: Use when 收到代码审查请求，需要按项目规范逐项检查
---
```

description 写"何时用"，不写"怎么干"。写得越具体，命中越准：泛泛的"审查代码"会让它在不该加载时也加载，白白多烧上下文。我调试过的最常见问题，就是 description 写成了流程摘要，结果 Agent 只照着 description 做，根本不读正文。

技能正文再写检查顺序、输出格式、常见错误，脚本放校验逻辑。整套跑在我的统一接入层上：本地技能目录 + 4sapi（https://4sapi.com）接入 Claude，命中的技能注入 system prompt 后发请求。

## 七、自建技能：用真任务触发测试

技能是给 Agent 用的，不是给人读的，所以测试必须用真任务。

我的测试流程是固定的四步：

1. 拿一个真实的历史任务当测试用例，先不挂技能跑一遍，记录基线输出；
2. 挂上技能再跑一遍，确认技能被触发、正文被注入、输出符合预期；
3. 换两个变体任务，看技能在边界场景下会不会误触发、漏触发；
4. 输出不稳定就回去改 description 或正文，改完重跑。

没有真实任务验证过的技能，我默认它不工作。凭空写的技能最容易犯的错，是以为 Agent 会像我一样理解上下文——实际上它只认 description 里的触发词。

## 八、自建技能：守卫语句

技能是可执行指令，不是说明文档，所以每个技能文件里都要有守卫语句，把边界写清楚。

```text
## 守卫
- 仅当任务目标涉及 X 时才执行本技能；
- 如果输入包含敏感信息（密钥、个人数据），停止并询问；
- 如果执行结果与预期不符，先输出差异说明，不自动重试；
- 不覆盖任何现有文件，所有修改先出 diff。
```

守卫语句的作用是防止两件事：**误触发**（任务不匹配时技能自己跳出来指手画脚）和**越界执行**（Agent 拿到技能就放开了干，忘了哪些不能碰）。守卫写得越具体，Agent 在模糊场景下越容易正确停下。

## 九、技能服役与退役标准

技能库会膨胀，所以我的技能库有明确的服役与退役标准。

**服役标准**（三条全满足才转正）：

1. 在真实任务中被连续命中 5 次以上，没有误触发记录；
2. 输出稳定，同一输入多次运行结果一致；
3. 职责单一，不与已有技能重叠。

**退役标准**（满足任一条就退役）：

1. 连续 90 天零触发——没人用的技能说明方法论过时或描述失准；
2. 被新技能或新工具替代——旧技能直接归档，不保留两份；
3. 引用的知识已过期（框架版本、接口参数变了），无法低成本更新。

退役不是删除，是归档。归档目录里的技能不参与匹配，不烧任何 token，但保留历史，随时可查可复活。

## 十、成本与风险提示

Skills 降本是真，风险也是真的，我踩过几个坑，逐一记下：

- **技能膨胀**：技能越攒越多，匹配列表越来越长，每次调用都要遍历。技能库要按服役/退役标准持续清理，而不是只进不出。
- **过期知识**：技能文件里的规范会随着框架、政策更新而过期。过期知识比没有知识更危险，因为它看起来权威。技能要定期复查来源和时效。
- **注入风险**：技能本质是一段会被注入到系统上下文的可执行指令。第三方技能里可能藏了"忽略之前所有指令"之类的恶意文本，也可能藏了危险的脚本命令。装第三方技能之前，必须读一遍源码，脚本逐行审。
- **第三方代码审查**：来自生态的技能默认不可信。我审查的顺序是：front matter 的 description 是否含诱导性措辞 → 正文是否有越权指令 → scripts 里的脚本是否有网络请求、文件删除、环境变量读取。全部通过才进库。

**合规底线**：接入一律走合法渠道，API 接入用正规中转服务，知识管理遵守数据安全规范——机构内部资料、客户数据不写进公开技能库，敏感技能留在本地并做权限控制。

## 十一、验收清单

技能库接入完成前，我逐条过一遍：

1. 每个技能有独立目录，front matter 的 description 写"何时用"且足够具体；
2. 用真实任务验证过触发：该命中的命中，不该命中的不误触发；
3. 技能文件包含守卫语句，边界场景下 Agent 会停下而不是越界执行；
4. 第三方技能全部通过源码审查，无诱导性描述、无越权指令、无可疑脚本；
5. 技能库按服役与退役标准管理，没有长期零触发的僵尸技能；
6. 敏感知识不落公开库，机构数据按合规要求脱敏与权限隔离；
7. 单次调用的上下文有对比基线：挂技能前 vs 挂技能后，token 下降且质量不降。

这七条全过，技能库才算接入完成。

## 十二、总结

OpenAI 官方开源 openai/skills，把 Codex 的 Skills Catalog 变成生态标准，superpowers、ECC、andrej-karpathy-skills 等仓库把技能从个人技巧变成开源基础设施。Skills 的本质是把方法论固化成"触发描述 + 指令正文 + 可执行脚本"的文件单元，用文件替代每次重贴的长提示词，压缩每次调用的上下文，同时让机构知识可复用、可审计。我的接入路径是：本地技能目录 + 4sapi（https://4sapi.com）统一接入，真任务测试驱动，服役与退役标准管理，第三方技能先审后用。欢迎在评论区聊聊我的技能库是怎么搭的、踩过哪些坑。
