# 【大模型API中转站】[第246期] RAG 时效性治理｜检索到旧文档会让答案反向

检索增强最常见的卖点是"补上模型不知道的新信息"，但很少有人说清它的反面：**检索也可能把模型本来知道的正确答案改错**。

我把这类问题叫时间对齐失效——检索到的证据本身没问题，只是它已经过期了。它比幻觉更难发现，因为答案读起来有理有据，还带着引用。在 4sapi（https://4sapi.com）上跑检索类工作负载时，这套治理流程是我目前固定下来的做法。

## 一、先看清失效模式：不检索时答对，检索后答错

判断一个系统有没有这类问题，有一个很干净的对照实验：同一个问题，一次走检索、一次不走检索，比对答案。

如果**不检索时答对、检索后答错**，那就不是模型的知识缺口，而是检索把错误的时间版本证据推进了上下文。这个方向性很重要：它意味着增加检索量、提高召回率、换更强的模型，都不会让问题变好，反而可能让它更频繁地发生。

我见过的典型场景是接口说明与政策条款：旧版文档还留在索引里，检索器按相似度把它排在前面，模型忠实引用，答案就停在过去。

## 二、把时间对齐拆成两件事

治理这类问题的第一步是拆解。证据的可用性由两个互相独立的判断组成：

一是**语义相关性**——这段内容是否在讲同一个主题。这是向量检索与重排器一直在做的事。

二是**时间适用性**——这段内容在当下是否仍然成立。这件事现有链路基本没做。

两者正交。一段 2019 年的文档可以在语义上完美匹配今天的问题，同时完全失效。把两个判断混成一个相似度分数，是这类失效长期被掩盖的根因。

```text
用户提问
    |
    v
[语义相关性]  向量召回 + 重排        <- 现有链路覆盖
    |
    v
[时间适用性]  生效/失效时间比对      <- 常被漏掉的一层
    |
    +-- 通过 -> 进入上下文
    +-- 过期 -> 丢弃 / 降权 / 显式标注为历史版本
```

## 三、量化：过期证据的翻转率有多高

这件事的严重程度可以用一组对照数字说明。在一份覆盖医学、法律、软件与平台政策四个领域、基于有日期官方来源构建的 **317 个已验证知识反转**基准上，跨 **12 个模型**测试的结果是：

- **过时检索在没有任何"信任该文档"指令的情况下，翻转了 30% 的 Llama 与 37% 的 Qwen 答案**。也就是说，模型只是"看到了"旧文档，就改变了原本正确的回答。
- **而显式给出"请依据文档回答"一类指令，会把这一比例推高到 66% 与 75%。**
- 在四个开源模型与四个领域上，投毒率介于 **17%–91%**。
- 作为对照，**匹配的最新证据在 97%–100% 的实验中被遵从**。

另外，反转的**新旧程度**也有影响：近期发生的医学反转，比长期确立的结论更难处理。

这里最该记住的是那个 17%–91% 的区间：同一套检索管线，换一个模型，过期证据造成错误的比例可以差出五倍以上。这说明**时效风险不是一个固定的系统属性，而是与选型强耦合的**——换模型时必须重测。

要在自己的系统里测出这个比例，方法并不复杂，也不需要标注新数据：从已有的知识反转类问题里挑一批，每条保留一份历史版本证据与一份当前版本证据，然后只把历史证据喂给模型，看答案跟着哪一边走。跟旧证据走的那部分，就是当前管线的时效失效率。这个数字应当作为检索系统的常规监控项，和召回率、答案正确率一起看，而不是等出了错再回头查。

## 四、为什么"请依据文档回答"会让情况更糟

上一条里最反直觉的数字是 30% 到 66%、37% 到 75% 的跳变。为了减少幻觉，工程上普遍会加一句"只依据检索内容回答、不要凭记忆"。这句话在减少模型自由发挥的同时，也**取消了模型对文档的怀疑权**。

结果就是：文档过期时，模型被要求忠实，于是忠实地给出过时答案。约束越强，时效失效越彻底。

这引出一条设计原则：**忠实性约束必须与时效校验配套出现**。只加忠实性、不加时效判断，等于把检索的错误放大成系统的错误。

## 五、检索链路的时效校验全链路

我固定下来的链路如下，时间校验分布在入库、检索与生成三段：

```text
文档入库
    |
    +-- 抽取并校验时间元数据（生效时间 / 失效时间 / 来源 / 版本 / 替代关系）
    +-- 建立版本替代链，旧版本标记为 superseded
    |
    v
检索
    |
    +-- 语义召回
    +-- 时效过滤：排除已失效文档；保留但标注历史版本
    +-- 时效感知重排
    |
    v
生成
    |
    +-- 上下文内显式标注每段证据的有效期
    +-- 提示词告知"旧证据从何时起不再适用"
    |
    v
输出
    |
    +-- 答案时效校验：结论是否依赖了已过期区间
```

## 六、时间元数据的最小字段集

整套治理的地基是元数据。缺了它，后面的过滤与重排都无从谈起。我要求入库时必须带齐这几项：

| 字段 | 作用 | 缺失后果 |
| --- | --- | --- |
| 生效时间 | 该版本从何时开始适用 | 无法判断是否早于当前时点 |
| 失效时间 | 该版本到何时不再适用 | 无法自动淘汰旧版本 |
| 来源与可信级别 | 决定冲突时采信哪一方 | 官方与二手内容无法区分 |
| 版本号 | 同一主题的多版本排序 | 无法建立替代链 |
| 替代关系 | 被哪一版取代 | 旧文档无法自动降权 |
| 抓取时间 | 区分内容时间与获取时间 | 把抓取时间误当生效时间 |

最后一行是最常见的错。页面的抓取时间与内容的生效时间是两回事：一份 2023 年的政策文件今天被抓取，抓取时间是今天，生效时间仍是 2023 年。若用抓取时间做时效判断，所有旧文档都会被当成新的。

## 七、提示词设计：只给当前日期 vs 显式告知失效时点

时间信息怎么给模型，效果差别很大。一组对照实验很能说明问题：在 50 个知识反转上**保持历史证据不变、只改评测日期**，得到两个不同量级的结果：

**只给出当前日期时，模型只表现出有限的适应**——它知道现在是哪一年，但不会自动推出"这份文档已经过期"。

**当明确告知旧证据从何时起不再适用时，较大的模型几乎完美地切换到正确答案。**

因果干预进一步确认，这条"有效性信息"直接塑造了最终决策，而不是仅作为一种提示被忽略。

这条结论的可操作性很强：与其让模型自己推算文档时效，不如在拼装上下文时就把有效期写进去。两种写法的差别大致如下。

| 写法 | 上下文里给什么 | 模型需要自己做的事 | 效果 |
| --- | --- | --- | --- |
| 只给当前日期 | "今天是 2026-09-28" | 推断每段证据是否过期 | 适应有限 |
| 标注证据有效期 | "该条款适用至 2025-06-30" | 只做一次比对 | 切换准确 |
| 显式失效声明 | "此政策已于 2025-07 被新版取代，新版见下条" | 无需推断 | 最稳 |

## 八、时效感知重排的实现要点

过滤解决"明确过期"，重排解决"新旧共存时的排序"。一个固定的时效感知混合重排器在**日期准确**的前提下，把过期证据造成的错误降低了 **4.6–10.0 个百分点**。

注意这里的限定条件：**增益依赖可靠的时间元数据**。日期不准，重排器的收益会显著缩水甚至反向。所以顺序不能颠倒——先把元数据做对，再上重排；不要用重排去弥补元数据的缺失。

我在实现时会坚持三条：

第一，时效信号作为独立特征参与排序，不直接混进相似度分数，便于单独调参与归因。

第二，新旧冲突时保留旧文档但降权，而不是直接删除。旧文档对"历史沿革"类问题是有效证据。

第三，把"是否已过期"作为重排结果的可见字段输出，让下游能审计。

## 九、优先治理哪些文档

不必一次治理全库。按"会发生知识反转"的程度排优先级，收益最高：

1. **价格与计费口径**——最常反转，且错了直接影响结算。
2. **政策与法规条款**——有明确生效与废止日期，元数据最容易补齐。
3. **接口与 SDK 说明**——版本迭代快，旧参数会让代码跑不通。
4. **医学与临床指南**——反转频率高，且近期反转比长期结论更难处理。
5. **平台规则与准入条件**——常以公告形式发布，容易被当成长期有效。

反过来，原理性、历史性的内容可以放低优先级：它们不随版本失效。

## 十、时效回归测试怎么设计

这类问题很容易在改版后回归，所以要进持续集成。我用的测试结构是：

固定一批"知识反转"问题，每条都准备**两份证据**——旧版本与当前版本——然后跑三组对照：只给旧证据、只给新证据、两者都给。观察三组答案是否与预期一致。

其中最关键的一组是"只给旧证据"：它测的不是模型知识，而是**系统的时效防线是否生效**。若这组答案跟着旧证据走，说明过滤与提示词都没起作用。

## 十一、接入示例：把时效过滤做成网关能力

下面这段代码把时效过滤与两种提示词模板做成可切换的能力，便于做上面的对照实验。Key 从环境变量读取，接口走 OpenAI 兼容格式。

```python
import os
from datetime import date, datetime
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("FOURSAPI_API_KEY"),
    base_url="https://4sapi.com/v1",
)

TODAY = date(2026, 9, 28)


def is_expired(doc, today=TODAY):
    """失效时间为空视为长期有效。"""
    exp = doc.get("expires_at")
    if not exp:
        return False
    return datetime.strptime(exp, "%Y-%m-%d").date() < today


def render_evidence(doc):
    """把有效期写进上下文，而不是只给当前日期。"""
    if doc.get("superseded_by"):
        head = f"[历史版本] 本条已于 {doc['expires_at']} 被新版取代，仅用于追溯历史沿革。"
    elif doc.get("expires_at"):
        head = f"[有效] 本条适用于 {doc['effective_at']} 至 {doc['expires_at']}。"
    else:
        head = f"[有效] 本条自 {doc.get('effective_at', '未知')} 起适用，未声明失效时间。"
    return f"{head}\n来源：{doc.get('source')}\n内容：{doc['text']}"


def answer(question, docs, allow_stale=False, today=TODAY):
    kept = [d for d in docs if allow_stale or not is_expired(d, today)]
    dropped = [d for d in docs if is_expired(d, today)]

    ctx = "\n\n".join(render_evidence(d) for d in kept) or "（无可用证据）"
    system = (
        f"当前日期：{today.isoformat()}。"
        "只依据给出的证据回答。若证据标注为历史版本或已失效，"
        "必须明确说明该信息已不再适用，并说明其失效时点，不得当作现行规则陈述。"
    )
    if dropped:
        system += " 已排除 " + str(len(dropped)) + " 条过期证据。"

    resp = client.chat.completions.create(
        model="gpt-6-sol",
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": f"证据：\n{ctx}\n\n问题：{question}"},
        ],
        temperature=0,
    )
    return resp.choices[0].message.content
```

把 `allow_stale` 打开再跑同一批问题，就能看到没有时效防线时的答案会偏到哪去。这个开关是我做时效回归测试的主要工具。

## 十二、成本与风险提示

- **元数据维护是持续成本**，不是一次性工作。文档每更新一次，就要同步失效时间与替代关系，否则防线会随时间自然失效。把这项要求写进入库流程，比事后补标注便宜得多。
- **失效时间写错比没有更危险**。标错失效时间会让有效文档被误杀，或者过期文档被放行。建议对价格、法规这类高风险文档加人工复核。
- **换模型必须重测时效防线**。过期证据造成的错误率在 17%–91% 之间浮动，同一套管线换模型后的表现无法外推。
- **不要把时效问题当成提示词问题**。提示词能提升模型对有效期的敏感度，但过期文档只要进了上下文就会持续干扰，过滤与重排才是主干。
- **保留原文与版本链**。审计时需要还原"当时依据的是哪一版"，只留摘要会丢失这项能力。

## 结论

检索增强的失效有两种，语义不相关是明面上的，时间不适用是暗处的。后者更值得投入，因为它会让本来正确的答案变错，而且答案带着引用，看不出问题。治理路径已经很清楚：补时间元数据、在检索链路上加一层时效判断、把有效期显式写进上下文、用时效感知重排处理新旧共存、再用"只给旧证据"的对照做回归测试。这五步都不依赖模型能力提升，做完了系统的可靠性才是可预测的。我在 4sapi.com 上把这些环节串起来跑过之后，最大的变化不是模型换了，而是终于能说清"这个答案是依据哪一版证据给出的"——可追溯本身就是时效治理的产物。
