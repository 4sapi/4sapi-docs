# 【大模型API中转站】[第147期] NeoHorse数据飞轮｜4B小模型逼近9B省成本

Agent 时代的账单越来越像开盲盒：能力强的模型按 token 计价毫不手软，便宜的模型又总在最关键的一步掉链子。NeoHorse-1 把"路由记录"变成"训练养料"，让 4B 小模型在 11 项基准上逼近 9B——4sapi.com 的中转路由每天产生大量分级调用记录，这套数据飞轮思路直接戳中了我。

## 先说痛点：token 单价压得预算喘不过气，小模型又常掉链子

大模型 token 单价压得预算喘不过气，这句话我大概重复了上百遍。Agent 工作流一跑起来，一轮任务几十次模型调用，系统提示词、工具结果、中间推理来回灌进上下文，输入输出 token 双双膨胀，月末账单的增长曲线经常比业务曲线还要陡。

换小模型呢？单次调用的单价和延迟都好看，可复杂任务一上强度就露怯：工具调用参数填错、多步规划中途跑偏、长指令读到一半忘了前半截。返工重试的隐性成本，常常把省下来的钱原路吃回去。

所以我一直在做最经典的分级路由：简单问题走小模型，难题兜底走大模型。这招立竿见影，但天花板明显——路由只是让钱花得更准，模型本身的能力曲线一点没动。NeoHorse-1 妙就妙在，它把路由从"省钱手段"升级成了"训练信号的产生端"。省钱的上限，从此由训练闭环决定，而不是由路由表决定。

## NeoHorse-1 是什么：把递归自我改进做成 agent 原生的后训练

NeoHorse-1 是一个探索递归自我改进（RSI, Recursive Self-Improvement）的 agent 原生模型家族，走的路径叫 agentic post-training。RSI 听起来科幻，拆开看很朴素：让模型在真实工作过程中生产数据，再用这些数据反过来改进模型本身，如此循环。传统后训练依赖人工造数据和静态数据集，天花板取决于标注预算；RSI 想让数据生产本身自动化——线上流量就是数据工厂，飞轮转起来就自己供血。

它的工程底座是异构模型池加智能路由：不同规格的模型同时在线，路由层按每个用户轮次的预测能力需求分配服务档位，并把档位选择与后续交互一并记录下来。这些记录不是日志柜里的陈列品，而是下一轮训练的原料。代码开源于 GitHub 的 TokenRhythm/NeoHorse，实现细节可以对着源码慢慢研究。

## 原理速览：一条从路由记录转回训练配比的飞轮

整条飞轮浓缩成一句话：路由记录变成训练样本，样本过三道准入后组成课程，课程产出能力，评估结果再回头改写训练配比，更强的模型接住下一轮线上流量。画成图是这样的：

```text
路由记录（预测能力需求 + 所选档位 + 后续交互）
        │  保留交错推理 / 工具调用 / harness 上下文
        v
样本准入（结构校验 → 六维语义评估 → 子场景级标注）
        │
        v
课程化训练（路由信号组织三阶段 SFT + routing-guided on-policy distillation）
        │
        v
评估（11 项基准：harness 型 agent / 工具使用 / 编码 / 指令遵循）
        │
        v
配比更新（capability-guided allocation，评估反馈变成下一轮训练配比）
        │
        └──────────> 回到路由：更强的模型接住下一轮线上流量
```

六个节点各有分工：路由记录负责"记账"，样本准入负责"质检"，课程化训练负责"消化"，评估负责"体检"，配比更新负责"开药方"，最后回到路由完成闭环。下面按顺序把关键几环掰开看。

## 三道准入：不是每条线上流量都配当训练样本

数据飞轮最怕的事故是"垃圾进、垃圾出"。线上流量里混着大量低价值轮次：答非所问的、敷衍了事的、甚至模型自己胡编的。NeoHorse-1 给样本设了三道准入，只有全部通过的记录才有资格进训练集。

第一道是结构校验：样本必须保留交错推理、工具调用与 harness 上下文——这正是 agent 轮次区别于普通问答的地方。丢了 harness 上下文的样本，等于把现场证据全删了，只留一问一答的骨架，训练价值大打折扣。

第二道是六维语义评估：从六个语义维度给样本打分，把"答案碰巧对、过程一团糟"的轮次挡在门外。agent 数据的特殊性在于过程即质量，一个错误的中间步骤比一个错误答案危害更大，因为它会被模型当成范式学走。

第三道是子场景级标注：每条样本落到具体子场景上，编码归编码、指令遵循归指令遵循。没有这一层，后续的课程编排和配比调整就是无米之炊——飞轮后面所有"按能力分配"的动作，都靠这层标注提供坐标。

## 课程化训练：路由信号变三阶段课程，教师在位监督

准入之后的样本怎么学？NeoHorse-1 用路由信号把监督微调（SFT）组织成三阶段课程。路由信号天然带着难度与能力标签——哪个档位接的单、任务属于哪类能力面——这比人工划课程更贴近真实流量分布：先易后难，按真实场景的密度安排学习顺序。

更有意思的一步，是把它扩展成 routing-guided on-policy distillation：教师在同一课程进程下，监督学生自己生成的回复。传统蒸馏是让学生背教师的标准答案，学生的真实错误分布根本没被覆盖；on-policy 的做法是让学生先自己答题，教师盯着学生自己的输出做纠正。学生的错误发生在哪，教学就落在哪——这恰好继承了路由信号的"按需"哲学：按能力需求选档位，按学生实际表现给监督。

## 能力引导分配：系统学会做什么，决定它接下来从什么里学

飞轮的最后一环叫 capability-guided allocation（能力引导分配）：把评估反馈直接转成下一轮的训练配比。哪类子场景掉分，下一轮就多喂哪类数据；哪类能力已经吃饱，就收缩配比省下预算。整个系统由此形成"评估-选择-更新"闭环。

这句话值得多读一遍：系统学会做什么，决定它接下来从什么里学。传统训练流程是"先攒数据、再训练、最后评测"的单行道，评测结果顶多影响下一版数据集的立项；飞轮把评测变成了训练的输入端，能力地图实时驱动数据预算的流向。所谓数据飞轮，转的其实就是这个闭环。

## 成绩单：4B 从 58.94 到 64.87，离 9B 只差半步

看数字。评测覆盖 11 项基准，横跨 harness 型 agent、工具使用、编码、指令遵循四类场景，指标取宏观平均分：

| 模型 | 后训练前宏观平均 | 后训练后宏观平均 | 提升 | 相对成本关系（比例描述） |
| --- | --- | --- | --- | --- |
| 4B | 58.94 | 64.87 | +5.93 | 参数量约为 9B 的 4/9，推理开销与 token 单价大体按同比例走低 |
| 9B | 65.60 | 69.04 | +3.44 | 质量兜底档，推理开销约为 4B 的 9/4 |

两组数字放在一起看，有两个结论。第一，后训练后的 4B 宏观平均 64.87，离 9B 基座的 65.60 只差 0.73 分——"小模型逼近大模型"不再是感觉，而是有宏观平均背书的事实。第二，4B 涨了 5.93 分，9B 只涨 3.44 分：小模型从飞轮里吃到的红利更大，因为它头顶上有一整个异构模型池当教师，能力天花板被外挂拉高了。省成本叙事的钥匙就在这。

## 成本账：省的是单价，也是延迟，更是返工

小模型替换大模型的省钱逻辑，我习惯拆成三层。

第一层是 token 单价。参数规模降一档，单价跟着降一截，量级通常是"几分之一"而不是"打九折"。Agent 场景的乘法效应明显：一轮任务几十次调用，单价差乘上调用次数，就是月账单上数量级的差距。

第二层是延迟。小模型推理更快，首 token 延迟和每 token 延迟都更低。Agent 循环里调用是串行叠加的，单次省半秒，一轮任务就是十几秒的墙钟时间差；对交互式产品来说，这部分比钱更影响体验。

第三层是返工成本。4B 后训练后宏观平均 64.87 逼近 9B 基座，意味着"大部分活交给 4B"有了数据支撑——把 9B 留给真正的硬骨头，兜底调用的比例降了，误判重试的次数少了，三层账一起省。

## 接入教程：用中转路由搭一个小型飞轮

飞轮的第一圈是路由与记录，这一步在任何 OpenAI 兼容的中转站上都能复刻。下面这段 Python 示例演示：按任务难度在 4B/9B 两档模型间路由，并把每个调用轮次的元数据落盘成 JSONL，方便后续脱敏回流。

```python
import json
import os
import time

from openai import OpenAI

client = OpenAI(
    base_url="https://4sapi.com/v1",  # OpenAI 兼容入口
    api_key=os.environ["SAPI_API_KEY"],  # 密钥只从环境变量读取，不写死在代码里
)

# 两档模型别名，按中转站后台实际配置替换
MODEL_LITE = "neohorse-4b"
MODEL_HEAVY = "neohorse-9b"

# 粗粒度难度信号：多步规划、代码执行、工具编排、超长上下文归入重档
HEAVY_HINTS = ("多步", "执行", "工具", "重构", "agent", "code")


def pick_model(user_text: str, history_len: int = 0) -> str:
    """按任务难度在 4B / 9B 两档之间路由。"""
    hit_heavy = any(h in user_text.lower() for h in HEAVY_HINTS) or history_len > 20
    return MODEL_HEAVY if hit_heavy else MODEL_LITE


def chat_once(user_text: str, history_len: int = 0) -> str:
    model = pick_model(user_text, history_len)
    started = time.time()
    resp = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": user_text}],
        temperature=0.3,
    )
    answer = resp.choices[0].message.content or ""

    # 记录"预测能力需求 -> 所选档位 -> 后续交互"，这就是飞轮的原料
    record = {
        "ts": time.strftime("%Y-%m-%dT%H:%M:%S%z"),
        "predicted_need": "heavy" if model == MODEL_HEAVY else "lite",
        "model": model,
        "history_len": history_len,
        "input_chars": len(user_text),
        "output_chars": len(answer),
        "latency_ms": int((time.time() - started) * 1000),
        "usage": resp.usage.model_dump() if resp.usage else None,
        "answer_head": answer[:200],  # 落盘前先过脱敏，别把敏感信息带进日志
    }
    with open("routing_trace.jsonl", "a", encoding="utf-8") as f:
        f.write(json.dumps(record, ensure_ascii=False) + "\n")
    return answer


if __name__ == "__main__":
    print(chat_once("写一个快速排序函数，并解释时间复杂度", history_len=6))
```

跑一段时间后，`routing_trace.jsonl` 里就攒出了飞轮的第一层原料。每个字段的含义对齐 NeoHorse-1 的设计：`predicted_need` 对应预测能力需求，`model` 对应所选服务档位，`latency_ms` 和 `usage` 记录后续交互证据。回流时先过结构校验、再脱敏、再按场景打标，就能分别沉淀成评测集与训练集——线上流量分级回流，评测集管"体检"，训练集管"进补"。示例只是工程骨架，正式回流前要把三道准入补齐。

## 避坑清单：飞轮落地前先想清楚的三类问题

飞轮方向对了，细节翻车的例子我见过不少。动手前先把这份 checklist 过一遍：

**数据质量**

- [ ] 样本准入有没有真挡住低质量轮次？结构校验、语义评估、场景标注，三道门槛缺一不可
- [ ] 样本分布是否偏向高频简单任务？难样本长期欠采样，飞轮只会把模型越转越"偏科"
- [ ] 记录是否保留了交错推理、工具调用与 harness 上下文？只剩问答骨架的样本不要混进训练集

**隐私与合规**

- [ ] 回流日志是否先脱敏再入库？手机号、邮箱、密钥、内网地址一个都不能留
- [ ] 日志留存范围与用途是否明确声明，用户是否知情
- [ ] 密钥与凭据是否永远只存在于环境变量，绝不落盘

**评估有效性**

- [ ] 评测集与训练集是否严格隔离？数据污染会让分数虚高，飞轮空转
- [ ] 宏观平均之外，弱项子场景有没有单独跟踪
- [ ] 路由策略本身有没有对照实验？别把"看起来更聪明"当成真提升

## 成本与风险提示：省钱不能省掉合规

几个务实提醒。第一，回流日志务必脱敏——这是数据合规的底线，不是可选项。日志里最值钱的是交互结构，最危险的是个人信息与凭据，入库前把后者清洗干净，飞轮才转得心安。

第二，路由判别会误判。把难题错分给 4B，返回质量下降触发重试，重试本身又是成本；建议保留 9B 兜底与快速降级通道，误判的代价用架构消化，而不是硬扛。

第三，警惕反馈回路放大偏差。模型学习自己生成的数据，天生有"自我强化"的倾向——NeoHorse-1 用三道样本准入和外部基准评估当锚点，就是在给回路装刹车。自建飞轮时同样要保留外部评测校准，否则分数会跟数据一起漂移。

第四，只做合法接入。多档路由、负载均衡、计费优化的空间都在官方 API 约定之内，任何绕过官方限制的方案都别碰——省小钱翻大车，不值。
