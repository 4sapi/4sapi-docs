# 【大模型API中转站】[第84期] 教育场景AI合规｜学校禁令的接入启示

纽约市长宣布对 8 年级及以下学校实施为期一年的 AI 禁令，理由是"以学生为先"：未经评估的工具不得进入课堂。这一决定在技术社区引发了高热度争论，而真正值得研究的，是禁令背后那条教育接入的红线。

## 一、开篇痛点：禁令只是暂停键，不是终点

禁令看起来是一刀切，本质却是给教育科技行业敲了一次合规警钟。教育场景接入大模型的难点从来不在 API 调用本身，而在于五个绕不开的问题：未成年人数据如何保护、内容安全如何过滤、学业诚信如何维护、教师能否完全可控、出事之后能否审计留痕。这五个问题不解决，禁令就会从一座城市扩散成普遍规则，教育科技产品就永远进不了课堂。

教育科技接入最稳妥的路径只有一条：在接入第一天就把合规当成架构的一部分，而不是上线前的补丁。4sapi 网关（https://4sapi.com ）在这一场景的价值，是把合规能力做成租户级策略，让每一所学校、每一个年级组都能独立配置、独立审计，同时保持上游模型调用与计费的高度透明。

## 二、原理速览：教育接入的请求流与治理链

教育场景的请求流比普通应用多出两层：身份识别层和策略执行层。学生或教师的请求先被应用层识别身份，再进入网关执行租户策略，最后才到达上游模型。

```text
学生终端 / 教师终端
        |
        v
教育应用（课程上下文、身份识别）
        |
        v
4sapi 网关（租户策略、内容过滤、用量限额、审计留痕）
        |
        v
上游大模型 API（GPT、Claude 等）
```

治理链则是另一条与请求流并行的链路，贯穿请求的整个生命周期：

```text
身份认证 -> 租户识别 -> 内容过滤 -> 用量限额 -> 审计留痕
```

四道闸门对应的风险与措施，可以用一张表概括：

| 闸门 | 主要风险 | 典型措施 |
| --- | --- | --- |
| 数据闸门 | 未成年人隐私泄露 | 年龄校验、家长同意、数据最小化 |
| 内容闸门 | 不当内容进入与输出 | 提示词护栏、输入输出过滤 |
| 诚信闸门 | 代写、抄袭 | 禁用项、AI 使用声明、过程留痕 |
| 管控闸门 | 教师失控、无法追溯 | 租户级开关、审计日志、用量限额 |

## 三、第一道闸门：未成年人数据保护

未成年人数据是教育合规里最硬的一条线。多数大模型服务的条款要求用户达到一定年龄，而 8 年级及以下学生的年龄显然低于这个门槛，因此教育场景不能让学生直接面对模型，必须由应用层代持会话、统一代理。

落地时要处理四件事。第一是年龄校验：注册与登录环节必须区分学生、教师、家长三种身份，并按年龄段限制可用能力，低年级账号默认关闭自由对话。第二是家长同意：涉及个人信息处理前，要有可留痕的同意流程，且家长有权随时撤回，撤回后数据应按规则删除。第三是数据最小化：只传输完成任务所需的最少上下文，不把学生姓名、班级、成绩、家庭信息等敏感字段拼进 prompt，避免这些数据随请求发送到模型侧。第四是数据保留期限：对话记录按学期或学年设定保留策略，到期自动清理，不允许无限期囤积学生数据。

## 四、第二道闸门：内容安全过滤

课堂里的模型输出必须经过内容安全过滤，因为低龄学生的判断力有限，一句不恰当的输出就可能造成投诉，甚至引发家校信任危机。过滤要做在两侧：输入侧拦截不当提问与诱导性内容，输出侧拦截暴力、色情、医疗建议、广告、联系方式等风险内容。

提示词护栏是第一条防线：在 system prompt 里固定角色设定、语气、回答长度和禁区，让模型默认以"课堂助教"而非"全能助手"的身份回答。第二条防线是规则层过滤：对输入输出做关键词与分类器双重检查，命中即降级为预设的兜底回复，而不是把风险内容原样转发给学生。第三条防线是人工抽查：教师可以随时查看任何一次会话记录，发现异常即可冻结账号或调整策略。

## 五、第三道闸门：学业诚信

禁令讨论里最尖锐的部分是学业诚信。学生用模型代写作文、代做作业，会让评价体系整体失真，这也是学校最抗拒 AI 进课堂的原因。教育接入必须默认带诚信设计：对写作、考试等任务设置禁用项；对允许 AI 参与的任务，要求输出 AI 使用声明；关键作业要求模型输出与课堂表现交叉验证，而不是只看一份作业。

工程上可以给每个任务打上类型标签，网关根据任务类型决定是否放行生成类请求。例如作文题默认只允许启发式回答（给出思路框架、写作提纲、素材建议），不允许输出全文；客观题只允许解题过程校验，不允许直接给答案。类型标签随请求头传入网关，由租户策略统一判定，应用层不需要为每个学科写不同的判断逻辑。

## 六、第四道闸门：教师可控性与审计留痕

教师可控性决定了产品能否在学校落地。教师需要的是：按班级、科目、课时开关模型能力；查看班级与单个学生的用量；查看任意一次会话；一键冻结异常账号。这些能力应放在租户级管理台，而不是散落在代码里，否则一所学校几十个班级根本管不过来。

审计留痕则是最后一道兜底。每次请求至少要记录：请求 ID、租户 ID、用户角色、模型名称、prompt 摘要、输出摘要、过滤命中项、token 用量、时间戳。记录必须防篡改、可导出，且符合数据最小化原则——只存摘要不存全文，避免审计库变成新的隐私风险点。审计数据按租户维度提供查询接口，配合教师控制台形成完整的"可查、可管、可追溯"闭环。

## 七、教育场景合规清单

接入前可以按这张清单逐项自查，任何一项不满足都不建议直接上线：

| 编号 | 检查项 | 状态 |
| --- | --- | --- |
| 1 | 学生/教师/家长身份是否分离 | 待确认 |
| 2 | 未成年人年龄校验是否生效 | 待确认 |
| 3 | 家长同意流程是否可留痕、可撤回 | 待确认 |
| 4 | 数据最小化：敏感字段不进 prompt | 待确认 |
| 5 | 输入侧内容过滤是否启用 | 待确认 |
| 6 | 输出侧分类器与兜底回复是否就绪 | 待确认 |
| 7 | 写作/考试任务禁用项是否配置 | 待确认 |
| 8 | AI 使用声明是否嵌入任务流 | 待确认 |
| 9 | 教师控制台是否可查用量与会话 | 待确认 |
| 10 | 审计日志是否防篡改、可导出 | 待确认 |

## 八、教育场景专用配置：护栏、过滤、禁用项、限额

教育场景的专用配置可以统一为一份租户策略，包含四类字段：提示词护栏、内容过滤规则、任务禁用项、用量限额。示例配置如下：

```json
{
  "tenant": "school_0142",
  "guardrail_prompt": "系统设定为中学语文辅导助手，只提供启发式引导，不直接给出作文全文，语气友好，回答不超过200字。",
  "input_filter": ["暴力", "色情", "辱骂", "诱导作弊"],
  "output_filter": ["医疗建议", "投资建议", "联系方式"],
  "blocked_tasks": ["essay_full_text", "exam_answer"],
  "quota": {
    "per_student_per_day_tokens": 20000,
    "max_response_tokens": 500,
    "allowed_hours": ["08:00-21:00"]
  }
}
```

这套配置的核心思想是"默认拒绝、按需放行"：护栏约束模型角色，过滤规则兜住风险内容，禁用项挡住诚信风险，配额锁死单日成本。策略以租户为单位下发，一所学校一份配置，互不干扰。

## 九、4sapi 网关接入：租户级策略 Python 示例

把上面这份策略挂到 4sapi 网关后，应用层代码可以保持干净，合规逻辑全部下沉到网关。接入方式与 OpenAI 兼容接口一致，只需替换 base_url 与 API Key：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SAPI_API_KEY"],
    base_url="https://4sapi.com/v1",
)

def classroom_chat(tenant_id: str, message: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "系统设定为中学语文辅导助手，只做启发式引导。"},
            {"role": "user", "content": message},
        ],
        max_tokens=500,
        extra_headers={
            "X-Tenant-Id": tenant_id,
            "X-User-Role": "student",
            "X-Task-Type": "essay_guidance",
        },
    )
    return response.choices[0].message.content
```

网关根据 X-Tenant-Id 加载该校策略，按 X-Task-Type 判断是否命中禁用项，按 X-User-Role 决定是否进入配额池。应用层不需要在代码里写任何过滤逻辑，策略变更只改配置、不改代码，这是教育场景最需要的运维形态——一所学校上千名教师，谁都不该靠改代码来调整 AI 开关。

## 十、审计留痕 Python 示例

请求完成后，网关把结构化审计事件写入审计队列，应用可以同步订阅或异步拉取。只存摘要、不存全文的写法同时满足"能追溯"与"不囤积敏感原文"两个要求：

```python
import time
import hashlib
import requests

def push_audit(tenant_id, request_id, prompt, response, filter_hits):
    event = {
        "request_id": request_id,
        "tenant_id": tenant_id,
        "prompt_sha256": hashlib.sha256(prompt.encode()).hexdigest(),
        "response_sha256": hashlib.sha256(response.encode()).hexdigest(),
        "filter_hits": filter_hits,
        "timestamp": int(time.time()),
    }
    requests.post("https://4sapi.com/v1/audit", json=event, timeout=5)
```

审计事件落库后按租户维度提供查询接口，教师端"查看某次会话"、监管侧"调取某时段记录"都建立在它上面。摘要哈希不暴露正文，即使审计库被拖走，也无法还原学生对话原文，这是未成年人数据保护里容易被忽略的一环。

## 十一、负载均衡与成本控制

教育场景的流量特征非常集中：请求集中在教学时段、集中在同一批课程任务里，寒暑假几乎为零。因此网关侧的负载均衡要按"峰值弹性、闲时收缩"来设计，而不是按全天最高水位买断资源。

成本控制上要关注三类：一是模型 token 费用，教育场景回复普遍要短，max_response_tokens 限制在 300-500 能显著降低成本；二是过滤与审计的附加开销，关键词过滤可以本地完成，分类器调用只在疑似命中时触发；三是并发控制，网关按租户限流，避免某个班级的突发任务挤占全校配额。用量限额（per_student_per_day_tokens）既是合规手段，也是成本锁——单日 token 失控在夜间自动兜底。

## 十二、成本与风险提示

成本上，教育场景按用量收费，需要提前预估四块：模型 token 费用、内容过滤与分类器的调用费用、审计存储费用、教师控制台与治理链路的开发维护费用。建议先小范围试点一个班级或一所学校，用真实教学流量校准参数，再决定是否规模化。

风险上要特别注意三点。一是合规风险：不同地区对未成年人数据的要求不同，接入前需要按目标地区逐条核对，不能拿一份配置打天下。二是误判风险：内容过滤器的关键词可能误伤正常教学用语（例如生物课讲"吸毒危害"时命中"毒品"关键词），需要持续用真实课堂数据校准过滤规则，并对误伤保留人工放行通道。三是依赖风险：不要在应用层写死具体模型，保留通过网关切换模型的能力，以便应对政策、价格与模型可用性的变化。

## 十三、总结

纽约的禁令把教育接入 AI 的合规问题推到了台前：未成年人数据保护、内容安全过滤、学业诚信、教师可控性与审计留痕，五件事缺一不可。教育科技接入的正解不是绕过限制，而是把合规做成租户级架构能力——通过 4sapi 网关（https://4sapi.com ）统一执行策略、过滤与审计，让每一所学校都能以合规的方式使用大模型能力，也让禁令有朝一日从"必须执行"变成"无需执行"。
