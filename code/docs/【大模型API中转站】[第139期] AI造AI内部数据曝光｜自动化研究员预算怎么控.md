# 【大模型API中转站】[第140期] AI造AI内部数据曝光｜自动化研究员预算怎么控

OpenAI 首次曝光"AI 造 AI"内部数据，自动化研究员路线图一路指到 2028 年；这一期 4sapi（https://4sapi.com）把自举循环的编排与预算控制拆开讲，重点回答一个没人给出标准答案的问题：自动化实验到底怎么控预算。

## 一、OpenAI 曝光了什么

今天 OpenAI 首次放出"AI 造 AI"的内部数据：自动化能力自举（AI 造 AI）路线图明确指向 2028 年训练出 AI 研究员。黄仁勋高调祝贺，直接表态 AGI 已到来。比起"AGI 是否已到来"的争论，我读到的是另一层工程含义——模型开始训练模型，实验开始设计实验，整条链路从"人驱动"切换成"循环驱动"。

循环驱动意味着两件事同时发生：单轮任务的人类监督密度大幅下降，单位时间内的计算消耗指数上升。前者是能力问题，后者是钱的问题。而钱的问题，恰恰是所有打算跟进的团队最容易忽视的问题。

## 二、三条旁证拼出同一方向

同一天前后，还有三条信息把方向拼得更完整。

旁证一：OpenAI 公开发文称"更好的模型会开辟新的工作领域"。言下之意，模型越强，能自动接管的岗位级任务就越多，自动化研究员不是科幻，而是路线图上的下一站。

旁证二：OpenAI 总裁发帖预测"未来的 AI，不用人费劲学"，学习曲线交给模型侧。人类侧的学习成本趋近于零，代价是模型侧的编排与验证成本全部转移到预算表上。

旁证三：Anthropic 一名研究员因对"失控"AI 的担忧辞职，安全隐忧正式从外部讨论蔓延进顶级实验室内部。顶级实验室一边加速自举，一边有人因失控风险离开，这个张力本身就是成本。

三条拼在一起，我看到的信号只有一个：自动化的推进速度，已经明显快于预算治理的速度。

## 三、痛点：自动化实验烧钱且不可逆

自动化研究员的第一特征不是"聪明"，而是"烧钱且不可逆"。这是我在接入实践中体会最深的一点。

先说烧钱。一个自举循环跑起来，每小时可能消耗数百次 API 调用加大量 GPU 时长；更糟的是成本曲线是超线性的——模型越强，单个实验越长，每轮实验的 token 消耗越大。预算不做闸门，账单会以天为单位失控。

再说不可逆。坏样本一旦混进训练集，后续所有轮次都被拖下水；评测集过拟合会让"分数上涨"变成自我欺骗；权重漂移发生之后没有回滚按钮。钱的损失可以复盘，不可逆的损失只能吞下。

所以我的结论很直接：预算治理必须先于能力建设被设计，不是"跑起来再补"的选修课。

## 四、原理速览：数据自举循环

先看循环本身。所谓 AI 造 AI，落到工程上就是一条数据自举循环（bootstrap loop）：

```text
任务池 → 自动实验 → 验证 → 筛选 → 再训练 → 合格数据回流任务池
```

四个节点各司其职：

- **任务池**：候选研究问题与数据生成任务的队列，是整个循环的入口，也是预算的第一道闸门位置；
- **自动实验**：R&D Agent 从任务池取任务，调用模型设计实验、执行实验、产出结果；
- **验证**：用独立评测集与人工抽检核对结果质量，这是整条循环里唯一可以低成本叫停的位置；
- **筛选与再训练**：按收益阈值筛选合格结果，合成数据回流训练集，模型能力提升后再派生新任务回填任务池。

循环每转一圈，模型能力上一个台阶，任务池的复杂度也上一个台阶。能力可以自举，成本不会自举——每一圈的账单都比上一圈更贵，这就是必须引入预算治理的根本原因。

## 五、自举循环成本构成

把循环拆成账目，才谈得上控制。我给出一张"自举循环成本构成"表，六个环节的消耗、属性与失控信号一目了然：

| 环节 | 主要消耗 | 成本属性 | 失控信号 |
| --- | --- | --- | --- |
| 任务池维护 | 人工整理、向量检索、去重 | 固定成本 | 任务积压、重复实验 |
| 自动实验 | LLM API、GPU、工具调用 | 随并发线性增长 | 单轮 token 超预算 |
| 验证评估 | 评测集构建、人工抽检 | 隐性成本 | 通过率异常升高 |
| 筛选合并 | 代码审查、数据清洗 | 容易被低估 | 脏数据悄悄入库 |
| 再训练 | GPU 集群、权重存储 | 陡增成本 | 训练不收敛、过拟合 |
| 审批监督 | 人工复核工时 | 常被漏算 | 审批积压、走形式 |

这张表里最容易翻车的是最后两行：再训练的成本曲线最陡，审批监督的成本最容易被漏算。预算表如果只记 API 与 GPU，不记人工复核工时，账面上"便宜"的循环实际上每天都在透支。

## 六、Python 教程：实验编排伪代码

预算治理落到代码上，就是四个组件：预算闸门、实验排队、失败止损、结果回流审批。下面给出编排层的伪代码，跑在循环之外，不碰模型内部。

**预算闸门：任何实验开工前，先问钱够不够。**

```python
class BudgetGate:
    """预算闸门：任何实验开工前，先问钱够不够"""

    def __init__(self, daily_cap, total_cap):
        self.daily_cap = daily_cap      # 当日预算上限（元）
        self.total_cap = total_cap      # 循环总预算上限（元）
        self.spent_today = 0
        self.spent_total = 0

    def allow(self, est_cost):
        """预估成本放行；超任意一档预算都拒绝"""
        return (self.spent_today + est_cost <= self.daily_cap
                and self.spent_total + est_cost <= self.total_cap)

    def commit(self, cost):
        """实验结束后实际记账"""
        self.spent_today += cost
        self.spent_total += cost
```

**实验排队：控制并发，防止循环自我加速。**

```python
class ExperimentQueue:
    """实验排队：控制并发，防止循环自我加速"""

    def __init__(self, max_concurrency=2):
        self.tasks = deque()
        self.max_concurrency = max_concurrency
        self.running = 0

    def submit(self, task):
        self.tasks.append(task)

    def pop_next(self):
        """并发未满且队列非空时才放行"""
        if self.running < self.max_concurrency and self.tasks:
            self.running += 1
            return self.tasks.popleft()
        return None

    def release(self):
        self.running -= 1
```

**失败止损：连续退化的实验提前终止，不把预算烧在没有希望的轮次上。**

```python
class StopLoss:
    """失败止损：连续退化的实验提前终止"""

    def __init__(self, patience=3, min_score=0.3):
        self.patience = patience
        self.min_score = min_score

    def should_stop(self, history):
        """连续 patience 轮不进步，或低于底线分数，就止损"""
        if len(history) < self.patience:
            return False
        recent = history[-self.patience:]
        if recent[-1] < self.min_score:
            return True
        return all(recent[i] >= recent[i + 1] for i in range(len(recent) - 1))
```

**结果回流审批：人工点头，数据才进训练集。**

```python
class ApprovalGate:
    """结果回流审批：人工点头，数据才进训练集"""

    def __init__(self, approval_threshold):
        self.approval_threshold = approval_threshold

    def review(self, result):
        """分数低于阈值直接拒收；达标的转人工审批"""
        if result.score < self.approval_threshold:
            return "REJECT"
        return human_review(result.id)   # 人工审批接口，返回 APPROVE / REJECT
```

**主循环：把四个组件按顺序串起来。**

```python
def bootstrap_loop(gate, queue, stopper, approver):
    while True:
        task = queue.pop_next()                    # 1. 排队取任务
        if task is None:
            break
        est = estimate_cost(task)                  # 2. 成本预估
        if not gate.allow(est):                    # 3. 预算闸门：钱不够就挂起
            hold_for_next_day(task)
            continue
        result = run_experiment(task)              # 4. 自动实验（带超时与重试）
        gate.commit(result.cost)                   # 5. 记账
        score = evaluate(result)                   # 6. 独立评测集验证
        history = track(task.id, score)
        if stopper.should_stop(history):           # 7. 失败止损：终止退化实验
            kill(task.id)
            queue.release()
            continue
        decision = approver.review(result)         # 8. 结果回流审批
        if decision == "APPROVE":
            merge_into_train_set(result)           # 9. 审批通过才进训练集
            queue.submit(derive_next_task(result)) # 10. 派生新任务回填
        queue.release()
```

这套编排的要点是顺序：闸门在最前，止损在验证之后，审批在回流之前。四个组件缺任何一个，循环都会在某个维度上失控——缺闸门烧钱，缺排队自加速，缺止损空耗，缺审批污染训练集。编排层只负责治理，模型能力由模型自己负责。

## 七、安全治理：权限隔离、人工审批水位与监督成本

预算之外，安全治理是自举循环的第二根支柱，三件事必须同时落地。

**权限隔离。** 数据源一律只读挂载，实验在沙箱内执行；工具集按最小权限签发，网络出口走白名单；模型拿到的凭证只够"做实验"，不够"改系统"。自举循环里的模型既是研究者又是执行者，权限不隔离，一次坏样本就可能变成一次越权操作。

**人工审批水位。** 数据回流训练集之前必须经过人工审批；单任务成本超过设定水位自动冻结，等人工复核再解冻；删除权重、发布产物这类高危动作要求双人复核。审批不是流程表演，而是循环唯一的人类刹车。

**监督成本要入账。** Anthropic 研究员因担忧"失控"而辞职这件事，说明对齐与监督在顶级实验室里都是真金白银的支出，不是口号。我把对齐成本（红队测试、独立评测、人工复核、权限审计）单列一个预算科目，而不是塞进"合规杂费"。监督工时一旦不入账，循环就会"看起来便宜，实则失控"——等到失控才补监督，成本比预先计提贵一个数量级。

## 八、企业接入建议：先托管试水，别急着自建

对企业的第一句建议：不要盲目自建自动化研究员。自建意味着同时自建五样东西——任务池、评测集、沙箱、审批流、监控，缺一样循环就失控。而五样全部自建，上线周期以月计，试错成本全部自己扛。

我的建议路径是先托管后内化：先用托管智能体小规模试水，把编排与治理交给平台侧，用真实业务数据验证 ROI；确认投入产出比之后再逐步把核心环节内化到自有系统。接入阶段的统一记账，可以用 4sapi（https://4sapi.com）做统一 API 入口，把多家模型的 token 消耗汇总成一张预算表，按天分桶、按任务记账，先解决"钱花在哪"再讨论"钱怎么省"。

合规红线只有一条：只走官方授权与合法中转接入，评估编排与预算治理可以谈，任何绕过限制的方案都不碰。

## 九、个人接入建议：从单轮自动实验起步

个人做自动化研究，最忌一步到位上循环。我的做法是从单轮自动实验起步：固定一个评测集、一个任务池、一个日预算上限，先跑 100 次小实验，统计收益分布。

收益分布决定一切。如果 100 次实验里绝大多数结果低于阈值，说明当前任务池的难度超过了模型能力，循环转起来也只是空转烧钱；如果通过率稳定且成本可预测，再考虑把单轮升级成完整循环。个人场景里，预算闸门和失败止损两个组件优先实现，审批可以简化为"每日一次人工过目"，但绝不能省略。

## 十、成本与风险提示

成本账本三件套：token 计量、GPU 时长、人工复核工时。三者缺一，预算表就是假的。

风险清单六条：

- **评测集过拟合**：模型对着评测集刷分，验证环节失灵，循环空转；
- **训练数据污染**：坏样本通过审批进入训练集，后续轮次全部受牵连；
- **API 抖动**：一次超时触发无限重试，单个实验烧掉整个日预算；
- **权限泄漏**：沙箱不隔离，实验过程触达生产数据；
- **循环失控**：缺少并发上限，任务派生速度超过消化速度；
- **审批走形式**：人工复核变成点按钮，刹车失灵。

三条实操技巧：每天零点重置日预算，让失控最多只烧一天的钱；每个实验携带唯一 id，成本、日志、结果全部可回溯；监控指标只看"通过率 × 单位成本"，单独看通过率会被高成本轮次带偏。另备一个紧急熔断开关，一键停掉整个循环。

## 十一、验收清单

上线自举循环前，逐项核对这张清单：

- [ ] 预算闸门在实验开始前拦截超预算任务，日预算与总预算双上限生效
- [ ] 并发上限已配置，且运行时可以动态调低
- [ ] 失败止损能在连续退化时提前终止实验
- [ ] 任何数据回流训练集之前经过人工审批，阈值水位可调
- [ ] 沙箱权限最小化，数据源只读，网络出口走白名单
- [ ] 对齐与监督工时已单独计入预算科目
- [ ] 全链路日志可回溯，实验可复现，成本按任务归因
- [ ] 存在一键熔断开关，且开关权限与实验权限分离

八项全过再放流量；任何一项不过，先把那一项补上。
