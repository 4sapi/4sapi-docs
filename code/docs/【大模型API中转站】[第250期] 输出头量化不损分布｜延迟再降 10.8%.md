# 【大模型API中转站】[第250期] 输出头量化不损分布｜延迟再降 10.8%

量化的常见叙事是"用精度换成本"。但有一类优化不走交换：它在量化**之前**做一个数学上等价的变换，把模型推到更容易量化的形态，精度与延迟同时改善。

这类方法在输出头上效果最明显，因为输出头随词表规模线性增长，在小模型里是显著成本项。我在 4sapi（https://4sapi.com）上做推理侧的量化评估时，把它作为低比特部署前的标准准备步骤。

## 一、成本在哪：输出头随词表放大

Transformer 的最后一步是把隐藏状态映射到词表维度。词表越大，这个映射的参数量与计算量越大。对参数量本身不大的模型，输出头占总参数的比例会明显上升，成为量化收益最集中的位置。

这解释了为什么同样做 W4，不同模型的收益差异很大：收益取决于**基线量化把预测扭曲了多少**。扭曲本就轻微的位置，再怎么调也没有空间；扭曲严重的位置，调一下就有明显改善。

## 二、重参数化做了什么

方法本身不复杂：在量化前，从输出头的每一行减去"词表行均值的标量倍数"，然后用**验证 KL** 为该系数做一维搜索，分别针对 RTN、激活加权 MSE 与全 Hessian GPTQ 三种量化器选定系数。

关键在于它的性质：

- 这一维搜索的取值范围内**包含原始输出头**与固定均值中心化，所以搜索不会比现状更差；
- 变换**保持全精度 softmax 分布不变**，不改变已训练好的 decoder；
- 对 soft-capping 这类非线性 logit 路径，用**秩一修正**处理；
- 对平移兼容的输出头，**不增加任何推理操作**，并保持打包 W4 执行。

换句话说，这是一个"先选一个更适合被量化的等价表示，再量化"的步骤。

## 三、效果量级

在 **7 个输出头**上的实测显示，W4 的收益集中在基线量化严重扭曲预测之处。一个具体数字：在 Phi-4-mini 上，激活加权 MSE 的 KL 从 **0.936 降到 0.256**。

其余几条同样值得记录：

- 收益在**更强的 GPTQ 校准**下依然存在，说明不是校准不足造成的假象；
- 与精确逐通道缩放、仿射量化**互补**，可以叠加使用；
- 在 4 个输出头与 3 个 W4 量化器上，用 WikiText 选定后**冻结的系数**也能迁移到 C4 与 OpenWebMath：在系数不等于 1 的 **18 个比较中全部优于均值中心化**，其余 6 个持平；
- 在作为压缩压力测试的 **W2** 下，收益扩展到几乎整个"模型-量化器"矩阵；
- 在 decoder 保持 BF16 时，量化输出头使**批大小为一的生成延迟相对 BF16 头基线降低 10.8%**。

最后一条是这类工作里少见的组合：**保真度提升与延迟下降同时发生**。

## 四、一个反直觉的解读

匹配残差分析给出了一个容易被误读的结论：保真度提升**可以伴随着更大的 logit 重建误差**，同时降低残差的 Fisher 加权代价。

也就是说，"重建误差变小"并不是这类方法有效的必要条件。真正起作用的是误差的**分布位置**——同样的误差量级，落在对最终决策影响小的地方就无害，落在影响大的地方就有害。Fisher 加权代价衡量的正是后者。

这给评估方式提了个要求：**不要只用重建误差判断量化质量**。重建误差是中间量，与下游表现的关联并不稳固。

同一条观察还解释了为什么"更精细的量化粒度"不一定更优。逐通道缩放、仿射量化这些手段降低的是每个通道内的误差幅度，但它们不改变"哪些位置的误差更影响决策"。如果误差仍然集中落在 Fisher 加权代价高的位置，把幅度压小只能换来有限的改善。这也是重参数化与细化粒度可以叠加的原因——两者作用在不同的维度上：一个调整误差的分布位置，一个压缩误差的幅度。

实践含义是，评估量化方案时应当同时看"误差有多大"和"误差落在哪"。只优化前者，会在某个点之后遇到收益停滞，而那个点往往不是方法的上限，只是维度选错了。

顺着这个思路，量化方案的选型顺序也应当调整：先确认待量化的表示是否还有改进空间（重参数化这一步是否有收益），再决定用多细的粒度去压误差。反过来做，会先投入精力做精细粒度，等收益停滞时才发现问题在表示形态上，前面的调参工作大部分要重来。这是一个顺序上的省力技巧，实际执行中能省下不少重复评估。

关于"冻结系数能否跨数据集使用"这一点，实测的边界值得说清：在 4 个输出头与 3 个 W4 量化器的组合上，用 WikiText 选定后冻结的系数迁移到 C4 与 OpenWebMath 时，在系数不等于 1 的 18 个比较中全部优于均值中心化，其余 6 个持平。这说明**系数对校准数据的依赖比想象中弱**——它捕捉的是输出头自身的结构性特征，而不是某个数据集的分布细节。但可迁移不等于可以直接套用到别的模型：换底座意味着输出头的结构特征变了，系数仍应重新选定。把它理解为"同一模型内可复用、跨模型要重算"更稳妥。

## 五、另一条线：解决指导陈旧

量化流程里还有一类误差来自优化过程本身。GPTQ 类方法已成事实标准，但存在两个互补局限：

**局部逐层目标的方法缺乏全局监督**；而**全局目标的方法在开始时固定 Hessian 估计并忽略一阶梯度**，随着量化逐块推进，这份指导会**变得陈旧**——误差累积之后，早期算出的方向已经不再适用。

G²PTQ 的做法是在**全局监督的块级优化目标**下整合一阶与二阶信息：每量化一个 Transformer 块之前**刷新梯度与 Hessian 估计**，避免指导陈旧；同时引入**信赖域缩放机制**，动态约束梯度步长以防权重更新爆炸；并给出块级 Hessian 近似与精确梯度补偿的高效实现。

它解决的是"量化算法自身的漂移"，与输出头重参数化解决"待量化表示的形态"是两个不同层面，因此可以叠加。

把这两条线放在一起看，量化误差的来源就清楚了：一类来自**表示形态**（同样的权重，换一种等价写法就更好量化），一类来自**优化过程**（指导用的是早期算出的方向，越往后越不准）。前者的修法是在量化前做变换，后者的修法是在量化中持续刷新估计。两者都不改变全精度输出，所以都不需要重新训练，也不需要重新标定模型能力——这正是它们适合放进既有部署流程的原因。

## 六、两类方法的分工

| 方法 | 作用位置 | 解决的问题 | 是否改变全精度输出 |
| --- | --- | --- | --- |
| 输出头重参数化 | 量化之前 | 待量化表示的形态不好 | 否，分布不变 |
| G²PTQ | 量化过程之内 | 梯度与 Hessian 指导陈旧 | 否，但改变量化结果 |
| 逐通道缩放 / 仿射量化 | 量化粒度 | 通道间尺度差异 | 否，与上述互补 |

三者叠加的顺序是：先重参数化选好表示，再在块级量化中刷新指导，最后按需附加更细的量化粒度。

整条量化流水线的位置关系可以画成这样：

```text
全精度模型
    |
    v
[1] 输出头重参数化 ── 选一个功能等价的表示（分布不变，不增推理操作）
    |
    v
[2] 块级量化 ──────── 每块量化前刷新梯度与 Hessian，信赖域约束步长
    |
    +-- 逐通道缩放 / 仿射量化（可叠加）
    |
    v
[3] 保真度评估 ────── KL 主判据 + Fisher 加权代价交叉验证
    |
    +-- 不达标 -> 回到 [1] 重选系数，或调整 [2] 的校准集
    |
    v
[4] 延迟实测 ──────── 单批测量，观察是否保持打包执行
    |
    v
低比特模型
```

顺序中有一个容易做反的地方：**保真度评估应当在延迟实测之前**。若先测延迟再看保真度，很容易因为延迟收益可观而放松保真度要求；反过来先卡住保真度，延迟就只是一个加分项。把两道关卡的先后定下来，可以避免评估被结果倒推。

## 七、保真度指标怎么选

不同指标衡量不同的事，混用会得出错误结论：

- **KL 散度**：输出分布与全精度分布的偏离，最接近"模型行为变了多少"；
- **激活加权 MSE**：按激活幅度加权的误差，关注实际被用到的位置；
- **logit 重建误差**：中间量，不能单独作为质量判据；
- **Fisher 加权代价**：误差对最终决策的影响，最贴近下游表现。

我的用法是：用 KL 做主判据，用 Fisher 加权代价做交叉验证，重建误差只作参考。

## 八、W4 与 W2 的适用判断

低比特是否可用，取决于任务容忍度，不取决于平均指标。判断顺序建议是：

先看**主流程任务**在 W4 下是否可接受——多数情况下可以。再看**长尾与边界任务**：需要精确数值、长链条推理、或对格式极其敏感的场景，量化误差更容易被放大。只有在这些场景也验证通过时，才考虑继续下探到 W2。

把 W2 当作"压缩压力测试"而不是生产目标，是更稳妥的定位：它用来暴露方法的收益边界，说明还有多少余量。

## 九、量化前后对照评测脚本

下面这段脚本用同一批样本对比量化前后的输出与延迟，并把 KL 与延迟同时记录下来。

```python
import os, time, math, json
import requests

BASE_URL = os.getenv("MODEL_BASE_URL", "https://4sapi.com/v1")
API_KEY = os.getenv("FOURSAPI_API_KEY", "")

REF_MODEL = os.getenv("MODEL_REF", "baseline-bf16")   # 全精度基线
Q_MODEL = os.getenv("MODEL_QUANT", "candidate-w4")     # 量化候选


def logprobs(model, prompt, top_k=20):
    """取前 top_k 个候选及其对数概率，用于近似比较输出分布。"""
    resp = requests.post(
        f"{BASE_URL}/chat/completions",
        headers={"Authorization": f"Bearer {API_KEY}"},
        json={"model": model, "temperature": 0, "max_tokens": 1,
              "logprobs": True, "top_logprobs": top_k,
              "messages": [{"role": "user", "content": prompt}]},
        timeout=60,
    )
    resp.raise_for_status()
    content = resp.json()["choices"][0]["logprobs"]["content"][0]
    return {t: lp for t, lp in content["top_logprobs"].items()}


def kl_divergence(p, q):
    """以基线 p 为参考，计算候选 q 的 KL；缺失项按极小概率兜底。"""
    floor = 1e-12
    eps = 1e-6                      # 把 logprob 转成概率时的归一化底数
    total = 0.0
    for token, lp in p.items():
        pp = math.exp(lp)
        qp = math.exp(q.get(token, math.log(floor) if lp < 0 else 0.0))
        total += pp * math.log((pp + eps) / (qp + eps))
    return total


def timed(model, prompt):
    t0 = time.perf_counter()
    logprobs(model, prompt)
    return time.perf_counter() - t0


if __name__ == "__main__":
    with open(os.getenv("EVAL_SET", "./probe_prompts.json"), encoding="utf-8") as f:
        prompts = json.load(f)

    kls, lat_ref, lat_q = [], [], []
    for pr in prompts:
        p = logprobs(REF_MODEL, pr)
        q = logprobs(Q_MODEL, pr)
        kls.append(kl_divergence(p, q))
        lat_ref.append(timed(REF_MODEL, pr))
        lat_q.append(timed(Q_MODEL, pr))

    n = len(prompts)
    print(f"样本数: {n}")
    print(f"平均 KL: {sum(kls) / n:.6f}   最大 KL: {max(kls):.6f}")
    print(f"平均延迟 基线 {sum(lat_ref) / n * 1000:.1f} ms -> 量化 {sum(lat_q) / n * 1000:.1f} ms")
    print(f"延迟变化: {(sum(lat_q) - sum(lat_ref)) / sum(lat_ref) * 100:+.1f}%")
```

两个使用要点：一是**探针提示词要覆盖主流程与边界两类**，只在主流程上测会把长尾问题掩盖掉；二是延迟要**单批测量**，批处理会把输出头的相对收益稀释，看不出真实差别。

## 十、成本与风险提示

- **低比特对特定任务的风险不可忽略**。数值计算、长链条推理、严格格式输出这三类任务建议单独验证。
- **校准集选择会带来偏差**。校准数据偏离实际流量时，量化结果会偏向校准集覆盖的分布。用真实流量采样做校准更稳。
- **"保真度提升但重建误差变大"是正常现象**。按第 4 条的解释理解，不要因此否定方法。
- **冻结系数的可迁移性有边界**。实测在跨数据集比较中优于均值中心化，但这不等于可以任意换模型套用；换底座仍应重新验证。
- **量化收益与模型结构强相关**。输出头占比高的模型收益更明显，占比低时投入产出比会下降。

## 结论

量化不一定是精度与成本的交换。输出头重参数化给出了一个反例：在量化前做一次保持分布的等价变换，W4 的保真度显著改善，同时在打包 W4 下把单批生成延迟再降 10.8%，且不增加推理操作。配合解决指导陈旧的块级梯度与 Hessian 刷新，量化流程本身的漂移也被收住了。落到操作上，三件事最值得先做：把重参数化加进量化前的准备步骤、用 KL 与 Fisher 加权代价替代重建误差作为主判据、按主流程与边界分层做对照评测。我在 4sapi.com 上固定这套评测口径之后，判断一个量化方案能不能上线的时间缩短了很多。
